# Debugging in VS Code and Visual Studio

A **debugger** pauses your program so you can look inside. It's how you find **logic errors**: the program runs, but gives the wrong answer.

> **Optional video above.** Part of freeCodeCamp's *Learn C#: Full Course with Mini-Projects* (6:26:00 to 6:50:14, about 24 min), coding the same ideas in Visual Studio. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

| Key | Does |
|---|---|
| F9 | put a **breakpoint** on the line (or click left of the line number) |
| F5 | start debugging; it stops at the breakpoint |
| F10 | **step over**: run this line |
| F11 | **step into**: go inside the method on this line |
| Shift+F11 | step out of the method |

While paused, the **Variables** (Locals) panel shows every value, **Watch** follows the expressions you choose, and **Call Stack** shows how you got here. Form a guess ("I think `total` is wrong after the loop"), stop just before that point, and check.
