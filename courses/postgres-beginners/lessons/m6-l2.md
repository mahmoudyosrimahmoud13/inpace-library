# Upserts: ON CONFLICT

"Insert this, but if it already exists, do something else" is an **upsert**.

## Ignore duplicates

```sql
INSERT INTO customers (first_name, last_name, email)
VALUES ('Sara', 'Ali', 'sara@example.com')
ON CONFLICT (email) DO NOTHING;
```

Perfect for imports you might run twice: rows already there are skipped, no error.

## Update the existing row

```sql
INSERT INTO customers (first_name, last_name, email, country_code)
VALUES ('Sara', 'Ali', 'sara@example.com', 'AE')
ON CONFLICT (email)
DO UPDATE SET country_code = EXCLUDED.country_code,
              last_name    = EXCLUDED.last_name;
```

`EXCLUDED` is the row you **tried** to insert. The conflict target (`(email)`) must have a unique constraint or index.

## A counter that creates itself

```sql
CREATE TABLE page_views (page text PRIMARY KEY, views bigint NOT NULL DEFAULT 0);

INSERT INTO page_views (page, views) VALUES ('/pricing', 1)
ON CONFLICT (page) DO UPDATE SET views = page_views.views + 1;
```

This is safe even with many users at once: the database handles the race that a "SELECT, then INSERT or UPDATE" in your app would get wrong.

## MERGE

Postgres 15+ also supports the SQL-standard `MERGE` for more complex "insert, update or delete depending on a match" jobs, mostly used in data loading.
