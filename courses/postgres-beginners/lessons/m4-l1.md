# Aggregates: COUNT, SUM, AVG and GROUP BY

Aggregate functions turn many rows into one answer.

```sql
SELECT count(*)            AS customers,
       count(country_code) AS with_country,      -- count(column) skips NULLs
       min(birth_date), max(birth_date)
FROM customers;
```

Add an `orders` table to practise with:

```sql
CREATE TABLE orders (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id bigint NOT NULL,
    total       numeric(10,2) NOT NULL CHECK (total >= 0),
    status      text NOT NULL DEFAULT 'new',
    ordered_at  timestamptz NOT NULL DEFAULT now()
);
INSERT INTO orders (customer_id, total, status, ordered_at)
SELECT 1 + (random() * 999)::int, round((random() * 500)::numeric, 2),
       (ARRAY['new','paid','shipped','cancelled'])[1 + (random() * 3)::int],
       now() - (random() * interval '365 days')
FROM generate_series(1, 5000);
```

## GROUP BY: one answer per group

```sql
SELECT status, count(*) AS orders, sum(total) AS revenue, round(avg(total), 2) AS avg_order
FROM orders
GROUP BY status
ORDER BY revenue DESC;
```

Rule: every column in `SELECT` must be either **grouped** or inside an **aggregate**. "column must appear in the GROUP BY clause" means you broke it.

## HAVING: filter the groups

```sql
SELECT customer_id, count(*) AS orders, sum(total) AS spent
FROM orders
WHERE status <> 'cancelled'        -- filters ROWS before grouping
GROUP BY customer_id
HAVING sum(total) > 1000           -- filters GROUPS after
ORDER BY spent DESC
LIMIT 10;
```

## Group by time

```sql
SELECT date_trunc('month', ordered_at) AS month, count(*), sum(total)
FROM orders
GROUP BY 1                          -- 1 = the first SELECT column
ORDER BY 1;
```

If you've used pivot tables, this is the same idea in SQL.
