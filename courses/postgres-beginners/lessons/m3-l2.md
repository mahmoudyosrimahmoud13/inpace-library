# IN, BETWEEN, LIKE and ILIKE

```sql
SELECT * FROM customers WHERE country_code IN ('EG', 'SA', 'AE');
SELECT * FROM customers WHERE country_code NOT IN ('US');

SELECT * FROM customers WHERE birth_date BETWEEN '1990-01-01' AND '1999-12-31';   -- inclusive at both ends
```

## Pattern matching

| Pattern | Matches |
|---|---|
| `LIKE 'sa%'` | Starts with "sa" (case-sensitive) |
| `LIKE '%@gmail.com'` | Ends with @gmail.com |
| `LIKE '%ali%'` | Contains "ali" |
| `LIKE '_a%'` | Second letter is a |
| `ILIKE 'SA%'` | Like LIKE, ignoring case (a Postgres extra) |

```sql
SELECT email FROM customers WHERE email ILIKE '%@GMAIL.COM';
```

`LIKE '%word%'` can't use a normal index and scans every row. Fine for thousands of rows; for millions, the advanced course covers trigram indexes and full-text search.

## A note on NOT IN and NULL

If the list (or a subquery) contains a NULL, `NOT IN` returns no rows at all, because "is it different from unknown?" is unknown. Use `NOT EXISTS` with subqueries, or make sure there are no NULLs.

## Checking your work

```sql
SELECT count(*) FROM customers WHERE country_code IN ('EG', 'SA');
```

Counting before and after a filter is the fastest way to catch a WHERE clause that's wrong.
