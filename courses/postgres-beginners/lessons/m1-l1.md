# Start here: databases, SQL and PostgreSQL

A **database** keeps data so many people and programs can store, find and change it safely at the same time. A **relational** database keeps data in **tables** (rows and columns) that link to each other, and you talk to it in **SQL**.

| Concept | Spreadsheet word | Example |
|---|---|---|
| Table | Sheet | `customers` |
| Row | Row | One customer |
| Column | Column header | `email` |
| Primary key | A unique ID column | `id = 42` |
| Foreign key | A column pointing to another sheet's ID | `orders.customer_id -> customers.id` |

Why not just spreadsheets? A database enforces rules (no duplicate emails, no order for a customer who doesn't exist), handles thousands of users at once without overwriting each other, survives crashes, and answers questions over millions of rows in milliseconds.

## Why PostgreSQL

- Free and open source, around since the 1990s, extremely reliable.
- Follows the SQL standard closely, so what you learn transfers to MySQL, SQL Server, BigQuery and others.
- Powerful extras: JSON columns, full-text search, geospatial data (PostGIS), and extensions.
- The default choice for new projects at many companies, and on every cloud (AWS RDS, Google Cloud SQL, Azure, Supabase, Neon).
