# Dates, times and intervals

```sql
SELECT now();                         -- timestamptz: this moment
SELECT current_date;                  -- today
SELECT now()::date;                   -- cast a timestamp to a date
SELECT now() - interval '7 days';     -- a week ago
SELECT now() + interval '1 year 2 months';
SELECT age(date '1998-04-12');        -- 28 years 7 mons 5 days
SELECT extract(year FROM now()), extract(dow FROM now());   -- day of week, 0 = Sunday
SELECT date_trunc('week', now());     -- the start of this week
SELECT to_char(now(), 'YYYY-MM-DD HH24:MI');   -- format for display
```

## Everyday questions

```sql
-- orders in the last 30 days
SELECT count(*) FROM orders WHERE ordered_at >= now() - interval '30 days';

-- customers' ages
SELECT first_name, extract(year FROM age(birth_date)) AS age FROM customers WHERE birth_date IS NOT NULL;

-- orders per weekday
SELECT to_char(ordered_at, 'Day') AS weekday, count(*) FROM orders GROUP BY 1 ORDER BY 2 DESC;
```

## Time zones, done right

- Store moments as **`timestamptz`**. Postgres stores them in UTC and shows them in the session's time zone.
- `SET timezone = 'Africa/Cairo';` changes how they're **displayed**, not what's stored.
- Plain `timestamp` (without time zone) is "a wall-clock reading with no zone": confusing as soon as users or servers are in different zones.

## Filtering one day correctly

```sql
-- good: uses ranges (and can use an index on ordered_at)
WHERE ordered_at >= '2026-11-17' AND ordered_at < '2026-11-18'
-- avoid: wrapping the column in a function stops normal indexes being used
WHERE ordered_at::date = '2026-11-17'
```
