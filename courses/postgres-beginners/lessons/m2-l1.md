# Creating tables and choosing data types

```sql
CREATE TABLE customers (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    first_name  text        NOT NULL,
    last_name   text        NOT NULL,
    email       text        NOT NULL UNIQUE,
    country     text,
    birth_date  date,
    created_at  timestamptz NOT NULL DEFAULT now()
);
```

## The types you'll use most

| Type | For | Notes |
|---|---|---|
| `bigint` / `integer` | Whole numbers, IDs | `bigint` for IDs: you won't run out |
| `numeric(10,2)` | Money, exact decimals | Never use `float` for money |
| `double precision` | Measurements, science | Approximate |
| `text` | Any string | Same speed as `varchar(n)`; add a CHECK if you need a length limit |
| `boolean` | true / false | |
| `date` | A calendar day | |
| `timestamptz` | A moment in time | Always prefer it over `timestamp` (it stores UTC, shows your time zone) |
| `uuid` | Random unique IDs | Day 8 |
| `jsonb` | Flexible JSON documents | Searchable and indexable |

## IDs: identity columns

`GENERATED ALWAYS AS IDENTITY` makes Postgres number rows 1, 2, 3... automatically. Older tutorials use `serial`; identity is the modern standard way to do the same.

## Changing tables later

```sql
ALTER TABLE customers ADD COLUMN phone text;
ALTER TABLE customers RENAME COLUMN country TO country_code;
ALTER TABLE customers DROP COLUMN phone;
\d customers
```

## Naming habits

- Lower case with underscores: `order_items`, `created_at`. (Mixed case forces you to quote names forever.)
- Plural table names or singular: pick one and stick to it.
- Every table gets a primary key.
