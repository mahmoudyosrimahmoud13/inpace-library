# Build: scores, and the price of guidance

Section 20.3 looks at diffusion from a second angle: the **score**, `∇ ln p(z)`, the direction in which the density rises
fastest. Predicting the noise and predicting the score turn out to be the same job. Section 20.4 then uses scores to
**steer** generation towards a label, with a knob, the guidance scale λ, that trades variety for accuracy. Today you
measure both, on data simple enough that every score can be computed exactly.

## 1. Noise prediction is score estimation

Take data from a Gaussian `N(1, 0.5²)` and noise it to step `t`. Then `z_t` is Gaussian too, with a known mean and
variance, so its true score is a straight line: `∇ ln p(z_t) = −(z_t − mean) / variance`.

Denoising score matching (section 20.3.1) never uses that formula. It only sees pairs (noisy `z_t`, noise `ε` that was
added), and fits a function to the target `−ε / √(1 − α_t)`. Fit a straight line to those targets by least squares, and
compare it with the true score.

```python
import numpy as np

T = 500
beta = np.linspace(1e-4, 0.04, T)
alpha = np.cumprod(1 - beta)

rng = np.random.default_rng(0)
t = 100
a = alpha[t]
x = rng.normal(1.0, 0.5, 500_000)
eps = rng.normal(size=x.shape)
z = np.sqrt(a) * x + np.sqrt(1 - a) * eps
target = -eps / np.sqrt(1 - a)                          # what denoising score matching regresses on

slope, intercept = np.polyfit(z, target, 1)             # the best straight line through (z, target)
mean, var = np.sqrt(a) * 1.0, a * 0.25 + (1 - a)
print(f"fitted from noisy examples: score(z) = {slope:+.3f} z {intercept:+.3f}")
print(f"true score of p(z_t):       score(z) = {-1 / var:+.3f} z {mean / var:+.3f}")
```

```output
fitted from noisy examples: score(z) = -1.980 z +1.610
true score of p(z_t):       score(z) = -1.981 z +1.610
```

The two lines agree, although each single target is pure noise. On average over many examples, the noise you added
points back towards where the data came from, and that average is exactly the score. So a network trained to predict
noise is, up to the factor `−1/√(1 − α_t)`, a network that estimates the score. That's the bridge between sections 20.2
and 20.3.

## 2. Two classes, and guided sampling

Now the data has two labelled classes that **overlap**, like real classes do (some 3s look like 8s): "left" from
`N(−1, 0.8²)` and "right" from `N(+1, 0.8²)`, equally common. At every
noise level both the **conditional** score `∇ ln p(z_t | c)` and the **unconditional** score `∇ ln p(z_t)` of the mixture
have exact formulas. Classifier-free guidance (equation 20.60) samples with

```text
score(z, c, λ) = λ ∇ ln p(z | c) + (1 − λ) ∇ ln p(z)
```

λ = 0 ignores the label, λ = 1 is the plain conditional model, λ > 1 pushes further.

```python
mu, sd = {"left": -1.0, "right": 1.0}, 0.8

def class_score(z, t, c):
    m, v = np.sqrt(alpha[t]) * mu[c], alpha[t] * sd ** 2 + 1 - alpha[t]
    return -(z - m) / v, -(z - m) ** 2 / (2 * v) - 0.5 * np.log(v)     # score, and log density (up to a constant)

def mixture_score(z, t):
    (sl, ll), (sr, lr) = class_score(z, t, "left"), class_score(z, t, "right")
    w_right = 1 / (1 + np.exp(ll - lr))                                 # p(right | z_t), by Bayes' theorem
    return (1 - w_right) * sl + w_right * sr

def sample(c, lam, n=100_000, seed=1):
    rng = np.random.default_rng(seed)
    z = rng.normal(size=n)
    for t in range(T - 1, -1, -1):
        score = lam * class_score(z, t, c)[0] + (1 - lam) * mixture_score(z, t)
        eps = -np.sqrt(1 - alpha[t]) * score                           # score -> predicted noise
        mean = (z - beta[t] / np.sqrt(1 - alpha[t]) * eps) / np.sqrt(1 - beta[t])
        z = mean + np.sqrt(beta[t]) * rng.normal(size=n) if t > 0 else mean
    return z

print("asking for class 'right' (real 'right' values: mean 1.00, spread 0.80, 89% of them above 0)")
for lam in [0, 1, 3, 7]:
    z = sample("right", lam)
    print(f"guidance {lam}: mean {z.mean():+.2f}, spread {z.std():.2f}, share above 0 {np.mean(z > 0):.1%}")
```

```output
asking for class 'right' (real 'right' values: mean 1.00, spread 0.80, 89% of them above 0)
guidance 0: mean +0.00, spread 1.28, share above 0 50.2%
guidance 1: mean +1.00, spread 0.80, share above 0 89.4%
guidance 3: mean +1.55, spread 0.62, share above 0 99.9%
guidance 7: mean +1.88, spread 0.60, share above 0 100.0%
```

Read the table from the top:

- **λ = 0** ignores the request: the samples follow the whole mixture, centred at 0.
- **λ = 1** samples the true conditional distribution: mean 1.00 and spread 0.80, like real "right" values, including
  the 11% of them that fall on the left side because the classes overlap.
- **λ = 3 and λ = 7** make almost every sample clearly "right", but at a price. The samples move **past** the real centre
  (pushed away from anything that could look "left"), and their spread shrinks well below the real 0.80.

That's section 20.4's warning in numbers: strong guidance buys samples that unmistakably match the label, at the expense
of **diversity** and of faithfulness to the real data. Image generators use guidance scales well above 1 because people
prefer clear, typical pictures; the cost is that the results look more alike. You'll see the same trade-off with real
digits in the module project.

## What to take away

- Predicting the added noise and estimating the score are the same task, up to a known factor.
- Guidance mixes a conditional and an unconditional score; λ above 1 pushes samples towards the label.
- More guidance means more on-target samples, and less variety.
