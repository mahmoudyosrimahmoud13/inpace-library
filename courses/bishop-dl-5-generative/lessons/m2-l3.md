# Build: change of variables, and a coupling layer by hand

A normalizing flow is an invertible function between a simple distribution and the data. Everything rests on one
formula, the **change of variables** (equation 18.1): if `x = f(z)` and `z = f⁻¹(x)`, then

```text
p_x(x) = p_z(f⁻¹(x)) · |det J(x)|,     J = the Jacobian of f⁻¹ at x
```

Today you check that formula numerically, then build a real NVP coupling layer (section 18.1) in NumPy and verify its
two promises: it's exactly invertible, and its Jacobian determinant is cheap.

## 1. The formula, in one dimension

Take `z ~ N(0, 1)` and `x = exp(z)`. Then `z = ln x`, and `dz/dx = 1/x`, so the formula predicts
`p_x(x) = N(ln x | 0, 1) / x`. Check it against a histogram of a million samples.

```python
import numpy as np

rng = np.random.default_rng(0)
x = np.exp(rng.normal(0, 1, 1_000_000))
normal = lambda u: np.exp(-u ** 2 / 2) / np.sqrt(2 * np.pi)
p_x = lambda v: normal(np.log(v)) / v                       # change of variables

counts, edges = np.histogram(x, bins=[0.25, 0.5, 1, 2, 4])
for lo, hi, c in zip(edges[:-1], edges[1:], counts):
    grid = np.linspace(lo, hi, 2001)
    predicted = np.trapezoid(p_x(grid), grid)
    print(f"x in [{lo}, {hi}): samples {c / len(x):.4f}   formula {predicted:.4f}")
```

```output
x in [0.25, 0.5): samples 0.1611   formula 0.1613
x in [0.5, 1.0): samples 0.2556   formula 0.2559
x in [1.0, 2.0): samples 0.2554   formula 0.2559
x in [2.0, 4.0): samples 0.1622   formula 0.1613
```

The `1 / x` factor is the whole story: stretching space spreads probability thinner, squeezing concentrates it. Leave it
out and the "density" wouldn't even add up to 1.

## 2. One coupling layer

Real NVP splits the input into two halves `(x_A, x_B)`. The first half passes through untouched and decides how to scale
and shift the second (equations 18.10 and 18.11):

```text
z_A = x_A,     z_B = exp(s(x_A)) ⊙ x_B + t(x_A)
```

`s` and `t` can be any functions at all, even huge neural networks: the layer stays invertible, because `x_A` is known
on the way back too. Here they're small random networks in two dimensions.

```python
rng = np.random.default_rng(1)
W1, W2 = rng.normal(0, 1, (1, 16)), rng.normal(0, 0.5, (16, 2))
def s_and_t(xa):
    h = np.tanh(xa @ W1)
    out = h @ W2
    return np.tanh(out[:, :1]), out[:, 1:]                # a gentle scale s, and a shift t

def forward(x):                                           # data -> latent, and log |det J|
    xa, xb = x[:, :1], x[:, 1:]
    s, t = s_and_t(xa)
    return np.hstack([xa, xb * np.exp(s) + t]), s[:, 0]

def inverse(z):                                           # latent -> data
    za, zb = z[:, :1], z[:, 1:]
    s, t = s_and_t(za)
    return np.hstack([za, (zb - t) * np.exp(-s)])

x = rng.normal(0, 1, (5, 2))
z, log_det = forward(x)
print("largest error after going forward and back:", np.abs(inverse(z) - x).max())
```

```output
largest error after going forward and back: 2.220446049250313e-16
```

Invertible to the last digit of floating point, with no equation solving: the backward pass just undoes the shift and
the scale.

## 3. The cheap determinant

Because `z_A` doesn't depend on `x_B`, the Jacobian is triangular (equation 18.14), and its determinant is the product of
the diagonal: `exp(s)`. So `log |det J| = s`, one number we already computed. Check it against a Jacobian built the slow
way, by finite differences.

```python
def numeric_log_det(point, eps=1e-6):
    J = np.zeros((2, 2))
    for j in range(2):
        d = np.zeros((1, 2)); d[0, j] = eps
        J[:, j] = (forward(point + d)[0] - forward(point - d)[0])[0] / (2 * eps)
    return np.log(abs(np.linalg.det(J)))

for i in range(3):
    print(f"point {i}: log|det J| from s = {log_det[i]:+.6f},  from finite differences = {numeric_log_det(x[i:i+1]):+.6f}")
```

```output
point 0: log|det J| from s = -0.570749,  from finite differences = -0.570749
point 1: log|det J| from s = -0.377075,  from finite differences = -0.377075
point 2: log|det J| from s = -0.627197,  from finite differences = -0.627197
```

They agree. In `D` dimensions a general determinant costs about `D³` operations; this one costs `D`. That's what makes it
possible to train flows on images with millions of dimensions by maximum likelihood (equation 18.3), which is exactly
what you'll do, in two dimensions, in the module project.

## What to take away

- A flow's density is the simple density at `f⁻¹(x)`, times how much `f⁻¹` stretches space there.
- Coupling layers are invertible by construction, whatever networks compute `s` and `t`.
- Their Jacobian is triangular, so the log-determinant is just a sum.
- One layer only changes half the coordinates, so flows alternate which half is fixed.
