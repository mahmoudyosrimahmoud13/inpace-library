# Binary, hex, MAC addresses and Ethernet

## Just enough binary

IP addresses and masks are binary numbers written in a friendly way. One byte (8 bits) holds 0 to 255:

| Bit value | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|---|
| 192 = | 1 | 1 | 0 | 0 | 0 | 0 | 0 | 0 |
| 168 = | 1 | 0 | 1 | 0 | 1 | 0 | 0 | 0 |
| 255 = | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |

To convert 200: 128 fits (72 left), 64 fits (8 left), 32 no, 16 no, 8 fits (0). So `11001000`. Practise until it's quick; subnetting depends on it.

**Hexadecimal** uses 0-9 and a-f, one digit per 4 bits: `ff` = 255, `0a` = 10. MAC addresses and IPv6 are written in hex.

## MAC addresses

A **MAC address** is a 48-bit hardware address on a network card: `3c:22:fb:1a:9e:07`.

- The first half usually identifies the maker; the second half is the card.
- It only matters **on the local network**. Routers replace the Ethernet header at every hop; the IP addresses stay the same end to end.
- Phones and laptops now use **random MACs** per Wi-Fi network for privacy.

```bash
ip link            # link/ether ... is your MAC
```

## An Ethernet frame

```text
| dest MAC | source MAC | type (0x0800 = IPv4) | payload: the IP packet (up to 1500 bytes) | checksum |
```

That 1500-byte payload limit is the **MTU**. Bigger IP packets must be split, or (better) not sent: Day 7.

## Same network or not?

A host decides by comparing the destination IP with its own address and **subnet mask**:

- Same network: send straight to the host's MAC (found with ARP, next lesson).
- Different network: send to the **default gateway's** MAC, and let the router handle it.
