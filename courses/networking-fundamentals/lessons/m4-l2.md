# The internet: summarization and BGP

## Route summarization

Routers can't list every network on Earth one by one. They **summarize**: four networks `10.1.0.0/24` to `10.1.3.0/24` can be announced as one `10.1.0.0/22`. Good address planning makes summaries possible, which keeps routing tables small and fast.

## Autonomous systems and BGP

The internet is about 75,000 **autonomous systems** (ASes): networks run by one organization (an ISP, a cloud, a university), each with a number (Google is AS15169).

```mermaid
flowchart LR
  A["Your ISP (AS 1)"] -- BGP --> B["Transit provider (AS 2)"]
  B -- BGP --> C["Cloud provider (AS 3)"]
  C --- S["The server you want"]
```

- Inside an AS, an interior protocol (OSPF, IS-IS) finds the fastest paths.
- Between ASes, **BGP** exchanges "I can reach these prefixes". It's chosen by **policy and business deals** as much as by speed.
- A wrong BGP announcement can send a big chunk of the internet the wrong way. Famous outages (Facebook 2021) were BGP mistakes.

## Seeing the path

```bash
traceroute -n example.com      # each hop, by sending packets with TTL 1, 2, 3...
mtr -n example.com             # a live traceroute with loss and latency per hop
```

Reading `mtr`:

- Loss at **one** middle hop but not after it: that router just deprioritizes replies to you. Usually harmless.
- Loss that starts at a hop and **continues to the end**: a real problem from that hop on.
- A big jump in latency between two hops: often an ocean crossing. Light in fibre travels about 200 km per millisecond.
