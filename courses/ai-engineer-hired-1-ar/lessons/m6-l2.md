# انشر واكتب README وسجّل عرضًا

## النشر

الرابط الحي يحوّل «بنيتُ» إلى «جرّبه». تشغّل [Hugging Face Spaces](https://huggingface.co/docs/hub/spaces-sdks-docker) تطبيقات Docker، وفيها فئة CPU مجانية وقت كتابة هذا الدرس (اضبط `app_port: 8000` في رأس ملف README الخاص بالـ Space). وضع مفتاح API في **أسرار** المضيف، لا في الصورة أبدًا. والفئات المجانية تنام عند الخمول، فيكون أول طلب بعدها بطيئًا: اذكر ذلك في README.

## ملف README الذي يقرؤه المراجعون

1. **سطر واحد:** ماذا يفعل ولمن، ورابط العرض الحي والفيديو.
2. **صورة أو GIF.**
3. **مخطط معماري:** المستندات ← القطع ← BM25 + التضمينات ← RRF ← النموذج مع المصادر ← الواجهة البرمجية.
4. **النتائج:** جداول تقييمك (الاسترجاع والإجابات) وتكلفة السؤال.
5. **القرارات والموازنات:** حجم القطع، والبحث الهجين، والرفض، ولماذا لا توجد قاعدة بيانات متجهية بعد.
6. **الحدود والخطوات التالية:** ما يخطئ فيه وما ستفعله لو كان لديك وقت أطول.
7. **التشغيل:** ثلاثة أوامر.

## فيديو العرض

دقيقتان بصوتك: المشكلة، وإجابة جيدة مع مصدرها، ورفض لسؤال لا جواب له، وجدول التقييم، وموازنة واحدة. ويلاحظ الدليل أن المتقدمين الذين يرسلون فيديو قصيرًا مع المهام المنزلية يتميزون، والأمر نفسه ينجح مع مشاريع معرض الأعمال.
