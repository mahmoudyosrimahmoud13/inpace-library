> الفيديو بالإنجليزية: إن أردت مشاهدته فشغّل الترجمة (**CC**)، ثم **الإعدادات ← الترجمة ← ترجمة تلقائية ← العربية**.

```bash
git add forgotten.txt
git commit --amend -m "Add login form"   # replaces the last commit (new hash)
git commit --amend --no-edit             # same message, just add what you staged
```

## تراجَع عن commit عند الجميع: revert

`git revert <hash>` يصنع commit **جديدًا** يعمل العكس. ويبقى التاريخ كما هو، لذلك هو آمن بعد أن ترفع عملك.

```bash
git revert a1b2c3d        # opens the editor with "Revert ..." as the message
git revert HEAD            # undo the last commit
```

## أرجِع الفرع للخلف: reset

`git reset` ينقل فرعك إلى commit أقدم. وتختلف الأوضاع الثلاثة في مصير تغييرات الـ commits التي تتركها خلفك:

| الأمر | الـ commits التي بعده | منطقة التجهيز | ملفاتك |
|---|---|---|---|
| `git reset --soft HEAD~1` | تختفي من الفرع | التغييرات تبقى **مجهَّزة** | لا تتغير |
| `git reset HEAD~1` (mixed، الافتراضي) | تختفي | تُفرَّغ | التغييرات تبقى **في ملفاتك** |
| `git reset --hard HEAD~1` | تختفي | تُفرَّغ | **التغييرات تُحذف** |

و `--soft` مفيد لدمج آخر عدة commits في واحد: `git reset --soft HEAD~3` ثم `git commit` واحد.

## القاعدة

**لا تُعِد كتابة commits صارت عند غيرك** (amend و reset و rebase على عمل مرفوع): يتوقف تاريخهم عن مطابقة تاريخك. للعمل المرفوع استخدم `revert`، وللعمل الذي على جهازك فقط أعد الكتابة بحرية.
