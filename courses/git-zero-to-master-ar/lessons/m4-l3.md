# تعارضات الدمج

إذا غيّر الفرعان نفس الأسطر، لا يستطيع Git الاختيار بدلًا منك. فيتوقف ويعلّم الملف:

> **فيديو اختياري في الأعلى.** جزء من كورس freeCodeCamp *Git for Professionals* (مع Tower)، من 24:07 إلى 33:48. كل ما تحتاجه موجود في النص أدناه، فشاهده فقط إن كان يفيدك: يحفظ inPace المكان الذي توقفت عنده.
>
> الفيديو بالإنجليزية: إن أردت مشاهدته فشغّل الترجمة (**CC**)، ثم **الإعدادات ← الترجمة ← ترجمة تلقائية ← العربية**.

```text
<<<<<<< HEAD
<h1>Welcome back</h1>
=======
<h1>Hello again</h1>
>>>>>>> login
```

ما بين `<<<<<<<` و `=======` هو جانبك (HEAD)، وما بين `=======` و `>>>>>>>` هو جانبهم. ولحل التعارض:

1. `git status` يسرد الملفات التي فيها تعارض ("both modified").
2. عدّل كل ملف: احتفظ بجانب، أو بالآخر، أو بمزيج، و**احذف أسطر العلامات الثلاثة**. ويعرض VS Code أزرارًا: *Accept Current* و *Accept Incoming* و *Accept Both*.
3. `git add` لكل ملف أصلحته.
4. `git commit` (يكتب Git الرسالة بدلًا منك).

غيّرت رأيك؟ `git merge --abort` يعيد كل شيء كما كان قبل الدمج.

```bash
git checkout --ours styles.css      # take your whole version of one file
git checkout --theirs styles.css    # take theirs
git config --global merge.conflictStyle zdiff3   # also show the original lines, which makes conflicts easier to read
git config --global rerere.enabled true          # remember how you solved a conflict and reuse it next time
```

**تعارضات أقل:** اجعل الفروع قصيرة العمر، وادمج main فيها كثيرًا، ولا تعِد تنسيق ملفات كاملة في فرع ميزة.
