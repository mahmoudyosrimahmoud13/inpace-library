# عُدّة الإنقاذ

| المشكلة | الحل |
|---|---|
| رسالة خطأ في آخر commit | `git commit --amend` |
| نسيت ملفًا في آخر commit | `git add f && git commit --amend --no-edit` |
| حفظت على main بدل فرع (غير مرفوع) | `git branch feature && git reset --hard HEAD~1 && git switch feature` |
| حذفت فرعًا | `git reflog`، وابحث عن آخر commit له، ثم `git branch name <hash>` |
| ‏`reset --hard` أبعد من اللازم | `git reset --hard HEAD@{1}` (أو hash من الـ reflog) |
| دمج لم تُرده (غير مرفوع) | `git reset --hard ORIG_HEAD` |
| commit مرفوع سيئ | `git revert <hash>` |
| دمج مرفوع سيئ | `git revert -m 1 <merge-hash>` |
| rebase ساء | `git rebase --abort` (أثناءه) أو `git reset --hard ORIG_HEAD` (بعده) |
| عدّلت ملفًا وتريد القديم | `git restore --source=<hash> file` |
| كل شيء غريب | `git status` ثم `git reflog`: يخبرانك دائمًا أين أنت |

## رُفع سرّ بالخطأ

1. **ألغِه أولًا** (كلمة مرور جديدة، مفتاح API جديد). افترض أن البوتات نسخته بالفعل، فهي تفحص GitHub خلال دقائق.
2. ثم، إن لزم، احذفه من التاريخ بـ [git filter-repo](https://github.com/newren/git-filter-repo) (`git filter-repo --replace-text secrets.txt`) وارفع بالقوة. وعلى الجميع أن ينسخوا المستودع من جديد. وتبقى النسخ القديمة والـ forks تحمله، ولهذا الخطوة 1 هي الأهم.

وميزة **push protection** في GitHub (في إعدادات أمان المستودع) تمنع كثيرًا من صيغ الأسرار المعروفة قبل أن تصل.
