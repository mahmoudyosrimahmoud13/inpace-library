# ما الذي يفعله merge و rebase حقًا

مع فهم الكائنات والمراجع تصبح الأوامر الكبيرة بسيطة:

- **commit:** يكتب blobs و trees للملفات المجهَّزة، ويكتب كائن commit أبوه commit الـ HEAD، ثم ينقل مرجع الفرع إليه.
- **merge:** يجد **merge base** (أحدث جد مشترك، `git merge-base main login`)، ويجمع تغييرات الطرفين منذه، ويكتب commit له **أبَوان**.
- **rebase:** لكل commit من commits الخاصة بك، يطبّق تغييره على القاعدة الجديدة ويكتب commit **جديدًا** بأب جديد، ثم ينقل مرجع الفرع. وتبقى الـ commits القديمة موجودة (في الـ reflog) حتى ينظّف Git.
- **reset:** ينقل مرجع الفرع (ومنطقة التجهيز وملفاتك حسب الوضع).
- **fetch:** ينزّل الكائنات الناقصة ويحدّث `refs/remotes/origin/*`.

عندما تفهم هذا يتوقف Git عن كونه مخيفًا: كل أمر تقريبًا يكتب كائنات وينقل مراجع.

```bash
git merge-base main login        # the common ancestor
git log --oneline main..login     # commits on login that main doesn't have
git log --oneline --left-right main...login   # commits on either side, marked < and >
```
