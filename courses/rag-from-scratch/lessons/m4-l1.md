# Hybrid search: combine, don't choose

BM25 and embeddings fail on different questions. BM25 misses when the words differ ("folder" against "directory").
Embeddings miss when an exact name matters or a word has two senses ("copy" a file against the `copy` module). So
production RAG systems run both and **merge** the results. This is **hybrid search**.

## Merging two ranked lists

The scores can't be added: a BM25 score of 12 and a cosine of 0.6 mean nothing to each other, and their ranges change
from question to question. **Reciprocal rank fusion (RRF)** ignores the scores and uses only positions:

score(document) = sum over lists of 1 / (60 + its rank in that list)

A document ranked 1st in one list gets 1/61; 10th gets 1/70. A document that appears high in **both** lists beats one
that's first in only one. The 60 keeps a single first place from dominating. It's simple, has nothing to tune, and is
hard to beat.

## More than one view of each document

You can index the same document several ways and fuse them all. Docstrings start with a one-line summary ("Recursively
delete a directory tree."), the sentence that best says what a function is for. Embedding only `name: summary` gives
a sharp vector per document, while chunk vectors carry the details. Other common views: a generated summary of a long
document, questions the document answers (written by a model at index time), or the title alone.

## Retrieve more, then narrow

Recall@10 is usually much higher than recall@5. Many systems retrieve 20 to 50 candidates cheaply, then **rerank**
them with a slower, more careful model (a cross-encoder, or an LLM asked "does this passage answer the question?")
and keep the top 5 for the prompt. Reranking can only promote what retrieval found, which is another reason to fuse
several retrievers first.
