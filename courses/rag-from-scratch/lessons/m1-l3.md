# Project 1: the corpus, a test set, and your own search engine

You'll load the 1,517 documents, build BM25 from scratch with an inverted index, and score it against a simple
baseline on the 45 test questions.

The code is above this text. Save it as `p01_bm25.py`, next to `common.py`, `pydocs.json` and `evalset.json`.

## Read the code

- **`common.py`** is shared by every project:
  - `load_docs()` returns the documents. Each one has an `id` (like `shutil.rmtree`), a `title` (the name and its
    arguments) and a `text` (the docstring).
  - `tokenize()` lowercases, splits `snake_case` and dotted names into words, and drops very common words ("the",
    "how", "do"), so `shutil.rmtree` becomes `shutil`, `rmtree`.
  - `evaluate(retrieve)` runs your search on all 45 questions and returns recall@5 and MRR. With `show_misses` it
    prints questions where no right document was in the top 5.
- **`BM25.__init__`** counts the words of every document (`self.tfs`), builds the **inverted index**
  (`self.postings`: each word → the documents that contain it, with counts) and the idf of each word.
- **`BM25.search`** only visits documents that contain a question word, through the postings. That's why one search
  over 1,517 documents takes a fraction of a millisecond.
- **`grep`** is the baseline: rank documents by how many question words they share, with no weighting at all.

What it shows:

- Word overlap finds a right document in the top 5 for under half of the questions. BM25 finds about the same number,
  but ranks them higher (MRR up from 0.26 to 0.34).
- Look at the misses. "Delete a **folder**": the docs say **directory** ("Recursively delete a directory tree.").
  "Create a directory and any missing **parent folders**": the docs say "intermediate" ones. People and documents use
  different words for the same thing. Keyword search can't see that, and that's tomorrow's and day 3's problem.

## Make it yours

1. Try `k1` of 0.5 and 3, and `b` of 0 and 1. Which matters more on this corpus, and why might short docstrings make
   `b` matter less?
2. Add **stemming**: a tiny rule that cuts endings (`-ing`, `-es`, `-s`, `-ed`). Does "copying" now match "copy"?
   Measure it.
3. Add five questions of your own to `evalset.json`, ones you'd really ask. Keep them for the rest of the course.
4. Make `search` return the top 5 in under 0.1 ms even for a 10-word question. Where does the time go?

## What to take away

- A RAG system is a search engine first. Build a test set before anything else.
- BM25 is a few lines of counting, fast, and hard to beat on exact names.
- Its weakness is vocabulary: it only matches the words people happen to use.
