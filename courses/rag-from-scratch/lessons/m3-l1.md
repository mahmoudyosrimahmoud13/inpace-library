# Embeddings: search by meaning

An **embedding** is a list of numbers (a vector) that stands for a piece of text, made so that texts with similar
meaning get similar vectors. "Delete a folder" and "remove a directory" share no words, but their vectors point in
nearly the same direction.

## Cosine similarity

To compare two vectors, RAG systems use **cosine similarity**: the cosine of the angle between them. 1 means the same
direction (same meaning), 0 means unrelated. If you scale every vector to length 1 first (**normalize**), cosine
similarity is just the dot product, so comparing a question with 2,000 chunks is one matrix multiplication.

## Where embeddings come from

**LSA (latent semantic analysis)** is the old way, and you'll build it: count words in every chunk (a big table, one
column per word), then use an SVD to squeeze each row to 256 numbers. Words that appear in the same chunks end up
along the same directions. It learns only from your own corpus, so it only knows the word pairs your documents
happen to use together.

**Trained embedding models** learned from billions of sentences which texts mean the same. They know "folder" and
"directory" are close even if your corpus never uses "folder". In this course you use **model2vec potion-base-8M**:
30 MB, runs on any CPU, embeds 2,000 chunks in about a second. Bigger models (like `nomic-embed-text` in Ollama, or
hosted ones) are more accurate and slower; the code doesn't change, only the model.

## A vector index

A **vector database** stores the vectors and finds the closest ones to a question vector. With a few thousand chunks,
comparing with all of them (brute force) takes under a millisecond, and it's exact. Millions of vectors need an
approximate index (like HNSW or IVF) that checks only promising regions, trading a little recall for speed. Start
with brute force; switch when you measure that it's too slow.

## What embeddings miss

Embeddings blur exact details. A question about `rmtree` may match chunks about deleting files in general. Rare
names, error codes and version numbers are exactly what keyword search is good at. You'll see both kinds of failure
in today's project.
