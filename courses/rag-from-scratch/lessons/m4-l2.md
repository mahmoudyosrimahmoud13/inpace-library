# Project 4: hybrid search with rank fusion

You'll add a second view of every document (its one-line summary), fuse three retrievers with RRF, and compare all
five setups on recall@5, recall@10 and MRR.

The code is above this text. Save it as `p04_hybrid.py`.

## Read the code

- **`rrf()`** takes any number of ranked lists and returns one list, ordered by the sum of `1 / (60 + rank)`.
- **`SummaryIndex`** embeds one line per document: the name without arguments, a colon and the first line of the
  docstring, like `shutil.rmtree: Recursively delete a directory tree.`
- **`runs`** holds the five retrievers. Each hybrid asks every retriever for its top 20, fuses, and keeps the top k.

## Run it

```bash
python p04_hybrid.py
```

What it shows:

- **The one-line summaries are the best single retriever.** One clean sentence per function matches questions better
  than paragraphs full of argument details.
- **Fusing all three gives the best MRR and the best recall@10**: right documents rank higher, and three in four
  questions now have a right document in the top 10. Recall@5 is a little below the summaries alone: fusion pulled up
  a few documents the other two liked.
- "Delete a folder" now finds `shutil.rmtree`, third. "Create a directory and any missing parent folders" still
  misses `os.makedirs`: its docstring calls it "Super-mkdir; create a leaf directory and all intermediate ones." No
  retriever connects "parent folders" with "intermediate ones".
- Some misses are near-misses: `json.JSONEncoder.encode` for "dict into a JSON string" is a reasonable answer, just
  not the one in the test set. Read your misses before trusting your numbers.

## Make it yours

1. Change RRF's `k` from 60 to 1 and to 1,000. What happens to the ranking, and why?
2. Weight the lists: give the summaries twice the weight of the others. Does MRR improve? Is that overfitting to 45
   questions?
3. Write a **reranker**: take the hybrid's top 20 and reorder them by a score you design (for example, BM25 on the
   summary line plus cosine on the summary). Does it lift recall@5 toward recall@10?
4. For `os.makedirs`, add a "questions it answers" view: write three questions by hand for 10 documents, embed them,
   and fuse that list in too. This is what systems do with a model at index time.

## What to take away

- Different retrievers fail differently; fusing them is cheap and reliable.
- RRF merges rankings without comparing scores.
- A short, clean view of each document can beat its full text.
