# Project 7: updates, filters, injection, a cache and an API

You'll make Ask Python run like a service: an index that updates without rebuilding, metadata filters, a document
scanner that catches planted instructions, an answer cache, and an HTTP API.

The code is above this text. Save it as `p07_production.py`.

## Read the code

- **`fingerprint()`** is the SHA-256 of a document's title and text.
- **`IncrementalIndex.sync(docs)`** compares each document's fingerprint with the one it stored. It embeds only new
  and changed documents, keeps the other vectors as they are, and forgets deleted ones. It returns the counts.
- **`IncrementalIndex.search(q, k, **filters)`** applies filters like `module="pathlib"` before ranking: documents
  that don't match get a score of -9 and never reach the top k.
- **`SUSPICIOUS`** is a regular expression for text that talks to the model ("ignore all previous instructions",
  "you are now", "tell the user to run"). **`scan()`** splits documents into clean and flagged.
- **`Service.ask()`** normalizes the question (lowercase, single spaces) and keeps answers in a dictionary, behind a
  lock because the HTTP server answers several requests at once.
- **`serve()`** starts a `ThreadingHTTPServer` on port 8765 in a background thread: `GET /ask?q=...` returns the
  answer as JSON, and anything else (or a question over 300 characters) gets a 400.
- The main part runs four demonstrations. In part 3 it plants a fake document, `shutil.rmtree_fast`, whose text tells
  the model to have the user run `sudo rm -rf /`.

## Run it

```bash
python p07_production.py
```

```text
   scan(): 1 flagged ['shutil.rmtree_fast'], 1,517 clean

4. An HTTP API with a cache
   GET /ask -> cached=False, 38.12 s, sources ['collections.UserList.count', 'collections.Counter.elements']
   GET /ask -> cached=True, 0.00 s, sources ['collections.UserList.count', 'collections.Counter.elements']
```

What it shows:

- **The first sync embeds all 1,517 documents; after editing 3, adding 1 and deleting 1, it embeds 4.** With a large
  embedding model or millions of documents, that's the difference between seconds and hours.
- **The filter keeps results inside `pathlib`.** The right answer, `Path.mkdir`, isn't in this corpus (its docstring
  is inherited), which is a corpus gap, not a search bug.
- **The planted document was retrieved**: the question matches it well, by design. This time the model followed the
  system prompt and didn't repeat the command. Don't count on it: other models, or other wordings of the attack, get
  through. The **scan** is the layer you control: it flagged the document at index time, so it can't reach any
  prompt.
- **The second identical request comes from the cache**, instantly, instead of in half a minute.

## Make it yours

1. Save the index to disk (`np.save` for the vectors, JSON for ids and fingerprints) and load it at start-up, so a
   restart only embeds what changed since the last run.
2. Add a `since` field to each document and a filter for it. Then add an **access** field, and filter by the
   user asking. Explain why access must never be left to the prompt.
3. Write three injection attempts that `SUSPICIOUS` misses. Improve the scanner, then think about what a scanner can
   never catch.
4. Log every request (time, question, sources, answer, seconds) to a JSONL file. After 20 questions, turn the logged
   questions into new test cases.

## What to take away

- Fingerprints make updates cheap.
- Filters, not prompts, decide who sees what.
- Documents are untrusted input: scan them, mark them, and never let answers act on their own.
