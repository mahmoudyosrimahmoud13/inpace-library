# Project 6: measure the answers, then fix the prompt

You'll run 12 test questions and 3 questions the docs can't answer through the assistant, check every answer five
ways, then try a stricter answer format and compare.

The code is above this text. Save it as `p06_evaluate.py`. It calls the model 30 times, so it takes several minutes
on a CPU.

## Read the code

- **`qs`** takes every 4th question of the test set (12) and adds 3 out-of-scope ones in `OUT_OF_SCOPE`.
- **`check()`** runs the five checks from the concept lesson:
  - `found`: a gold id is among the answer's sources.
  - `correct`: the answer contains the last part of a gold id, like `rmtree`.
  - `cited`: at least one `[n]` pointed back to a source.
  - `grounded`: every `module.function(` in the answer, where `module` is a real module, appears in the sources text.
    `NAME` is the regular expression that finds them.
  - `refused`: the refusal sentence, for out-of-scope questions.
- **`SYSTEM_V2`** adds a fixed format: `Answer:`, `Example:`, `Sources:`.
- **`run()`** swaps the system prompt in `p05_answer` and answers every question. Everything is saved to
  `answers_eval.json`.

## Run it

```bash
python p06_evaluate.py
```

The real output, with `qwen2.5:1.5b`:

```text
12 questions with known answers + 3 the docs can't answer

prompt v1                  found  42%  correct  58%  cited   0%  grounded  92%  refused 3/3  (352 s)
   right without the right source (from the model's memory): 2  ['Turn a Python dict into a JSON string', 'Replace every match of a pattern in a string']
prompt v2 (fixed format)   found  42%  correct  83%  cited  17%  grounded  83%  refused 3/3  (305 s)
   right without the right source (from the model's memory): 5  ['Turn a Python dict into a JSON string', 'Replace every match of a pattern in a string']

Every answer is in answers_eval.json. Read the wrong ones: the numbers tell you where, not why.
```

What it shows:

- **Retrieval is the bottleneck.** A right document reached the prompt for only 5 of these 12 questions.
- **Yet most answers are correct**, because the model knows Python. "Right without the right source" counts those:
  correct answers that the sources didn't support. With prompt v2 the model answers more of these from memory (the
  `defaultdict` and `secrets` questions it refused with v1).
- **The fixed format brought citations from 0 to a couple of answers**: a format with a `Sources:` line works a little
  better on a small model than a rule.
- **All three out-of-scope questions were refused** with both prompts.
- **Grounded dropped with v2**: when the model answers from memory, it calls functions (`logging.basicConfig`,
  `secrets.token_urlsafe`) the sources never mentioned.

So the next improvement isn't the prompt: it's retrieval (day 4's ideas, a reranker, better views of each document)
and, if you can, a bigger model.

## Make it yours

1. Run all 45 questions overnight, and make a table of the four groups: found and correct, found and wrong, not found
   and correct (memory), not found and wrong.
2. Add a **prompt v3** that tells the model to refuse when no source names a function for the task. Does "right
   without the right source" go down? What does it cost in correct answers?
3. Write an **LLM judge**: for each answer, ask the model "Is every statement in this answer supported by these
   sources? Reply YES or NO." Compare its verdicts with `grounded` on 12 answers. Where do they disagree?
4. Change one retrieval setting from day 4 and rerun. Does `found` move, and does `correct` follow?

## What to take away

- Measure retrieval and answers separately; their combination tells the real story.
- Mechanical checks are cheap and repeatable; read the failures by hand anyway.
- "Right from memory" isn't grounded, and won't be right on private data.
