# Evaluating RAG: search numbers and answer checks

Retrieval metrics (recall@k, MRR) tell you whether the right text reached the prompt. They don't tell you whether the
answer is any good. You need checks on the answers too, and enough of them to run after every change.

## What to check

| Check | Question it answers | How |
|---|---|---|
| Found | Did retrieval do its job? | A right document is among the sources |
| Correct | Is the answer right? | It names the expected function (or matches a reference answer) |
| Cited | Can the user verify it? | It contains at least one source number |
| Grounded (faithful) | Is everything in it supported by the sources? | Every API it calls appears in the sources |
| Refused | Does it know when to stop? | On questions the docs can't answer, it says the refusal sentence |

Some checks are mechanical, like the ones above. Others need judgment ("is this explanation faithful to the source?").
Teams use three ways to judge:

- **Rules in code**: fast, free, repeatable, but narrow.
- **An LLM as a judge**: a strong model reads the question, the sources and the answer, and says whether each claim is
  supported. Good at scale, but it has its own errors, so check it against human labels first.
- **People**: the ground truth, slow and expensive. Use them to label a small set and to check the judge.

## Read the failures together

The most useful number in RAG is the combination **correct but not found**: the answer is right, but the right
document wasn't in the sources. The model answered from memory. On public topics that looks like success; on your
private documents it's how confident wrong answers happen.

And always read the failing answers. "Correct 58%" says where to look, not why.

## Change one thing at a time

Keep the questions fixed, change one thing (the prompt, the chunk size, the model), and run everything again. Save
every answer, so you can compare versions line by line, not only their averages. With 15 questions, one question is
almost 7 points: treat small differences as noise.
