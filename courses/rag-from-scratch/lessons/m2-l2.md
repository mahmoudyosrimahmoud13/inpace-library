# Project 2: cut the documents, and measure each way

You'll cut the corpus three ways, with and without a title header, and measure recall and the size of the context
each way would send to the model.

The code is above this text. Save it as `p02_chunking.py`.

## Read the code

- **`fixed()`** takes 400 characters, steps forward 320, takes 400 again: 80 characters of overlap.
- **`by_paragraph()`** splits at blank lines (docstrings use them between sections) and glues small paragraphs
  together until the next one would pass about 500 characters.
- **`make_chunks()`** keeps, for every chunk, the id of its document (`doc`) and its position (`n`). With
  `header=True` the chunk starts with the document's title.
- **`chunk_search()`** builds BM25 (from project 1) over chunks. Several chunks can come from one document, so it asks
  for 4 × k chunks and keeps the first chunk of each document, until it has k documents. Your test set is about
  documents, so it can score any chunking the same way.
- The **top-5 context** column adds up the characters of the 5 best chunks for each test question, and averages it.

## Run it

```bash
python p02_chunking.py
```

The real output:

```text

fixed 400 chars, 80 overlap          2,340     303      536       53%  0.38       1,680 ch

The subprocess.Popen document (1,524 chars) as paragraph chunks: [363, 458, 496, 195]
   fixed-size chunk 2 starts mid-sentence: 'ecutable: A replacement program to execute.\n\n  stdin, stdout'
   paragraph chunk 2 starts cleanly:       'stdin, stdout and stderr: These specify the executed program'
```

What it shows:

- **Chunks beat whole documents** on both counts: higher recall, and a smaller context. The longest whole document
  is over 6,000 characters; the longest paragraph chunk is under 2,000.
- **Paragraph chunks with a title header win.** Remove the header and recall drops, because a chunk from the middle
  of `subprocess.Popen`'s docs no longer contains the word "Popen".
- Fixed-size chunks start in the middle of a word ("ecutable: ..."); paragraph chunks start at the beginning of an
  idea.

From now on the project uses paragraph chunks with headers.

## Make it yours

1. Try `by_paragraph(target=250)` and `target=1000`. Plot recall and context size against the target. Where would you
   set it?
2. Try `fixed()` with no overlap. Does recall change on this corpus? Why might overlap matter more for long prose,
   like a book?
3. Write a **heading-aware** splitter for Markdown files: cut at `#` headings, and put the heading path
   ("Install > On Windows") in each chunk's header.
4. Find the test question whose best chunk changed most between whole documents and paragraphs, and explain why.

## What to take away

- Chunk size is a trade: recall and focus against context cost. Measure both.
- Cut where the text's own structure cuts.
- A title in every chunk is the cheapest improvement in RAG.
