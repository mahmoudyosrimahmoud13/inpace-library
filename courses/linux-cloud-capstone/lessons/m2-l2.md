# Server images and configuration

Your servers should come up ready to serve, with nothing done by hand.

## Ansible roles

| Role | Does |
|---|---|
| `common` | Updates, time sync, `journald` limits, sysctl hardening, auditd, unattended security updates or Patch Manager tags, CloudWatch/OTel agents |
| `nginx` | Reverse proxy, `/health`, real client IP from the ALB, gzip, security headers |
| `app` | App user, directory permissions, systemd unit (Restart=on-failure, hardening options), env file written at boot from Parameter Store/Secrets Manager |

## systemd hardening (from the Linux courses)

```ini
[Service]
User=app
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/app
PrivateTmp=yes
```

`systemd-analyze security app.service` scores it; aim to get the exposure rating down.

## Bake with Packer

- A Packer template runs the `common` and `nginx` roles (and optionally `app`) on the latest official AMI.
- AMIs named with a timestamp; Terraform's `aws_ami` data source picks the newest.
- A scheduled CI job rebuilds the AMI weekly, so patches roll out as new images.

## Boot-time steps (user data)

Only what must be per-instance: fetch config and secrets, start the app, signal readiness. Keep it under ~30 seconds so instance refreshes are fast.

## Done means

Terminate an instance by hand: the replacement serves traffic with no manual steps, and `ansible-lint` passes in CI.
