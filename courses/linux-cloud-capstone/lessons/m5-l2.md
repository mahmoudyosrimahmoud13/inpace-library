# Write it up and show it

A project nobody can understand doesn't help your career. Package it.

## The README (top of the repo)

1. **One-paragraph summary** and the architecture diagram.
2. **What it demonstrates**: a bullet per area (IaC, CI/CD, security, observability, SRE) with a link to the file or doc that shows it.
3. **How to run it**: bootstrap, deploy staging, deploy prod, roll back, destroy.
4. **Results**: deploy lead time, rollback time, rebuild time, restore RTO/RPO, monthly cost estimate, SLOs met during the test period.
5. **Decisions**: link to the ADRs.
6. **What I'd do next** with more time (multi-region, Kubernetes, canary analysis, cost tuning).

## Evidence folder

Screenshots of: a full pipeline run, the dashboard during the game day, an alert notification, a PR with a Terraform plan comment, and the postmortem.

## Talk about it in an interview (2 minutes)

- The problem and the constraints (cost, one person, a week).
- The two decisions you're proudest of, and an alternative you rejected and why.
- One thing that broke during the game day, how you found it, and what you changed.
- One number that shows it works (rebuild in 18 minutes, rollback in 4).

## Clean up

Destroy staging and anything you don't need running; keep prod only if you want a live demo, and check the bill in a few days.

## You've finished the track

From what an operating system does to running a monitored, automated, recoverable cloud service. Keep going by repeating the game day every few months, adding one new tool at a time, and helping someone else through the track: teaching it is the best test that you know it.
