# Game day: break it and recover

Prove the system works when things go wrong. Run these in **staging** (or prod if you're brave and it's your own project), keeping a timeline.

| # | Break | Expect | Check |
|---|---|---|---|
| 1 | Terminate an app instance | ALB routes around it; ASG replaces it | No SLO burn; replacement healthy in minutes |
| 2 | Deploy a version with 10% errors | Burn-rate alert pages; you roll back | Time from deploy to alert, and alert to recovery |
| 3 | Stop the database (or reboot with failover) | Errors during the failover window; app reconnects | Does the app recover without a restart? |
| 4 | Fill a disk on one instance | Ticket alert fires before it's full | Runbook works |
| 5 | Change a security group in the console | Drift check catches it next morning (or run it now) | Issue opened |
| 6 | Lose staging completely | `terraform apply` + pipeline rebuild it | Total rebuild time |
| 7 | Restore the database from backup | Data back, app working | Real RTO and RPO |

## How to run it

1. Announce the plan, even if only to yourself in the timeline doc.
2. For each test: write the **hypothesis**, do it, watch the dashboard, record what actually happened and the times.
3. Stop immediately if something unexpected and harmful happens; that's a finding too.

## Afterwards

For the worst surprise of the day, write a **blameless postmortem** with owned action items, then fix at least one of them before you finish the course.

Most teams discover that some alert didn't fire, a runbook step was wrong, or a recovery took 5x longer than they thought. Finding that now is the whole point.
