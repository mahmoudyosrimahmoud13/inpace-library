# Security and backups review

Go through this checklist and fix every "no". Write the results in `docs/security.md`.

## Identity and access

- [ ] Root has MFA and no access keys; humans use Identity Center with MFA.
- [ ] No long-lived access keys anywhere (CI uses OIDC; instances use roles).
- [ ] Instance role limited to its own secrets, parameters, S3 prefix and logs.
- [ ] Break-glass admin role exists, is logged, and is tested once.

## Network

- [ ] No security group allows 0.0.0.0/0 except the ALB on 443/80.
- [ ] No SSH port open; admin access through Session Manager, sessions logged.
- [ ] Database and app instances have no public IPs.
- [ ] TLS everywhere users connect; HTTP redirects to HTTPS; TLS 1.2+.

## Servers and app

- [ ] IMDSv2 required; EBS encrypted; AMIs rebuilt at least monthly.
- [ ] systemd hardening options on the app service.
- [ ] No secrets in Git, AMIs, user data or logs (search with gitleaks; grep logs).
- [ ] Dependencies and images scanned in CI; Dependabot on.

## Data and recovery

- [ ] RDS automated backups 7+ days, deletion protection on; snapshot copied to a second region (optional).
- [ ] S3 versioning on; Block Public Access on.
- [ ] Terraform state bucket versioned and restricted.
- [ ] **Restore test done**: restore the database to a new instance from last night's backup, point a test copy of the app at it, record the time (your real RTO) and the data age (your real RPO).

## Audit

- [ ] CloudTrail on in all regions, delivered to a protected bucket.
- [ ] Budget alert and cost allocation tags in place.

## Done means

Every box is checked, or has a written reason and a date for fixing it.
