# Measure retrieval before you generate

If the right chunk isn't retrieved, no prompt can save the answer. Build a **golden set**: questions, each with the id of the chunk that holds the answer.

1. Write 30 questions yourself from real user needs, and find each answer's chunk.
2. Add 30 more by picking random chunks and writing a question each one answers (you can draft them with an LLM, then fix them by hand; LLM questions copy the chunk's words and make search look better than it is).
3. Save them in `evals/retrieval.jsonl`: `{"question": "...", "chunk_id": "handbook.pdf:12:0"}`.

```python
# evals/eval_retrieval.py
"""Hit rate@k and MRR on the golden set: each question names the chunk that holds its answer."""
import json

from docanswer.search import Searcher


def evaluate(searcher, golden, k=5):
    hits, reciprocal = 0, 0.0
    for row in golden:
        ids = [c["id"] for c in searcher.search(row["question"], k=k)]
        if row["chunk_id"] in ids:
            hits += 1
            reciprocal += 1 / (ids.index(row["chunk_id"]) + 1)
    return {"hit_rate": round(hits / len(golden), 3), "mrr": round(reciprocal / len(golden), 3)}


if __name__ == "__main__":
    golden = [json.loads(line) for line in open("evals/retrieval.jsonl", encoding="utf-8")]
    print(evaluate(Searcher(), golden))
```

## Read the numbers like an engineer

- **Hit rate@5:** how often the right chunk is in the top 5. **MRR:** how high it ranks on average (1.0 means always first).
- Compare **keyword only, vector only, and hybrid**, and two chunk sizes. Put the table in your README: it's the kind of evidence interviewers rarely see from candidates.
- Read every miss. Typical causes: the answer spans two chunks, a table was flattened, the question uses a synonym, or your golden label is wrong.
