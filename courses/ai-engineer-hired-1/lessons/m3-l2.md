# Set up the repository like a professional

Reviewers open your repository before they read your code. Make the first 30 seconds good:

```text
docanswer/
  docanswer/          the package: ingest.py, search.py, answer.py, api.py
  evals/              golden sets and evaluation scripts
  tests/              pytest tests
  data/raw/           your documents (or a script that downloads them)
  .env.example        the settings, with fake values
  requirements.txt
  Dockerfile
  README.md
```

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install pypdf rank_bm25 sentence-transformers openai fastapi uvicorn httpx pytest
pip freeze > requirements.txt
git init && git add . && git commit -m "Project skeleton"
```

## Choose your model, cheaply

The code in this course talks to any **OpenAI-compatible** API, chosen with three settings in `.env`, so you can switch without changing code:

```bash
# .env.example: copy to .env and never commit .env
# Free and local, with Ollama (ollama.com): ollama pull llama3.1
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=llama3.1
# Or a hosted API: leave LLM_BASE_URL empty for OpenAI and set your key and model
```

Add `.env`, `.venv/` and `data/*.npy` to `.gitignore` now. A leaked API key in a public repository is found by bots within minutes, and it's the kind of mistake reviewers remember.
