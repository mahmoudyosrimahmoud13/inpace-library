# Deploy, write the README, record a demo

## Deploy

A live link turns "I built" into "try it". [Hugging Face Spaces](https://huggingface.co/docs/hub/spaces-sdks-docker) runs Docker apps, with a free CPU tier at the time of writing (set `app_port: 8000` in the Space's README header). Put your API key in the host's **secrets**, never in the image. Free tiers sleep when idle, so the first request after a while is slow: mention that in the README.

## The README reviewers read

1. **One line:** what it does, for whom. A link to the live demo and the video.
2. **A screenshot or GIF.**
3. **Architecture diagram:** documents → chunks → BM25 + embeddings → RRF → LLM with citations → API.
4. **Results:** your eval tables (retrieval and answers) and cost per question.
5. **Decisions and trade-offs:** chunk size, hybrid search, the refusal, why no vector database yet.
6. **Limits and next steps:** what it gets wrong and what you'd do with more time.
7. **Run it:** three commands.

## The demo video

Two minutes, your voice: the problem, a good answer with its citation, a refusal on an unanswerable question, the eval table, one trade-off. The field guide notes candidates who send a short video walkthrough with take-homes stand out; the same works for portfolio projects.
