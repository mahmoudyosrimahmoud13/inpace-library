# The security mindset

Security is about protecting **things that matter** (data, money, accounts, systems) from **people or accidents that could harm them**, at a cost that makes sense. It's not about being unhackable; nothing is. It's about making attacks hard, noticing them fast, and recovering well.

## The CIA triad

Every security goal is one of three:

| Goal | Means | Broken when... |
|---|---|---|
| **Confidentiality** | Only the right people can read it | A database of passwords leaks |
| **Integrity** | Nobody can change it without permission | Someone edits a bank transfer amount |
| **Availability** | It works when it's needed | A website is flooded and goes down |

When you look at any system, ask what would hurt each of the three.

## Words you'll use every day

- **Asset**: something worth protecting (customer data, a server, your reputation).
- **Threat**: who or what could cause harm (a criminal group, an angry ex-employee, a flood).
- **Vulnerability**: a weakness (an unpatched server, a weak password, a missing check in code).
- **Exploit**: a way to use a vulnerability.
- **Risk**: how likely × how bad. You fix the biggest risks first.
- **Attack surface**: every place an attacker could try: open ports, login pages, file uploads, employees' inboxes.

Making the attack surface **smaller** (closing ports, removing old accounts, deleting unused features) is one of the cheapest defences there is.

## Who attacks, and why

| Attacker | Usually wants |
|---|---|
| Opportunistic criminals | Money, fast: ransomware, stolen cards, account takeovers |
| Organised groups | Big ransoms, data to sell |
| Insiders | Revenge, money, or simple mistakes |
| Hacktivists | Attention for a cause |
| Nation states | Spying, disruption |

Most attacks on people and small companies are **not targeted**. Automated tools scan the whole internet for known weaknesses and default passwords. If you're behind on updates, you'll be found.

## Defence in depth

Never rely on one control. Layer them, so one failure isn't a disaster:

```
Person -> Strong password + MFA -> Updated device -> Firewall -> App checks input
       -> Database user with limited rights -> Encrypted backups -> Logs and alerts
```

## Least privilege

Every person and program gets **only the access it needs, only for as long as it needs it**. The web app's database user can't drop tables; the intern can't approve payments; your daily account isn't an administrator. When something is compromised, least privilege limits the damage.

## Thinking like a defender (and an attacker)

Good defenders ask attacker questions about their own systems:
- What happens if this input is 10,000 characters long, or contains `'`, or `<script>`?
- What if someone changes the id in this address from 41 to 42?
- What if this employee's laptop is stolen today?
- How would we know?

That last question matters most. You'll learn to log and detect on Day 6.

## Ethics, from day one

Everything in this course is for **protecting systems you own or have written permission to test**. Accessing other people's systems without permission is a crime in Egypt (Law 175 of 2018 on cybercrime) and almost everywhere else, even "just to look". Day 6 shows you legal places to practise.
