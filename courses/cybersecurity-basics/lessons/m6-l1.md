# Practise legally, the right way

Security skills grow by doing. But "doing" on systems you don't own is a crime, can get you expelled or fired, and harms real people. Fortunately, there are excellent **legal** places to practise.

## The rules

1. **Only test what you own, or what you have written permission to test.** Permission must be explicit, in writing, with a clear scope ("these addresses, these dates, these methods").
2. "I was just looking" and "I was going to tell them" are not legal defences.
3. Never touch real users' data, even inside a legal test. Stop and report.
4. Be careful with tools: one wrong IP in a scan reaches someone else's network.

Run Juice Shop locally:

```bash
docker run --rm -p 3000:3000 bkimminich/juice-shop
# open http://localhost:3000 and look for its "Score Board"
```

It only listens on your own computer, so you're attacking yourself: completely legal.

## Responsible disclosure and bug bounties

If you **accidentally** notice a vulnerability in a real site (an error page leaking data, someone else's order in your account):

1. Stop. Don't dig further, don't download data, don't tell anyone publicly.
2. Look for a **security contact**: `/.well-known/security.txt`, a "security" or "bug bounty" page.
3. Report clearly: what you saw, how to reproduce it, the impact. No threats, no payment demands.
4. Give them time to fix it before ever talking about it.

**Bug bounty programs** (HackerOne, Bugcrowd, Intigriti, and companies' own programs) give **written permission** to test within published rules, and pay for valid findings. Read the scope and rules carefully: out-of-scope testing is still unauthorized.

## Capture the flag (CTF)

CTFs are competitions where you solve security puzzles to find hidden "flags": web, cryptography, forensics, reverse engineering. They're legal, social and a great way to learn. Many Egyptian universities and communities run them; picoCTF is a good first one.

## Building a home lab

A safe home lab lets you practise attack and defence:
- A virtual machine program (VirtualBox, free).
- An attacker VM (Kali Linux) and target VMs (Metasploitable, Juice Shop in Docker).
- Put them on a **host-only network** so nothing reaches your real network or the internet.

## Keep notes

Write up what you learn from each lab: what the vulnerability was, how you found it, how to fix it. Public write-ups (for retired labs and CTFs that allow it) make an excellent portfolio for security jobs.
