# How the web works, for security

Most modern attacks target **web applications**. To defend them you need to know exactly what travels between a browser and a server.

## A request and a response

```
GET /account?id=41 HTTP/1.1
Host: shop.example
Cookie: session=8f3c...e91
User-Agent: Mozilla/5.0 ...

HTTP/1.1 200 OK
Content-Type: text/html
Set-Cookie: theme=dark; Secure; HttpOnly; SameSite=Lax

<html>... Sara's account ...</html>
```

The most important security fact of the web: **everything the client sends can be changed by the user.** The address, form fields, hidden inputs, cookies, headers, JSON bodies: anyone can edit them with the browser's DevTools or a tool like Burp Suite. The server must check everything itself.

## Sessions and cookies

HTTP forgets you between requests. After you log in, the server gives the browser a **session cookie**: a long random value that means "this is Sara". Whoever has that cookie **is** Sara, so it must be protected.

Cookie flags that matter:

| Flag | Protects against |
|---|---|
| `Secure` | Sent only over HTTPS, never in plain text |
| `HttpOnly` | JavaScript can't read it, so an XSS bug can't steal it |
| `SameSite=Lax` (or `Strict`) | Not sent with most requests started by other sites (helps against CSRF) |

Also: new session ID after login, expiry after inactivity, and logout that really ends the session on the server.

## Authentication vs authorization

- **Authentication**: *who are you?* (login)
- **Authorization**: *are you allowed to do this?* (checked on **every** request)

Most serious web bugs are authorization bugs: the server checks that you're logged in, but not that order 42 is **yours**.

## The same-origin policy

An **origin** is scheme + host + port: `https://shop.example:443`. Browsers stop JavaScript on one origin from **reading** responses from another. Without it, any website you visit could read your email in another tab.

**CORS** is how a server deliberately allows another origin to read its responses. Misconfigured CORS (`Access-Control-Allow-Origin: *` together with credentials, or reflecting any origin) can undo this protection.

## Security headers

Servers can ask the browser for extra protection:

```
Content-Security-Policy: default-src 'self'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
```

- **CSP**: which scripts may run; a strong defence against XSS.
- **HSTS**: always use HTTPS for this site.
- **X-Frame-Options / frame-ancestors**: the site can't be shown inside another site (stops clickjacking).

Check any site's headers at **securityheaders.com**, or in DevTools → Network.

## Tools to look inside

- **Browser DevTools** (F12): Network tab for requests and cookies, Application tab for storage.
- **Burp Suite Community** or **OWASP ZAP** (free): a proxy that shows and lets you edit every request. Use them only on your own apps or legal practice labs (Day 6).
