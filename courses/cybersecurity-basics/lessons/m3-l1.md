# Network security basics

## Ports and services

A computer has one IP address but runs many network services. Each listens on a **port**:

| Port | Service | Should it be open to the internet? |
|---|---|---|
| 22 | SSH | Only if needed; keys only, no passwords |
| 80 / 443 | HTTP / HTTPS | Yes, for a website |
| 3306 / 5432 | MySQL / PostgreSQL | **No**: only to the app server |
| 3389 | Windows Remote Desktop | **No**: a top target for ransomware |
| 6379 / 27017 | Redis / MongoDB | **No**: often left open with no password |

Every open port is part of your attack surface. **Close what you don't need**, and limit who can reach the rest.

## Firewalls

A firewall decides which connections are allowed. The safe default is **deny everything incoming, then allow only what you need**.

On Ubuntu/Zorin:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp          # only if you run SSH
sudo ufw enable
sudo ufw status verbose
```

In the cloud, **security groups** do the same job. Rule: databases accept connections only from the app servers, never from `0.0.0.0/0` (everyone).

## Seeing what's open (on your own machines)

```bash
ss -tulpn                      # what's listening on this computer, and which program
```

**nmap** checks a machine from the outside:

```bash
sudo apt install nmap
nmap -sV localhost             # your own computer
nmap -sV 192.168.1.1           # your own home router
```

Only scan machines you own or have **written permission** to test. Scanning others' systems can be illegal and will get your IP blocked.

## Wi-Fi and home networks

- Router: change the **admin password**, update the firmware, use **WPA2 or WPA3**, turn off **WPS** and remote administration.
- Put smart devices (cameras, TVs) on a **guest network** so a hacked camera can't reach your laptop.
- On public Wi-Fi, HTTPS protects your traffic; a trusted **VPN** adds privacy from the café owner, but isn't magic: it moves trust to the VPN company.

## Segmentation

Split networks so one compromised machine can't reach everything: office PCs, servers, guests and cameras on separate networks, with firewalls between them. In the cloud: public subnets only for load balancers, private subnets for apps and databases.

## Denial of service

A **DoS/DDoS** attack floods a service so real users can't reach it (attacking **availability**). Defences: rate limiting, caching, and services like Cloudflare that absorb floods before they reach you.

## Remote access done right

- SSH with **keys**, password login turned off, root login turned off.
- Better: no public SSH at all. Use a VPN (WireGuard, Tailscale) or a cloud session manager.
- **fail2ban** blocks IPs that keep failing to log in.
