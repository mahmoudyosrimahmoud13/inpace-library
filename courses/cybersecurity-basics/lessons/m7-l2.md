# Careers in security, and the final project

## Security jobs

| Role | Does | Good starting skills |
|---|---|---|
| **SOC analyst** | Watches alerts, investigates, escalates | Networking, Linux and Windows logs, curiosity |
| **Incident responder** | Handles breaches end to end | SOC experience, forensics, calm under pressure |
| **Penetration tester** | Legally attacks systems to find weaknesses | Web security, networking, scripting, report writing |
| **Application security engineer** | Helps developers build secure software | Programming, OWASP Top 10, code review |
| **Cloud security engineer** | Secures AWS/Azure/GCP setups | Cloud fundamentals, IAM, infrastructure as code |
| **GRC analyst** | Policies, risk, compliance (ISO 27001, PCI DSS) | Clear writing, risk thinking, organisation |

Security is rarely an entry-level-from-zero job. Most people come from **IT support, networking, system administration or development**. The skills in this library's Linux, networking and programming courses are exactly the foundation employers look for.

## Certifications (optional, but they help with HR filters)

- **CompTIA Security+**: the most common first certification; broad fundamentals.
- **ISC2 Certified in Cybersecurity (CC)**: entry level, often with free training.
- **Google Cybersecurity Certificate**: beginner, SOC-oriented.
- Later: **eJPT** or **PNPT** (practical pentesting), **OSCP** (respected, hard), cloud security certs.

Skills you can **show** (lab write-ups, a home lab, CTF results, a secure project on GitHub) matter as much as certificates.

## A learning path

1. Linux and networking basics (this library's Linux, Cloud and DevOps track).
2. This course.
3. PortSwigger Web Security Academy, all the "apprentice" labs.
4. TryHackMe's beginner and SOC paths, or a CTF each month.
5. One programming language well (Python), for scripting and reading code.
6. Pick a direction (blue team, red team, AppSec, cloud) and go deep.

## Final project: secure a small web app

Choose a small app: your own (for example the study app from the React or Python backend courses), or OWASP Juice Shop. Produce a **security report** with:

1. **System diagram** with trust boundaries.
2. **STRIDE threat model**: at least 8 threats, each with a risk rating (low/medium/high) and a decision.
3. **Findings**: test the app **you own** (or Juice Shop) for at least 4 issues from this course: access control, injection, XSS, CSRF, misconfiguration, missing headers, weak authentication. For each: how you found it, impact, and the fix.
4. **Fixes**: apply at least 3 fixes in code or configuration, with before/after evidence (screenshots, headers, test results).
5. **Hardening checklist** for the server or container it runs on.
6. **Incident plan**: one page: who to contact, how to contain, where the backups are.

Keep it in a GitHub repository with a clear README. It shows employers you can think like a defender, test carefully and explain risk in plain language: the three things every security job needs.

## Keep going

Security changes every week. Follow a few good sources (OWASP, PortSwigger Research, the CISA advisories, your local CERT: EG-CERT in Egypt), practise regularly, and share what you learn. Teaching others is the fastest way to understand something deeply.
