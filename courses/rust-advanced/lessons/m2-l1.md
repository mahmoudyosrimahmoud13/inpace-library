# Closures and iterators in depth

## The three closure traits

How a closure uses what it captures decides which trait it implements:

<!-- diagram -->
```mermaid
flowchart LR
  FO["FnOnce<br/>can be called at least once"] --> FM["FnMut<br/>many times, may change captures"]
  FM --> FN["Fn<br/>many times, only reads"]
```

| Trait | The closure... | Can be called |
|---|---|---|
| `Fn` | only reads its captures | many times, even at once |
| `FnMut` | changes its captures | many times, one at a time |
| `FnOnce` | moves a capture out (uses it up) | once |

Functions that take closures say which they need:

```rust
fn apply_twice<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(f(x))
}

fn repeat<F: FnMut()>(mut f: F, times: usize) {
    for _ in 0..times {
        f();
    }
}

fn run_once<F: FnOnce() -> String>(f: F) -> String {
    f()
}

fn main() {
    let add = 3;
    println!("{}", apply_twice(|n| n + add, 10));

    let mut count = 0;
    repeat(|| count += 1, 4);
    println!("count {count}");

    let report = String::from("monthly report");
    let send = move || report + " sent";           // moves report in, then uses it up
    println!("{}", run_once(send));
}
```

```output
16
count 4
monthly report sent
```

- `move` makes the closure **take ownership** of what it captures. You need it when the closure outlives the current function: returning it, or sending it to a thread.
- Accept the most general trait you can: `FnOnce` accepts all closures, `FnMut` accepts `Fn` and `FnMut` ones, `Fn` only the read-only ones.

## Returning closures and iterators: impl Trait

```rust
fn multiplier(k: i32) -> impl Fn(i32) -> i32 {
    move |x| x * k
}

fn evens_squared(limit: u32) -> impl Iterator<Item = u32> {
    (1..=limit).filter(|n| n % 2 == 0).map(|n| n * n)
}

fn main() {
    let triple = multiplier(3);
    println!("{}", triple(14));
    println!("{:?}", evens_squared(10).collect::<Vec<_>>());
}
```

```output
42
[4, 16, 36, 64, 100]
```

`impl Iterator<Item = u32>` says "some iterator of u32" without writing its long real type. The caller can keep chaining on it, and nothing runs until they consume it.

## Iterator adapters you'll use constantly

```rust
fn main() {
    let names = ["Ali", "Mona", "Karim", "Huda"];
    let scores = [72, 95, 64, 88];

    for (name, s) in names.iter().zip(scores.iter()) {
        print!("{name}={s} ");
    }
    println!();

    let (pass, fail): (Vec<i32>, Vec<i32>) = scores.iter().partition(|&&s| s >= 70);
    println!("pass {:?} fail {:?}", pass, fail);

    let best = names.iter().zip(scores).max_by_key(|&(_, s)| s).unwrap();
    println!("best: {} with {}", best.0, best.1);

    let chunks: Vec<i32> = scores.chunks(2).map(|c| c.iter().sum()).collect();
    println!("pairs summed {:?}", chunks);

    let running: Vec<i32> = scores
        .iter()
        .scan(0, |total, &s| {
            *total += s;
            Some(*total)
        })
        .collect();
    println!("running total {:?}", running);

    let words = "one two three two one two";
    let first_repeat = words
        .split(' ')
        .enumerate()
        .find(|(i, w)| words.split(' ').take(*i).any(|x| x == *w));
    println!("first repeat {:?}", first_repeat);
}
```

```output
Ali=72 Mona=95 Karim=64 Huda=88 
pass [72, 95, 88] fail [64]
best: Mona with 95
pairs summed [167, 152]
running total [72, 167, 231, 319]
first repeat Some((3, "two"))
```

A short glossary: `zip` pairs two iterators; `partition` splits into two collections; `max_by_key` finds the biggest by some measure; `chunks` groups a slice; `scan` carries state along; `find` stops at the first match. Others worth knowing: `flat_map`, `take_while`, `skip_while`, `windows`, `rev`, `fold`, `position`, `dedup` (on Vec).

## Iterators are zero-cost

A chain like `.iter().filter(..).map(..).sum()` compiles to the same machine code as a hand-written loop, often better, because the compiler can see the whole thing. Prefer iterator chains for clarity; you don't pay for them.

## Summary

- `Fn` reads, `FnMut` changes, `FnOnce` consumes; `move` gives captures to the closure.
- Return closures and iterator chains with `impl Fn(..)` and `impl Iterator<Item = T>`.
- Learn zip, partition, max_by_key, chunks, scan and find; iterator chains cost nothing extra.
