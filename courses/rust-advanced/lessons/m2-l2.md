# Smart pointers: Box, Rc, RefCell and Weak

Rust's ownership rules are strict: one owner, many readers **or** one writer. Smart pointers let you bend those rules safely when a design needs it.

## Box<T>: put it on the heap

`Box` owns a value on the heap. Use it for:

- recursive types (a type that contains itself needs a fixed size)
- trait objects (`Box<dyn Trait>`)
- moving large values around cheaply

```rust
#[derive(Debug)]
enum Expr {
    Num(f64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

fn eval(e: &Expr) -> f64 {
    match e {
        Expr::Num(n) => *n,
        Expr::Add(a, b) => eval(a) + eval(b),
        Expr::Mul(a, b) => eval(a) * eval(b),
    }
}

fn main() {
    // (2 + 3) * 4
    let e = Expr::Mul(
        Box::new(Expr::Add(Box::new(Expr::Num(2.0)), Box::new(Expr::Num(3.0)))),
        Box::new(Expr::Num(4.0)),
    );
    println!("{}", eval(&e));
}
```

```output
20
```

Without `Box`, `Expr` would contain an `Expr`, which contains an `Expr`... and have no finite size.

## Rc<T>: several owners

`Rc` ("reference counted") lets several parts of a program **share** ownership. The value is dropped when the last `Rc` goes away:

```rust
use std::rc::Rc;

struct Photo {
    name: String,
}

fn main() {
    let photo = Rc::new(Photo { name: "sunset.jpg".to_string() });
    let album_a = vec![Rc::clone(&photo)];
    let album_b = vec![Rc::clone(&photo), Rc::clone(&photo)];
    println!("{} is in {} places", photo.name, Rc::strong_count(&photo) - 1);
    drop(album_b);
    println!("now {}", Rc::strong_count(&photo) - 1);
    println!("{}", album_a.len());
}
```

```output
sunset.jpg is in 3 places
now 1
1
```

`Rc::clone` doesn't copy the photo; it adds one to the count. `Rc` gives **shared, read-only** access, and only works in one thread (use `Arc` for threads, next module).

## RefCell<T>: change through a shared reference

Sometimes you need to change something that several parts of the program hold. `RefCell` moves the borrowing rule from compile time to **run time**:

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Account {
    balance: i64,
}

fn main() {
    let shared = Rc::new(RefCell::new(Account { balance: 100 }));
    let salma = Rc::clone(&shared);
    let omar = Rc::clone(&shared);

    salma.borrow_mut().balance += 50;     // a mutable borrow, checked at run time
    omar.borrow_mut().balance -= 30;

    println!("{:?}", shared.borrow());
    let r1 = shared.borrow();
    let r2 = shared.borrow();             // many readers: fine
    println!("{} {}", r1.balance, r2.balance);
    // let w = shared.borrow_mut();       // would panic: already borrowed for reading
}
```

```output
Account { balance: 120 }
120 120
```

`Rc<RefCell<T>>` is the classic "shared and changeable" combination in single-threaded code. The cost: breaking the rule now **panics** at run time instead of failing to compile. Keep borrows short (don't hold a `borrow_mut()` across a long function) and use this only when the design really needs shared mutation. `try_borrow_mut()` returns a `Result` instead of panicking.

`Cell<T>` is a simpler cousin for small `Copy` values: `.get()` and `.set()` with no borrowing at all.

## Weak<T>: references that don't keep things alive

Two `Rc`s pointing at each other never reach a count of zero: a memory leak. For back-references (child to parent), use `Weak`:

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

fn main() {
    let root = Rc::new(Node { name: "root".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
    let leaf = Rc::new(Node { name: "leaf".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });

    *leaf.parent.borrow_mut() = Rc::downgrade(&root);
    root.children.borrow_mut().push(Rc::clone(&leaf));

    let parent_name = leaf.parent.borrow().upgrade().map(|p| p.name.clone());
    println!("leaf's parent: {:?}", parent_name);
    println!("root has {} child", root.children.borrow().len());
}
```

```output
leaf's parent: Some("root")
root has 1 child
```

`upgrade()` returns `Some(Rc)` if the value still exists, `None` if it's gone. Parents own children (strong `Rc`); children only point back (`Weak`).

## Which one?

| Need | Use |
|---|---|
| One owner, value on the heap | `Box<T>` |
| Several owners, read only, one thread | `Rc<T>` |
| Several owners, changeable, one thread | `Rc<RefCell<T>>` |
| A back-reference that mustn't keep things alive | `Weak<T>` |
| Shared across threads | `Arc<T>`, `Arc<Mutex<T>>` (next module) |

Many Rust programs need none of these. Plain ownership and borrowing, plus indexes into a `Vec` instead of pointers, often make simpler designs.

## Summary

- `Box` for heap values, recursive types and trait objects.
- `Rc` shares ownership; `RefCell` checks borrowing at run time; together they allow shared mutation.
- `Weak` breaks reference cycles; reach for these only when plain ownership doesn't fit.
