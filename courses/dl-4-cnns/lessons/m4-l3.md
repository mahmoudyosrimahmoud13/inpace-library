# Transfer learning, augmentation and the state of vision

**Transfer learning** is how almost all vision projects start: take a network pre-trained on millions of images, freeze
most of it, and train new last layers on your data (more data → unfreeze more).

```python
from torchvision.models import resnet18, ResNet18_Weights
weights = ResNet18_Weights.DEFAULT                      # the modern API (no more pretrained=True)
net = resnet18(weights=weights); preprocess = weights.transforms()
for p in net.parameters(): p.requires_grad = False
net.fc = nn.Linear(net.fc.in_features, 3)               # only this trains
```

**Augmentation:** mirroring, random crops, rotation, colour shifts, done on the fly while training
(`torchvision.transforms.v2`, or Keras layers like `RandomFlip`, `RandomRotation`).

**Data vs hand-engineering:** with little data, more hand design (and transfer learning) helps; with lots of data,
simpler architectures and less hand design win. Benchmark tricks (ensembles, multi-crop at test time) rarely belong in
production.
