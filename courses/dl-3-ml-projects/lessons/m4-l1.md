# Carrying out error analysis

Before spending a month on "dogs mistaken for cats", take **100 dev mistakes** and count. If only 5% are dogs, fixing
them perfectly takes error from 10% to 9.5% at best: a **ceiling** on what that idea can bring.

Make a spreadsheet: one row per mistake, one column per idea (dog, big cat, blurry, filter...), and a comment column.
Count, then pick the ideas with the biggest share. New categories appear while you look; add columns.

**Incorrect labels:** random label errors in training data are mostly fine (deep learning is robust to them);
systematic ones aren't. Add a column "incorrect label" to the dev error analysis. If you fix labels, do it on dev
**and** test, and look at examples the model got right too.

**Build your first system quickly, then iterate.** Error analysis needs a working system.
