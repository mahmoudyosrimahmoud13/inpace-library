# Why strategy, and orthogonalization

A team can spend six months collecting data that doesn't help. Strategy is choosing the **next** thing to try, quickly
and with evidence.

**Orthogonalization:** like a TV with one knob per job, use one kind of fix per problem, in this order:

| If this fails | Try |
|---|---|
| fit the training set well | bigger network, better optimizer (Adam) |
| fit the dev set well | regularization, more training data |
| fit the test set well | a bigger dev set |
| perform in the real world | change the dev set or the cost function |

Early stopping is a knob that turns two of these at once, which is why some people avoid it.
