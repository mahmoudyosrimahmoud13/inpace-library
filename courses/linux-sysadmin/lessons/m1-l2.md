# Kernel modules, devices and dmesg

Most drivers are **kernel modules**: pieces of the kernel loaded only when needed.

```bash
lsmod | head                  # loaded modules
modinfo e1000                 # what a module is, its options
sudo modprobe loop            # load a module (and what it needs)
sudo modprobe -r loop         # unload it
```

## Loading or blocking at boot

| Want | Put a file in | Containing |
|---|---|---|
| Load at boot | `/etc/modules-load.d/my.conf` | `loop` |
| Set options | `/etc/modprobe.d/my.conf` | `options loop max_loop=16` |
| Never load | `/etc/modprobe.d/blacklist-x.conf` | `blacklist nouveau` |

After changing blacklists that affect early boot, rebuild the initramfs.

## Devices

```bash
lspci                 # PCI devices (network, storage controllers, GPUs)
lsusb                 # USB devices
lsblk                 # block devices
ls -l /dev/disk/by-uuid/   # stable names for disks
udevadm info /dev/sda | head
```

**udev** creates the files in `/dev` when hardware appears and can run rules (name a network card, set permissions on a USB device). Rules live in `/etc/udev/rules.d/`.

## dmesg: the kernel's own log

```bash
sudo dmesg -T | tail -30      # human-readable times
sudo dmesg -T --level=err,warn
journalctl -k -b              # the same, through systemd's journal
```

Plug in a USB stick and watch `sudo dmesg -w`: you'll see the kernel find it, pick a driver, and name it `/dev/sdb`. Disk errors, out-of-memory kills and hardware faults also show up here first.
