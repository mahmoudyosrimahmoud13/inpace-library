# Managing users, groups and sudo

## Users

```bash
sudo useradd -m -s /bin/bash -c "Sara Ali" sara   # -m make home, -s shell
sudo adduser sara                                  # Debian/Ubuntu friendly wrapper (asks questions)
sudo passwd sara                                   # set a password
sudo usermod -aG sudo sara                         # add to a group (-a = append! without it you replace all groups)
sudo usermod -L sara                               # lock the account
sudo usermod -s /usr/sbin/nologin svcuser          # no interactive login
sudo userdel -r olduser                            # delete with home directory
```

## Groups

```bash
sudo groupadd devs
sudo usermod -aG devs sara
groups sara
sudo gpasswd -d sara devs     # remove from a group
```

Group changes apply at the user's **next login** (or `newgrp devs` in the current shell).

## The account files

| File | Holds |
|---|---|
| `/etc/passwd` | Accounts: name, UID, GID, home, shell (no passwords) |
| `/etc/shadow` | Password hashes and expiry (root-only) |
| `/etc/group` | Groups and members |
| `/etc/skel/` | Files copied into every new home directory |
| `/etc/login.defs` | Defaults: UID ranges, password ageing |

```bash
sudo chage -l sara                # password expiry details
sudo chage -M 90 -W 7 sara        # max 90 days, warn 7 days before
```

## sudo rules

Edit only with `sudo visudo` (or add files to `/etc/sudoers.d/` with `visudo -f`):

```text
%sudo   ALL=(ALL:ALL) ALL                       # members of group sudo may do anything
deploy  ALL=(root) NOPASSWD: /usr/bin/systemctl restart myapp   # one exact command, no password
```

Give people the **smallest** rights that let them do their job. "Can restart the app" is much safer than "is root".

## Service accounts

Every service should run as its own user with no login shell:

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin myapp
```

If that service is hacked, the attacker gets only what `myapp` could touch.
