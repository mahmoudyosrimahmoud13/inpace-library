# Capstone: build and document a small server

Put the whole course together on a fresh VM or cloud server.

## The brief

Build **web01**, a small web server for a team:

1. Hostname `web01`, timezone set (`timedatectl set-timezone`), fully updated, automatic security updates on.
2. An admin user for you with SSH keys; **no** root login, **no** passwords over SSH.
3. A `deploy` user that can only run `systemctl restart nginx` with sudo.
4. A second disk (add one to the VM) as LVM, mounted at `/srv` via fstab by UUID.
5. nginx serving a page from `/srv/www`, logs rotated for 14 days.
6. Firewall: only SSH and HTTP/HTTPS open.
7. A systemd timer that backs up `/srv/www` and `/etc` nightly with a dated `tar` file, keeping 7 days.
8. A restore test: delete the page, restore it from last night's backup, show it works.

## Checks to prove it

```bash
hostnamectl; timedatectl
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication'
sudo -l -U deploy
lsblk; findmnt /srv; sudo lvs
systemctl status nginx --no-pager; curl -s localhost | head -3
sudo ufw status verbose
systemctl list-timers | grep backup; ls -lh /backup
```

## Write a runbook

A runbook is the page someone else reads at 3 a.m. Keep it short:

| Section | What to write |
|---|---|
| What this server is | Role, who uses it |
| How to get in | Who has access, how |
| Services | Names, ports, config files, log files |
| Storage | Disks, mounts, how to grow `/srv` |
| Backups | When, where, **how to restore** (the exact commands) |
| Common problems | Disk full, nginx won't start: what to check |

Doing all eight steps **by hand** once is exactly what makes the Bash Automation and Infrastructure as Code courses click: you'll know what you're automating.
