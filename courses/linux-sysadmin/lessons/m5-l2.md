# Scheduled jobs: cron, systemd timers and at

## cron

Each user has a crontab (`crontab -e` to edit, `crontab -l` to list). System-wide jobs go in `/etc/crontab` or `/etc/cron.d/`.

```text
# minute  hour  day-of-month  month  day-of-week   command
  30      2     *             *      *             /usr/local/bin/backup.sh
  */15    *     *             *      *             /opt/app/healthcheck.sh
  0       9     *             *      1-5           /opt/app/report.sh      # weekdays at 09:00
  0       0     1             *      *             /opt/app/monthly.sh
```

Gotchas that bite everyone:

- cron runs with a tiny `PATH` and no `.bashrc`: use **full paths** in commands.
- Output goes nowhere useful unless you redirect it: `>> /var/log/backup.log 2>&1`.
- `%` is special in crontab lines; escape it as `\%` (common with `date +%F`).
- crontab.guru explains any schedule in plain words.

Drop-in folders `/etc/cron.daily/`, `/etc/cron.weekly/` run any executable script placed there.

## systemd timers

The modern alternative. Two files: a service that does the work, and a timer that triggers it.

`/etc/systemd/system/backup.service`:

```ini
[Unit]
Description=Nightly backup

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

`/etc/systemd/system/backup.timer`:

```ini
[Unit]
Description=Run backup nightly

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true
RandomizedDelaySec=10m

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer
systemctl list-timers
journalctl -u backup.service      # output and errors are logged for free
```

| | cron | systemd timer |
|---|---|---|
| Setup | One line | Two small files |
| Logs | Do it yourself | In the journal automatically |
| Missed runs (machine was off) | Lost | `Persistent=true` catches up |
| Resource limits, sandboxing | No | Yes, like any service |

## at: run once, later

```bash
echo "/usr/local/bin/backup.sh" | at 23:00
atq; atrm 3
```
