# Capstone: make a service observable and reliable

Take a service you've built in this track (or any small web app) and run it like an SRE team would.

## Requirements

1. **Metrics**: Prometheus scraping node_exporter on each host and RED metrics from the app (counter + latency histogram).
2. **Logs**: structured JSON logs with `trace_id`, shipped to Loki or CloudWatch Logs, with retention set.
3. **Traces**: OpenTelemetry auto-instrumentation plus one custom span, through a Collector to Tempo or Jaeger.
4. **Dashboard** (as code in Git): SLO status, RED by route, deploy annotations, resources, dependencies.
5. **SLOs**: two SLIs (availability and latency) for one user journey, with targets and a written error budget policy.
6. **Alerts**: multi-window burn-rate pages with runbook links; ticket alerts for disk, certificates and backups.
7. **Runbook** for each page.

## Game day

With a friend acting as incident commander (or alone, keeping a timeline):

- Deploy a version with an injected bug (slow query or 5% errors).
- Let the alert fire; mitigate with a rollback; confirm SLIs recover.
- Write a **blameless postmortem** with at least three action items.

## Deliver

Repository link, a screenshot of the dashboard during the game day, the SLO document and the postmortem.

## And the whole track

Then go on to the final project course: one system that uses everything from Linux fundamentals to this course.
