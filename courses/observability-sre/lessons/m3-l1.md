# Grafana dashboards that help at 3 a.m.

**Grafana** draws dashboards from Prometheus, Loki, CloudWatch, PostgreSQL and many more.

```bash
docker run -d --name grafana -p 3000:3000 grafana/grafana
# Add Prometheus as a data source: http://prom:9090
```

## A service dashboard, top to bottom

```text
Row 1: Is it OK?    SLO status, error budget left, current error ratio, p95 latency
Row 2: RED          request rate, error rate, latency p50/p95/p99, all by route
Row 3: Changes      deploy annotations (version), feature flag changes
Row 4: Resources    CPU, memory, disk, DB connections, queue depth (USE)
Row 5: Dependencies database, cache, payment API latency and errors
```

## Make it useful

- **Start from the user's view** (SLO, RED), then drill down to resources. Most dashboards are the reverse and nobody can tell if users are affected.
- Use **variables** (`$env`, `$instance`, `$route`) instead of copying panels.
- Add **annotations for deploys**: half of all incidents start with a change.
- Same time range and units everywhere; label axes (`ms`, `req/s`, `%`).
- Fewer panels: if nobody would act on a graph, delete it.
- Keep dashboards **as code** (JSON in Git, Grafana provisioning, or Terraform's Grafana provider), so they're reviewed and restorable.

The **Node Exporter Full** community dashboard (ID 1860) is a good starting point for Linux hosts; import it, then trim it to what you actually use.
