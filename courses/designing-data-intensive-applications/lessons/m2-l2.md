# Choosing a data model by its relationships

## The deciding question: how is the data connected?

| Relationship | Example | Best fit |
|---|---|---|
| One-to-many, a tree | A résumé: one person, many jobs, many schools | Document: load it all in one read |
| Many-to-one | Many people live in one region | Relational: store the region's ID, the name once |
| Many-to-many | People, companies, schools, all linked | Relational with joins, or a graph |
| Paths of unknown length | "Who is connected to whom, through anything?" | Graph |

## Why IDs instead of copies

If each document stores `"region": "Greater Cairo"` and the region is renamed, every document must be rewritten, and
any you miss now disagrees forever. Storing `region_id: 1` keeps the name in one place: that's **normalization**, and
it's why relational databases need joins. Document databases avoid joins, so the application ends up doing them, or
copying data around.

## Schema on read versus schema on write

```text
Schema on write (relational):              Schema on read (documents):
  ALTER TABLE users ADD first_name;          new documents have first_name,
  UPDATE users SET first_name = ...;         old ones don't;
  every reader sees one shape.               every reader handles both shapes:
                                               doc.get("first_name") or doc["name"].split()[0]
```

Neither is "schemaless": with documents the schema is just **implicit**, enforced by the code that reads. Schema on
read suits data whose shape really varies, or comes from outside your control.

## Recursive queries: walking a graph in SQL

```sql
WITH RECURSIVE in_usa(vertex_id) AS (
    SELECT vertex_id FROM vertices WHERE name = 'United States'      -- start here
  UNION
    SELECT e.tail FROM edges e JOIN in_usa ON e.head = in_usa.vertex_id
    WHERE e.label = 'within'                                         -- then follow 'within' edges, again and again
)
SELECT * FROM in_usa;
```

The query keeps adding vertices that are "within" ones already found, until nothing new appears. It finds Idaho
inside the United States, and a town inside Idaho, without knowing the depth in advance. That's the difficulty graph
query languages like Cypher make easy to express.

## What to take away

- Let the relationships choose the model: trees to documents, references to relational, networks to graphs.
- Copies of many-to-one data go stale; references don't.
- "Schemaless" means the schema moved into your reading code.
