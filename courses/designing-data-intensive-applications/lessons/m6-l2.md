# Binary encodings and schema evolution, byte by byte

## The record, three ways

```json
{"userName": "Martin", "favoriteNumber": 1337, "interests": ["daydreaming", "hacking"]}
```

JSON spends most of its 81 bytes on field names and punctuation. Binary formats with a schema don't send names at all.

## Varints

Small numbers are common, so binary formats spend fewer bytes on them. A **varint** uses 7 bits of each byte for the
number and the top bit to say "more bytes follow":

```text
1337 = 0b10100111001
low 7 bits  0111001 -> 0x39, more follows -> 0xB9
next 7 bits 0001010 -> 0x0A, last byte    -> 0x0A
varint(1337) = b9 0a    (2 bytes instead of 8)
```

## Protocol Buffers style: tag, then value

```text
0a        field 1, wire type 2 (length-delimited)      <- tag = (field number << 3) | wire type
06        length 6
4d 61 72 74 69 6e    "Martin"
10        field 2, wire type 0 (varint)
b9 0a     1337
1a 0b ... field 3, "daydreaming"
1a 07 ... field 3 again, "hacking"                     <- a repeated field is just the tag again
```

The **wire type** tells a reader how long a value is, even for a field it has never heard of. That's how old code
**skips** new fields: forward compatibility for free. The **field number** is the field's real identity: rename the
field all you like, never change or reuse its number.

## Avro style: no tags at all

```text
0c 4d 61 72 74 69 6e    "Martin"  (length 6, zigzag-encoded as 0x0c)
02 f2 14                union branch 1 (long), then 1337 zigzag-encoded
04 16 ... 0e ... 00     an array block of 2 strings, then 0 = end of array
```

Nothing in the bytes says which field is which. The reader must know the exact **writer's schema** to decode, and
then maps fields to **its own schema by name**:

| Situation | What happens |
|---|---|
| Field in writer's schema, not in reader's | Ignored |
| Field in reader's schema, not in writer's | Reader's default value used |
| Field in reader's schema, not in writer's, no default | Error: incompatible |

So: **only add or remove fields that have a default**. In Avro, "null" is only allowed as a value through a union
type, like `union { null, long }`.

## Which compatibility does which change need?

| Change | Backward (new reads old) | Forward (old reads new) |
|---|---|---|
| Add an optional field / field with a default | Yes: use the default | Yes: old code skips or ignores it |
| Add a required field / field without a default | No: old data lacks it | Yes |
| Remove an optional field / field with a default | Yes | Yes |
| Remove a required field | Yes | No: old code requires it |
| Change a field number (Protobuf, Thrift) | No | No |

## What to take away

- Schemas let binary formats drop field names and shrink records two to three times.
- Tags make skipping unknown fields possible; never change a tag.
- In Avro, defaults are what make adding and removing fields safe.
