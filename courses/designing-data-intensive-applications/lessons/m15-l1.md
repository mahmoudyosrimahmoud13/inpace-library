# Capstone: publish your data systems lab

You've built, in plain Python: a Twitter timeline model, three data models, a Bitcask-style store, an LSM-tree, a
column store, binary encodings, replication, partitioning, an MVCC store with three isolation levels, fault
simulations, Lamport clocks and leader election, MapReduce, a partitioned log with CDC, and an unbundled database.
That's a portfolio few developers have. Publish it so others can see it.

## 1. Clean the repository

- `lab_data/` is in `.gitignore`: it's generated by the scripts.
- Each script runs from a fresh clone with `python pNN_....py` and nothing to install. Check that.
- Keep your "Make it yours" changes; they're the most interesting part. Put bigger ones in their own files (for
  example `p04_lsm_recovery.py`).

## 3. Push it to GitHub

Create an empty repository called `ddia-lab` on GitHub, then in your `lab` folder:

```bash
git add .
git commit -m "DDIA lab: storage engines, replication, transactions, consensus, batch and streams"
git branch -M main
git remote add origin git@github.com:YOUR-NAME/ddia-lab.git
git push -u origin main
```

`git add .` stages every file except what `.gitignore` excludes; `git commit` saves a snapshot with a message;
`git branch -M main` names the branch `main`; `git remote add origin ...` tells git where your GitHub repository is;
`git push` uploads it. Replace `YOUR-NAME` with your GitHub username. The `git@github.com:` address uses SSH; GitHub's
guide "Connecting to GitHub with SSH" shows how to set up a key.

## 4. Use it in interviews

System design interviews ask exactly these questions: "how would you store this?", "what happens if this node dies?",
"how do you avoid double charging?". Answer from what you built: "I implemented an LSM-tree; for a write-heavy
workload I'd choose ...". A CV line:

> Implemented core distributed-data mechanisms from scratch in Python (LSM-tree storage engine with Bloom filters,
> MVCC with snapshot isolation and SSI, quorum replication, MapReduce with sort-merge joins, partitioned log with CDC),
> each with measurements.

## What to take away

- A from-scratch lab shows understanding that a certificate can't.
- Put your measurements and your own changes front and centre.
