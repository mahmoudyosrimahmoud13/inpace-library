# Project 6: write your own binary encodings

You'll encode the book's example record yourself, Protocol Buffers style and Avro style, get exactly the sizes the
book reports, then evolve the schemas and see what stays compatible.

The code is above this text. Save it as `p06_encoding.py`.

## Read the code

- **`varint()`** and **`read_varint()`**: 7 bits per byte, top bit "more follows".
- **`zigzag()`**: Avro maps signed numbers to unsigned ones (0, -1, 1, -2, 2... become 0, 1, 2, 3, 4...) so small
  negative numbers stay small.
- **`pb_encode()`** writes `varint(field_number << 3 | wire_type)` before each value: wire type 0 for integers, 2 for
  strings (followed by a length). A repeated field repeats the tag. **`pb_decode()`** reads tag by tag; a tag it
  doesn't know is skipped using its wire type, and listed under `(skipped unknown fields)` so you can see it happen.
- **`avro_encode()`** writes only values, in schema order: strings as length plus bytes, `union<null,long>` as a branch
  number plus the value, arrays as a count, the items, and a 0. **`avro_decode()`** needs the **writer's schema** to
  read the bytes, then builds the record for the **reader's schema** by field name, using defaults.
  `NO_DEFAULT` marks a field without a default.
- Schemas: `PB_V2` adds field 4. `AVRO_V2` removes `favoriteNumber` and adds `photoUrl` with a default. `AVRO_V3` adds
  `country` without a default: a mistake.

Compare with the book: JSON **81 bytes**, Protocol Buffers **33 bytes**, Avro **32 bytes**. Your encoders produce the
same sizes, and the hex bytes match Figures 4-4 and 4-5.

The evolution results:

- Old Protobuf code reading new data **skipped field 4**, and kept everything else.
- New code reading old data simply doesn't find `photoUrl`; it uses a default.
- **Renumbered fields** crash the decoder: field 2's bytes are read as if they were field 3's type.
- Avro: v2 reads v1 data (default for `photoUrl`); v1 reads v2 data (default null for the removed `favoriteNumber`);
  v3 can't read v1 data, because `country` has no default.

## Make it yours

1. Encode `favoriteNumber = -1` both ways. How many bytes does the varint take without zigzag (as a 64-bit
   two's-complement number) and with it?
2. Add a nested record (an `address` with `city` and `zip`) to the Protobuf-style encoder, as wire type 2 holding an
   encoded sub-message.
3. Write a **compatibility checker**: given two Avro-style schemas, list every change and say whether it keeps
   backward and forward compatibility (use the table in the concept lesson).
4. Save 1,000 encoded records to a file in each format. Compare the file sizes, then compress each with `zlib`. Does
   JSON catch up?

## What to take away

- You can read and write the bytes of real encoding formats; there's no magic in them.
- Tags allow skipping unknown fields; Avro relies on schema resolution and defaults.
- Compatibility rules are what make rolling upgrades possible.
