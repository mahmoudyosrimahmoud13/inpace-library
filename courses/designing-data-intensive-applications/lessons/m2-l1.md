# Read: Chapter 2, Data Models and Query Languages

The data model is probably the most important decision in software: it shapes how you think about the problem, not
just how you store it. This chapter compares the three big families.

## Relational model versus document model

- **The birth of NoSQL**: the reasons people wanted alternatives (scale, open source, specialized queries, more
  dynamic schemas).
- **The object-relational mismatch**: a résumé (Figure 2-1) as tables versus as one JSON document (Example 2-1). Note
  **locality**: the document is one read.
- **Many-to-one and many-to-many relationships**: why storing a region's *ID* rather than its *name* matters, and how
  documents struggle once data becomes interconnected (Figure 2-4).
- **Are document databases repeating history?** The hierarchical model of the 1970s (IMS), the network model
  (CODASYL, "access paths") and why the relational model won: the query optimizer chooses the access path for you.
- **Relational versus document databases today**: which leads to simpler application code; **schema-on-read versus
  schema-on-write** (compare it to dynamic versus static type checking); data locality; and the convergence of the
  two.

## Query languages for data

**Declarative** (SQL: say *what* you want) versus **imperative** (code: say *how* to get it), and why declarative
languages let the database improve performance without changing your queries. Then the CSS analogy and MapReduce
querying (skim).

## Graph-like data models

When many-to-many relationships are the norm, model the data as a graph.

- **Property graphs** (vertices and edges with properties, Example 2-2) and **Cypher** (Example 2-4: people who
  emigrated from the US to Europe).
- **Graph queries in SQL**: the same query as a **recursive common table expression** (Example 2-5), much longer.
- **Triple-stores and SPARQL**, and **Datalog** (skim; note the idea of building rules from rules).

## What to take away

- Documents: good locality and schema flexibility for one-to-many, tree-shaped data.
- Relational: joins and references for many-to-one and many-to-many data.
- Graphs: when everything can relate to everything, and queries walk paths of unknown length.
