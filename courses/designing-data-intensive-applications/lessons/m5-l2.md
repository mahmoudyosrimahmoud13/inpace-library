# Column storage, bitmaps and run-length encoding

## Rows versus columns, on disk

```text
Row store: each row whole, one after another
  [2014-01-01, 69, 4, 0, 1001, 1, 13.99, 0.0] [2014-01-01, 30, 7, 1, 2002, 3, 14.99, 0.1] ...

Column store: each column whole, in the same row order
  date_key:    2014-01-01, 2014-01-01, 2014-01-01, ...
  product_sk:  69, 30, 68, ...
  quantity:    1, 3, 1, ...
  ...
```

"Total quantity of products 30, 68 and 69" needs `product_sk` and `quantity`: 2 of 8 columns. A row store still reads
all 8. The k-th value of every column belongs to the k-th row, which is how the store puts rows back together.

## Bitmap encoding

For a column with few distinct values, keep one bit array per value:

```text
product_sk:  69  30  68  69  30  31  68
bitmap 30:    0   1   0   0   1   0   0
bitmap 68:    0   0   1   0   0   0   1
bitmap 69:    1   0   0   1   0   0   0
IN (30,68,69) = OR of the three bitmaps:
              1   1   1   1   1   0   1
```

Bitwise OR on whole words is something CPUs do extremely fast, and sparse bitmaps (mostly zeros) shrink further with
run-length encoding.

## Sort order and run-length encoding

```text
date_key, sorted:    0101 0101 0101 ... (3,761 times) 0102 0102 ... (3,794 times) ...
run-length encoded:  (0101, 3761) (0102, 3794) ...      a million values -> a few hundred pairs
```

Sorting by the column you filter on most puts equal values next to each other, so the first sort column compresses
best; a second sort column helps within each run of the first. An unsorted column (like `product_sk` here) gets almost
nothing from run-length encoding.

## Data cubes

```text
                product 30   product 68   product 69   ...
2014-01-01          112           98          105
2014-01-02           87          120           91
...
```

Precompute `sum(quantity)` for every (date, product) pair once. "Quantity of products 30, 68, 69" becomes adding up a
few hundred cells instead of a million rows. But a question about **stores** can't be answered from this cube: you
chose its dimensions in advance. That's why warehouses keep the raw data too.

## What to take away

- Columns read less and compress better; rows are better for fetching whole records.
- Bitmaps turn filters into fast bitwise operations.
- Sort by the most filtered column; build cubes only for questions you know you'll ask often.
