# WSGI vs ASGI, and a server with no framework

**WSGI** (Flask, classic Django) is one function call per request, synchronous. **ASGI** is async and also handles
long-lived connections (WebSockets, streaming).

An ASGI app is just an async callable:

```python
async def app(scope, receive, send):
    assert scope["type"] == "http"
    body = f"You asked for {scope['path']}".encode()
    await send({"type": "http.response.start", "status": 200,
                "headers": [(b"content-type", b"text/plain; charset=utf-8")]})
    await send({"type": "http.response.body", "body": body})
```

Run it with `uvicorn hello:app`. That's all a framework is built on.

| Piece | Role |
|---|---|
| **Uvicorn** | The ASGI **server**: sockets, HTTP parsing, the event loop |
| **Starlette** | A small **toolkit**: requests, responses, routing, middleware, static files, test client |
| **FastAPI** | Starlette + **Pydantic** + dependency injection + automatic OpenAPI docs |

inPace starts Uvicorn itself, only on the loopback address:

```python
config = uvicorn.Config(create_app(vault), host="127.0.0.1", port=port, log_level="warning")
server = uvicorn.Server(config)
```
