# Interview drill

1. **WSGI vs ASGI?** Sync, one request per call vs async, long-lived connections too.
2. **Starlette vs FastAPI?** Toolkit vs toolkit + validation + DI + docs. Pick by the job (Day 3).
3. **How does FastAPI validate?** Pydantic models from type hints; 422 on failure.
4. **What's dependency injection good for?** Reuse, testing (overrides), clean handlers.
5. **async def vs def routes in FastAPI?** async runs on the loop (don't block it); def runs in a thread pool.
6. **How do you handle a slow third-party call?** Async client with timeouts, or a thread pool; retries with backoff;
   a circuit breaker for repeated failures.
7. **Post/Redirect/Get?** Answer form POSTs with 303 so refresh and Back don't resend.
8. **How would you rate-limit?** A token bucket per key, in Redis for many servers.
9. **How would you version an API?** `/v1/` paths or headers; never break existing clients.
10. **How do you make a POST idempotent?** An idempotency key stored with the result; or a unique constraint.
11. **Middleware vs dependency?** Middleware sees every request at the ASGI level; dependencies are per route and typed.
12. **Tell me about a server-side design you're proud of.** inPace's NavMiddleware: one place turns redirects into
    JSON for the page script, so 112 routes stay plain and navigation is consistent.

## System design mini-question

> "Design the course library service so the app can browse and download courses."

inPace's answer is **static**: GitHub Actions validates submissions, then publishes `library.json` and zipped packs
with SHA-256 sums to GitHub Pages. No server to run, a CDN for free, integrity checked by hashes. If you needed search,
ratings or private courses, you'd add a small FastAPI service with a database, keeping packs on object storage
behind a CDN.
