# Starlette or FastAPI? A design answer

| | Starlette | FastAPI |
|---|---|---|
| Size | Small, few dependencies | Starlette + Pydantic + more |
| Best for | HTML apps, custom protocols, tiny services | JSON APIs used by other programs |
| Validation | By hand | Automatic from types |
| Docs | None | OpenAPI + Swagger UI for free |
| Start-up and binary size | Smaller | Larger (Pydantic core is compiled) |

**Why inPace uses Starlette:** it serves HTML forms to one local user, not a public JSON API. Automatic API docs
add nothing; Pydantic would add size to the frozen desktop app and the Android build; forms are validated with
friendly sentences shown on the page, not 422 JSON.

**When you'd pick FastAPI:** a mobile app or another team calls your API; you want typed contracts, generated
clients, and docs. For example, if inPace ever offered an optional sync relay, that service would be a natural
FastAPI app.

Saying "it depends, and here's on what" with a real example is exactly what interviewers want.
