# Testing the whole app

inPace's biggest test drives two people through the real pages:

```python
from starlette.testclient import TestClient
from inpace.app import create_app
from inpace.vault import Vault

def client(tmp_path, name):
    v = Vault(tmp_path / name)
    c = TestClient(create_app(v))
    r = c.post("/setup", data={"name": name, "color": "#1F7A56"})
    assert r.status_code == 200 and f"Hi {name}" in html.unescape(r.text)
    return v, c

def test_everything(tmp_path):
    lv, learner = client(tmp_path, "Omar")
    cv, checker = client(tmp_path, "Sara")
    for path in ["/", "/courses", "/milestones", "/people", "/open", "/ai", "/settings"]:
        assert learner.get(path).status_code == 200, path
    ...
```

- `TestClient` runs the ASGI app in the test process: no server, no ports.
- `tmp_path` (pytest) gives each test a clean folder.
- A `conftest.py` sets `INPACE_SCHEDULER=off` so tests never touch the real computer's scheduler.
- FastAPI uses the same TestClient (`from fastapi.testclient import TestClient`), or `httpx.AsyncClient` with
  `ASGITransport` for async tests.

Test pyramid: many fast unit tests (canon, exam order, chain checks), fewer page-level tests, a few end-to-end
checks in CI (inPace starts the built app and loads its first page).
