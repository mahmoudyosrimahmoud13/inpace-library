# The algorithm

Start somewhere, then repeat until convergence, updating both parameters **at the same time**:

```text
tmp_w = w − α · ∂J/∂w
tmp_b = b − α · ∂J/∂b
w, b = tmp_w, tmp_b
```

- `α` is the **learning rate**: step size.
- The derivative says which way is uphill; we step the other way.
- **Simultaneous update**: computing `b`'s step with the already-updated `w` is a subtle bug.

## The learning rate

- Too small: correct, but painfully slow.
- Too large: overshoots, can **diverge** (cost grows).
- With a fixed `α`, steps still shrink near the minimum because the slope gets smaller.

## Advanced

- Gradient descent finds a **local** minimum in general; for convex `J` that's the global one.
- Variants: **batch** (all `m` examples per step, as in this course), **stochastic** (one example), **mini-batch**
  (e.g. 32 to 512). Mini-batch is what everyone uses for big data: noisy but much faster per step, and the noise can
  help escape poor regions. Part 2 adds **Adam**, which adapts the step size per parameter.
