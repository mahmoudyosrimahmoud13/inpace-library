# Regularized cost and gradient descent

Add a penalty on the weights' size:

```text
J(w,b) = (1/2m) Σᵢ ( f(x⁽ⁱ⁾) − y⁽ⁱ⁾ )²  +  (λ/2m) Σⱼ w_j²
```

- `λ` (lambda) sets the trade-off. `λ = 0`: no regularization (may overfit). Huge `λ`: all `w ≈ 0`, the model is a flat
  line at `b` (underfit).
- `b` is usually **not** regularized; it makes little difference.

The gradient gets one extra term:

```text
w_j = w_j − α [ (1/m) Σᵢ (f(x⁽ⁱ⁾) − y⁽ⁱ⁾) x_j⁽ⁱ⁾ + (λ/m) w_j ]
    = w_j (1 − αλ/m) − α · (usual gradient)
```

So each step first **shrinks** `w_j` a little ("weight decay"), then does the usual update. The same works for
logistic regression.

## Going further: L2 vs L1

| | L2 (ridge), `Σ w²` | L1 (lasso), `Σ |w|` |
|---|---|---|
| Effect | shrinks all weights smoothly | pushes many weights to exactly 0 |
| Good for | many small useful features | automatic feature selection |
| Bayesian view | Gaussian prior on `w` | Laplace prior on `w` |

**Elastic net** mixes both. In scikit-learn, `C = 1/λ` for `LogisticRegression`: a smaller `C` means **more**
regularization, a classic trick question.
