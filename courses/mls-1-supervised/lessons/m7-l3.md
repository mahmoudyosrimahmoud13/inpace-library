# Project 5: overfitting, seen and fixed

You'll make Homes overfit on purpose, with high-degree polynomials and only 100 districts, then fix it two ways:
regularization and more data.

The code is above this text. Save it as `p5_regularization.py`.

## Read the code

- **`poly(df, degree)`** makes every product `income^i * age^j` up to the degree (44 features at degree 8). Inputs are
  first mapped to -1..1 using the training range, so high powers stay manageable.
- **`fit(X, y, lam)`** solves ridge regression exactly: `(X^T X + lam I)^-1 X^T y`, with the bias not penalized. With
  `lam = 0` it's ordinary least squares.
- It trains on 100 districts and tests on 3,930.

## Run it

```bash
python p5_regularization.py
```

The real output:

```text
1. Polynomials of income and age, trained on 100 districts:
   degree  features  train RMSE  test RMSE
        1         2         63k        71k
        2         5         60k        72k
        4        14         59k        75k
        6        27         54k       220k
        8        44         45k      6929k
   Training error keeps falling; test error rises: the model learns the 100 districts' noise.

2. Degree 8 with L2 regularization (lambda):
   lambda      0: train   45k, test   6929k, largest weight     45,701
   lambda    0.1: train   57k, test     79k, largest weight        214
   lambda      1: train   60k, test     73k, largest weight        161
   lambda     10: train   66k, test     73k, largest weight         86
   lambda    100: train   84k, test     87k, largest weight         24
   lambda   1000: train   96k, test     97k, largest weight          3

3. Or get more data: degree 8, no regularization, all 15,718 training districts: test 70k
```

What it shows:

- **Classic overfitting**: from degree 1 to 8, training error falls from 63k to 45k while test error explodes to
  millions. With 44 features and 100 districts, the model fits the noise with enormous weights (45,701).
- **A little regularization fixes it**: `lambda = 1` brings the test error to 73k, the same as a simple line, by
  keeping weights small. **Too much** (`1000`) underfits: both errors rise.
- **More data fixes it too**: with 15,718 districts, the same degree-8 model tests at 70k without any regularization.

## Make it yours

1. Find the best `lambda` with a validation set carved out of the training data (never the test set).
2. Repeat with 1,000 training districts. At which degree does overfitting start now?

## What to take away

- Overfitting: training error down, test error up.
- Regularization and more data are the two cures; choose lambda on validation data.
