# Project 6: check it all against scikit-learn

You'll check that your from-scratch models match a trusted library, then see how much further a non-linear model
goes.

The code is above this text. Save it as `p6_check_with_sklearn.py`.

## Read the code

- Your `gd()` from project 3 for 5,000 steps, against scikit-learn's `LinearRegression` (which solves exactly), on
  the same 12 scaled features. It compares test errors and the weights themselves.
- Your logistic regression against `LogisticRegression(C=np.inf)` (no regularization, like yours).
- Last, `HistGradientBoostingRegressor`, gradient boosted trees, on the same features.

## Run it

```bash
python p6_check_with_sklearn.py
```

The real output:

```text
1. Linear regression, 12 features:
   yours (gradient descent, 5,000 steps)  test RMSE $60.51k
   scikit-learn (exact solution)          test RMSE $60.51k
   largest difference between the two sets of weights: 0.000

2. Logistic regression, expensive or not:
   yours          test accuracy 87.25%
   scikit-learn   test accuracy 87.56%   (same answer on 98.6% of districts)

3. Beyond straight lines: gradient boosted trees (the refresh's part 2) on the same features: test RMSE $42k in 0.5 s
   Location matters in curved ways (coast, cities) that one weight per feature can't capture.
```

What it shows:

- **Your linear regression is scikit-learn's**: the same error to the cent and the same weights. Gradient descent,
  run long enough, finds the exact solution.
- **Your logistic regression agrees on 98.6% of districts**: scikit-learn trains longer with a better optimizer,
  so it's a fraction better.
- **Trees cut the error by a third** ($42k against $61k): they can learn that location matters in curved ways (near
  the coast, near cities), which one weight per feature can't. That's part 2 of this refresh.
