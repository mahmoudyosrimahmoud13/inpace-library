# الـ issues والوسوم والمشاريع

الـ **issue** قطعة عمل واحدة: خطأ، أو ميزة، أو سؤال. والـ issue الجيدة لها عنوان واضح، وخطوات لإعادة إنتاج المشكلة (للأخطاء)، وما كنت تتوقعه.

- **الوسوم (labels)** ترتّبها: `bug` و `enhancement` و `good first issue` و `help wanted`.
- **المسؤولون (assignees)** يحددون من يعمل عليها، و**المراحل (milestones)** تجمع issues لإصدار ما.
- اكتب `#12` في أي مكان لتربط الـ issue رقم 12، و `@name` لتنبّه شخصًا.
- **أغلقها من commit أو طلب دمج:** كتابة `Fixes #12` أو `Closes #12` في الوصف تغلق الـ issue عندما يُدمج في الفرع الافتراضي.
- **الـ sub-issues** تقسم issue كبيرة إلى أصغر، مع نسبة التقدم.

## نماذج الـ issues

ملف في `.github/ISSUE_TEMPLATE/` يحوّل زر "New issue" إلى نموذج، فتأتي البلاغات بما تحتاجه:

```yaml
# .github/ISSUE_TEMPLATE/bug.yml
name: Bug report
description: Something doesn't work as it should.
labels: [bug]
body:
  - type: textarea
    id: what
    attributes:
      label: What happened?
      description: What did you do, what did you expect, and what happened instead?
    validations:
      required: true
  - type: input
    id: browser
    attributes:
      label: Browser
      placeholder: Chrome 140 on Windows 11
```

## المشاريع (Projects)

الـ **project** لوحة أو جدول من الـ issues وطلبات الدمج، من مستودع واحد أو عدة مستودعات. أضف أعمدة مثل *Todo و In progress و Done*، وحقولًا خاصة (الأولوية، والحجم، والدورة)، وأتمتة (طلب الدمج المدموج ينقل بطاقته إلى *Done*). إنه Trello مجاني ومدمج.
