# مراجعة الكود

في تبويب **Files changed** اضغط **+** بجوار سطر لتعلّق. واضغط **Start a review** لتجمع عدة تعليقات وترسلها معًا، ثم اختر:

- **Comment:** أسئلة أو ملاحظات، دون حكم.
- **Approve:** جاهز للدمج.
- **Request changes:** يجب الإصلاح قبل الدمج.

و**الاقتراحات (suggestions)** أفضل أنواع التعليقات: يطبقها المؤلف بضغطة واحدة.

````markdown
```suggestion
const total = tasks.reduce((sum, t) => sum + t.minutes, 0);
```
````

## كيف تراجع جيدًا

- ابحث عمّا يهم: الأخطاء، والأمان، والاختبارات الناقصة، والأسماء المربكة. واترك التنسيق للأدوات.
- اسأل، لا تأمر: *"ماذا يحدث إن كانت القائمة فارغة؟"*
- علّم الأشياء الصغيرة بكلمة **nit:** كي يعرف المؤلف أنها اختيارية.
- قل ما هو جيد أيضًا.
- راجع خلال يوم: طلب الدمج المنتظر يعطّل شخصًا ما.

**عندما تُراجَع:** المراجعة عن الكود لا عنك. أجب على كل تعليق (أصلحه، أو اشرح لماذا لا)، وارفع الإصلاحات كـ commits جديدة كي يرى المراجع ما تغيّر، واضغط **Re-request review**.
