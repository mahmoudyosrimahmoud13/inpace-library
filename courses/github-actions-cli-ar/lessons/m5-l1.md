# workflow للاختبارات

**التكامل المستمر (CI)** يعني أن كل تغيير يُختبر تلقائيًا قبل أن يصل إلى main. وهذا workflow اختبارات كامل لمشروع Node، يعمل مع كل push إلى main ومع كل طلب دمج، على نظامين ونسختين من Node:

```yaml
# .github/workflows/ci.yml
name: Tests

on:
  push:
    branches: [main]
  pull_request:

concurrency:                     # a new push cancels the run that's still going for the same branch
  group: tests-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read                 # this workflow only needs to read the code

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: [20, 22]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: ${{ matrix.node }}
      - run: npm test
```

- **matrix** يصنع 4 jobs من وصف واحد (نظامان × نسختان). و `fail-fast: false` يترك الباقي يكمل عندما يفشل واحد، فترى الصورة كاملة.
- **concurrency** يلغي التشغيل القديم عندما ترفع مرة أخرى إلى الفرع نفسه: دقائق مهدرة أقل.
- **permissions** يعطي رمز التشغيل ما يحتاجه فقط (الوحدة 6).

ولبايثون تكون الخطوات `actions/setup-python@v7` مع `python-version`، ثم `pip install -e ".[test]"` ثم `pytest`.

## اجعله مؤثرًا

لا يحمي workflow الاختبارات main إلا إذا انتظره الدمج. في الـ ruleset من الوحدة 2 أضف **Require status checks to pass** واختر jobs الـ `test`. والآن لا يمكن دمج طلب دمج أحمر.
