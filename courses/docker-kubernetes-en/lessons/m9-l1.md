# 20 interview questions

Answer out loud first, then read the short answer.

1. **Container vs VM?** A container shares the host kernel; a VM has a full OS.
2. **Namespaces and cgroups?** Isolation and resource limits.
3. **Image vs container?** Read-only template vs running instance.
4. **CMD vs ENTRYPOINT?** Default arguments vs the fixed program.
5. **COPY vs ADD?** COPY just copies; ADD also unpacks archives and fetches URLs.
6. **How do you shrink an image?** Multi-stage builds, a small base, .dockerignore, cleaning caches in the same RUN.
7. **How do you keep data?** Volumes.
8. **How do containers talk?** A user-defined network with DNS by name.
9. **What's the build cache?** Reusing layers up to the first changed instruction.
10. **Why not run as root?** A breakout gives more power.
11. **Compose vs Swarm vs Kubernetes?** One machine; a simple cluster; a full, rich platform.
12. **Pod?** The smallest unit: one or more containers sharing a network.
13. **Deployment?** Manages replicas, updates and rollbacks.
14. **Service types?** ClusterIP, NodePort, LoadBalancer (and ExternalName).
15. **ConfigMap vs Secret?** Plain settings vs sensitive ones (Secrets are only base64 by default; enable encryption in etcd).
16. **Liveness vs readiness probe?** Should it be restarted? Should it get traffic?
17. **OOMKilled?** The container went over its memory limit.
18. **CrashLoopBackOff?** It crashes and restarts repeatedly: check `kubectl logs --previous` and `describe`.
19. **Ingress?** HTTP routing from outside by host and path.
20. **Zero-downtime deploys?** Rolling updates with readiness probes, or blue/green and canary releases.

## Design question

> "Design how you'd deploy a web app with a database on Kubernetes."

A Deployment with 3 replicas and readiness/liveness probes, a Service and an Ingress in front. The database as a
managed service (best) or a StatefulSet with a PersistentVolume. Settings in a ConfigMap, secrets in a Secret. An HPA
for autoscaling, requests and limits on every container, and CI that builds and pushes the image, then updates the
Deployment.
