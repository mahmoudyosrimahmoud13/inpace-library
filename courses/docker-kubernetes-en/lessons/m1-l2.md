# What containers are

## The idea in two lines

A program needs an **environment** to run: a language version, libraries, settings. A container packs the program
**with** its environment, so it runs the same on your laptop, on a server and on a teammate's machine. Goodbye
"but it works on my machine!".

## From servers to containers

| Stage | Idea | Problem |
|---|---|---|
| One server per app | one application on a whole machine | huge waste, and buying servers takes weeks |
| Virtual machines (VMs) | several operating systems on one machine | each VM carries a full OS: heavy and slow to boot |
| Containers | isolated apps sharing one OS kernel | light, start in seconds |

## Watch for

- The difference between **isolation** and **sharing**: containers share the kernel, but each sees its own files,
  network and processes.
- Why containers made **microservices** practical: each service in its own container, updated and scaled on its own.
