# Data lake to warehouse (ELT)

## ETL vs ELT

| | ETL | ELT |
|---|---|---|
| Transform where | Before loading, in a separate engine | **Inside the warehouse**, after loading |
| Fits | Limited warehouses, strict privacy filtering | Cheap cloud warehouses (BigQuery, Snowflake) |
| Raw data kept? | Often not | Yes, so you can re-transform anytime |

Modern stacks are mostly **ELT**: land raw, then transform with SQL (dbt).

## Lake layout

```
gs://project-data-lake/
  raw/taxi/yellow/2026/10/yellow_tripdata_2026-10.parquet
  staging/...
```

- **Parquet** over CSV: columnar, compressed, typed, and it's fast to scan only the columns you need.
- Partition folders by date so loads and deletes target one period.
- Keep raw files **immutable**.

## Getting files into BigQuery

- **Load job** (`LOAD DATA` / `bq load`): copies data into native storage. Fast queries, and loading is free.
- **External table** over GCS: queries files where they are, with no copy. Good for exploration, but slower and with no cache benefits.

```sql
CREATE OR REPLACE EXTERNAL TABLE trips_ext
OPTIONS (format = 'PARQUET', uris = ['gs://bucket/raw/taxi/yellow/2026/*.parquet']);

CREATE OR REPLACE TABLE trips AS SELECT * FROM trips_ext;
```

> **Key idea:** keep immutable raw Parquet in the lake, load into the warehouse, and transform there.
