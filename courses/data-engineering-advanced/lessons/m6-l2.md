# Kafka in depth

This lesson has no video. The Zoomcamp's Kafka module is in the course playlist if you want to watch it.

## Core model

| Concept | Meaning |
|---|---|
| Topic | Named stream of records |
| Partition | Ordered, append-only log; the unit of parallelism |
| Offset | A record's position in a partition |
| Producer | Writes records (key, value) |
| Consumer group | Consumers that share the partitions; each partition has one consumer per group |
| Broker | A Kafka server; partitions are replicated across brokers |

## Keys and ordering

- Records with the **same key go to the same partition**, so they stay in order.
- Ordering is guaranteed **only within a partition**.
- More partitions mean more parallelism, but you can't easily reduce them later, and a hot key still lands on one partition.

## Durability settings

- `replication.factor=3` and `min.insync.replicas=2`
- Producer `acks=all` plus `enable.idempotence=true` prevent loss and duplicates from retries.

## Consumers and offsets

- Consumers **commit offsets** to record progress.
- Commit **after** processing gives at-least-once, so make processing idempotent.
- A **rebalance** happens when consumers join or leave, and partitions get reassigned.

## Schemas

Use **Avro** (or Protobuf) with a **Schema Registry**:
- Compact binary format.
- **Compatibility rules** (backward or forward) stop a producer from breaking consumers. For example, adding a field needs a default value.

## Processing

- **Kafka Streams / ksqlDB**: stream processing inside the Kafka ecosystem (joins, windows, tables).
- **Flink / Spark Structured Streaming**: bigger stateful jobs.
- **Kafka Connect**: ready-made source and sink connectors (Debezium CDC from Postgres, a BigQuery sink).

> **Key idea:** partition by the key you need ordered, use acks=all with idempotent producers, and enforce schemas with a registry.
