# Analytics engineering and dbt

## The role

**Analytics engineers** sit between data engineers and analysts. They turn raw loaded tables into clean, tested, documented models using software practices: version control, code review, tests and CI.

## What dbt does

dbt is the **T in ELT**. You write `SELECT` statements; dbt:
- Turns them into tables or views in the warehouse.
- Works out the order from `ref()` dependencies (a DAG).
- Runs tests and builds documentation and lineage.

```sql
-- models/staging/stg_yellow_trips.sql
select
  cast(vendorid as integer)               as vendor_id,
  cast(tpep_pickup_datetime as timestamp) as pickup_at,
  cast(fare_amount as numeric)            as fare_amount
from {{ source('raw', 'yellow_trips') }}
where vendorid is not null
```

## dbt Core vs dbt Cloud

| | dbt Core | dbt Cloud |
|---|---|---|
| Cost | Free, open source | Paid (free developer tier) |
| Runs | Your CLI, CI or orchestrator | Hosted IDE and scheduler |
| Good for | Teams with their own orchestration (Kestra, Airflow) | Teams wanting a managed setup |

## Materializations

| Type | Behavior |
|---|---|
| view | No storage, computed on every query |
| table | Fully rebuilt each run |
| incremental | Only new or changed rows are processed |
| ephemeral | Inlined as a CTE |

> **Key idea:** dbt brings software engineering to SQL transformations: refs, tests, docs and version control.
