# Terraform basics in practice

## Variables and outputs

```hcl
variable "region" {
  type    = string
  default = "europe-west1"
}

output "bucket_name" {
  value = google_storage_bucket.data_lake.name
}
```

Pass values per environment with `-var` or a `terraform.tfvars` file, for example `dev.tfvars` and `prod.tfvars`.

## How Terraform decides what to change

Terraform compares three things: **your config**, **the state file**, and **the real cloud**.
- A resource is in the config but not in state, so it's **created**.
- A setting changed, so it's **updated in place**, or **destroyed and recreated** when the setting can't change in place (the plan marks this `-/+`).
- A resource is in state but not in the config, so it's **destroyed**.

**Read every `-/+` in the plan.** Recreating a database or bucket can delete data.

## Common mistakes

- Two people running `apply` with local state, which corrupts or diverges the state. Use a remote backend with locking.
- Hardcoding the project ID and secrets. Use variables and a secret manager.
- Changing resources by hand in the console, which causes **drift**. The next plan tries to undo your manual change.

## Modules

Group repeated resources (for example "a bucket plus a dataset per team") into a **module** and call it several times with different inputs.

> **Key idea:** Terraform is declarative: you describe the end state, and the plan shows the path. Always review destroys.
