# Kestra concepts

## Flows are YAML

```yaml
id: taxi_ingest
namespace: zoomcamp
inputs:
  - id: taxi
    type: SELECT
    values: [yellow, green]
variables:
  file: "{{ inputs.taxi }}_tripdata_{{ trigger.date | date('yyyy-MM') }}.csv"
tasks:
  - id: extract
    type: io.kestra.plugin.scripts.shell.Commands
    commands:
      - wget -qO- https://.../{{ render(vars.file) }}.gz | gunzip > {{ render(vars.file) }}
    outputFiles: ["*.csv"]
  - id: load
    type: io.kestra.plugin.jdbc.postgresql.CopyIn
    from: "{{ outputs.extract.outputFiles[render(vars.file)] }}"
    table: staging_trips
triggers:
  - id: monthly
    type: io.kestra.plugin.core.trigger.Schedule
    cron: "0 9 1 * *"
```

## Vocabulary

| Term | Meaning |
|---|---|
| Flow | The pipeline definition |
| Namespace | Folder for flows, files and secrets |
| Task | One step (a script, SQL, an HTTP call, a file copy) |
| Inputs | Parameters chosen at run time |
| Outputs | Values or files a task passes to later tasks |
| Trigger | Schedule, webhook or event that starts the flow |
| Execution | One run of a flow |

## Secrets and key-value store

Don't hardcode passwords. Use `{{ secret('POSTGRES_PASSWORD') }}`, and store small state (for example "last processed date") in the KV store.

> **Key idea:** in Kestra, everything is declarative YAML: tasks, inputs, outputs and triggers. That makes pipelines easy to review in git.
