# Docker for data pipelines

The video is the Data Engineering Zoomcamp playlist. Watch the module 1 Docker videos, then use this page as your notes.

## Why data engineers use Docker

- **Same environment everywhere**: your laptop, CI and production run the same image.
- **Throwaway infrastructure**: start Postgres, pgAdmin or Kafka in seconds, then delete them.
- **Pipelines as images**: an ingestion script plus its dependencies becomes one runnable unit.

## Core pieces

| Piece | What it is |
|---|---|
| Image | Read-only template (`python:3.12-slim`, `postgres:16`) |
| Container | A running instance of an image |
| Volume | Persistent storage that outlives the container |
| Network | Lets containers reach each other by name |

## A pipeline image

```dockerfile
FROM python:3.12-slim
RUN pip install pandas sqlalchemy psycopg2-binary pyarrow
WORKDIR /app
COPY ingest.py .
ENTRYPOINT ["python", "ingest.py"]
```

```bash
docker build -t taxi_ingest:v1 .
docker run --network pg-net taxi_ingest:v1 --table yellow_trips --url https://...
```

## Docker Compose for the local stack

```yaml
services:
  pgdatabase:
    image: postgres:16
    environment: {POSTGRES_USER: root, POSTGRES_PASSWORD: root, POSTGRES_DB: ny_taxi}
    volumes: ["./pg_data:/var/lib/postgresql/data"]
    ports: ["5432:5432"]
  pgadmin:
    image: dpage/pgadmin4
    ports: ["8080:80"]
```

- Inside Compose, services reach each other by **service name** (`pgdatabase:5432`), not `localhost`.
- `localhost` inside a container means **that container**, a classic beginner bug.

## Loading big files properly

- Read in **chunks** (`pd.read_csv(..., chunksize=100_000)`) or use Parquet, never load 10 GB at once.
- Create the table from the schema first, then append chunks.
- For Postgres, `COPY` is far faster than row-by-row inserts.

> **Key idea:** containers make pipelines reproducible. Inside a network, use service names, and stream data in chunks.
