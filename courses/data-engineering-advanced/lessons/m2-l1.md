# What workflow orchestration is

## Scripts aren't pipelines

A cron job running `python ingest.py` breaks quietly: no retries, no dependencies between steps, no history, no alerts, and no clean way to re-run last Tuesday.

## What an orchestrator gives you

| Feature | Why it matters |
|---|---|
| DAG of tasks | Steps run in order and in parallel where possible |
| Scheduling | Cron-like triggers, or event triggers (a file lands) |
| Retries and timeouts | Transient failures fix themselves |
| Backfills | Re-run past dates in one command |
| Logs and lineage | See what ran, when, with what inputs |
| Alerts | Know about failures before the business does |

Tools: **Kestra** (used in the Zoomcamp), Airflow, Dagster, Prefect, Mage.

## A typical batch pipeline

```
extract (API / files)  ->  load raw to data lake (GCS/S3)
   ->  load to warehouse (BigQuery)  ->  transform (dbt)  ->  tests  ->  notify
```

## Design rules

- **Small tasks with one job each**: easier retries and clearer failures.
- **Pass references, not data**: tasks hand over a file path or table name, not a giant dataframe.
- **Parameterize by date**: every run processes one logical period, for example `{{ trigger.date }}`.

> **Key idea:** an orchestrator turns scripts into reliable, observable, re-runnable pipelines.
