# RAG questions you'll be asked

You built DocAnswer, so answer from experience. The usual questions and the core of a strong answer:

| Question | The core of a strong answer |
|---|---|
| Text or vector search? | both: keywords for exact terms and ids, vectors for meaning; hybrid with RRF; measure |
| How do you process huge PDF reports? | extract with layout (tables!), OCR scans, chunk by structure, keep metadata, deduplicate |
| Model hallucinates when context lacks the answer? | refusal instruction and check, faithfulness evals, show sources, confidence |
| Common RAG failure points? | missing content, missed top-k, lost in a long context, wrong extraction, bad format |
| Citations? | number the sources, require citations, verify cited ids exist, link to the page |
| Semantic caching? | reuse answers for questions whose embeddings are very close; risky when answers depend on the user or time |
| Scale to 10M+ documents? | a vector DB with approximate search (HNSW), metadata filters, sharding, incremental indexing, cache |
| Key trade-offs? | chunk size vs context, k vs noise and cost, reranker quality vs latency, freshness vs index cost |

**Permissions** are the question people forget: in a company, users must only retrieve documents they're allowed to see. Filter by access rights at retrieval time, never after generation.
