# Back-of-the-envelope numbers

Interviewers want you to estimate out loud. Write the formula, then the numbers (state that prices are assumptions and change often):

- **Tokens per request:** system prompt 500 + 8 chunks × 200 + question 50 + history 0 = about 2,150 input; answer about 300 output.
- **Daily cost:** requests per day × (input tokens × input price + output tokens × output price).
- **Index size:** 10M documents × 5 chunks × 1,024 dimensions × 4 bytes ≈ 205 GB of float32 vectors, before index overhead; halve it with float16, or much more with quantization.
- **Throughput:** peak requests per second × average generation seconds = concurrent generations to provision.

## Two more estimates interviewers like

**GPU memory to serve an open model:** parameters × bytes per parameter, plus the KV cache.

- A 70B model in 16-bit: 70 × 10⁹ × 2 bytes ≈ **140 GB** of weights: two 80 GB GPUs before any cache. In 4-bit: about 35 GB.
- **KV cache per token** = 2 (keys and values) × layers × KV heads × head size × bytes. For a model with 80 layers, 8 KV heads of size 128, in 16-bit: 2 × 80 × 8 × 128 × 2 ≈ **330 KB per token**, so one 32K-token conversation needs about 10 GB. That's why long contexts limit how many users fit on a GPU.

**A worked cost example** (assumed round prices, to show the method): 50,000 requests a day, 2,150 input and 300 output tokens each. At $1 per million input tokens and $4 per million output: 50,000 × (2,150 × 1 + 300 × 4) / 10⁶ = 50,000 × 0.00335 ≈ **$168 a day**. If 70% of the input is a cached prefix billed at a tenth, input cost falls from $107.50 to about $40, and the day costs about $100. Say the formula, show one line of arithmetic, then the lever.
