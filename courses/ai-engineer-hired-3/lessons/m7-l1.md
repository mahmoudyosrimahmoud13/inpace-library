# Cost, latency and reliability

**Cost per request = input tokens × input price + output tokens × output price** (plus embeddings and retrieval). Output tokens usually cost several times more than input. Levers, roughly in the order to try them:

1. **Shorter context:** fewer, better chunks; trimmed history.
2. **Model tiering / routing:** a small model for easy or classified cases, a big one for the hard rest.
3. **Caching:** exact-match caching for repeated requests, prompt caching for long shared prefixes (many APIs offer it), semantic caching where safe.
4. **Batching** for offline jobs.
5. **Fine-tune or distil** a small model when volume is high and the task is narrow.

## Latency and reliability

- **TTFT** is what users feel: stream tokens, start retrieval and the model call early, run independent calls in parallel.
- Measure **p50 and p95** per step (retrieval, each LLM call, tools); fix the biggest.
- Every external call gets a **timeout, retries with backoff, and a fallback** (another model, a cached answer, or a clear "try again").
- Respect **rate limits**; queue bursts.
