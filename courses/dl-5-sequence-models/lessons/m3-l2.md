# GRU and LSTM

**GRU:** a memory cell `c<t>` with an **update gate** `Γu`: `c<t> = Γu·c̃<t> + (1 − Γu)·c<t−1>`. When `Γu ≈ 0`, the
cell just keeps its value, so information (and gradient) survives many steps. A relevance gate `Γr` decides how much
of the past to use in the candidate `c̃<t>`.

**LSTM:** separate **forget** `Γf`, **update** (input) `Γu` and **output** `Γo` gates:
`c<t> = Γu·c̃<t> + Γf·c<t−1>`, `a<t> = Γo·tanh(c<t>)`.

Which one? LSTM is the more flexible, historically the default; GRU is simpler and faster. Both were the standard for
sequence work until transformers. They're still used where memory and latency are tight, and new recurrent designs
(state-space models such as Mamba) bring back the "fixed-size state" idea at large scale.

```python
nn.LSTM(input_size, hidden_size, num_layers=2, batch_first=True, bidirectional=True)
keras.layers.Bidirectional(keras.layers.LSTM(64, return_sequences=True))
```
