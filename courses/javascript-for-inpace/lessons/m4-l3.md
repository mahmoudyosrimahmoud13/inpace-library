# Reading inPace's background form sender

This is the heart of app.js's navigation (simplified):

```js
document.addEventListener("submit", async (e) => {
  const f = e.target;
  if (!(f instanceof HTMLFormElement) || !f.hasAttribute("data-nav-form") || e.defaultPrevented) return;
  e.preventDefault();
  if (f.dataset.sending) return;                     // no double sends
  f.dataset.sending = "1";
  f.querySelectorAll("button").forEach((b) => { b.disabled = true; });
  const body = new FormData(f);
  if (e.submitter && e.submitter.name) body.append(e.submitter.name, e.submitter.value);
  try {
    const r = await fetch(f.action || location.href, { method: "POST", body, headers: { "X-InPace-Nav": "1" } });
    const type = r.headers.get("content-type") || "";
    if (type.includes("application/json")) {
      const data = await r.json();
      if (data && data.go) { goFresh(data.go); return; }
    }
    if (type.includes("text/html")) {                // a page with a message, e.g. a mistake in the form
      const html = await r.text();
      document.open(); document.write(html); document.close();
      return;
    }
    location.reload();
  } catch (err) {
    delete f.dataset.sending;   // let the user try again
  }
});
```

Things to notice for an interview:

- **Guard clauses** keep the handler fast for forms it doesn't own.
- **Idempotency on the client**: `dataset.sending` and disabled buttons stop double submits.
- **Content negotiation by header**: the server answers JSON only when it sees `X-InPace-Nav`.
- **Graceful fallback**: if anything fails, the user can try again, and without JavaScript the form still works.
