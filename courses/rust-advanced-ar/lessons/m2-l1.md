# الـ Closures والـ iterators بعمق

## ثلاثة traits للـ closures

طريقة استخدام الـ closure لما تلتقطه تحدد أي trait تنفّذ:

<!-- diagram -->
```mermaid
flowchart LR
  FO["FnOnce<br/>تُستدعى مرة على الأقل"] --> FM["FnMut<br/>عدة مرات، قد تغيّر ما التقطته"]
  FM --> FN["Fn<br/>عدة مرات، تقرأ فقط"]
```

| الـ Trait | الـ closure... | يمكن استدعاؤها |
|---|---|---|
| `Fn` | تقرأ ما التقطته فقط | مرات كثيرة، وحتى في نفس الوقت |
| `FnMut` | تغيّر ما التقطته | مرات كثيرة، واحدة في كل مرة |
| `FnOnce` | تنقل شيئًا ملتقطًا للخارج (تستهلكه) | مرة واحدة |

والـ functions التي تأخذ closures تقول أيها تحتاج:

```rust
fn apply_twice<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(f(x))
}

fn repeat<F: FnMut()>(mut f: F, times: usize) {
    for _ in 0..times {
        f();
    }
}

fn run_once<F: FnOnce() -> String>(f: F) -> String {
    f()
}

fn main() {
    let add = 3;
    println!("{}", apply_twice(|n| n + add, 10));

    let mut count = 0;
    repeat(|| count += 1, 4);
    println!("count {count}");

    let report = String::from("monthly report");
    let send = move || report + " sent";           // moves report in, then uses it up
    println!("{}", run_once(send));
}
```

```output
16
count 4
monthly report sent
```

- `move` تجعل الـ closure **تأخذ ownership** ما تلتقطه. وتحتاجها عندما تعيش الـ closure أطول من الـ function الحالية: عند إرجاعها، أو إرسالها إلى thread.
- اقبل أعم trait تستطيعه: `FnOnce` تقبل كل الـ closures، و`FnMut` تقبل الـ `Fn` والـ `FnMut`، و`Fn` تقبل القارئة فقط.

## إرجاع closures وiterators: ‏impl Trait

```rust
fn multiplier(k: i32) -> impl Fn(i32) -> i32 {
    move |x| x * k
}

fn evens_squared(limit: u32) -> impl Iterator<Item = u32> {
    (1..=limit).filter(|n| n % 2 == 0).map(|n| n * n)
}

fn main() {
    let triple = multiplier(3);
    println!("{}", triple(14));
    println!("{:?}", evens_squared(10).collect::<Vec<_>>());
}
```

```output
42
[4, 16, 36, 64, 100]
```

‏`impl Iterator<Item = u32>` تقول "iterator ما من u32" بدون كتابة نوعه الحقيقي الطويل. ويستطيع المستدعي الاستمرار في الربط عليه، ولا يعمل شيء حتى يستهلكه.

## محوّلات iterators ستستخدمها دائمًا

```rust
fn main() {
    let names = ["Ali", "Mona", "Karim", "Huda"];
    let scores = [72, 95, 64, 88];

    for (name, s) in names.iter().zip(scores.iter()) {
        print!("{name}={s} ");
    }
    println!();

    let (pass, fail): (Vec<i32>, Vec<i32>) = scores.iter().partition(|&&s| s >= 70);
    println!("pass {:?} fail {:?}", pass, fail);

    let best = names.iter().zip(scores).max_by_key(|&(_, s)| s).unwrap();
    println!("best: {} with {}", best.0, best.1);

    let chunks: Vec<i32> = scores.chunks(2).map(|c| c.iter().sum()).collect();
    println!("pairs summed {:?}", chunks);

    let running: Vec<i32> = scores
        .iter()
        .scan(0, |total, &s| {
            *total += s;
            Some(*total)
        })
        .collect();
    println!("running total {:?}", running);

    let words = "one two three two one two";
    let first_repeat = words
        .split(' ')
        .enumerate()
        .find(|(i, w)| words.split(' ').take(*i).any(|x| x == *w));
    println!("first repeat {:?}", first_repeat);
}
```

```output
Ali=72 Mona=95 Karim=64 Huda=88 
pass [72, 95, 88] fail [64]
best: Mona with 95
pairs summed [167, 152]
running total [72, 167, 231, 319]
first repeat Some((3, "two"))
```

قاموس قصير: `zip` تزاوج مُكرِّرين؛ و`partition` تقسم إلى مجموعتين؛ و`max_by_key` تجد الأكبر بمقياس ما؛ و`chunks` تجمّع slice في مجموعات؛ و`scan` تحمل حالة أثناء المرور؛ و`find` تتوقف عند أول تطابق. وغيرها يستحق المعرفة: `flat_map` و`take_while` و`skip_while` و`windows` و`rev` و`fold` و`position` و`dedup` (على Vec).

## الـ iterators بدون تكلفة

سلسلة مثل `.iter().filter(..).map(..).sum()` تُترجم إلى نفس كود الآلة الذي تنتجه loop مكتوبة يدويًا، وغالبًا أفضل، لأن الـ compiler يرى الصورة كاملة. فضّل سلاسل الـ iterators لوضوحها؛ فأنت لا تدفع ثمنها.

## الخلاصة

- `Fn` تقرأ، و`FnMut` تغيّر، و`FnOnce` تستهلك؛ و`move` تعطي الملتقطات للـ closure.
- أرجع الـ closures وسلاسل الـ iterators بـ `impl Fn(..)` و`impl Iterator<Item = T>`.
- تعلّم zip وpartition وmax_by_key وchunks وscan وfind؛ وسلاسل الـ iterators لا تكلف شيئًا إضافيًا.
