# الـ smart pointers: Box وRc وRefCell وWeak

قواعد الـ ownership في Rust صارمة: مالك واحد، وقرّاء كثيرون **أو** كاتب واحد. والـ smart pointers تسمح لك بثني هذه القواعد بأمان عندما يحتاج التصميم ذلك.

## ‏Box<T>: ضعه في الـ heap

‏`Box` يملك قيمة في الـ heap. استخدمه لـ:

- الأنواع التكرارية (النوع الذي يحتوي نفسه يحتاج حجمًا ثابتًا)
- trait objects ‏(`Box<dyn Trait>`)
- نقل القيم الكبيرة بتكلفة رخيصة

```rust
#[derive(Debug)]
enum Expr {
    Num(f64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

fn eval(e: &Expr) -> f64 {
    match e {
        Expr::Num(n) => *n,
        Expr::Add(a, b) => eval(a) + eval(b),
        Expr::Mul(a, b) => eval(a) * eval(b),
    }
}

fn main() {
    // (2 + 3) * 4
    let e = Expr::Mul(
        Box::new(Expr::Add(Box::new(Expr::Num(2.0)), Box::new(Expr::Num(3.0)))),
        Box::new(Expr::Num(4.0)),
    );
    println!("{}", eval(&e));
}
```

```output
20
```

بدون `Box`، سيحتوي `Expr` على `Expr` يحتوي على `Expr`... ولن يكون له حجم محدود.

## ‏Rc<T>: عدة مُلّاك

‏`Rc` ("عدّ الـ references") يسمح لعدة أجزاء من البرنامج **بمشاركة** الـ ownership. والقيمة تُسقط عندما يذهب آخر `Rc`:

```rust
use std::rc::Rc;

struct Photo {
    name: String,
}

fn main() {
    let photo = Rc::new(Photo { name: "sunset.jpg".to_string() });
    let album_a = vec![Rc::clone(&photo)];
    let album_b = vec![Rc::clone(&photo), Rc::clone(&photo)];
    println!("{} is in {} places", photo.name, Rc::strong_count(&photo) - 1);
    drop(album_b);
    println!("now {}", Rc::strong_count(&photo) - 1);
    println!("{}", album_a.len());
}
```

```output
sunset.jpg is in 3 places
now 1
1
```

‏`Rc::clone` لا تنسخ الصورة؛ بل تضيف واحدًا إلى العدّاد. و`Rc` تعطي وصولًا **مشتركًا للقراءة فقط**، وتعمل في thread واحد فقط (استخدم `Arc` للـ threads، في الوحدة القادمة).

## ‏RefCell<T>: التغيير عبر reference مشترك

أحيانًا تحتاج تغيير شيء تمسكه عدة أجزاء من البرنامج. و`RefCell` تنقل قاعدة الـ borrowing من compile time إلى **runtime**:

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Account {
    balance: i64,
}

fn main() {
    let shared = Rc::new(RefCell::new(Account { balance: 100 }));
    let salma = Rc::clone(&shared);
    let omar = Rc::clone(&shared);

    salma.borrow_mut().balance += 50;     // a mutable borrow, checked at run time
    omar.borrow_mut().balance -= 30;

    println!("{:?}", shared.borrow());
    let r1 = shared.borrow();
    let r2 = shared.borrow();             // many readers: fine
    println!("{} {}", r1.balance, r2.balance);
    // let w = shared.borrow_mut();       // would panic: already borrowed for reading
}
```

```output
Account { balance: 120 }
120 120
```

‏`Rc<RefCell<T>>` هي التركيبة الكلاسيكية "مشترك وقابل للتغيير" في الكود ذي الـ thread الواحد. والثمن: كسر القاعدة الآن يسبب **panic** runtime بدل الفشل في الترجمة. اجعل الاستعارات قصيرة (لا تمسك `borrow_mut()` عبر function طويلة) واستخدم هذا فقط عندما يحتاج التصميم فعلًا تغييرًا مشتركًا. و`try_borrow_mut()` ترجع `Result` بدل panic.

و`Cell<T>` قريبة أبسط للقيم الصغيرة من نوع `Copy`: ‏`.get()` و`.set()` بدون borrowing إطلاقًا.

## ‏Weak<T>: references لا تُبقي الأشياء حية

‏`Rc` اثنان يشير كل منهما للآخر لن يصل عدّادهما إلى الصفر أبدًا: memory leak. وللـ references العكسية (من الابن إلى الأب)، استخدم `Weak`:

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

fn main() {
    let root = Rc::new(Node { name: "root".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
    let leaf = Rc::new(Node { name: "leaf".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });

    *leaf.parent.borrow_mut() = Rc::downgrade(&root);
    root.children.borrow_mut().push(Rc::clone(&leaf));

    let parent_name = leaf.parent.borrow().upgrade().map(|p| p.name.clone());
    println!("leaf's parent: {:?}", parent_name);
    println!("root has {} child", root.children.borrow().len());
}
```

```output
leaf's parent: Some("root")
root has 1 child
```

‏`upgrade()` ترجع `Some(Rc)` لو كانت القيمة ما زالت موجودة، و`None` لو ذهبت. الآباء يملكون الأبناء (`Rc` قوي)؛ والأبناء يشيرون فقط للخلف (`Weak`).

## أيها؟

| الحاجة | استخدم |
|---|---|
| مالك واحد، والقيمة في الـ heap | `Box<T>` |
| عدة مُلّاك، للقراءة فقط، thread واحد | `Rc<T>` |
| عدة مُلّاك، قابل للتغيير، thread واحد | `Rc<RefCell<T>>` |
| reference عكسي يجب ألا يُبقي الأشياء حية | `Weak<T>` |
| مشترك بين الـ threads | `Arc<T>` و`Arc<Mutex<T>>` (الوحدة القادمة) |

برامج Rust كثيرة لا تحتاج أيًا منها. الـ ownership والـ borrowing العاديتان، مع فهارس داخل `Vec` بدل الـ pointers، تصنعان غالبًا تصميمات أبسط.

## الخلاصة

- `Box` للقيم في الـ heap والأنواع التكرارية وtrait objects.
- `Rc` تشارك الـ ownership؛ و`RefCell` تتحقق من الـ borrowing runtime؛ ومعًا تسمحان بالتغيير المشترك.
- `Weak` تكسر دوائر الـ references؛ ولا تلجأ لهذه إلا عندما لا تناسبك الـ ownership العادية.
