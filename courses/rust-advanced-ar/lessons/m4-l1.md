# معالجة الأخطاء في البرامج الحقيقية

في كورس المبتدئين أرجعت `Result`، واستخدمت `?`، وكتبت enums للأخطاء. والبرامج الحقيقية تجمع أخطاء من مصادر كثيرة: الملفات، والقراءة والتحويل، والشبكة، وقواعدك الخاصة. وهذا الدرس يبيّن الأنماط التي يستخدمها المحترفون.

## تحويل الأخطاء بـ From

‏`?` لا ترجع الخطأ فقط. بل تستدعي أولًا `From::from` عليه، فتستطيع **تحويل** نوع خطأ إلى آخر. نفّذ `From` لنوع خطئك وتتولى `?` الباقي:

```rust
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum ConfigError {
    Missing(String),
    BadNumber(ParseIntError),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Missing(key) => write!(f, "missing setting '{key}'"),
            ConfigError::BadNumber(e) => write!(f, "bad number: {e}"),
        }
    }
}

impl std::error::Error for ConfigError {}

impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self {
        ConfigError::BadNumber(e)
    }
}

fn read_port(settings: &[(&str, &str)]) -> Result<u16, ConfigError> {
    let (_, value) = settings
        .iter()
        .find(|(k, _)| *k == "port")
        .ok_or_else(|| ConfigError::Missing("port".to_string()))?;
    let port: u16 = value.parse()?;          // ParseIntError becomes ConfigError automatically
    Ok(port)
}

fn main() {
    println!("{:?}", read_port(&[("port", "8080")]).map_err(|e| e.to_string()));
    println!("{:?}", read_port(&[("host", "x")]).map_err(|e| e.to_string()));
    println!("{:?}", read_port(&[("port", "80a")]).map_err(|e| e.to_string()));
}
```

```output
Ok(8080)
Err("missing setting 'port'")
Err("bad number: invalid digit found in string")
```

نوع الخطأ الصحيح ينفّذ `Debug` و`Display` و`std::error::Error`. وهذا كود متكرر كثير، ولهذا يُستخدم crateان في كل مكان تقريبًا.

## ‏thiserror: للمكتبات

‏`thiserror` تكتب كود `Display` و`Error` و`From` بدلًا منك من خلال السمات (attributes):

<!-- skip -->
```rust
use thiserror::Error;

#[derive(Debug, Error)]
pub enum ConfigError {
    #[error("missing setting '{0}'")]
    Missing(String),
    #[error("bad number: {0}")]
    BadNumber(#[from] std::num::ParseIntError),
    #[error("can't read the config file")]
    Io(#[from] std::io::Error),
}
```

نفس سلوك النسخة المكتوبة يدويًا، في ربع الأسطر. استخدمها في **المكتبات** والوحدات التي يحتاج مستدعوها التمييز بين الأخطاء والتصرف (إعادة المحاولة مع `Io`، وعرض خطأ في النموذج مع `BadNumber`).

## ‏anyhow: للتطبيقات

في المستوى الأعلى من التطبيق (main ومعالجات الأوامر)، غالبًا تريد فقط الإبلاغ عن الخطأ جيدًا. و`anyhow::Result` تقبل **أي** خطأ، و`.context()` تضيف شرحًا بلغة البشر:

<!-- skip -->
```rust
use anyhow::{bail, Context, Result};
use std::fs;

fn load_limit(path: &str) -> Result<u32> {
    let text = fs::read_to_string(path)
        .with_context(|| format!("reading {path}"))?;
    let limit: u32 = text.trim().parse()
        .context("the limit must be a whole number")?;
    if limit == 0 {
        bail!("the limit can't be zero");
    }
    Ok(limit)
}

fn main() -> Result<()> {
    std::fs::write("limit.txt", "abc")?;
    let limit = load_limit("limit.txt")?;
    println!("limit {limit}");
    Ok(())
}
```

```text
Error: the limit must be a whole number

Caused by:
    invalid digit found in string
```

تقرير الخطأ يعرض شرحك **و**السبب الأصلي. وهذا ما يحتاجه المستخدمون وملفات السجلات.

## الـ Panics مرة أخرى

الـ panics ما زالت للأخطاء البرمجية. وأداتان إضافيتان:

- `debug_assert!(cond)` تتحقق فقط في بناءات التصحيح: مجانية في بناءات الإصدار.
- `std::panic::catch_unwind` موجودة لحالات نادرة (مثل إبقاء خادم حيًا عندما تُصاب إضافة بـ panic)، لكن لا تستخدمها كمعالجة exceptions.

## قائمة تحقق للأخطاء

1. كود المكتبات يرجع أخطاء بأنواع (`thiserror`)؛ والتطبيقات تجمعها (`anyhow`).
2. أضف سياقًا حيث يساعد القارئ: أي ملف، وأي مستخدم، وأي خطوة.
3. لا تستخدم `unwrap()` أبدًا على مدخلات من الخارج (ملفات، مستخدمين، شبكة).
4. سجّل الخطأ أو اعرضه **مرة واحدة** في الأعلى، بدل كل مستوى.

## الخلاصة

- `?` تحوّل الأخطاء عبر `From`؛ نفّذها، أو دع `#[from]` تفعل ذلك.
- `thiserror` لأخطاء المكتبات ذات الأنواع؛ و`anyhow` مع `.context()` للتطبيقات.
- اترك الـ panics للأخطاء البرمجية؛ وأبلغ عن الأخطاء مرة واحدة مع سياق.
