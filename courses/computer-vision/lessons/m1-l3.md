# Project 1: the coin inspector starts with pixels

From today to day 5 you build one app: a **coin inspector** that finds, counts and measures coins in a photo, and
keeps working when the photo is worse. The photo is `coins.png`: 24 Greek coins from the Pompeii collection, a
sample image that ships with scikit-image (public domain).

The project folder is above this text. Save all its files in one folder and install:

```bash
pip install opencv-python-headless scikit-image numpy
```

PyTorch (`pip install torch`, CPU is fine) is needed from day 3.

## Read the code

- `cv2.imread(..., IMREAD_GRAYSCALE)` gives a NumPy array: rows, columns, one brightness value (0 to 255) each.
- **The histogram** counts pixels per brightness, in 8 bins, drawn with `#`.
- **Edges**: Canny on the clean photo, on a copy with random noise added, and on the noisy copy after a 5 × 5
  Gaussian blur.
- **Your own convolution**: a 3 × 3 Sobel kernel applied with `filter2D`, checked against OpenCV's `Sobel`.

## Run it

```bash
python p1_pixels.py
```

What it shows:

- An image is just numbers: here 303 × 384 of them, from 1 to 252.
- Most pixels are dark background; the coins make up the brighter part. Tomorrow you separate them.
- **Noise triples the edge count** (39,135 against 12,139): thousands of false edges. A blur first cuts them to fewer
  than the clean photo's. That's why almost every vision pipeline starts with a blur.
- A Sobel filter is a small convolution, and yours matches OpenCV's exactly.

## Make it yours

1. Try Canny thresholds of 50/100 and 150/300. Which gives clean coin outlines?
2. Write the convolution yourself with two loops over the pixels (no `filter2D`), and time it against OpenCV.
3. Take a photo of coins on a table with your phone and run the script on it (convert to grayscale). What's different
   about its histogram?

## What to take away

- Images are arrays; histograms and filters are array operations.
- Blur before you look for edges.
