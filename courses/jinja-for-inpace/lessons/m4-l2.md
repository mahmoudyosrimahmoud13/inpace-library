# Performance and security checklist

## Performance

- One Environment, `auto_reload=False` in production (it skips checking file times).
- Precompute in Python, not in loops in templates. A nested loop over thousands of items is slow in any template.
- `{% cache %}` doesn't exist in core Jinja; cache the data, not the HTML.
- Bytecode cache (`FileSystemBytecodeCache`) helps start-up when there are many templates.

## Security

| Risk | Defence |
|---|---|
| XSS through user text | Autoescape on; `Markup` only for trusted output |
| JSON in `<script>` | `|tojson` |
| Untrusted **templates** (users writing Jinja) | `jinja2.sandbox.SandboxedEnvironment`; never render user-written templates in a normal Environment (that's server-side template injection) |
| Attribute injection | Always quote attributes: `value="{{ v }}"` |
| URLs from users | Check the scheme (no `javascript:`) before putting them in `href` |
