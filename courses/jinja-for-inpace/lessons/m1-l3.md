# Autoescaping and Markup

With `autoescape=select_autoescape(["html"])` (inPace's setting), every `{{ value }}` in an `.html` template is
**escaped**: `<` becomes `&lt;`, quotes become `&#34;`. A learner who names themselves `<script>alert(1)</script>`
shows up as text, not as code. This is your main defence against XSS.

## When you need real HTML

Mark it as safe **in Python**, where you control it, with `markupsafe.Markup`:

```python
from markupsafe import Markup
def icon(name: str, size: int = 20) -> Markup:
    return Markup(f'<svg width="{size}" height="{size}" viewBox="0 0 24 24" ... aria-hidden="true">'
                  f'{_ICONS.get(name, "")}</svg>')
```

Then `{{ icon('island', 22) }}` prints the SVG without escaping. Rules:

- Only wrap **trusted** strings in `Markup`. Never `Markup(user_input)`.
- If you must insert user data inside markup, escape it: `Markup("<b>{}</b>").format(name)` escapes `name`.
- `|safe` in a template does the same as `Markup`; use it sparingly and only on data you produced (inPace uses it for
  lesson HTML that markdown-it rendered with raw HTML turned off).
- Inside `<script>`, use `|tojson`, not `|safe`: it escapes `<`, `>` and `&` so a `</script>` in the data can't break
  out. inPace does the same by hand for the trip state: `json.dumps(...).replace("<", "\\u003c")`.
