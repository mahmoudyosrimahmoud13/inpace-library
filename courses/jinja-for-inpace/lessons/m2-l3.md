# Macros: functions for markup

```jinja
{% macro goal_text(g) %}{% if g %}{{ T(g[2], n=g[1]) }}{% endif %}{% endmacro %}

<p>{{ goal_text(next_goal) }}</p>
```

That's a real macro from `island.html`. A bigger example you might write:

```jinja
{# _ui.html #}
{% macro field(name, label, value="", type="text", required=false) -%}
  <label for="f-{{ name }}">{{ label }}</label>
  <input id="f-{{ name }}" name="{{ name }}" type="{{ type }}" value="{{ value }}"{{ " required" if required }}>
{%- endmacro %}

{# in a page #}
{% import "_ui.html" as ui %}
{{ ui.field("title", _("Course title"), course.title, required=true) }}
```

- Macros don't see the page's variables unless you `import ... with context`.
- `caller()` lets a macro wrap a block of content (`{% call card() %}...{% endcall %}`).
- The `-` in `{%-` and `-%}` trims whitespace around the tag, which keeps the HTML tidy.

## Macro or Python global?

inPace draws icons, avatars, covers and island art as **Python functions registered as globals** (Day 3), because
they need Python logic (SVG building, file lookups). Macros are better for pure markup patterns.
