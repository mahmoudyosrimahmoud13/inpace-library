# Losses and the standard training loop

## Choosing the loss

| Task | Model output | Loss |
|---|---|---|
| Regression | one number per target | `nn.MSELoss` (or `nn.L1Loss`, `nn.HuberLoss` with outliers) |
| Binary classification | one logit | `nn.BCEWithLogitsLoss` |
| Multi-class classification | one logit per class | `nn.CrossEntropyLoss` |
| Multi-label (several tags at once) | one logit per label | `nn.BCEWithLogitsLoss` |

**Pass raw logits, not probabilities.** `CrossEntropyLoss` applies log-softmax itself, in a numerically stable way; adding your own softmax first is a classic bug that trains badly.

```python
import torch
from torch import nn

logits = torch.tensor([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]])
labels = torch.tensor([0, 2])                        # class indices, dtype int64
print(nn.CrossEntropyLoss()(logits, labels))         # about 0.18
probs = logits.softmax(dim=1)
print(probs.argmax(dim=1))                           # predictions: tensor([0, 2])
```

## The training loop, as a function

Every project ends up with the same loop. Write it once, carefully:

```python
def train_one_epoch(model, X, y, loss_fn, opt, batch_size=32):
    model.train()
    perm = torch.randperm(len(X))                    # shuffle each epoch
    total = 0.0
    for i in range(0, len(X), batch_size):
        idx = perm[i:i + batch_size]
        xb, yb = X[idx], y[idx]
        logits = model(xb)                           # forward
        loss = loss_fn(logits, yb)                   # loss
        opt.zero_grad()                              # reset gradients
        loss.backward()                              # backward
        opt.step()                                   # update
        total += loss.item() * len(idx)
    return total / len(X)

@torch.no_grad()
def evaluate(model, X, y):
    model.eval()
    pred = model(X).argmax(dim=1)
    return (pred == y).float().mean().item()

torch.manual_seed(0)
X = torch.randn(600, 2)
y = ((X[:, 0] ** 2 + X[:, 1] ** 2) > 1.0).long()     # inside or outside a circle: not linearly separable
X_train, y_train, X_val, y_val = X[:500], y[:500], X[500:], y[500:]

model = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 32), nn.ReLU(), nn.Linear(32, 2))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)
loss_fn = nn.CrossEntropyLoss()
for epoch in range(30):
    loss = train_one_epoch(model, X_train, y_train, loss_fn, opt)
    if epoch % 10 == 9:
        print(f"epoch {epoch + 1}: train loss {loss:.3f}, val accuracy {evaluate(model, X_val, y_val):.3f}")
```

A linear model can't separate a circle; two hidden layers reach well above 90% validation accuracy.

## What each line protects against

- `model.train()` / `model.eval()`: dropout and batch norm behaving correctly.
- shuffling each epoch: the model not learning the order of the data.
- `loss.item()`: storing a Python number, not a tensor that keeps the whole graph alive (a memory leak).
- `@torch.no_grad()` on evaluation: no wasted memory on gradients.
