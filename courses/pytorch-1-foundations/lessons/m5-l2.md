# Debugging training: a field guide

Neural network bugs rarely crash. The code runs, the loss goes down a little, and the model is quietly bad. These habits find problems fast.

## 1. Overfit one batch first

Before training on everything, check the model can memorise a single small batch. If loss doesn't go to nearly zero, something is broken (wrong labels, a missing `backward`, a frozen layer, a bad loss), and no amount of data will fix it.

```python
import torch
from torch import nn

torch.manual_seed(0)
xb = torch.randn(16, 20)
yb = torch.randint(0, 3, (16,))
model = nn.Sequential(nn.Linear(20, 64), nn.ReLU(), nn.Linear(64, 3))
opt = torch.optim.Adam(model.parameters(), lr=1e-2)
for step in range(200):
    loss = nn.functional.cross_entropy(model(xb), yb)
    opt.zero_grad(); loss.backward(); opt.step()
print(f"loss on one batch after 200 steps: {loss.item():.4f}")   # close to 0: the pipeline can learn
```

## 2. Check the starting loss

With C classes and random weights, cross-entropy should start near ln(C), because the model guesses about 1/C for each class. For 10 classes that's about 2.30. A much higher start means badly scaled inputs or initial weights.

```python
fresh = nn.Sequential(nn.Linear(20, 64), nn.ReLU(), nn.Linear(64, 10))
with torch.no_grad():
    start = nn.functional.cross_entropy(fresh(torch.randn(512, 20)), torch.randint(0, 10, (512,)))
print(round(start.item(), 2), "vs ln(10) =", round(torch.log(torch.tensor(10.0)).item(), 2))
```

## 3. Symptoms and causes

| Symptom | Likely causes |
|---|---|
| loss becomes `nan` | learning rate too high; `log(0)` or division by zero; inputs with nan; fix with a lower lr, gradient clipping, checking the data |
| loss doesn't move | `opt.zero_grad()`/`step()` missing; parameters not passed to the optimizer; learning rate far too low; labels shuffled separately from inputs |
| great train, poor validation | overfitting, or train and validation preprocessed differently |
| validation better than train | dropout active in training only (normal), or leakage between splits |
| noisy validation scores | `model.eval()` forgotten |
| `RuntimeError: mat1 and mat2 shapes cannot be multiplied` | print shapes; wrong flatten size |
| `Expected all tensors to be on the same device` | the model or a batch wasn't moved with `.to(device)` |

## 4. Inspect gradients

```python
loss = nn.functional.cross_entropy(model(xb), yb)
opt.zero_grad(); loss.backward()
for name, p in model.named_parameters():
    print(f"{name:10s} grad norm {p.grad.norm().item():.4f}")
```

Gradients that are all zero point at a dead path (a detached tensor, a ReLU that never activates); huge ones point at exploding training (use `torch.nn.utils.clip_grad_norm_`).

## 5. Make runs repeatable

```python
import random
import numpy as np

def seed_everything(seed=0):
    random.seed(seed); np.random.seed(seed); torch.manual_seed(seed)   # torch.manual_seed also seeds CUDA

seed_everything(0); a = torch.randn(3)
seed_everything(0); b = torch.randn(3)
print(torch.equal(a, b))
```

Change one thing at a time, and keep a short log of each run (settings and result). Part 2 automates that with experiment tracking.
