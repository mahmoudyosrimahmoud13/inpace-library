# A comfortable development workflow

## Live code reload

Mount your source and run the dev server, so edits show instantly without rebuilding:

```yaml
# compose.override.yaml: Compose merges this automatically with compose.yaml
services:
  api:
    volumes: ["./src:/app/src"]
    command: ["uvicorn", "app:app", "--host", "0.0.0.0", "--reload"]
    environment:
      DEBUG: "1"
```

Newer Compose also has `develop: watch:` which syncs files or rebuilds when they change:

```yaml
services:
  api:
    develop:
      watch:
        - action: sync
          path: ./src
          target: /app/src
        - action: rebuild
          path: requirements.txt
```

```bash
docker compose watch
```

## Dev vs production files

| File | Holds |
|---|---|
| `compose.yaml` | What's the same everywhere: services, images, networks, volumes |
| `compose.override.yaml` | Dev only: bind mounts, debug, extra ports (loaded automatically) |
| `compose.prod.yaml` | Production: restart policies, resource limits, no bind mounts |

```bash
docker compose -f compose.yaml -f compose.prod.yaml up -d
```

## Profiles: optional services

```yaml
services:
  mailpit:
    image: axllent/mailpit
    profiles: ["tools"]
```

`docker compose --profile tools up` starts it; normally it stays off.

## Running one-off commands

```bash
docker compose run --rm api pytest            # tests in a throwaway container
docker compose run --rm api alembic upgrade head
docker compose exec api bash                  # a shell in the running one
```

Now a new teammate needs only Git and Docker: `git clone`, `docker compose up`, and they're working.
