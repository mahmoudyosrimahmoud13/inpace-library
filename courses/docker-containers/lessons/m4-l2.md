# Networking between containers

## Publishing ports

`-p 8080:80` publishes the container's port 80 on **all** of the host's interfaces at 8080. To keep a database private to your machine:

```bash
docker run -d -p 127.0.0.1:5432:5432 postgres:16
```

Docker writes its own firewall rules, and published ports can bypass ufw on Linux. Bind to `127.0.0.1` for anything that shouldn't be public.

## User-defined networks and DNS

```bash
docker network create appnet
docker run -d --name db  --network appnet -e POSTGRES_PASSWORD=dev postgres:16
docker run -d --name api --network appnet -e DATABASE_URL=postgresql://postgres:dev@db:5432/postgres shop-api:dev
docker exec api getent hosts db        # "db" resolves to the database container
```

```mermaid
flowchart LR
  U["Your browser"] -- "localhost:8000 (published)" --> API["api container"]
  subgraph N["network: appnet"]
    API -- "db:5432 (container name = hostname)" --> DB["db container (not published)"]
  end
```

On a user-defined network, containers find each other **by name** through Docker's built-in DNS. The database doesn't need a published port at all.

## Network drivers

| Driver | Use |
|---|---|
| `bridge` (default and user-defined) | Containers on one host; use your own, not the default bridge (no DNS there) |
| `host` | The container uses the host's network directly (Linux only; fastest, no isolation) |
| `none` | No network at all |
| `overlay` | Across several hosts (Swarm) |

## Debugging connections

```bash
docker network inspect appnet
docker run --rm -it --network appnet nicolaka/netshoot   # a toolbox: dig, curl, ss, tcpdump
```

Inside a container, `localhost` means **that container**, not your machine and not another container. "Connection refused to localhost:5432" from the API container is the classic mistake: use the service's name.
