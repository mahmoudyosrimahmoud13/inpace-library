# Security that matters

Containers share the host's kernel. A careless container can hand an attacker the whole machine.

## The checklist

| Do | Why |
|---|---|
| Run as a **non-root user** (`USER app`) | A break-in isn't root inside the container |
| Small, current base images; rebuild regularly | Fewer packages, fewer vulnerabilities |
| **Scan images** in CI (`trivy image shop-api:1.4.2`) | Find known vulnerabilities before shipping |
| Never put secrets in the image (`ENV`, `COPY .env`, build args) | Anyone who pulls the image can read every layer |
| Pin versions and digests | No surprise changes |
| `--read-only` filesystem plus a `tmpfs` for `/tmp` | The app can't modify itself |
| `--cap-drop ALL`, add back only what's needed | Removes most root powers |
| `--security-opt no-new-privileges` | Blocks privilege escalation through setuid programs |

## Never do these

- `--privileged`: turns off nearly all isolation.
- `-v /var/run/docker.sock:/var/run/docker.sock` for an app: whoever controls that container controls **every** container and, effectively, the host.
- Publishing database ports to `0.0.0.0` on a server.

## Secrets

```bash
# Build-time secret (e.g. a private package token), not saved in any layer:
docker build --secret id=npmrc,src=$HOME/.npmrc .
#   RUN --mount=type=secret,id=npmrc,target=/root/.npmrc npm ci
```

At run time, pass secrets as environment variables from a secrets manager, or as files (Compose `secrets:`, Kubernetes Secrets), never baked in.

## Scanning

```bash
trivy image --severity CRITICAL,HIGH --ignore-unfixed shop-api:1.4.2
docker scout cves shop-api:1.4.2      # Docker's own scanner
```

**Rootless Docker** (or Podman) runs the whole engine without root: a good choice for shared machines.
