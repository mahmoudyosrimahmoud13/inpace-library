# Images, tags, digests and registries

## Image names

```text
ghcr.io/acme/shop-api:1.4.2
└─registry─┘└repository┘ └tag┘
```

No registry means Docker Hub; no tag means `:latest`. So `nginx` is really `docker.io/library/nginx:latest`.

## Tags move, digests don't

| Reference | Example | Can change? |
|---|---|---|
| Tag | `python:3.12-slim` | **Yes**: the publisher pushes new builds under the same tag |
| Digest | `python@sha256:4f1c...` | **Never**: it's the hash of the content |

```bash
docker pull python:3.12-slim
docker images --digests python
```

- In development, tags are convenient.
- For production and CI, pin a specific version tag at least, and ideally the digest, so builds are reproducible. Never deploy `latest`.

## Choosing base images

| Base | Size | Notes |
|---|---|---|
| `ubuntu`, `debian` | ~30 to 80 MB | Familiar, lots of packages |
| `*-slim` (e.g. `python:3.12-slim`) | Smaller | Good default for most apps |
| `alpine` | ~5 MB | Tiny, but uses musl libc: some Python and Node packages break or build slowly |
| `distroless`, `scratch` | Minimal | No shell or package manager: great for production, harder to debug |

Prefer **official** images (marked on Docker Hub) or ones from the software's own publisher.

## Registries

```bash
docker login ghcr.io
docker tag shop-api:dev ghcr.io/acme/shop-api:1.4.2
docker push ghcr.io/acme/shop-api:1.4.2
```

Public: Docker Hub, GitHub Container Registry (ghcr.io), Quay. Cloud: Amazon ECR, Google Artifact Registry, Azure ACR. Docker Hub limits anonymous pulls per hour, so CI should log in or use a mirror.
