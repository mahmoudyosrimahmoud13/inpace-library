# Good Dockerfiles: cache, size and multi-stage builds

## Order for the cache

Docker reuses a layer if the instruction **and everything before it** are unchanged. So copy what changes rarely first:

```dockerfile
# Slow: any code change reinstalls every dependency
COPY . .
RUN pip install -r requirements.txt

# Fast: dependencies are reinstalled only when requirements.txt changes
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
```

## Smaller images

- Start from `-slim` (or distroless for production).
- Combine install and cleanup in **one** `RUN`, or the deleted files still live in the earlier layer:

```dockerfile
RUN apt-get update \
 && apt-get install -y --no-install-recommends curl \
 && rm -rf /var/lib/apt/lists/*
```

## Multi-stage builds

Build with all the tools; ship only the result:

```dockerfile
# Stage 1: build the frontend
FROM node:22-slim AS build
WORKDIR /src
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: serve the built files
FROM nginx:1.27-alpine
COPY --from=build /src/dist /usr/share/nginx/html
```

The final image has nginx and the static files: no Node, no `node_modules`, no source. For Go or Rust, the final stage can be `scratch` or distroless with one binary: a few MB.

## Run as a normal user

```dockerfile
RUN useradd --create-home --uid 10001 app
USER app
```

If someone breaks into your app, they're not root inside the container.

## Check your work

```bash
docker images shop-api               # size
docker history shop-api:dev          # which layer is big
docker build --progress=plain .      # see each step and what was cached
```

Linters like **hadolint** catch common mistakes (`apt-get` without cleanup, missing `--no-install-recommends`, `latest` bases).
