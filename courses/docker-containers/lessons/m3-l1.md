# Writing a Dockerfile

```dockerfile
# Dockerfile for a small Python web app
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

ENV PORT=8000
EXPOSE 8000

CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]
```

```bash
docker build -t shop-api:dev .
docker run --rm -p 8000:8000 shop-api:dev
```

## The instructions

| Instruction | Does |
|---|---|
| `FROM` | The base image to start from |
| `WORKDIR` | Sets (and creates) the working directory |
| `COPY src dest` | Copies files from the build context into the image |
| `RUN` | Runs a command at **build** time and saves the result as a layer |
| `ENV` | Environment variables for build and run |
| `ARG` | Build-time variables (`--build-arg`), not kept at run time |
| `EXPOSE` | Documents the port (doesn't publish it: `-p` does) |
| `USER` | Which user runs the following steps and the app |
| `CMD` | The default command when the container starts |
| `ENTRYPOINT` | The fixed program; `CMD` becomes its default arguments |

## CMD vs ENTRYPOINT

```dockerfile
ENTRYPOINT ["python", "manage.py"]
CMD ["runserver", "0.0.0.0:8000"]
# docker run img            -> python manage.py runserver 0.0.0.0:8000
# docker run img migrate    -> python manage.py migrate
```

Always use the **JSON array form** (`["a", "b"]`). The plain string form runs through `sh -c`, so your app isn't PID 1 and doesn't receive `docker stop`'s signal: it gets killed after 10 seconds instead of shutting down cleanly.

## The build context

`docker build .` sends the whole folder (the **context**) to the builder. Add a `.dockerignore`:

```text
.git
__pycache__/
*.pyc
.venv/
node_modules/
.env
```

Smaller context, faster builds, and no secrets (`.env`) accidentally copied into the image.
