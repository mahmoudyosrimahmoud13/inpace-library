# Debugging and running containers well

## When something's wrong

```bash
docker ps -a                                   # is it running? what's its exit code?
docker logs --tail 100 api                     # what did it print?
docker inspect api --format '{{.State.ExitCode}} {{.State.OOMKilled}}'
docker exec -it api sh                         # look around inside
docker stats                                   # live CPU and memory
docker events --since 10m                      # what Docker did recently
```

## Exit codes

| Code | Usually means |
|---|---|
| 0 | The main process finished normally (a server shouldn't do this) |
| 1 | The app crashed: read the logs |
| 125 / 126 / 127 | Docker couldn't run the command / not executable / not found (typo in `CMD`?) |
| 137 | Killed with SIGKILL: out of memory (`OOMKilled: true`) or `docker stop` timed out |
| 143 | SIGTERM: stopped normally |

## Restart policies

| Policy | Restarts when |
|---|---|
| `no` (default) | Never |
| `on-failure[:5]` | It exits with an error (up to 5 times) |
| `unless-stopped` | Always, unless you stopped it yourself (good for servers) |
| `always` | Always, even after you stopped it, once Docker restarts |

## Health checks

```dockerfile
HEALTHCHECK --interval=15s --timeout=3s --retries=3 \
  CMD curl -fsS http://localhost:8000/health || exit 1
```

`docker ps` then shows `healthy` or `unhealthy`, and Compose and orchestrators can wait for or replace unhealthy containers.

## Logs

- Apps in containers should log to **stdout and stderr**, not files.
- Docker's default `json-file` log driver grows forever: set limits.

```json
// /etc/docker/daemon.json
{ "log-driver": "json-file", "log-opts": { "max-size": "10m", "max-file": "3" } }
```

## Shut down cleanly

On `docker stop`, your app gets SIGTERM and 10 seconds to finish. Handle it (finish requests, close database connections), use the JSON form of `CMD`, and use `--init` (or `tini`) if your app doesn't reap child processes.
