# Keeping data: volumes and bind mounts

The container's writable layer is deleted with the container. Data that matters lives **outside** it.

| Kind | Syntax | Lives | Use for |
|---|---|---|---|
| **Named volume** | `-v pgdata:/var/lib/postgresql/data` | Managed by Docker | Databases, uploads: anything to keep |
| **Bind mount** | `-v $(pwd)/src:/app/src` | A folder on your machine | Development: edit code on the host, see it inside |
| **tmpfs** | `--tmpfs /tmp` | Memory | Scratch files that must never hit disk |

```bash
docker volume create pgdata
docker run -d --name db -e POSTGRES_PASSWORD=dev \
  -v pgdata:/var/lib/postgresql/data -p 5432:5432 postgres:16
docker rm -f db                     # container gone...
docker run -d --name db -e POSTGRES_PASSWORD=dev \
  -v pgdata:/var/lib/postgresql/data -p 5432:5432 postgres:16   # ...data still there
docker volume ls
docker volume inspect pgdata
```

## Backing up a volume

```bash
docker run --rm -v pgdata:/data -v $(pwd):/backup ubuntu:24.04 \
  tar czf /backup/pgdata-$(date +%F).tar.gz -C /data .
```

For databases, prefer the database's own tool (`pg_dump`), which gives a consistent backup while it runs:

```bash
docker exec db pg_dump -U postgres app > app-$(date +%F).sql
```

## Gotchas

- **Permissions**: with bind mounts, files belong to user IDs. A container running as UID 10001 can't write to a host folder owned by you (UID 1000) unless you arrange it.
- `docker rm -v` and `docker volume prune` **delete volumes**. Read twice before running them.
- A bind mount hides whatever the image had in that folder.
