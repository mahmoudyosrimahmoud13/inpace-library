# الأخطاء: Result و? وpanic

‏Rust تقسم الأخطاء إلى نوعين:

- **غير قابلة للإصلاح**: خطأ برمجي، مثل فهرس بعد النهاية. البرنامج يُصاب بـ **panic**: يتوقف برسالة.
- **قابلة للإصلاح**: ملف غير موجود، أو مدخلات خطأ. وهذه تُرجع كقيمة من نوع `Result`.

لا توجد exceptions.

## ‏Result

‏`Result` هو enum، مثل `Option` تمامًا:

```rust
enum Result<T, E> {
    Ok(T),     // success, with the value
    Err(E),    // failure, with the error
}
```

```rust
fn main() {
    for text in ["42", "abc", "-7"] {
        match text.parse::<i32>() {
            Ok(n) => println!("{text} -> {n}"),
            Err(e) => println!("{text} -> error: {e}"),
        }
    }
}
```

```output
42 -> 42
abc -> error: invalid digit found in string
-7 -> -7
```

لأن نوع النتيجة `Result`، لا تستطيع نسيان أن القراءة قد تفشل. والـ compiler يحذّرك حتى لو تجاهلت `Result` تمامًا.

## أخطاؤك الخاصة

```rust
#[derive(Debug)]
enum OrderError {
    Empty,
    NotANumber(String),
    TooMany(u32),
}

fn parse_quantity(input: &str) -> Result<u32, OrderError> {
    let input = input.trim();
    if input.is_empty() {
        return Err(OrderError::Empty);
    }
    let n: u32 = input.parse().map_err(|_| OrderError::NotANumber(input.to_string()))?;
    if n > 50 {
        return Err(OrderError::TooMany(n));
    }
    Ok(n)
}

fn main() {
    for input in ["12", "", "lots", "99"] {
        match parse_quantity(input) {
            Ok(n) => println!("order {n}"),
            Err(OrderError::Empty) => println!("nothing typed"),
            Err(OrderError::NotANumber(s)) => println!("'{s}' is not a number"),
            Err(OrderError::TooMany(n)) => println!("{n} is more than 50"),
        }
    }
}
```

```output
order 12
nothing typed
'lots' is not a number
99 is more than 50
```

## العملية ?

انظر إلى هذا السطر مرة أخرى:

```rust
let n: u32 = input.parse().map_err(|_| OrderError::NotANumber(input.to_string()))?;
```

علامة `?` في النهاية معناها: **لو كانت هذه `Err`، أرجعها من دالتي الآن؛ ولو كانت `Ok`، أعطني القيمة**. وهي تحل محل `match` كاملة وتجعل معالجة الأخطاء قصيرة:

```rust
use std::fs;
use std::io;

fn count_lines(path: &str) -> Result<usize, io::Error> {
    let text = fs::read_to_string(path)?;        // a missing file returns the error
    Ok(text.lines().count())
}

fn main() {
    fs::write("notes.txt", "buy milk\ncall Sara\nfix bike\n").expect("can't write");
    match count_lines("notes.txt") {
        Ok(n) => println!("{n} lines"),
        Err(e) => println!("error: {e}"),
    }
    match count_lines("missing.txt") {
        Ok(n) => println!("{n} lines"),
        Err(e) => println!("error: {}", e.kind()),
    }
}
```

```output
3 lines
error: entity not found
```

‏`?` تعمل فقط داخل function ترجع هي نفسها `Result` (أو `Option`). ويمكن لـ `main` أن ترجع `Result` أيضًا:

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let n: i32 = "17".parse()?;
    println!("{}", n * 2);
    Ok(())
}
```

```output
34
```

‏`Box<dyn std::error::Error>` معناها "أي نوع من الأخطاء". إنه نوع إرجاع مفيد لـ `main` والبرامج الصغيرة. ولو وصل خطأ إلى نهاية `main`، تطبعه Rust وتخرج برمز فشل.

## الـ Panics

```rust
let v = vec![1, 2, 3];
v[10];                 // panics: index out of bounds
None::<i32>.unwrap();  // panics: called `Option::unwrap()` on a `None` value
panic!("this should never happen");
```

الـ panic مخصص **للأخطاء البرمجية**: مواقف لا يستطيع برنامجك الاستمرار منها بشكل معقول. لا تستخدم الـ panics للفشل العادي مثل مدخلات المستخدم الخطأ.

‏`unwrap()` و`expect("message")` تحوّلان `None` أو `Err` إلى panic. وهما مقبولتان في الأمثلة والاختبارات والسكريبتات السريعة. وفي الكود الحقيقي فضّل `?` أو `match` أو `unwrap_or` أو `if let`. ولو استخدمت واحدة منهما، ففضّل `expect` مع رسالة تقول لماذا لا يمكن أن تفشل.

## الخلاصة

- الأخطاء القابلة للإصلاح قيم: `Result<T, E>` مع `Ok` و`Err`؛ والـ panics للأخطاء البرمجية.
- `?` ترجع الخطأ مبكرًا أو تفك القيمة؛ استخدمها في الـ functions التي ترجع Result.
- عرّف enums للأخطاء في برنامجك؛ واستخدم `Box<dyn Error>` لـ main والأدوات الصغيرة.
