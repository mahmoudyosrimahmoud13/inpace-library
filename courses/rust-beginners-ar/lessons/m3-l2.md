# الـ borrowing والـ references والـ slices

نقل كل قيمة إلى كل function سيكون ثقيلًا. وبدلًا من ذلك تستطيع **إعارة** قيمة: تعطي reference وتحتفظ بالـ ownership.

## الـ references المشتركة: ‏&T

```rust
fn count_vowels(text: &str) -> usize {
    text.chars().filter(|c| "aeiou".contains(*c)).count()
}

fn length(s: &String) -> usize {
    s.len()
}

fn main() {
    let word = String::from("education");
    println!("{} letters, {} vowels", length(&word), count_vowels(&word));
    println!("still mine: {word}");     // word was only borrowed
}
```

```output
9 letters, 5 vowels
still mine: education
```

‏`&word` تُنشئ reference؛ والـ function تستعير النص وتقرؤه وترجعه عندما تنتهي. لا شيء ينتقل.

## الـ references القابلة للتغيير: ‏&mut T

لكي تسمح لـ function **بتغيير** القيمة، أعرها إعارة قابلة للتغيير:

```rust
fn add_exclamation(s: &mut String) {
    s.push_str("!!");
}

fn main() {
    let mut msg = String::from("Goal");
    add_exclamation(&mut msg);
    println!("{msg}");
}
```

```output
Goal!!
```

الـ variable (`let mut`) والـ reference (`&mut msg`) يجب أن يقولا `mut` كلاهما. وعند قراءة الكود ترى من نظرة أي الاستدعاءات قد تغيّر بياناتك.

## قاعدة الـ borrowing

في أي لحظة يمكن أن يكون لديك **إما**:

- أي عدد من الـ references المشتركة `&T`، **أو**
- reference واحد قابل للتغيير `&mut T` بالضبط

لكن ليس الاثنين معًا. والـ references لا يمكن أبدًا أن تعيش أطول من القيمة التي تشير إليها.

```rust
fn main() {
    let mut scores = vec![70, 85];
    let first = &scores[0];        // a shared borrow
    // scores.push(90);            // error: cannot borrow `scores` as mutable
    println!("first is {first}");  // ...because `first` is still used here
    scores.push(90);               // fine now: `first` is no longer used
    println!("{:?}", scores);
}
```

```output
first is 70
[70, 85, 90]
```

لماذا الخطأ؟ قد تنقل `push` عناصر الـ vector إلى ذاكرة جديدة أكبر. وحينها سيشير `first` إلى ذاكرة محررة: نفس خطأ الـ pointer الذي في درس مشروع C++. و‏Rust ترفض ترجمته. ونفس هذه القاعدة هي ما يجعل data races مستحيلة: لا يستطيع خيطان تغيير شيء في نفس الوقت.

‏`{:?}` تطبع القيمة في شكل "debug"؛ وتعمل مع الـ vectors وأغلب الأنواع القياسية.

## الـ references المعلّقة لا تُترجم

```rust
fn make() -> &String {        // error: missing lifetime specifier
    let s = String::from("hi");
    &s                        // s is dropped at the end of the function
}
```

الحل أن ترجع الـ `String` نفسها (تنقلها للخارج). والكورس المتقدم يشرح **lifetimes**، وهي طريقة الـ compiler في تتبّع مدة صلاحية الـ references.

## الـ slices: نوافذ على جزء من مجموعة

**الـ slice** تستعير مدى من نص أو قائمة بدون نسخ:

```rust
fn first_word(s: &str) -> &str {
    match s.find(' ') {
        Some(i) => &s[..i],
        None => s,
    }
}

fn average(nums: &[f64]) -> f64 {
    nums.iter().sum::<f64>() / nums.len() as f64
}

fn main() {
    let sentence = String::from("hello wide world");
    println!("{}", first_word(&sentence));
    println!("{}", &sentence[6..10]);

    let temps = [30.0, 32.5, 29.0, 35.5, 33.0];
    println!("{}", average(&temps));
    println!("{}", average(&temps[1..3]));   // only items 1 and 2
}
```

```output
hello
wide
32
30.75
```

- `&s[6..10]` هو النص من البايت 6 حتى البايت 10 (بدون 10).
- `&[f64]` slice من قيم f64؛ وتقبل الـ arrays والـ vectors وأجزاءها.

## ‏String مقابل &str

- `String` **تملك** نصها، ويمكن أن تكبر، وتعيش في الـ heap.
- `&str` نافذة **مستعارة** على نص ما: جزء من `String`، أو نص حرفي مثل `"hello"` مكتوب داخل البرنامج.

اجعل الـ functions التي تقرأ النص فقط تأخذ `&str`. وحينها تقبل الاثنين: `first_word(&my_string)` و`first_word("a literal")` يعملان معًا.

ملاحظة عن النصوص: نصوص Rust بترميز UTF-8. والحرف العربي يأخذ بايتين، فالتقطيع بأرقام البايتات قد يقع في منتصف حرف ويوقف البرنامج. استخدم `.chars()` للعمل حرفًا بحرف.

## الخلاصة

- `&T` تستعير للقراءة، و`&mut T` تستعير للتغيير؛ والـ ownership تبقى مكانها.
- قرّاء كثيرون **أو** كاتب واحد، والـ references لا تعيش أطول من قيمتها. والـ compiler يتحقق.
- الـ slices (`&str` و`&[T]`) تستعير جزءًا من مجموعة؛ وخذ `&str` للنصوص التي تقرؤها فقط.
