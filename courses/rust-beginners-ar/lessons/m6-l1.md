# الـ Traits والـ Generics والوحدات والاختبارات

## الـ Traits: سلوك مشترك

الـ **trait** يصف شيئًا تستطيع الأنواع فعله. وأي نوع يستطيع تنفيذه:

```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String;
    fn describe(&self) -> String {                 // a default method
        format!("{} with area {:.2}", self.name(), self.area())
    }
}

struct Circle { r: f64 }
struct Rect { w: f64, h: f64 }

impl Shape for Circle {
    fn area(&self) -> f64 { 3.14159 * self.r * self.r }
    fn name(&self) -> String { "circle".to_string() }
}

impl Shape for Rect {
    fn area(&self) -> f64 { self.w * self.h }
    fn name(&self) -> String { "rectangle".to_string() }
}

fn main() {
    let c = Circle { r: 1.0 };
    let r = Rect { w: 3.0, h: 4.0 };
    println!("{}", c.describe());
    println!("{}", r.describe());
}
```

```output
circle with area 3.14
rectangle with area 12.00
```

الـ traits مثل المفاهيم والواجهات في C++ مجتمعة. والـ standard library مليئة بها: `Debug` و`Clone` و`PartialEq` و`Display` (للطباعة بـ `{}`) و`Iterator` و`Add` (لـ `+`)...

## functions عامة بقيود traits

```rust
use std::fmt::Display;

fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

fn show_all(items: &[impl Display]) {
    for x in items {
        print!("[{x}] ");
    }
    println!();
}

fn main() {
    println!("{}", largest(&[4, 19, 7]));
    println!("{}", largest(&[2.5, 0.5]));
    println!("{}", largest(&['q', 'z', 'a']));
    show_all(&["tea", "coffee"]);
    show_all(&[1, 2, 3]);
}
```

```output
19
2.5
z
[tea] [coffee] 
[1] [2] [3] 
```

‏`T: PartialOrd + Copy` تقول إن T يجب أن تدعم المقارنة وأن تكون قابلة للنسخ. ومثل مفاهيم C++، يُتحقق من القواعد عند استدعاء الـ function، مع أخطاء واضحة. و`impl Display` طريقة مختصرة لكتابة نفس الشيء لمعامل.

## قوائم من أنواع مختلفة: objects الـ trait

الـ generics تصنع نسخة منفصلة من الكود لكل نوع. ولكي تضع أنواعًا **مختلفة** في قائمة واحدة، استخدم **object trait** ‏`Box<dyn Trait>`:

```rust
trait Shape {
    fn area(&self) -> f64;
}
struct Circle { r: f64 }
struct Square { s: f64 }
impl Shape for Circle { fn area(&self) -> f64 { 3.14159 * self.r * self.r } }
impl Shape for Square { fn area(&self) -> f64 { self.s * self.s } }

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![
        Box::new(Circle { r: 1.0 }),
        Box::new(Square { s: 2.0 }),
        Box::new(Circle { r: 2.0 }),
    ];
    let total: f64 = shapes.iter().map(|s| s.area()).sum();
    println!("total area {:.2}", total);
}
```

```output
total area 19.71
```

‏`Box` تضع القيمة في الـ heap؛ و`dyn Shape` معناها "نوع ما ينفّذ Shape"، يُحدد runtime. وهذه هي الـ functions virtual في C++، لكن بدون inheritance.

## تنفيذ Display

لكي تطبع نوعك بـ `{}`، نفّذ `std::fmt::Display`:

```rust
use std::fmt;

struct Money { piasters: i64 }

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{}.{:02} EGP", self.piasters / 100, self.piasters % 100)
    }
}

fn main() {
    let m = Money { piasters: 5505 };
    println!("total: {m}");
}
```

```output
total: 55.05 EGP
```

## الوحدات (Modules): تنظيم الكود

عندما يكبر البرنامج، قسّمه إلى **وحدات**. في ملف واحد:

```rust
mod shop {
    pub struct Item {
        pub name: String,
        price: u32,                 // private: only code in `shop` can touch it
    }

    impl Item {
        pub fn new(name: &str, price: u32) -> Item {
            Item { name: name.to_string(), price }
        }
        pub fn price_with_tax(&self) -> u32 {
            self.price * 114 / 100
        }
    }
}

use shop::Item;

fn main() {
    let pen = Item::new("pen", 100);
    println!("{} costs {}", pen.name, pen.price_with_tax());
}
```

```output
pen costs 114
```

كل شيء **خاص** افتراضيًا؛ و`pub` تجعله ظاهرًا خارج الوحدة. وفي مشروع حقيقي تكون كل وحدة ملفًا خاصًا: `mod shop;` في `main.rs` تحمّل `src/shop.rs`.

استخدام مكتبات من crates.io يأخذ سطرًا واحدًا في `Cargo.toml`:

```toml
[dependencies]
rand = "0.8"
```

ثم `cargo build` ينزّلها ويترجمها، و`use rand::Rng;` تُحضرها.

## الاختبارات مبنية في اللغة

اكتب الاختبارات بجوار كودك وشغّلها بـ `cargo test`:

```rust
pub fn is_leap_year(y: u32) -> bool {
    (y % 4 == 0 && y % 100 != 0) || y % 400 == 0
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn normal_years() {
        assert!(is_leap_year(2024));
        assert!(!is_leap_year(2026));
    }

    #[test]
    fn centuries() {
        assert!(!is_leap_year(1900));
        assert!(is_leap_year(2000));
    }
}
```

```text
running 2 tests
test tests::centuries ... ok
test tests::normal_years ... ok

test result: ok. 2 passed; 0 failed
```

- `#[cfg(test)]` معناها "لا تترجم هذا إلا عند الاختبار".
- `assert!(cond)` و`assert_eq!(a, b)` تُفشلان الاختبار برسالة تعرض القيم.
- `use super::*;` تُحضر كل شيء من الملف المحيط.

## الخلاصة

- الـ traits تصف السلوك؛ و`impl Trait for Type` تنفّذه؛ ويمكن أن تكون للـ traits functions افتراضية.
- الـ generics مع القيود (`T: PartialOrd`) تعمل compile time؛ و`Box<dyn Trait>` تخلط الأنواع runtime.
- `mod` و`pub` تنظّمان الكود؛ وfunctions `#[test]` تعمل بـ `cargo test`.
