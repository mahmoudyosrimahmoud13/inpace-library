# Write, run and read a workflow

Make this file, commit and push:

> **Optional video above.** Part of TechWorld with Nana's *GitHub Actions Tutorial*, from 9:50 to 20:40. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```yaml
# .github/workflows/hello.yml
name: Hello

on:
  push:
  workflow_dispatch:        # adds a "Run workflow" button in the Actions tab

jobs:
  say-hello:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7          # get the repository's files
      - name: Say hello
        run: echo "Hello from ${{ github.actor }} on ${{ github.ref_name }}"
      - name: List the files
        run: ls -la
```

Open the **Actions** tab: the run appears within seconds. Click it, then the job, then a step to see its output. Green means every step exited with code 0; red means one failed, and the steps after it were skipped.

## YAML in two minutes

- Indentation is meaning: use **spaces, never tabs**, and keep levels aligned.
- `key: value`, and lists start with `- `.
- `${{ ... }}` is an **expression**: GitHub fills it in before the step runs. `github.actor` is who pushed, `github.ref_name` the branch or tag, `secrets.NAME` a secret.
- `run: |` lets a step have several lines of commands.

## When it fails

1. Read the red step's log from the bottom up: the real error is usually near the end.
2. **Re-run** it (top right) if it looks like a network hiccup.
3. Make the step print more (`echo`, `ls`), push, and look again. `gh run view --log-failed` saves clicks.
4. A typo in the YAML shows as an error on the run itself ("Invalid workflow file"). The editor on GitHub, and the free tool [actionlint](https://github.com/rhysd/actionlint), find these before you push.
