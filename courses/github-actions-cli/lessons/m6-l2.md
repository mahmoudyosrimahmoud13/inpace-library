# Publish a site and a release

## GitHub Pages from a workflow

In **Settings → Pages**, set *Source* to **GitHub Actions**. Then this workflow tests, and only if the tests pass, publishes the site:

```yaml
# .github/workflows/pages.yml
name: Publish the site

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write          # to publish to GitHub Pages
  id-token: write       # to prove to Pages that this run is really from this repository

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 22
      - run: npm test

  deploy:
    needs: test                  # only publish if the tests passed
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/configure-pages@v6
      - uses: actions/upload-pages-artifact@v5
        with:
          path: .                # the folder to publish
      - id: deployment
        uses: actions/deploy-pages@v5
```

`needs: test` makes the deploy wait for the tests. The `github-pages` **environment** shows the live link on the run, and you can add protection to an environment (a required approval, or only from main).

## A release when you push a tag

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    tags: ["v*"]                 # runs when you push a tag like v1.2.0

permissions:
  contents: write                # to create the release

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 22
      - run: npm test
      - name: Make the zip
        run: zip -r "study-tasks-${GITHUB_REF_NAME}.zip" index.html style.css tasks.js storage.js app.js
      - name: Create the release
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: gh release create "$GITHUB_REF_NAME" "study-tasks-${GITHUB_REF_NAME}.zip" --generate-notes --verify-tag
```

Now publishing is: `git tag -a v1.1.0 -m "..."` and `git push origin v1.1.0`. The tests run, and if they pass, the release appears with notes and the zip. The `gh` CLI is already installed on GitHub's runners and reads the token from `GH_TOKEN`.
