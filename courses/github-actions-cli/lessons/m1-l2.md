# Issues, labels and projects

An **issue** is one piece of work: a bug, a feature, a question. Good issues have a clear title, steps to reproduce (for bugs), and what you expected.

- **Labels** sort them: `bug`, `enhancement`, `good first issue`, `help wanted`.
- **Assignees** say who's on it. **Milestones** group issues for a release.
- Write `#12` anywhere to link issue 12, and `@name` to notify someone.
- **Close it from a commit or pull request:** `Fixes #12` or `Closes #12` in the description closes the issue when it's merged into the default branch.
- **Sub-issues** break a big issue into smaller ones, with progress.

## Issue forms

A file in `.github/ISSUE_TEMPLATE/` turns "New issue" into a form, so reports come with what you need:

```yaml
# .github/ISSUE_TEMPLATE/bug.yml
name: Bug report
description: Something doesn't work as it should.
labels: [bug]
body:
  - type: textarea
    id: what
    attributes:
      label: What happened?
      description: What did you do, what did you expect, and what happened instead?
    validations:
      required: true
  - type: input
    id: browser
    attributes:
      label: Browser
      placeholder: Chrome 140 on Windows 11
```

## Projects

A **project** is a board or a table of issues and pull requests, from one repository or many. Add columns like *Todo, In progress, Done*, custom fields (priority, size, sprint), and automations (a merged pull request moves its card to *Done*). It's a free, built-in Trello.
