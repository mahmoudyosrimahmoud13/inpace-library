# Reviewing code

In **Files changed**, click a line's **+** to comment. Click **Start a review** to collect several comments and send them together, then choose:

- **Comment:** questions or notes, no verdict.
- **Approve:** good to merge.
- **Request changes:** must be fixed before merging.

**Suggestions** are the best kind of comment: the author applies them with one click.

````markdown
```suggestion
const total = tasks.reduce((sum, t) => sum + t.minutes, 0);
```
````

## How to review well

- Look for what matters: bugs, security, missing tests, confusing names. Leave formatting to tools.
- Ask, don't order: *"What happens if the list is empty?"*
- Mark small things as **nit:** so the author knows they're optional.
- Say what's good too.
- Review within a day: a waiting PR blocks someone.

**Receiving a review:** it's about the code, not you. Answer every comment (fix it, or explain why not), push the fixes as new commits so the reviewer sees what changed, and press **Re-request review**.
