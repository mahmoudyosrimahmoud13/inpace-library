# Events, runners and the schedule

> **Optional video above.** Part of TechWorld with Nana's *GitHub Actions Tutorial*, from 20:40 to 24:35. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```yaml
on:
  push:
    branches: [main]
    paths-ignore: ["docs/**", "*.md"]   # don't run for README changes
  pull_request:
  schedule:
    - cron: "30 5 * * 1"                  # every Monday at 05:30 UTC
  workflow_dispatch:
    inputs:
      level:
        type: choice
        options: [quick, full]
```

- **cron** times are in UTC. [crontab.guru](https://crontab.guru) explains any cron line. Scheduled runs can be a few minutes late, and stop after 60 days without activity in a public repository.
- **Runners:** `ubuntu-latest` is the fastest and cheapest; `windows-latest` and `macos-latest` cost more minutes in private repositories. You can also run your own (**self-hosted runner**) on your machine.
- **if:** runs a step or job only sometimes: `if: github.ref == 'refs/heads/main'`, or `if: failure()` to send a message when something broke.
