# Secrets, variables and the token

## Secrets

Passwords and API keys go in **Settings → Secrets and variables → Actions**, never in the YAML. In a workflow they're `${{ secrets.NAME }}`, and GitHub hides them in the logs.

```bash
gh secret set DEPLOY_KEY < key.txt        # from the terminal
gh variable set SITE_URL --body "https://mona.github.io/study-tasks"
```

```yaml
- run: ./deploy.sh
  env:
    API_KEY: ${{ secrets.DEPLOY_KEY }}   # pass secrets as environment variables
    SITE: ${{ vars.SITE_URL }}           # variables are for settings that aren't secret
```

Pull requests from **forks** don't get your secrets, so a stranger can't steal them with a pull request that prints them.

## The GITHUB_TOKEN

Every run gets a temporary token, `secrets.GITHUB_TOKEN`, that can act on this repository and expires when the job ends. Give it **only the permissions it needs**, at the top of the workflow:

```yaml
permissions:
  contents: write        # e.g. to create a release
  pull-requests: write   # e.g. to comment on a pull request
```

With `permissions:` set, everything not listed is off. That limits the damage if a step is ever compromised.
