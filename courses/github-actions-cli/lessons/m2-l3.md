# Merging, and protecting main

The merge button has three choices:

| Method | History on main | Good for |
|---|---|---|
| **Create a merge commit** | all the branch's commits plus a merge commit | keeping every step |
| **Squash and merge** | one commit for the whole PR | most teams: one PR, one clean commit |
| **Rebase and merge** | the branch's commits, replayed, no merge commit | tidy branches with meaningful commits |

You can turn off the ones your team doesn't use in **Settings → General**, and tick *Automatically delete head branches*.

## Rules for main

In **Settings → Rules → Rulesets** (or the older *Branch protection rules*), protect main so nobody can break it, not even by accident:

- **Require a pull request** before merging, with 1 or more approvals.
- **Require status checks to pass**: the tests from module 5 must be green.
- **Block force pushes** and deletion.
- Optional: require **signed commits**, a **linear history**, or that conversations are resolved.

## CODEOWNERS

A `.github/CODEOWNERS` file names who must review which files. With the rule *Require review from Code Owners*, those people must approve:

```text
# .github/CODEOWNERS
# These people are asked to review changes to these files.
*               @mona
.github/        @mona @ali
```
