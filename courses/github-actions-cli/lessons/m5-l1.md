# A test workflow

**Continuous integration (CI)** means every change is tested automatically, before it reaches main. Here's a complete test workflow for a Node project. It runs on pushes to main and on every pull request, on two systems and two Node versions:

```yaml
# .github/workflows/ci.yml
name: Tests

on:
  push:
    branches: [main]
  pull_request:

concurrency:                     # a new push cancels the run that's still going for the same branch
  group: tests-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read                 # this workflow only needs to read the code

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: [20, 22]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: ${{ matrix.node }}
      - run: npm test
```

- **matrix** makes 4 jobs from one description (2 systems × 2 versions). `fail-fast: false` lets the others finish when one fails, so you see the whole picture.
- **concurrency** cancels an old run when you push again to the same branch: fewer wasted minutes.
- **permissions** gives the run's token only what it needs (module 6).

For Python the steps are `actions/setup-python@v7` with `python-version`, then `pip install -e ".[test]"` and `pytest`.

## Make it count

A test workflow only protects main if merging waits for it. In the ruleset from module 2, add **Require status checks to pass** and pick the `test` jobs. Now a red pull request can't be merged.
