# Exit codes and failing safely

Every command returns a number: **0 = success**, anything else = failure. Scripts must check them.

```bash
cp a b
echo $?           # exit code of the last command

if cp a b; then echo "copied"; else echo "copy failed" >&2; fi
mkdir -p "$dir" || { echo "can't create $dir" >&2; exit 1; }
```

Your script should also **return** a meaningful code with `exit N`, so cron, systemd, CI and other scripts know it failed.

## Strict mode

Put this at the top of almost every script:

```bash
#!/usr/bin/env bash
set -euo pipefail
```

| Option | Means | Saves you from |
|---|---|---|
| `-e` | Stop when a command fails | Carrying on after a failed `cd` and deleting the wrong things |
| `-u` | Using an unset variable is an error | `rm -rf "$DIR/"*` with a typo in DIR |
| `-o pipefail` | A pipeline fails if **any** part fails | `cat missing.txt | sort` "succeeding" because sort did |

Know the gaps of `-e`:

- It doesn't trigger inside `if` conditions, or on the left of `&&` / `||` (by design).
- `local x=$(cmd)` hides cmd's failure (the `local` succeeds). Write `local x; x=$(cmd)`.
- When you **expect** a failure, say so: `grep -q pattern file || true`.

## A safe `cd`

```bash
cd "$target" || exit 1      # never run the next lines in the wrong directory
```

## Errors with context

```bash
die() { echo "ERROR: $*" >&2; exit 1; }
[[ -d $src ]] || die "source $src is not a directory"
command -v rsync >/dev/null || die "rsync is not installed"
```

`command -v` checks a program exists before you depend on it.
