# Start here: your first script

Administration without automation is the same manual work, again and again. A **bash script** is just the commands you'd type, saved in a file, plus a little logic.

## The smallest real script

```bash
#!/usr/bin/env bash
# hello.sh: say hello and show where we are
echo "Hello, $USER"
echo "You are on $(hostname), in $(pwd)"
```

```bash
chmod +x hello.sh     # allow running it
./hello.sh            # run it
bash hello.sh         # or hand it to bash directly (no chmod needed)
```

| Line | Why |
|---|---|
| `#!/usr/bin/env bash` | The **shebang**: tells the kernel which interpreter runs the file. `env` finds bash wherever it is installed |
| `# comment` | Ignored by bash. Say *why*, not *what* |
| `chmod +x` | The execute bit (Linux Fundamentals, Day 7) |
| `./` | The current directory isn't on `PATH`, on purpose |

Use `bash`, not `sh`, in the shebang for this course. On Debian/Ubuntu `sh` is **dash**, a smaller shell without arrays, `[[ ]]` and other things you'll use.

## Variables

```bash
name="web01"                 # no spaces around =
count=3
echo "Server $name has $count disks"
echo "Backup: ${name}_backup.tgz"   # braces when letters follow
readonly API_URL="https://example.com"   # can't be changed later
```

## Where scripts live

| Place | For |
|---|---|
| `~/bin` (on your `PATH`) | Your own tools |
| `/usr/local/bin` | Tools for every user on the machine |
| `/opt/<app>/scripts` | Scripts that belong to one application |
| A Git repository | Always. Scripts are code |

## What this course builds

By the last day you'll write `backup.sh`: it checks what it needs, makes a backup, verifies it, logs, handles failures, sends an alert, and cleans up old backups. Every day adds one of those skills.
