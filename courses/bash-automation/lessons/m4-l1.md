# Functions

```bash
log() {
  printf '%s [%s] %s\n' "$(date '+%F %T')" "${2:-INFO}" "$1"
}

backup_dir() {
  local src=$1 dest=$2          # local: doesn't leak into the rest of the script
  [[ -d $src ]] || { log "missing $src" ERROR; return 1; }
  tar czf "$dest/$(basename "$src")-$(date +%F).tgz" -C "$(dirname "$src")" "$(basename "$src")"
}

backup_dir /etc /var/backups || exit 1
log "done"
```

## Three ways a function hands back results

| Way | Use for | Example |
|---|---|---|
| **Exit status** (`return 0..255`) | Success or failure | `if is_running nginx; then` |
| **Printing** (stdout) | A value | `size=$(dir_size /srv)` |
| **A global variable** | Several values, rarely | `RESULT=...` |

`return` is only for a status. To get a string or number out, `echo` it and capture with `$(...)`.

```bash
is_running() { systemctl is-active --quiet "$1"; }
dir_size()   { du -sb "$1" | cut -f1; }

if is_running nginx; then echo "nginx ok"; fi
echo "srv uses $(dir_size /srv) bytes"
```

## Structure a script

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly LOG=/var/log/myjob.log

log()  { ... }
die()  { log "$*" ERROR; exit 1; }
check_requirements() { ... }
do_work() { ... }

main() {
  check_requirements
  do_work "$@"
  log "finished"
}

main "$@"
```

A `main` function at the bottom, called once, makes the script read top-down like a story and lets you define helpers anywhere.

## Libraries

Shared helpers can live in one file you `source`:

```bash
source /opt/scripts/lib.sh     # or: . /opt/scripts/lib.sh
```
