# Many servers: ssh loops and parallel work

## Run one command everywhere

```bash
for h in web01 web02 web03; do
  printf '%s: ' "$h"
  ssh -o BatchMode=yes -o ConnectTimeout=5 "$h" 'uptime -p' || echo "UNREACHABLE"
done
```

- `BatchMode=yes`: never stop to ask for a password (fail instead). Needs SSH keys.
- `ConnectTimeout`: one dead host doesn't hang the loop.

Read the host list from a file:

```bash
while IFS= read -r h; do
  ssh -n "$h" 'df -h /'      # -n: don't let ssh swallow the loop's input
done < hosts.txt
```

Forgetting `-n` is a classic bug: ssh reads the rest of `hosts.txt` as its input, so the loop runs only once.

## Run a local script remotely

```bash
ssh web01 'bash -s' < report.sh              # send the script over stdin
ssh web01 "bash -s -- --verbose" < report.sh # with arguments
scp backup.sh web01:/usr/local/bin/          # or copy it there
```

## Parallel

```bash
xargs -P 8 -I{} ssh -n -o BatchMode=yes {} 'hostname; uptime' < hosts.txt
```

`-P 8` runs 8 at a time. GNU `parallel` does the same with nicer output (`parallel --tag ssh {} uptime :::: hosts.txt`).

Inside one script, `&` and `wait` run things side by side:

```bash
for f in *.log; do gzip "$f" & done
wait                                  # wait for all background jobs
```

## Know when to graduate

A loop over 5 servers is fine. For 50 servers, repeated configuration, or anything that must be idempotent and reviewed, that's what **Ansible** is for (the Infrastructure as Code course). Ansible is, at heart, a careful version of this lesson.
