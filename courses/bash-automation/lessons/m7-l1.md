# Scheduling scripts and sending alerts

## Running from cron or a timer

Scripts that work in your terminal often fail on a schedule. The usual reasons and fixes:

| Problem | Fix |
|---|---|
| A tiny `PATH` (`/usr/bin:/bin`) | Full paths, or set `PATH=` at the top of the script |
| No `.bashrc`, no aliases, no variables | Set what you need in the script or the unit file (`Environment=`) |
| A different working directory | `cd "$(dirname "$0")"` or absolute paths |
| No terminal: `read` hangs or fails | Never prompt in scheduled scripts |
| Output disappears | Log to a file, or use a systemd timer (journal) |
| Runs overlap | `flock` |

Prefer a systemd timer for anything important (System Administration, Day 5): logs, missed-run catch-up, limits, and `OnFailure=` to trigger an alert unit.

```ini
# backup.service
[Unit]
OnFailure=notify-failure@%n.service
```

## Sending an alert

```bash
notify() {
  local msg="$1"
  # chat webhook (Slack, Discord, Teams all accept a JSON POST):
  curl -fsS -X POST -H 'Content-Type: application/json' \
       -d "$(jq -n --arg t "$msg" '{text: $t}')" "$WEBHOOK_URL" || true
  # or email, if the machine can send mail:
  # printf '%s\n' "$msg" | mail -s "[$(hostname)] alert" ops@example.com
}

./report.sh > /tmp/report.txt || notify "$(hostname): report needs attention\n$(cat /tmp/report.txt)"
```

- Keep secrets like `WEBHOOK_URL` out of the script: in a root-only env file (`EnvironmentFile=/etc/backup.env`, mode 600) or a secret manager.
- `|| true` so a failed alert doesn't hide the real failure.
- Alert on **failure and on silence**: a dead-man's switch (the job pings a URL when it succeeds; you're alerted when the ping stops) catches jobs that never ran at all. Healthchecks.io works this way.
