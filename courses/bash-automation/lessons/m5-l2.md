# Defensive scripting and ShellCheck

## ShellCheck: let a tool find your bugs

```bash
sudo apt install shellcheck
shellcheck backup.sh
```

It catches unquoted variables, `$(ls)` loops, `cd` without `|| exit`, unused variables, `[` vs `[[` mistakes and dozens more, each with a code (SC2086...) you can look up. Most editors show its warnings as you type. Run it on every script, and in CI.

## The defensive checklist

| Habit | Why |
|---|---|
| `set -euo pipefail` | Stop on errors and typos |
| Quote every expansion | Spaces and empty values can't split arguments |
| Check inputs early, with clear messages | Fail before doing damage |
| `command -v tool` for every dependency | A clear error instead of a strange one halfway |
| `--` before file names: `rm -- "$f"` | A file named `-rf` isn't treated as options |
| Absolute paths for anything dangerous | `cd` mistakes can't redirect deletions |
| A `--dry-run` option | See what would happen first |
| Idempotent steps (`mkdir -p`, check-then-act) | Running twice is safe |
| Lock with `flock` | No overlapping runs |
| Meaningful exit codes | Callers know it failed |

## Idempotent means "safe to run again"

```bash
# not idempotent: appends a duplicate line every run
echo "vm.swappiness=10" >> /etc/sysctl.d/90.conf

# idempotent: same result however many times you run it
grep -qxF "vm.swappiness=10" /etc/sysctl.d/90.conf 2>/dev/null ||
  echo "vm.swappiness=10" >> /etc/sysctl.d/90.conf
```

Idempotency is the core idea of Ansible and Terraform later in the track. You can practise it in bash now.

## When to stop using bash

Switch to Python (or Go) when the script needs: real data structures, JSON beyond simple `jq`, error handling across many steps, unit tests, or it's over about 200 lines. Bash is glue; it's brilliant at running other programs and terrible at being a big program.
