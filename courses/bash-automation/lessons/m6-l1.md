# Text and JSON inside scripts: awk, sed, jq, here-docs

You learned these tools in Linux Fundamentals. In scripts, they turn command output into decisions.

```bash
# percentage used on /, as a plain number
used=$(df --output=pcent / | awk 'NR==2 {gsub("%",""); print $1}')

# the second field of a config line "port = 8080"
port=$(awk -F' *= *' '$1=="port" {print $2}' app.conf)

# change a setting in place, keeping a backup
sed -i.bak "s/^port = .*/port = $new_port/" app.conf
```

## JSON with jq

APIs and modern tools speak JSON. `jq` is the tool for it (`sudo apt install jq`).

```bash
curl -s https://api.github.com/repos/torvalds/linux | jq '.stargazers_count'
jq -r '.items[] | "\(.name) \(.size)"' data.json          # -r: raw strings, no quotes
ip -j addr | jq -r '.[] | .ifname'                          # many Linux tools have JSON output (-j)
jq --arg h "$HOSTNAME" '.host = $h' config.json > new.json  # pass shell values in safely
```

## Here-documents: multi-line text

```bash
cat > /etc/motd <<EOF
Welcome to $(hostname)
Managed by scripts. Last update: $(date +%F)
EOF

cat > script.sql <<'EOF'
SELECT * FROM users WHERE name LIKE '$literal';
EOF
```

`<<EOF` expands variables; `<<'EOF'` keeps everything literal. `<<-EOF` strips leading tabs, so you can indent it inside functions.

## printf beats echo

```bash
printf '%-10s %5d MB\n' "$name" "$size"    # aligned columns
printf '%s\n' "${array[@]}"                # one item per line
```

`echo` behaves differently across shells with `-e` and backslashes; `printf` is predictable.
