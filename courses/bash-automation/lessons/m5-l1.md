# Traps, temp files, locks and logging

## trap: clean up no matter how the script ends

```bash
tmp=$(mktemp -d)                         # a private temporary directory
cleanup() { rm -rf "$tmp"; }
trap cleanup EXIT                        # runs on normal exit, on errors (set -e), and on Ctrl+C

trap 'echo "interrupted" >&2; exit 130' INT TERM
trap 'echo "failed at line $LINENO: $BASH_COMMAND" >&2' ERR
```

| Trap | Fires when |
|---|---|
| `EXIT` | The script ends, for any reason (except SIGKILL) |
| `ERR` | A command fails (with `set -e`, just before exiting) |
| `INT` / `TERM` | Ctrl+C / `kill` or systemd stopping it |

## Temporary files

- Always `mktemp` (or `mktemp -d`), never fixed names like `/tmp/out.txt`: two runs would clash, and fixed names in `/tmp` can be abused by other users.
- Pair every `mktemp` with a `trap ... EXIT`.

## Don't run twice at once: flock

A cron job that sometimes takes longer than its interval will overlap with itself. Lock it:

```bash
exec 9>/var/lock/backup.lock
flock -n 9 || { echo "already running" >&2; exit 0; }
# ... the rest of the script runs with the lock held, released automatically at exit
```

Or from cron directly: `flock -n /var/lock/backup.lock /usr/local/bin/backup.sh`.

## Logging

```bash
readonly LOG_FILE=/var/log/backup.log
log() { printf '%s %s\n' "$(date '+%F %T')" "$*" | tee -a "$LOG_FILE" >&2; }

# or send everything (stdout and stderr) to the log and the screen:
exec > >(tee -a "$LOG_FILE") 2>&1
```

Even simpler for scripts run by systemd: just print. The journal captures stdout and stderr with timestamps (`journalctl -u backup.service`). `logger -t backup "message"` writes to the system log from anywhere.
