# Project 6: look at the mistakes, then try a fix

You'll do one turn of the ML development loop: train, read the errors, add data aimed at them, and measure again.

The code is above this text. Save it as `p6_error_analysis.py`.

## Read the code

- After training, it lists the validation mistakes by true and predicted digit and draws one of them.
- **`shifted()`** makes new training examples by moving each digit one pixel in a random direction: **data
  augmentation**, realistic variety for free.
- It retrains on the original digits plus three shifted copies, and compares.

## Run it

```bash
python p6_error_analysis.py
```

The real output:

```text
1. Validation accuracy 98.1%: 7 mistakes of 359
   most common: 8 read as 1 (2x), 6 read as 1 (1x), 9 read as 3 (1x), 6 read as 4 (1x)
   one of them, a 6 read as 1:
           %%      
         ==@@..    
         @@**..    
       ::@@@@%%    
       --@@====**  
       ++@@::  @@  
       ..++**%%%%  
           **@@**  

2. Add 3 shifted copies of every training digit (4,312 examples) and retrain: validation accuracy 97.5% (9 mistakes)
   of the 7 earlier mistakes, 5 are now right
```

What it shows:

- **Only 7 mistakes in 359**, spread over different pairs: no single big problem to fix.
- Reading one helps: that "6" is drawn with a thin, tall stroke, close to a 1.
- **The augmentation fixed 5 of the 7 old mistakes but made new ones**: 9 mistakes in total, slightly worse. An idea
  that sounds right can still hurt. These digits are already centred, so shifted copies teach the network
  positions it will never see. You only know by measuring.

## Make it yours

1. Shift by at most one pixel in **one** direction only, or rotate by a few degrees instead. Does either help?
2. Group the mistakes by how faint the digit is (its mean pixel value). Are faint digits the problem?

## What to take away

- Read the mistakes before choosing a fix.
- Measure every fix; augmentation must match the data you'll really see.
