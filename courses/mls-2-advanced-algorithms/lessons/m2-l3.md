# Project 1: the Digit reader computes its first output

Through this course you build a **Digit reader**: a network that reads handwritten digits, built, trained,
diagnosed and compared with trees, one piece a day. The data is scikit-learn's copy of the UCI handwritten digits:
1,797 images of 8 × 8 pixels. `digits.py` splits it once into 60% training, 20% validation and 20% test.

The project folder is above this text. Install `pip install tensorflow scikit-learn scipy numpy`.

## Read the code

- **`dense(a_in, W, b, g)`** is one layer, exactly as in the lesson: `g(a_in @ W + b)`, with one column of `W` per
  unit.
- The script builds the lesson's 64 → 25 → 15 → 1 network in Keras, prints each layer's weight shapes, then runs
  forward propagation **with your own `dense()` and Keras's weights**, and compares.

## Run it

```bash
python p1_forward.py
```

The real output (your numbers in step 3 will differ: the starting weights are random):

```text

       **##@@**

2. A 64 -> 25 -> 15 -> 1 network: 2,031 parameters
   dense    W (64, 25)  b (25,)

3. Your forward pass:  [0.191  0.1944 0.1904 0.1919 0.1926]
   Keras's:            [0.191  0.1944 0.1904 0.1919 0.1926]
   identical: True. Untrained, so every digit gets about the same output.
```

What it shows:

- A digit is 64 numbers; the text picture is those numbers drawn with characters.
- Layer shapes follow from the sizes: 64 × 25 weights plus 25 biases, and so on: 2,031 parameters in all.
- **Your forward pass equals Keras's.** A framework's `Dense` layer is nothing more than this line of NumPy.
- Untrained, the network says about the same thing for every digit. Learning is what comes next.

## What to take away

- A layer is a matrix product, a bias and an activation.
- Frameworks do the same arithmetic; knowing it lets you check them.
