# Project 5: diagnose the Digit reader

You'll draw a learning curve to see whether more data would help, sweep regularization on validation data, and touch
the test set once at the end.

The code is above this text. Save it as `p5_bias_variance.py`. It trains 11 networks; a few minutes on a laptop.

## Read the code

- **`net(lam, width)`**: a 64-64 ReLU network with optional L2 regularization on its weights.
- **`errors(m, n)`** trains on the first `n` training digits for 150 epochs and returns training and validation
  error.
- **The learning curve** grows `n` from 50 to all 1,078. **The sweep** tries five values of lambda on 250 digits and
  keeps the one with the lowest validation error. Only then is the test set used, once.

## Run it

```bash
python p5_bias_variance.py
```

The real output:

```text
1. Learning curve: a 64-64 network trained for 150 epochs on more and more digits
    training digits  train error  validation error
                 50         0.0%             16.4%
                100         0.0%             10.6%
                250         0.0%              7.0%
                500         0.0%              3.6%
               1078         0.0%              1.7%
   Train error stays at 0 while validation error falls with data: high variance, fixed by more data.

2. Regularization sweep on 250 digits (pick lambda on validation, never on test):
   lambda 0       train error   0.0%   validation error   6.7%
   lambda 0.0001  train error   0.0%   validation error   5.8%
   lambda 0.001   train error   0.0%   validation error   7.0%
   lambda 0.01    train error   0.0%   validation error   7.2%
   lambda 0.1     train error  10.8%   validation error  17.5%

3. Chosen lambda 0.0001, retrained on all training digits. Test error, measured once: 2.8%
```

What it shows:

- **Training error is 0 everywhere; validation error falls from 16% to under 2% as data grows.** Zero training
  error with a big gap is high variance: the network memorizes. The cure that worked here is more data.
- **A little regularization helps a bit** (6.7% to 5.8%); **too much** (0.1) underfits: training error rises too.
- **The test error, measured once, is 2.8%**: close to validation, so the choice of lambda didn't overfit the
  validation set.
