# Random forests and XGBoost

A single tree is **very sensitive** to small data changes (high variance). Ensembles fix that.

## Bagging and random forests

1. Make `B` (around 64-128) **bootstrap samples**: draw `m` examples **with replacement**.
2. Train a tree on each.
3. Random forest: at each node, consider only a **random subset** of `k ≈ √n` features, so trees differ more.
4. Predict by **voting** (classification) or **averaging** (regression).

## Boosting and XGBoost

Train trees **one after another**; each new one focuses on examples the previous ones got wrong (in gradient boosting,
it fits the remaining errors). XGBoost adds regularization and is fast. It wins many tabular competitions.

```python
from xgboost import XGBClassifier
model = XGBClassifier(n_estimators=300, max_depth=4, learning_rate=0.1)
model.fit(X_train, y_train)
```

## Trees or neural networks?

| | Trees and ensembles | Neural networks |
|---|---|---|
| Data | **tabular** (spreadsheet-like) | everything, especially images, audio, text |
| Training speed | fast | slower |
| Small trees | readable | not readable |
| Transfer learning | no | yes |
| Combining models | harder | easy to chain and fine-tune |

For a spreadsheet of customers, start with gradient-boosted trees. For photos, a network.
