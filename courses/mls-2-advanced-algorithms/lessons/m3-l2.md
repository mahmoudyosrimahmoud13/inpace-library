# Backpropagation without fear

Training needs `∂J/∂w` for **every** weight. Backpropagation computes them all efficiently with the **chain rule**,
going backwards through a **computation graph**.

Tiny example: `J = (wx + b − y)² / 2` with `x = −2, y = 2, w = 2, b = 8`.

```text
c = w·x       = −4
a = c + b     = 4
d = a − y     = 2
J = d² / 2    = 2

∂J/∂d = d = 2
∂J/∂a = ∂J/∂d · 1 = 2
∂J/∂b = ∂J/∂a · 1 = 2
∂J/∂c = ∂J/∂a · 1 = 2
∂J/∂w = ∂J/∂c · x = −4
```

One backward pass reuses each intermediate derivative, so the cost is about the **same as one forward pass**:
roughly `N + P` steps instead of `N × P` for `N` nodes and `P` parameters. That's why training huge networks is
possible at all.

Frameworks do this automatically (**autodiff**: `tf.GradientTape`, PyTorch autograd).

## Interview topics that follow

- **Vanishing gradients:** sigmoids saturate, so products of small derivatives shrink through many layers. ReLU,
  careful initialization (He, Xavier), batch norm and residual connections help.
- **Exploding gradients:** gradient clipping.
