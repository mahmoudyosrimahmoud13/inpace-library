# Hooks, custom layers and initialisation

## Custom layers with parameters

Any learnable tensor wrapped in `nn.Parameter` and assigned in `__init__` is registered automatically. Non-learnable state that should move with the model and be saved goes in a **buffer**.

```python
import torch
from torch import nn

class RMSNorm(nn.Module):
    """The normalisation used by many modern LLMs: scale by the root-mean-square, no mean subtraction."""
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))   # learnable
        self.eps = eps

    def forward(self, x):
        return self.weight * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

class Standardize(nn.Module):
    def __init__(self, mean, std):
        super().__init__()
        self.register_buffer("mean", mean)            # saved in state_dict, moved by .to(), not trained
        self.register_buffer("std", std)

    def forward(self, x):
        return (x - self.mean) / self.std

x = torch.randn(4, 8) * 5
print(RMSNorm(8)(x).detach().pow(2).mean(-1).round(decimals=2))           # about 1 for every row
s = Standardize(torch.zeros(8), torch.ones(8))
print(list(s.state_dict().keys()), list(dict(s.named_parameters()).keys()))   # buffers saved, not trained
```

Putting preprocessing inside the model as buffers (like `Standardize`) means it's saved, exported and served together with the weights.

## Hooks: look inside a running model

A **forward hook** runs after a module's forward pass; use it to record activations without changing model code.

```python
model = nn.Sequential(nn.Linear(16, 64), nn.ReLU(), nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 2))
stats = {}

def save_stats(name):
    def hook(module, inputs, output):
        stats[name] = (output.mean().item(), output.std().item(), (output == 0).float().mean().item())
    return hook

handles = [m.register_forward_hook(save_stats(f"relu{i}")) for i, m in enumerate(model) if isinstance(m, nn.ReLU)]
model(torch.randn(256, 16))
for name, (mean, std, dead) in stats.items():
    print(f"{name}: mean {mean:.3f}, std {std:.3f}, zeros {dead:.0%}")
for h in handles:
    h.remove()                                          # always remove hooks when done
```

A layer where almost all outputs are zero ("dead ReLUs") or where the spread shrinks layer after layer is a training problem you can see before it shows in the loss. Backward hooks (`register_full_backward_hook`, or `tensor.register_hook`) inspect gradients the same way; feature extraction for transfer learning uses the same mechanism.

## Initialisation, on purpose

```python
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_normal_(m.weight, nonlinearity="relu")   # suits ReLU networks
        nn.init.zeros_(m.bias)

model.apply(init_weights)                                         # runs on every submodule
deep = nn.Sequential(*[nn.Sequential(nn.Linear(64, 64), nn.ReLU()) for _ in range(20)])
x = torch.randn(512, 64)
for init in ["default", "kaiming"]:
    if init == "kaiming":
        deep.apply(init_weights)
    with torch.no_grad():
        print(init, "output std after 20 layers:", round(deep(x).std().item(), 4))
```

With PyTorch's default initialisation the signal shrinks layer after layer in this deep ReLU stack; Kaiming initialisation, designed for ReLU, keeps it at a healthy size. Residual connections and normalisation layers (which every modern architecture uses) make deep networks much less sensitive to this.
