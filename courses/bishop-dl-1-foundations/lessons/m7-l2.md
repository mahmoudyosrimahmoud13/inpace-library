# Project part 1: two classifiers and an honest comparison

## 1. Load, split and standardize

In scikit-learn's version, label 0 means malignant. We flip it so that **t = 1 means cancer**, the "positive" class.

```python
import numpy as np
from sklearn.datasets import load_breast_cancer

data = load_breast_cancer()
X, t = data.data, 1 - data.target            # t = 1: malignant
print(X.shape, "share malignant:", round(t.mean(), 3))

rng = np.random.default_rng(42)
idx = rng.permutation(len(t))
tr, va, te = idx[:341], idx[341:455], idx[455:]

mean, std = X[tr].mean(0), X[tr].std(0)       # statistics from the training set only
Z = (X - mean) / std
print(len(tr), len(va), len(te))
```

```output
(569, 30) share malignant: 0.373
341 114 114
```

Standardizing (mean 0, standard deviation 1 for each feature) uses only training statistics, so no information leaks
from the validation or test sets.

## 2. The generative classifier (section 5.3)

Class priors, class means and one shared covariance, all by maximum likelihood. 30 features mean a 30 × 30 covariance:
465 numbers from 341 examples. That's a lot, so add a small ridge to the diagonal to keep it invertible and stable.

```python
def fit_generative(Z, t, ridge=1e-1):
    p1 = t.mean()
    mu0, mu1 = Z[t == 0].mean(0), Z[t == 1].mean(0)
    S = (p1 * np.cov(Z[t == 1].T, bias=True) + (1 - p1) * np.cov(Z[t == 0].T, bias=True))
    Si = np.linalg.inv(S + ridge * np.eye(Z.shape[1]))
    w = Si @ (mu1 - mu0)
    w0 = -0.5 * mu1 @ Si @ mu1 + 0.5 * mu0 @ Si @ mu0 + np.log(p1 / (1 - p1))
    return w0, w

def sigmoid(a):
    return 1 / (1 + np.exp(-a))

w0_g, w_g = fit_generative(Z[tr], t[tr])
p_gen = lambda rows: sigmoid(Z[rows] @ w_g + w0_g)
print("generative, validation accuracy:", round(np.mean((p_gen(va) > 0.5) == t[va]), 3))
```

```output
generative, validation accuracy: 0.965
```

## 3. Logistic regression with weight decay (section 5.4)

```python
def fit_logistic(Z, t, lam, steps=3000, lr=0.5):
    Phi = np.hstack([np.ones((len(Z), 1)), Z])
    w = np.zeros(Phi.shape[1])
    for _ in range(steps):
        y = sigmoid(Phi @ w)
        grad = Phi.T @ (y - t) / len(t) + lam * np.r_[0, w[1:]]     # don't penalize the bias
        w -= lr * grad
    return w

def cross_entropy(p, t):
    p = np.clip(p, 1e-12, 1 - 1e-12)
    return -np.mean(t * np.log(p) + (1 - t) * np.log(1 - p))

def predict_logistic(w, rows):
    return sigmoid(w[0] + Z[rows] @ w[1:])

print("  lambda   val cross-entropy   val accuracy")
results = {}
for lam in [0.0, 0.001, 0.01, 0.1, 1.0]:
    w = fit_logistic(Z[tr], t[tr], lam)
    p = predict_logistic(w, va)
    results[lam] = cross_entropy(p, t[va])
    print(f"{lam:8}   {results[lam]:17.4f}   {np.mean((p > 0.5) == t[va]):12.3f}")
best_lam = min(results, key=results.get)
print("chosen lambda:", best_lam)
```

```output
  lambda   val cross-entropy   val accuracy
     0.0              0.1028          0.982
   0.001              0.0931          0.982
    0.01              0.1090          0.974
     0.1              0.1649          0.974
     1.0              0.3048          0.939
chosen lambda: 0.001
```

We choose λ by **validation cross-entropy**, not accuracy: cross-entropy also rewards confident *correct* probabilities,
and probabilities are what part 2 needs.

## 4. Your own ROC curve and AUC (section 5.2.6)

Sort the cases by predicted probability, sweep the threshold through every value, and count.

```python
def roc_curve(p, t):
    order = np.argsort(-p)
    tps = np.cumsum(t[order]) / t.sum()                 # true positive rate as the threshold drops
    fps = np.cumsum(1 - t[order]) / (1 - t).sum()       # false positive rate
    return np.r_[0, fps], np.r_[0, tps]

def auc(p, t):
    fpr, tpr = roc_curve(p, t)
    return np.sum((fpr[1:] - fpr[:-1]) * (tpr[1:] + tpr[:-1]) / 2)    # trapezoid rule

w_log = fit_logistic(np.vstack([Z[tr], Z[va]]), np.r_[t[tr], t[va]], best_lam)   # refit on train + validation
w0_g, w_g = fit_generative(np.vstack([Z[tr], Z[va]]), np.r_[t[tr], t[va]])

for name, p in [("generative", p_gen(te)), ("logistic", predict_logistic(w_log, te))]:
    print(f"{name:10}  test accuracy {np.mean((p > 0.5) == t[te]):.3f}   "
          f"cross-entropy {cross_entropy(p, t[te]):.3f}   AUC {auc(p, t[te]):.4f}")
```

```output
generative  test accuracy 0.974   cross-entropy 0.064   AUC 1.0000
logistic    test accuracy 0.991   cross-entropy 0.063   AUC 0.9940
```

Before looking at the test set we refit both models on training + validation: once the choices are made, more data
helps. Then we look at the test set once.

## Read the result like an engineer

- Both models are excellent here. This data set is famously easy.
- They win on different measures. The generative model **ranks** every malignant case above every benign one (AUC 1.0),
  but its 0.5 threshold still misclassifies 3 cases. Logistic regression gets 1 case wrong at 0.5, yet ranks slightly
  worse. Their cross-entropies are almost equal.
- With 114 test cases, one case is almost a full point of accuracy. A difference of one or two cases isn't evidence
  that one model is better. Honest reporting says so.
- The generative model needed a ridge to work at all with 30 features. That's section 5.4's argument for discriminative
  models: far fewer numbers to estimate (31 instead of about 500).
- AUC says the ranking is nearly perfect, so the **threshold** is where the decisions are won or lost. That's part 2.
