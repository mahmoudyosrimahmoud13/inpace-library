## Why go deep?

The universal approximation theorem says two layers are enough in principle. Section 6.3 explains why we use many layers
anyway. Read the subsections in order; each is short.

- **Hierarchical representations** (6.3.1). Each layer builds features out of the previous layer's features: edges, then
  shapes, then objects. Some functions need exponentially fewer units when computed in many layers than in one wide
  layer.
- **Distributed representations** (6.3.2). A hidden layer with M yes/no units can describe 2^M different patterns. Each
  concept is spread over many units, and each unit takes part in many concepts. That's far more efficient than one unit
  per concept.
- **Representation learning** (6.3.3). The hidden layers transform the data into a space where the final task is easy,
  as you saw with XOR. Read Figure 6.11's idea carefully: the last hidden layer is an **embedding** of the input.
- **Transfer learning** (6.3.4). Features learned on one big task (say, millions of everyday photos) often help on a
  related small task (say, skin lesion images). Keep the early layers, and retrain only the last ones. This is how most
  real projects with little data work.
- **Contrastive learning** (6.3.5). A way to learn representations without labels: pull together the embeddings of two
  versions of the same example (an image and its crop), push apart those of different examples. The text–image model
  CLIP works this way.
- **General architectures and tensors** (6.3.6–6.3.7). Networks don't have to be simple chains: any graph without loops
  works, which is what backpropagation will need. And data in deep learning lives in **tensors**: arrays with many
  indices, like a batch of colour images with shape (batch, height, width, channels).

## The point of this section

Depth isn't just "more parameters". It changes what's easy to learn, because each layer can reuse the work of the
layers below it. The rest of this course is about how to actually train such deep stacks.
