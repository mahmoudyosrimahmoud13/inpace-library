# Read: parameter sharing, residual connections and model averaging (9.4–9.6)

Read sections 9.4 to 9.6 to the end of the chapter (pages 270 to 286).

## Parameter sharing (9.4)

Force groups of weights to be **equal**. Fewer free parameters, and a built-in assumption: the same pattern detector is
useful everywhere in an image, or at every time step of a sequence. Convolutional networks (chapter 10) and recurrent
networks are built on this. **Soft weight sharing** (9.4.1) is a gentler version: instead of forcing weights to be equal,
a regularizer encourages them to form a few groups of similar values.

## Residual connections (9.5)

The most important practical trick in this chapter. In a very deep network, gradients become erratic: tiny changes to an
early layer cause chaotic changes at the output (the book calls these **shattered gradients**), and training stalls.
The fix: let each block learn a **change** to its input instead of a whole new representation:

```text
z_out = z_in + F(z_in)
```

Gradients can then flow straight through the "+ z_in" path, and networks with hundreds of layers train well. Every
modern architecture, transformers included, uses them.

## Model averaging (9.6)

- **Ensembles**: train several models and average their predictions. Their errors partly cancel. The catch is the cost:
  several models to train and run.
- **Bagging**: train each model on a different random resample of the data, to make them differ.
- **Dropout** (9.6.1): during training, randomly switch off each hidden unit with some probability on every example.
  Each step trains a different "thinned" network, all sharing the same weights, so dropout behaves like an ensemble of
  exponentially many networks for the price of one. Units can't rely on particular partners, so they learn more robust
  features. At test time, use all units, and scale the activations so their expected size matches training. (The
  common "inverted dropout" does the scaling during training instead, which is what you'll code.)

## The point of this chapter

Regularization isn't one trick. It's every way of telling the model what kinds of functions to prefer: penalties on
weights, stopping early, sharing weights, averaging models, and architecture choices that build in what you know.
