# Build: high dimensions, and a network by hand

## 1. High-dimensional spaces are strange

Section 6.1.2 claims that most of a high-dimensional Gaussian's samples lie far from its centre, in a thin shell.
Check it.

```python
import numpy as np

rng = np.random.default_rng(0)
for D in [1, 2, 10, 100, 1000]:
    r = np.linalg.norm(rng.normal(size=(20000, D)), axis=1)
    print(f"D = {D:4d}: distance from centre  mean {r.mean():7.2f}   std {r.std():.2f}   "
          f"share within 1 of the centre {np.mean(r < 1):.4f}")
```

```output
D =    1: distance from centre  mean    0.80   std 0.60   share within 1 of the centre 0.6843
D =    2: distance from centre  mean    1.25   std 0.66   share within 1 of the centre 0.3957
D =   10: distance from centre  mean    3.09   std 0.69   share within 1 of the centre 0.0003
D =  100: distance from centre  mean    9.97   std 0.71   share within 1 of the centre 0.0000
D = 1000: distance from centre  mean   31.61   std 0.71   share within 1 of the centre 0.0000
```

In 1000 dimensions, the samples sit at a distance of about 31.6 (that's √1000) from the centre, give or take 0.7, and
**none** are near the centre, even though the density is highest there. The volume near the centre is just too small to
matter.

## 2. Why one layer can't solve XOR

Four points: (0,0) and (1,1) are class 0, (0,1) and (1,0) are class 1. No straight line separates them. Train logistic
regression and watch it get stuck.

```python
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
t = np.array([0, 1, 1, 0])

def sigmoid(a):
    return 1 / (1 + np.exp(-a))

w, b = np.zeros(2), 0.0
for _ in range(5000):
    y = sigmoid(X @ w + b)
    w -= 0.5 * X.T @ (y - t) / 4
    b -= 0.5 * np.mean(y - t)
print("logistic regression outputs:", np.round(sigmoid(X @ w + b), 3))
```

```output
logistic regression outputs: [0.5 0.5 0.5 0.5]
```

Every output is 0.5: the best a single layer can do here is to give up.

## 3. Two layers solve it

Two hidden ReLU units are enough. Here are weights set **by hand**, so you can see what each hidden unit does.

```python
def relu(a):
    return np.maximum(0, a)

W1 = np.array([[1.0, 1.0],      # hidden unit 1: x1 + x2
               [1.0, 1.0]])     # hidden unit 2: x1 + x2 - 1 (bias below)
b1 = np.array([0.0, -1.0])
W2 = np.array([1.0, -2.0])

Z = relu(X @ W1.T + b1)          # learned basis functions, here written by hand
print("hidden units:\n", Z)
print("network output:", Z @ W2)
```

```output
hidden units:
 [[0. 0.]
 [1. 0.]
 [1. 0.]
 [2. 1.]]
network output: [0. 1. 1. 0.]
```

The first hidden unit counts how many inputs are on; the second only fires when both are on. Their combination,
"count minus twice both", is exactly XOR. The hidden layer has **re-represented** the data so that a single linear
output can finish the job. That's section 6.1.4's data-dependent basis functions, in miniature.

## 4. Weight-space symmetry

Swap the two hidden units (and their output weights): the function doesn't change.

```python
perm = [1, 0]
print("same outputs after swapping hidden units:",
      np.allclose(relu(X @ W1[perm].T + b1[perm]) @ W2[perm], Z @ W2))
```

```output
same outputs after swapping hidden units: True
```

With M hidden units there are M! such orderings, so every good solution has many identical copies (section 6.2.4).
