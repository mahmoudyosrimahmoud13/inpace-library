# Build: optimizers on a narrow valley

Compare plain gradient descent, momentum and Adam on the kind of error surface section 7.3 worries about: a long,
narrow valley.

## 1. The surface

`E(w) = ½(w₁² + 50·w₂²)`. Its Hessian has eigenvalues 1 and 50: 50 times steeper across the valley than along it.

```python
import numpy as np

H = np.diag([1.0, 50.0])

def E(w):
    return 0.5 * w @ H @ w

def grad(w):
    return H @ w

start = np.array([-10.0, 1.0])
print("starting error:", E(start))
```

```output
starting error: 75.0
```

## 2. Plain gradient descent

The learning rate must stay below 2 / 50 = 0.04, or the steep direction blows up (section 7.3).

```python
def run(step_fn, steps=100):
    w, state = start.copy(), {}
    for k in range(1, steps + 1):
        w = step_fn(w, grad(w), state, k)
    return E(w)

def gd(lr):
    return lambda w, g, s, k: w - lr * g

for lr in [0.01, 0.039, 0.041]:
    print(f"gradient descent, lr = {lr}: error after 100 steps = {run(gd(lr)):.4g}")
```

```output
gradient descent, lr = 0.01: error after 100 steps = 6.699
gradient descent, lr = 0.039: error after 100 steps = 0.0184
gradient descent, lr = 0.041: error after 100 steps = 4.323e+05
```

At 0.041 it diverges. At 0.039, just under the limit, it gets to 0.018; with a safer 0.01 the shallow direction
crawls and the error is still 6.7 after 100 steps. That's the "limited by the largest eigenvalue, slowed by the
smallest" problem: you're forced to run right at the edge of divergence.

## 3. Momentum

```python
def momentum(lr, mu=0.9):
    def step(w, g, s, k):
        s["v"] = mu * s.get("v", 0) - lr * g
        return w + s["v"]
    return step

print(f"momentum, lr = 0.02: error after 100 steps = {run(momentum(0.02)):.4g}")
```

```output
momentum, lr = 0.02: error after 100 steps = 0.0009394
```

## 4. Adam

Adam's per-weight scaling makes the steep and shallow directions take similar-sized steps.

```python
def adam(lr, b1=0.9, b2=0.999, eps=1e-8):
    def step(w, g, s, k):
        s["m"] = b1 * s.get("m", 0) + (1 - b1) * g
        s["v"] = b2 * s.get("v", 0) + (1 - b2) * g ** 2
        m_hat = s["m"] / (1 - b1 ** k)          # bias correction for the first steps
        v_hat = s["v"] / (1 - b2 ** k)
        return w - lr * m_hat / (np.sqrt(v_hat) + eps)
    return step

for lr in [0.1, 0.5]:
    print(f"Adam, lr = {lr}: error after 100 steps = {run(adam(lr)):.4g}")
```

```output
Adam, lr = 0.1: error after 100 steps = 2.519
Adam, lr = 0.5: error after 100 steps = 0.001359
```

Momentum gets about 20 times lower than the best plain gradient descent, with a learning rate safely away from the
edge. Adam with lr = 0.1 is slow here, and the reason teaches you what Adam's learning rate means: it's roughly **how
far each weight may move per step**, whatever the scale of its gradient. w₁ starts 10 away from the minimum, and 100
steps of about 0.1 can't cover that. With lr = 0.5, Adam matches momentum.

## 5. Normalization makes the valley round

The valley exists because the two directions are scaled differently. In a real model that often comes from the inputs.
Fit a linear model to two features on very different scales, before and after standardizing.

```python
rng = np.random.default_rng(0)
X = np.column_stack([rng.normal(0, 1, 500), rng.normal(0, 30, 500)])   # second feature on a much bigger scale
t = X @ np.array([2.0, 0.1]) + rng.normal(0, 0.1, 500)

def hessian_ratio(X):
    ev = np.linalg.eigvalsh(X.T @ X / len(X))
    return ev.max() / ev.min()

Xn = (X - X.mean(0)) / X.std(0)
print(f"ratio of Hessian eigenvalues, raw inputs:          {hessian_ratio(X):10.1f}")
print(f"ratio of Hessian eigenvalues, standardized inputs: {hessian_ratio(Xn):10.1f}")
```

```output
ratio of Hessian eigenvalues, raw inputs:               774.4
ratio of Hessian eigenvalues, standardized inputs:        1.0
```

For squared error, the Hessian of a linear model is XᵀX / N. Standardizing turns a ratio of hundreds into about 1: a round
bowl, where plain gradient descent works fine. That's why section 7.4.1 says to always normalize your data.
