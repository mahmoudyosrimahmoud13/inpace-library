# Custom hooks: reuse your logic

When two components need the same stateful logic (fetching, saving to storage, a timer), move it into a **custom hook**: a function whose name starts with `use` and that calls other hooks.

## Saving to `localStorage`

```tsx
import { useEffect, useState } from "react";

export function useLocalStorage<T>(key: string, start: T) {
  const [value, setValue] = useState<T>(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved ? (JSON.parse(saved) as T) : start;
    } catch {
      return start;              // private mode, or broken JSON
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch {
      /* storage full or blocked: keep working in memory */
    }
  }, [key, value]);

  return [value, setValue] as const;
}
```

Use it exactly like `useState`:

```tsx
const [tasks, setTasks] = useLocalStorage<Task[]>("study-tasks", []);
```

Notes:
- `useState(() => ...)` with a **function** runs the slow work (reading storage) only once, not on every render.
- `as const` makes the return type a fixed pair, so `tasks` and `setTasks` keep their own types.
- The generic `<T>` means the same hook works for tasks, settings, anything.

## A fetch hook

```tsx
export function useFetch<T>(url: string) {
  const [data, setData] = useState<T | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const ctrl = new AbortController();
    setLoading(true);
    setError(null);
    fetch(url, { signal: ctrl.signal })
      .then((r) => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json() as Promise<T>;
      })
      .then(setData)
      .catch((e) => { if (e.name !== "AbortError") setError(e.message); })
      .finally(() => { if (!ctrl.signal.aborted) setLoading(false); });
    return () => ctrl.abort();
  }, [url]);

  return { data, error, loading };
}

// in a component
const { data: tasks, error, loading } = useFetch<Task[]>("/tasks.json");
```

Because `url` is a dependency, changing it (for example a search box) fetches again and cancels the old request.

## A timer hook

```tsx
export function useCountdown(seconds: number, running: boolean) {
  const [left, setLeft] = useState(seconds);
  useEffect(() => setLeft(seconds), [seconds]);
  useEffect(() => {
    if (!running || left <= 0) return;
    const id = setTimeout(() => setLeft((s) => s - 1), 1000);
    return () => clearTimeout(id);
  }, [running, left]);
  return left;
}
```

Good for a focus timer next to your tasks.

## What custom hooks share, and what they don't

Each component that calls a hook gets its **own** state. Two components using `useCountdown` have two separate timers. Hooks share **logic**, not data. To share **data** between components, lift state up (Day 3) or use Context (Day 5).

## Naming and testing

- Always start with `use`, so React's rules (and the linter) apply.
- Keep hooks small and focused: `useLocalStorage`, `useFetch`, `useDebounce`.
- Hooks are plain functions, so they're easy to test with React Testing Library's `renderHook` (Day 6).
