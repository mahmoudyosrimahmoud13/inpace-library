# Build, test and publish

## Production build

```bash
npm run build      # type-checks, then bundles into dist/
npm run preview    # serves dist/ locally, like the real site
```

`dist/` is plain HTML, CSS and JavaScript: any static host can serve it (GitHub Pages, Netlify, Cloudflare Pages, Vercel).

Vite's template runs `tsc -b` before building, so a **type error stops the build**. That's what you want: broken code never reaches users.

## Configuration through environment variables

```bash
# .env.production
VITE_API_URL=https://api.example.com
```

```ts
const api = import.meta.env.VITE_API_URL;
```

Only variables starting with `VITE_` reach the browser. **Everything in front-end code is public**: never put secret keys there. Secrets belong on a server.

## Publish to GitHub Pages with Actions

1. In `vite.config.ts`, set the folder your site lives in:

```ts
export default defineConfig({
  base: "/study-tasks/",       // your repository's name
  plugins: [react()],
});
```

2. Add `.github/workflows/pages.yml`:

```yaml
name: pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test -- --run
      - run: npm run build
      - run: cp dist/index.html dist/404.html   # routes work after a refresh
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
    steps:
      - uses: actions/deploy-pages@v4
```

3. In the repository's **Settings → Pages**, set **Source** to **GitHub Actions**.

Push, and in a minute or two your app is live at `https://<your-name>.github.io/study-tasks/`. Every push runs the tests first; if they fail, nothing is published.

If you use `BrowserRouter`, also set its basename: `<BrowserRouter basename="/study-tasks">`.

## A README that gets you interviews

Your repo's README is the first thing a recruiter sees. Include:
- One sentence: what the app does and who it's for.
- A **screenshot or short GIF**, and the **live link** at the top.
- The stack: React, TypeScript, Vite, React Router, Vitest.
- How to run it: `npm install`, `npm run dev`, `npm test`.
- What you'd add next. It shows you think beyond the tutorial.

## Linting and formatting

Vite's template comes with **ESLint**. Add **Prettier** so formatting is never discussed again:

```bash
npm install -D prettier
npx prettier --write .
```

Run `npm run lint` in your workflow too.
