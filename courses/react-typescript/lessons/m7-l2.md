# Final project, and what comes next

## Final project: Study Tasks, in React and TypeScript

Build a study planner and publish it. It must have:

1. **Tasks**: add (with a title and minutes), mark done, edit the title, delete. Empty title is refused with a clear message.
2. **Filters** in the address: `?filter=all|active|done`, so a refresh or a shared link keeps the view.
3. **Progress**: done/total and minutes done today, calculated from the tasks (not separate state).
4. **Saved**: tasks survive a reload (`localStorage` through your custom hook or reducer).
5. **Two pages** with React Router: the list, and a task's own page (`/tasks/:id`) with a "not found" message for bad ids.
6. **Loads starter data** from `public/starter.json` the first time, with loading and error states.
7. **Types everywhere**: `strict` on, no `any`, a `Task` type and an action union for the reducer.
8. **Tests**: at least three reducer tests and two user-journey tests with Testing Library.
9. **Accessible**: labels on every input, real buttons, works by keyboard alone, Lighthouse accessibility 90 or more.
10. **Published** on GitHub Pages by a workflow that runs the tests first, with a README, a screenshot and the live link.

Stretch goals, pick any:
- A focus timer (your `useCountdown` hook) that marks a task done when time is up.
- Drag to reorder tasks.
- Dark mode with Context, remembering the choice.
- Install as an app (a PWA) with `vite-plugin-pwa`.

## Checklist before you share it

- [ ] `npm run build` passes with no type errors
- [ ] No warnings in the browser console
- [ ] Works on a phone-sized screen
- [ ] Refreshing any page works
- [ ] Tab through the whole app: focus is always visible
- [ ] README has the live link at the top

## What to learn next

You now have the core that every React job uses. Good next steps, roughly in this order:

1. **TanStack Query** for server data: caching, refetching, loading and error states handled for you.
2. **A form library** (React Hook Form with Zod) for big, validated forms.
3. **A component library** (shadcn/ui or Radix) for accessible dialogs, menus and tabs you don't have to build.
4. **Next.js** (or React Router's framework mode) for server rendering, file-based routes and full-stack apps.
5. **A backend**: pair this course with inPace's **FastAPI** or **Python backend** path and build a real API for your app.

## Interview questions you can now answer

- What's the difference between props and state?
- Why do lists need keys, and why is the index a poor key?
- When would you use `useEffect`, and when should you avoid it?
- How do you share state between distant components?
- How would you find out why a page is slow?
- What does TypeScript add to a React project?

Practice answering them out loud, using your project as the example each time. That's what turns a course into a job.
