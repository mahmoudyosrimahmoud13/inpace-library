# TypeScript for JavaScript developers

TypeScript is JavaScript with **types**: you say what kind of value each thing holds, and the editor checks your whole program before it runs. It catches the boring bugs (a typo in a property name, a function called with the wrong thing, a value that might be `undefined`) while you type, not when a user clicks a button.

TypeScript doesn't run in the browser. A build tool **removes the types** and leaves plain JavaScript. So every JavaScript skill you have still counts.

## Your first types

```ts
let title: string = "Learn React";
let minutes: number = 25;
let done: boolean = false;
let tags: string[] = ["react", "typescript"];
```

Most of the time you don't write the type, because TypeScript **infers** it:

```ts
let title = "Learn React";   // TypeScript knows: string
title = 42;                   // ❌ Type 'number' is not assignable to type 'string'.
```

Rule of thumb: let TypeScript infer variables, and **write types on function parameters and on the shape of your data**.

## Functions

```ts
function minutesLeft(total: number, spent: number): number {
  return Math.max(0, total - spent);
}

minutesLeft(60, "20"); // ❌ Argument of type 'string' is not assignable to parameter of type 'number'.
```

Optional and default parameters:

```ts
function greet(name: string, emoji?: string) {
  return `Hi ${name}${emoji ?? ""}`;
}
```

## Describing objects: `type` and `interface`

```ts
type Task = {
  id: number;
  title: string;
  done: boolean;
  due?: string;          // optional: may be missing
};

const t: Task = { id: 1, title: "Read lesson 1", done: false };
t.titel = "x";           // ❌ Property 'titel' does not exist on type 'Task'. Did you mean 'title'?
```

`interface Task { ... }` does almost the same thing. Pick one style per project; this course uses `type`.

## Union types: "one of these"

```ts
type Filter = "all" | "active" | "done";

let f: Filter = "active";
f = "finished"; // ❌ not one of the three
```

Unions are how you model real states:

```ts
type Load =
  | { state: "loading" }
  | { state: "error"; message: string }
  | { state: "ready"; tasks: Task[] };
```

## Narrowing

When a value can be several types, TypeScript makes you check which one you have before using it:

```ts
function show(l: Load) {
  if (l.state === "error") return l.message;      // here l is the error case
  if (l.state === "ready") return l.tasks.length;  // here l has tasks
  return "Loading…";
}
```

The same works with `typeof x === "string"`, `Array.isArray(x)` and `if (x)` for `undefined`.

## `null` and `undefined`

With **strict mode** on (always turn it on), TypeScript won't let you forget that something might be missing:

```ts
const box = document.querySelector("#out");
box.textContent = "hi";   // ❌ 'box' is possibly 'null'.
if (box) box.textContent = "hi";  // ✅
```

This one check prevents a huge share of real-world crashes ("Cannot read properties of null").

## `any` and `unknown`

`any` switches checking off. Avoid it. If you truly don't know a value's type (for example JSON from a server), use `unknown` and narrow it before use.
