# Testing React apps

Tests let you change code without fear. For React, test **what the user sees and does**, not how the component works inside.

## Set up Vitest and Testing Library

```bash
npm install -D vitest jsdom @testing-library/react @testing-library/user-event @testing-library/jest-dom
```

In `vite.config.ts`:

```ts
/// <reference types="vitest/config" />
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  test: { environment: "jsdom", setupFiles: "./src/setup-tests.ts" },
});
```

`src/setup-tests.ts`:

```ts
import "@testing-library/jest-dom/vitest";
```

Add `"test": "vitest"` to the scripts in `package.json`, then run `npm test`.

## Test plain logic first

Reducers and helpers are just functions:

```ts
import { describe, it, expect } from "vitest";
import { tasksReducer } from "./tasks";

describe("tasksReducer", () => {
  it("toggles one task", () => {
    const start = [{ id: 1, title: "A", done: false }];
    expect(tasksReducer(start, { type: "toggle", id: 1 })[0].done).toBe(true);
  });

  it("clears only done tasks", () => {
    const start = [{ id: 1, title: "A", done: true }, { id: 2, title: "B", done: false }];
    expect(tasksReducer(start, { type: "clearDone" })).toEqual([{ id: 2, title: "B", done: false }]);
  });
});
```

## Test components like a user

```tsx
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { it, expect } from "vitest";
import App from "./App";

it("adds a task and marks it done", async () => {
  const user = userEvent.setup();
  render(<App />);

  await user.type(screen.getByLabelText("New task"), "Read lesson 6");
  await user.click(screen.getByRole("button", { name: "Add" }));

  const box = screen.getByRole("checkbox", { name: "Read lesson 6" });
  expect(box).not.toBeChecked();
  await user.click(box);
  expect(box).toBeChecked();
});
```

Find elements the way people (and screen readers) do, in this order of preference:
1. `getByRole("button", { name: "Add" })`
2. `getByLabelText("New task")`
3. `getByText("No tasks yet")`
4. `getByTestId(...)`: last resort.

A nice side effect: if a test can't find your button by its role and name, a screen reader user can't either. Tests push you toward accessible markup.

## Async UI

For things that appear later (after a fetch), use `findBy...`, which waits:

```tsx
expect(await screen.findByText("Read lesson 1")).toBeInTheDocument();
```

Mock the network so tests don't depend on a server:

```ts
import { vi } from "vitest";
vi.stubGlobal("fetch", vi.fn(async () => new Response(JSON.stringify([{ id: 1, title: "Read lesson 1", done: false }]))));
```

## What to test

| Worth it | Usually not |
|---|---|
| Reducers, helpers, calculations | That React renders a div |
| The main user journeys (add, complete, filter, delete) | Exact CSS classes |
| Error and empty states | Third-party libraries |
| Bugs you fixed (so they never return) | Every tiny prop |

Run tests in CI too (Day 7), so every push is checked.
