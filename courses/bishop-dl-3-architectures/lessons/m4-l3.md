# Build: tokens, next-token models and sampling

Before the transformer, build the simplest autoregressive model there is, a **bigram** model, and use it to try the
sampling strategies of section 12.3.2. The text is Python's own "Zen of Python", which ships with every Python.

## 1. Text to tokens

Use characters as tokens.

```python
import codecs, contextlib, io
import numpy as np

with contextlib.redirect_stdout(io.StringIO()):
    import this                                 # importing it prints the poem; we hide that

text = codecs.decode(this.s, "rot13")           # the module stores it lightly scrambled
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
ids = np.array([stoi[c] for c in text])
print("characters in the text:", len(text), "  vocabulary size:", len(chars))
print("first tokens:", ids[:20])
```

```output
characters in the text: 856   vocabulary size: 45
first tokens: [19 29 26  1 21 26 34  1 35 27  1 16 44 39 29 35 34  5  1 23]
```

## 2. A bigram model

The simplest autoregressive model: the next character depends only on the current one. Count every pair and normalize
each row to get `p(next | current)`. Add a tiny amount (0.01) to every count so that nothing has probability exactly
zero.

```python
V = len(chars)
counts = np.full((V, V), 0.01)
for a, b in zip(ids[:-1], ids[1:]):
    counts[a, b] += 1
P = counts / counts.sum(axis=1, keepdims=True)

nll = -np.mean(np.log(P[ids[:-1], ids[1:]]))
print(f"average negative log-likelihood: {nll:.3f} nats per character")
print(f"a uniform guess would give:      {np.log(V):.3f}")
```

```output
average negative log-likelihood: 1.993 nats per character
a uniform guess would give:      3.807
```

## 3. Sampling strategies

Generate text by drawing one character at a time from `p(next | current)`, with a **temperature** T and optional
**top-K** filtering.

```python
rng = np.random.default_rng(0)

def generate(start, n, T=1.0, top_k=None):
    out = [stoi[start]]
    for _ in range(n):
        logits = np.log(P[out[-1]]) / T             # temperature reshapes the distribution
        if top_k:
            cutoff = np.sort(logits)[-top_k]
            logits = np.where(logits >= cutoff, logits, -np.inf)
        p = np.exp(logits - logits.max()); p /= p.sum()
        out.append(rng.choice(V, p=p))
    return "".join(chars[i] for i in out)

print("greedy-like (T = 0.1):", repr(generate("T", 60, T=0.1)))
print("T = 1.0:              ", repr(generate("T", 60, T=1.0)))
print("T = 1.0, top-K = 3:   ", repr(generate("T", 60, T=1.0, top_k=3)))
print("T = 2.0:              ", repr(generate("T", 60, T=2.0)))
```

```output
greedy-like (T = 0.1): 'Than thathoughathathan than thathathan than the thathan is is'
T = 1.0:               'Tha.\nCobve nthon, ythones revesst tyt*sspldeven,IFlias\nSpt t '
T = 1.0, top-K = 3:    'Thethante is tharers ise it tet icimpr t is thanthe te thetho'
T = 2.0:               "TobTir even're yD\nTxif oZent is e o ethtouD',ple-earempEpathx"
```

A low temperature gets stuck repeating the most likely pairs, exactly the dullness of greedy search. A high temperature
produces junk. Top-K keeps variety while cutting off the silly choices.

## 4. What a bigram can't do

A bigram model has one row of probabilities per character: it can't know that after "Beautiful is better than " comes
"ugly", because it only sees the space. A transformer conditions on **all** earlier tokens through attention. That's
tomorrow's project, on a task where the whole input matters: sorting.
