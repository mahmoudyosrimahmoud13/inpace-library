## Why images need their own architecture (10.1)

A fully connected network treats an image as an unordered list of numbers: shuffle the pixels the same way in every
image and it learns just as well. That throws away what we know about images:

- Nearby pixels are related much more than distant ones (**locality**).
- A cat is a cat wherever it appears (**translation**).
- Images are huge: a small colour photo of 200 × 200 pixels has 120,000 inputs, so a fully connected first layer needs
  millions of weights.

Convolutional networks build these facts in, an example of the inductive biases from chapter 9.

## Convolutional filters (10.2)

- **Feature detectors** (10.2.1): a hidden unit looks at a small patch (its **receptive field**) through a small grid of
  weights, the **filter** or **kernel**. Slide the same filter over every position: the outputs form a **feature map**.
  Every position uses the same weights: that's **parameter sharing** from section 9.4.
- **Translation equivariance** (10.2.2): shift the input and the feature map shifts by the same amount. The network
  doesn't have to learn "an edge here" and "an edge there" separately.
- **Padding** (10.2.3): an image of size J with a filter of size M gives an output of size J − M + 1. Adding P rows and
  columns of zeros around the image gives J + 2P − M + 1; choosing P = (M − 1)/2 keeps the size the same ("same"
  padding).
- **Strides** (10.2.4): move the filter by more than one pixel at a time to get a smaller output.
- **Multi-dimensional convolutions** (10.2.5): real images have channels (red, green, blue), and hidden layers have many
  feature maps. Each filter spans **all** input channels, and a layer has many filters, one per output channel. Count
  the parameters for yourself in the book's example.
- **Pooling** (10.2.6): summarize each small region by its maximum (or average). The output shrinks, and small shifts
  of the input barely change it: pooling adds a little **invariance** on top of the equivariance.
- **Multilayer convolutions and architectures** (10.2.7–10.2.8): stack convolution, activation and pooling, again and
  again. Deeper layers see larger regions and detect more complex patterns. The section ends with the history: LeNet,
  ImageNet, AlexNet in 2012, and VGG-16, whose simple design of many 3 × 3 convolutions is worth studying.

## The key distinction

**Equivariant**: the output moves *with* the input (convolution). **Invariant**: the output *doesn't change* when the
input moves (what a classifier ultimately needs). Convolutions give equivariance; pooling, and the final layers, turn
it into approximate invariance.
