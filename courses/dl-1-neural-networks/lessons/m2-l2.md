# The model and its loss

`ŷ = σ(wᵀx + b)`, where `σ(z) = 1 / (1 + e^−z)` squashes any number into `(0, 1)`: a probability of class 1.

**Loss for one example** (binary cross-entropy): `L(ŷ, y) = −(y·log ŷ + (1 − y)·log(1 − ŷ))`.
**Cost** for the whole set: the average loss, `J(w, b) = (1/m) Σ L(ŷ(i), y(i))`.

![Binary cross-entropy](log_loss.png)

Why not squared error? With a sigmoid, squared error makes `J` non-convex (many bad local minima). Cross-entropy is
convex for logistic regression, and it punishes being confident and wrong very hard, as the chart shows.

## Today's code

```python
loss = torch.nn.BCEWithLogitsLoss()(logits, y)            # PyTorch: give it the raw scores
loss = keras.losses.BinaryCrossentropy(from_logits=True)  # Keras: same idea
```

Passing **logits** (scores before the sigmoid) is the modern habit: the library combines sigmoid and log in one
numerically stable step, so you never take `log(0)`.
