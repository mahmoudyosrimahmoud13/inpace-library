# Sorting

In real code you call `sorted()` (O(n log n), stable, very fast). In interviews you need to know **how sorting works**, and more importantly, **when sorting first makes a problem easy**.

## Merge sort: divide and conquer

```python
def merge_sort(a: list[int]) -> list[int]:
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]
```

Split in half (log n levels), merge each level in O(n): **O(n log n) always**, O(n) extra space. It's **stable**: equal items keep their order.

## Quick sort

Pick a pivot, put smaller items left and bigger ones right, sort both sides. Average O(n log n), worst O(n²) (with bad pivots), sorts in place. A random pivot makes the worst case very unlikely.

**Quickselect** uses the same partition idea to find the k-th smallest element in **O(n) on average**, without sorting everything.

## Comparison table

| Algorithm | Time | Extra space | Stable |
|---|---|---|---|
| Merge sort | O(n log n) | O(n) | Yes |
| Quick sort | O(n log n) average, O(n²) worst | O(log n) | No |
| Heap sort | O(n log n) | O(1) | No |
| Counting sort | O(n + k), values in range k | O(k) | Yes |
| Python's `sorted` (Timsort) | O(n log n), O(n) on nearly sorted data | O(n) | Yes |

## Sorting with keys

```python
people.sort(key=lambda p: (p.age, p.name))      # by age, then name
words.sort(key=len, reverse=True)
intervals.sort(key=lambda iv: iv[0])             # by start time
```

## When sorting first is the trick

Sorting costs O(n log n), which is usually fine, and it unlocks simpler ideas:

- **Two pointers** (3Sum, closest pair).
- **Merging intervals**: sort by start, then one pass.
- **Grouping**: sorted equal items sit next to each other.
- **Greedy choices**: meetings by end time, tasks by deadline (Day 8).

```python
def merge_intervals(iv: list[list[int]]) -> list[list[int]]:
    iv.sort(key=lambda x: x[0])
    out = []
    for start, end in iv:
        if out and start <= out[-1][1]:
            out[-1][1] = max(out[-1][1], end)
        else:
            out.append([start, end])
    return out
```

If an interviewer says "the input isn't sorted", ask yourself whether sorting it first would help.
