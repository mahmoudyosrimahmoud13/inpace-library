# Binary search

Binary search finds something in **sorted** data by halving the search space each step: O(log n). On a million items, that's about 20 checks.

## The template

```python
def search(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

Most binary search bugs are **off by one**: a loop that never ends, or misses the last element. Pick one template and use it every time.

## Find the first position where a condition becomes true

A more powerful version: in a range where a condition goes `False, False, ..., True, True`, find the first `True`.

```python
def first_true(lo: int, hi: int, ok) -> int:
    # smallest x in [lo, hi] with ok(x) True; returns hi + 1 if none
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid - 1
        else:
            lo = mid + 1
    return lo
```

Python's `bisect` module does this for sorted lists:

```python
import bisect
bisect.bisect_left(a, x)    # first index with a[i] >= x
bisect.bisect_right(a, x)   # first index with a[i] > x
```

## Binary search on the answer

Many problems don't look like searching. But if you can ask "**is answer X good enough?**", and the answer flips from no to yes only once as X grows, you can binary search X.

Koko eats bananas: piles `[3, 6, 7, 11]`, `h = 8` hours. Smallest eating speed `k` to finish in time?

```python
import math

def min_speed(piles: list[int], h: int) -> int:
    def fast_enough(k: int) -> bool:
        return sum(math.ceil(p / k) for p in piles) <= h
    return first_true(1, max(piles), fast_enough)
```

Speeds from 1 to max(piles); checking each costs O(n); total O(n log max). Without the binary search, O(n · max).

## Rotated sorted arrays

`[4, 5, 6, 7, 0, 1, 2]`: at any `mid`, **one half is sorted**. Check whether the target lies in the sorted half; if so, search there, otherwise search the other half. Still O(log n).

## Spotting it

- The input is sorted, or "rotated sorted".
- "Find the minimum / maximum X such that..." with a yes/no check.
- n is huge (10⁹), so you can't try every value.
