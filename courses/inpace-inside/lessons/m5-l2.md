# Verified exams

A checker can send a learner an exam the learner can't prepare for by memorising the library's answers.

1. The checker picks questions (including **private questions** only the checker has).
2. `exam.new_seed()` makes a random seed (`secrets.token_hex(8)`).
3. The order of questions and options comes **only from the seed**, using SHA-256 ranks:

```python
def _rank(*parts):
    return sha256_hex("\x1f".join(parts).encode("utf-8"))

for qid in sorted(question_ids, key=lambda q: _rank(seed, "order", q)): ...
```

Any app following SPEC.md rebuilds the exact same exam from the same seed. The learner's answers come back in the
approval/exam result flow, checked against the checker's own answer key.

## Why deterministic?

So the exam is reproducible and verifiable: the checker can rebuild what the learner saw and grade it without
trusting the learner's copy. In an interview: "deterministic randomness from a seed" is a pattern used in games,
tests and distributed systems.
