# Tests, CI, releases and safe updates

## Tests

About 150 pytest tests use Starlette's `TestClient` against a temporary vault: they click through the app as a
user would (`c.post("/island/buy", ...)`) and check pages and data. Platform quirks are tested by simulation (for
example removing `time.tzset` to act like Windows).

## CI

- `tests.yml`: Linux (Python 3.10, 3.12, 3.13), Windows and Mac on every push.
- `release.yml`: a version tag builds the three desktop apps, **starts each one and checks the first page**,
  checks the app opens in its own window, then publishes the release with `SHA256SUMS`.
- `android.yml`: builds the signed APK and adds it to the same release.

## Safe auto-update

`updater.py` downloads the new build **and** `SHA256SUMS` from the same release, compares the hash, and only then
swaps files, keeping the old copy until the new one starts. A failed check means nothing is replaced.

## A real CI failure from this project

The release check piped the first page into `grep -q`. When the page grew, `grep -q` stopped reading early,
curl got a broken pipe (exit 23), and the build failed although the app was fine. The fix: save the page to a
file first, then search it. Good interview story about **false failures** in pipelines.
