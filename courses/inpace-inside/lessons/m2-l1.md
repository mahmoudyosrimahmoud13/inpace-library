# vault.db: the tables and the append-only rule

Open `inpace/vault.py` and read `SCHEMA`. The important tables:

| Table | What it holds |
|---|---|
| `meta` | Key/value settings: name, language, avatar, island state, reminders (JSON) |
| `journeys` | One row per course you started (`archived=1` when you restart it) |
| `events` | Everything you did: lessons, uploads, quizzes, reflections, reviews |
| `milestones` | Your signed, chained milestones |
| `people` | Your checkers and the learners you check (with their turtle and island) |
| `received`, `receipts`, `approvals` | Files from learners, your decisions, decisions you got |
| `review_cards` | Spaced review (Leitner boxes) |
| `races`, `race_updates`, `race_cheers` | Races between friends |
| `garden` | Tempo's island: focus trips and plants |

## Append-only, enforced by the database

```sql
CREATE TRIGGER IF NOT EXISTS events_no_update BEFORE UPDATE ON events
BEGIN SELECT RAISE(ABORT, 'events are append-only'); END;
CREATE TRIGGER IF NOT EXISTS events_no_delete BEFORE DELETE ON events ...
```

The same triggers protect `milestones`. Even a bug in the app can't rewrite history: SQLite refuses. To "undo"
something you add a new event. This is the **event sourcing** idea in miniature.

## Migrations without a migration tool

New columns arrive with a small check at start-up:

```python
cols = {r[1] for r in self.db.execute("PRAGMA table_info(people)")}
if "island" not in cols:
    self.db.execute("ALTER TABLE people ADD COLUMN island TEXT DEFAULT ''")
```

Simple, safe to run every time, and enough for a single-user database.
