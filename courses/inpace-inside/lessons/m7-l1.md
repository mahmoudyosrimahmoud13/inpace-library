# One app, every platform

## Desktop

`__main__.py` starts Uvicorn in a thread and opens a **pywebview** window (WebView2 on Windows, WKWebView on Mac,
GTK WebKit on Linux). If that fails, it opens your browser. A second launch finds the first through `/ping` and
just brings it forward.

**PyInstaller** (`packaging/build.py`) freezes Python, the app and its data (`templates`, `static`, sample courses,
locales) into: a Windows zip, a Mac `.dmg` and a Linux `.tar.gz` and `.deb`.

## Android

`mobile/` is a **Flutter** app whose main screen is a WebView. `serious_python` packages the same `inpace` folder
and runs it on a free port. A JavaScript channel (`InPaceAndroid`) bridges what a WebView can't do alone: saving and
sharing files, picking folders, notifications, the trip countdown. The page script detects the bridge and adds the
`android` class.

Trade-off to name in an interview: a WebView UI is less "native", but one codebase serves five platforms, and
features ship everywhere on the same day.
