# The island's data and rules

## Focus trips

A trip is a row in `garden` with a `goal` (minutes), `banked` seconds and `run_from` (when it started running).
Elapsed time = `banked + (now - run_from)` while running. The **server decides** when it's done (`check()`), so
closing the app loses nothing. "Phone down" mode pauses when the trip screen is hidden (`sendBeacon` to
`/island/pause`).

## Computed, not stored

Shells are **computed from your data** every time (focus minutes, lessons, reviews, modules, milestones,
approvals, finished courses, course chests). Only what you **spent** and **own** is stored. The same idea as
progress-from-events: no number can drift.

## The villain's rules

`decay()` works out what happened during an absence from the last activity to now, so it gives the same
result whenever it runs:

| Days away | Effect |
|---|---|
| 10 | first plant wilts, friends flee |
| every 2 more | one more plant wilts |
| wilting + 14 | that plant dies |
| any finished trip | waters 2 wilting plants, friends return |

## Counting each course once

`course_rewards()` groups started courses by their **fingerprint** (the same course installed twice is one),
counts lessons as `(course, lesson)` pairs across every restart, and stores opened chests in `meta`, so chests stay
open even if a course later gets longer. A classic "idempotency and de-duplication" question.
