# Files and links

Everything people exchange is a small JSON file with `"inpace": "<kind>"`:

| Kind | From → to | Carries |
|---|---|---|
| `contact` | anyone → anyone | id, name, colour (signed), turtle and island (extras) |
| `progress` | learner → checker | learner, journey, milestones (all, or only the new ones after `since`), outline |
| `approval` | checker → learner | signed decisions per milestone, a note, exam results, file requests |
| `exam` | checker → learner | a verified exam (Day 5, lesson 2) |
| `race`, `race_update` | between racers | race rules and scores |

## Links instead of files

Small files travel as a link: `https://mahmoudyosrimahmoud13.github.io/inPace/open#BODY` (or `inpace://open/BODY`),
where BODY is the compact JSON, **zlib-compressed**, in **URL-safe base64 without padding**. The part after `#`
never reaches the website's server: the page just hands it to the app.

## Progress updates stay small

The first progress file has every milestone and the course outline. Later ones send only milestones after
`since`; the checker side (`complete_progress`) joins them with the stored copy and checks the **whole** chain
again. Nothing is taken on trust.
