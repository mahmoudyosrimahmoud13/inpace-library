# One video player for files and YouTube, and an ad guard you can update

## 1. Making YouTube behave like a `<video>`

**Problem:** video files used inPace's own player (big play button, ±10 s, speed, subtitles, full screen,
keyboard keys, remembers where you stopped). YouTube used YouTube's player, with its title bar, logo and
"More videos" panel. Two different players in one app.

**Choice: an adapter.** The file player became one function, `inpacePlayer(box, media)`, that only needs
something that *acts like* a video element. For YouTube, `YouTubeMedia` extends `EventTarget` and implements the
same surface:

| `<video>` part | `YouTubeMedia` does |
|---|---|
| `play()`, `pause()` | posts `playVideo` / `pauseVideo` to the iframe |
| `currentTime = t` | posts `seekTo [t, true]` |
| `volume`, `muted`, `playbackRate` | `setVolume`, `mute`/`unMute`, `setPlaybackRate` |
| `timeupdate`, `play`, `pause`, `ended`, `loadedmetadata` | fired from YouTube's `infoDelivery` messages |
| `textTracks` | one fake track whose `mode` loads or unloads YouTube's captions |

All of it goes through `postMessage` with YouTube's documented message format, with **no extra script** loaded
from Google. The embed uses `controls=0`, and a transparent cover over the iframe catches clicks, so YouTube's own
interface never appears. When paused, the cover shows the video's still picture instead of YouTube's pause screen.

**Interview point:** this is the *adapter pattern*. One player, many sources; the player didn't learn about
YouTube at all.

## 2. Quality: when the API says no

YouTube's `setPlaybackQuality` has done nothing since 2019. But YouTube chooses quality from the **size of its
player**. So "1080p" draws the iframe at 1920×1080 and scales it down with a CSS `transform`; "Auto" leaves it
alone. **Honest limit:** on a slow connection YouTube can still go lower.

## 3. The ad guard

While an ad plays, YouTube reports **the ad's** time and length. Without care, the player would save "you stopped
at 0:12" in the middle of an ad, and the cover would hide the **Skip ad** button.

Rules (all in `YouTubeMedia._hear`):
- Until the lesson's video is confirmed (it reached the second we asked for, or it's longer than an ad, or the
  reported video id matches), nothing is saved and the bar doesn't move.
- A "video" noticeably shorter than the lesson, mid-way, is an ad.
- During an ad the player gets the class `yt-ad`: the cover and the bar step aside, the iframe takes clicks, and a
  label says "Ad: the lesson starts after it". **Nothing is blocked or skipped automatically.**

It's on by default, with a switch in Settings.

## 4. Rules that update like yt-dlp, safely

YouTube changes things. So the numbers behind the guard live in `site/youtube.json` on the website, and the app
fetches them once a day (`inpace/ytrules.py`). **Data only, never code:**

```python
RULES = {"own_controls": (True, None, None), "fallback_ms": (9000, 3000, 60000), "ad_guard": (True, None, None), ...}

def clean(raw) -> dict:   # only known names, right types, inside a safe range; else the default
```

And a last line of defence: if YouTube doesn't answer within `fallback_ms`, the lesson switches to YouTube's own
player at the same second.

**Interview point:** remote config is powerful and dangerous. Whitelist names, check types and ranges, keep the
last good copy, and make "the remote file is broken" a non-event.
