# Starlette, routes and page()

`create_app(vault)` builds everything inside one function, so every route can use `V` (the vault) without
globals. At the end:

```python
routes = [
    Route("/", home),
    Route("/learn/{jid}/lesson/{lid}", needs_setup(lesson)),
    Route("/island/buy", needs_setup(island_buy), methods=["POST"]),
    ...  # 112 routes
    Mount("/static", StaticFiles(directory=HERE / "static")),
]
return Starlette(routes=routes, middleware=[Middleware(NavMiddleware)])
```

## Small helpers that do a lot

- `needs_setup(fn)` sends you to `/setup` until you've made your identity.
- `page(name, request, **ctx)` adds the shared context and renders a template. It also runs cheap
  "while we're here" jobs: the island's `decay()`, the news pop-up, reminders' `touch()`.
- `go(url, ok=..., err=..., yay=...)` makes a 303 redirect with a message in the query (before any `#`).
- `download(data, filename, mime)` sends a file with a safe `Content-Disposition`.

## Why Starlette and not Django or Flask?

Starlette is ASGI and tiny. There is one user, no ORM is needed (SQLite with plain SQL is clearer), and the
app must start fast inside a frozen desktop binary and on a phone. FastAPI would add Pydantic and OpenAPI that
an HTML app doesn't need. (Days 4-5 of the FastAPI & Starlette course go deeper.)
