# The CI workflow: lint, test, build

A good CI run is **fast** (under ~10 minutes), **reliable** (no flaky tests) and **tells you exactly what broke**.

```yaml
name: ci
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: "3.12", cache: pip}
      - run: pip install ruff && ruff check . && ruff format --check .
  test:
    needs: lint
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python: ["3.11", "3.12"]
    services:
      postgres:
        image: postgres:16
        env: {POSTGRES_PASSWORD: test}
        ports: ["5432:5432"]
        options: --health-cmd pg_isready --health-interval 5s --health-retries 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: "${{ matrix.python }}", cache: pip}
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: pytest -q --junitxml=report.xml
        env: {DATABASE_URL: "postgresql://postgres:test@localhost:5432/postgres"}
      - uses: actions/upload-artifact@v4
        if: always()
        with: {name: "test-report-${{ matrix.python }}", path: report.xml}
```

## What makes it fast

- **Cache** dependencies (`cache: pip`, `actions/cache`, Docker layer cache).
- **Fail fast**: cheap checks (lint, type check) first; `needs:` stops later jobs.
- **Run in parallel**: matrix, and split slow test suites.
- **Cancel superseded runs** with `concurrency`.
- **Path filters** (`on.push.paths`) in monorepos so docs changes don't run the whole suite.

## Flaky tests

A test that fails randomly teaches everyone to ignore red builds, which defeats CI. Quarantine it, fix it, or delete it. Never just add retries and forget.
