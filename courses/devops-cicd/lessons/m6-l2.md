# Measuring delivery: DORA and post-deploy checks

## Collect the four DORA metrics

| Metric | Data you need |
|---|---|
| Deployment frequency | Deploy events (GitHub deployments API, pipeline runs to prod) |
| Lead time for changes | Commit time -> production deploy time |
| Change failure rate | Deploys followed by a rollback, hotfix or incident |
| Time to restore | Incident start -> resolved |

```bash
gh api repos/acme/shop/deployments --jq '.[] | select(.environment=="production") | .created_at' | head
```

Start with a spreadsheet updated weekly; tools (DORA's Four Keys, Sleuth, LinearB, GitLab's value stream analytics) come later. Use them to improve the **system**, never to rank people.

## Automatic post-deploy verification

Don't stop at "the deploy job succeeded". Check that users are OK:

```bash
#!/usr/bin/env bash
set -euo pipefail
url=$1
for i in $(seq 1 10); do
  code=$(curl -s -o /dev/null -w '%{http_code}' "$url/health")
  [ "$code" = 200 ] && break
  sleep 6
done
[ "$code" = 200 ] || { echo "health failed: $code"; exit 1; }
curl -fsS "$url/api/products?limit=1" | jq -e '.items | length == 1' >/dev/null
echo "smoke ok"
```

Then for 10-15 minutes, watch **error rate and latency** compared with before the deploy (Observability course). Canary tools do this comparison automatically and roll back on their own.

## Deploy notifications

Post to the team channel: what changed (PR titles), who, which digest, link to the dashboard. When something breaks, "what changed?" is answered in seconds.
