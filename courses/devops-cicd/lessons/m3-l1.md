# Artifacts and container images

**Build once, deploy the same thing everywhere.** The image tested in CI is exactly the image that runs in staging and production; only configuration changes.

```yaml
  image:
    needs: test
    runs-on: ubuntu-latest
    permissions: {contents: read, packages: write}
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: {registry: ghcr.io, username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}"}
      - uses: docker/metadata-action@v5
        id: meta
        with:
          images: ghcr.io/${{ github.repository }}
          tags: |
            type=sha,format=long
            type=semver,pattern={{version}}
            type=ref,event=branch
      - uses: docker/build-push-action@v6
        with:
          push: ${{ github.event_name == 'push' }}
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

## Tagging

| Tag | Use |
|---|---|
| `sha-3f2c1ab...` | **What you deploy**: immutable, traceable to a commit |
| `v1.4.2` | Human-friendly release |
| `main`, `latest` | Convenience only; **never deploy by `latest`**: you can't tell what's running or roll back reliably |

Even better: deploy by **digest** (`image@sha256:...`), which can't be re-pointed.

## Registries

GitHub Container Registry (ghcr.io), Amazon ECR, Docker Hub, GitLab registry. Set **lifecycle rules** to delete old untagged images, and turn on scan-on-push where available.

## Non-container artifacts

Wheels, jars, binaries, static site bundles: upload them as **release assets** or to an artifact store (S3, GitHub Packages), named with the version and a checksum (`sha256sum`).
