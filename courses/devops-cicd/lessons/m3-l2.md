# Supply chain: SBOMs and signed images

Attacks now target the **pipeline** itself: a poisoned dependency, a hijacked GitHub Action, a swapped image in a registry. Three defences:

## 1. Know what's inside: SBOM

A **Software Bill of Materials** lists every package in your image or app (SPDX or CycloneDX format). When the next big vulnerability lands, you search your SBOMs instead of guessing.

```bash
syft ghcr.io/acme/shop@sha256:abc... -o cyclonedx-json > sbom.json
trivy sbom sbom.json                 # scan the SBOM later without rebuilding
```

## 2. Prove who built it: signing

**Sigstore cosign** signs images with **keyless** signing: the CI job's OIDC identity is the signature, so there's no private key to steal.

```yaml
      - uses: sigstore/cosign-installer@v3
      - run: cosign sign --yes ghcr.io/acme/shop@${{ steps.build.outputs.digest }}
        # needs: permissions: id-token: write
```

```bash
cosign verify ghcr.io/acme/shop@sha256:abc... \
  --certificate-identity-regexp 'https://github.com/acme/shop/.github/workflows/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Clusters can refuse unsigned images (Kyverno, Sigstore policy-controller).

## 3. Provenance

**SLSA provenance** records how, where and from which commit an artifact was built. GitHub's `actions/attest-build-provenance` creates it; `gh attestation verify` checks it.

You don't need all of this on day one. Order of value: pin and update dependencies, scan, then SBOM, then signing.
