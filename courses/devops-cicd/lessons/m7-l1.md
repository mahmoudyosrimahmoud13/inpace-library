# Hardening the pipeline itself

Your pipeline has the keys to production. Treat it like production.

| Risk | Defence |
|---|---|
| A third-party action gets hijacked | **Pin actions by full commit SHA**, not `@v4` (tags can move). Dependabot updates the SHAs |
| `GITHUB_TOKEN` can do too much | Top-level `permissions: contents: read`, widen per job only as needed |
| PRs from forks run your code with secrets | Use `pull_request` (no secrets for forks); avoid `pull_request_target` with checkout of PR code |
| Script injection from PR titles/branch names | Never put `${{ github.event.pull_request.title }}` directly into `run:`; pass via `env:` and quote |
| Self-hosted runners keep state between jobs | Ephemeral runners, never on public repos |
| Someone edits the workflow to deploy | Protect `.github/workflows` with CODEOWNERS; environments with required reviewers |

```yaml
permissions:
  contents: read
jobs:
  build:
    permissions:
      contents: read
      packages: write
      id-token: write
    steps:
      - uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2
      - name: Greet PR safely
        env:
          TITLE: ${{ github.event.pull_request.title }}
        run: echo "PR title: $TITLE"
```

## Audit tools

- **OpenSSF Scorecard**: rates your repo's security practices.
- **zizmor** / **actionlint**: find dangerous workflow patterns and mistakes.
- GitHub settings: require SHA pinning for actions (org policy), restrict which actions are allowed.
