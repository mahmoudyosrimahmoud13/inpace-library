# Sampling: temperature, top-k and top-p

The model gives a score (a **logit**) for every token in its vocabulary. Softmax turns scores into probabilities, and a **sampler** picks one. The sampler's settings change the output a lot.

```python
import numpy as np

def softmax(z):
    z = z - z.max()
    e = np.exp(z)
    return e / e.sum()

tokens = [" Cairo", " Alexandria", " Giza", " a", " the"]
logits = np.array([5.0, 3.0, 2.5, 1.0, 0.5])

for t in [0.2, 1.0, 2.0]:
    p = softmax(logits / t)
    print(f"temperature {t}:", dict(zip(tokens, p.round(3).tolist())))

def top_p_filter(p, top_p):
    order = np.argsort(-p)
    keep = np.cumsum(p[order]) - p[order] < top_p        # keep tokens until the mass reaches top_p
    q = np.zeros_like(p)
    q[order[keep]] = p[order[keep]]
    return q / q.sum()

p = softmax(logits)
print("top-p 0.9 keeps:", [tokens[i] for i in np.flatnonzero(top_p_filter(p, 0.9))])
rng = np.random.default_rng(1)
print("a sample:", tokens[rng.choice(len(tokens), p=top_p_filter(p, 0.9))])
```

## The settings

| Setting | What it does | Use |
|---|---|---|
| **Temperature** | divides the logits before softmax. Low makes the top token dominate; high flattens the distribution | 0 to 0.3 for extraction, code, classification, evals; 0.7 to 1 for creative writing |
| **Greedy** (temperature 0) | always the most likely token | repeatable outputs (mostly: tiny numeric differences on GPUs can still vary results) |
| **Top-k** | sample only from the k most likely tokens | cuts off the long tail of unlikely tokens |
| **Top-p** (nucleus) | sample from the smallest set whose probabilities add up to p | adapts: few options when the model is sure, more when it isn't |
| **Max tokens** | stops generation after a limit | controls cost and runaway answers |
| **Stop sequences** | stops when a given string appears | ends output at a known marker |

## Why randomness at all?

Always picking the top token tends to produce repetitive, flat text, and for creative tasks you want variety. For anything a program will parse or a test will check, keep temperature low, and still validate the output: low temperature makes a model consistent, not correct.

Note that reasoning models and some newer APIs fix or limit these settings; check the documentation of the model you use.
