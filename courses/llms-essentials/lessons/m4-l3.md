# Project 4: sampling settings and a KV cache

You'll generate text from the trained model with five sampling settings, and make generation faster with a KV
cache.

The code is above this text. Save it as `p4_generate.py`. It needs `tinygpt.pt` from project 3.

## Read the code

- **`generate()`** adds one token at a time. Each step divides the last position's scores by the **temperature**,
  optionally keeps only the **top k** tokens, or the smallest set of tokens whose probabilities add up to **top p**,
  then samples. Temperature 0 means always take the most likely token (greedy).
- **The KV cache**: without it, every new token runs the model over the whole text again. With it, each attention
  layer keeps the keys and values it already computed (the `cache` dictionary in `gpt.py`), and only the newest
  token goes through the model. The `start` argument keeps position numbers right.
- The main part prints five continuations of `JULIET: O Romeo,` (same seed), checks that the cache gives exactly the
  same greedy text, and times both.

## Run it

```bash
python p4_generate.py
```

The real output:

```text
The model from project 3 (validation loss 3.18). Prompt: 'JULIET:\nO Romeo,'

greedy (temperature 0):
   "JULIET:\nO Romeo, what's the crown?\n\nNurse:\nI am a word to better thanks.\n\nJULIET:\nI am a word to"

temperature 0.7:
   'JULIET:\nO Romeo, that this service ofd live!\n\nNurse:\nI die, his liege, fortune\nThat thou shalt begsest'

temperature 1.5:
   'JULIET:\nO Romeo, that this soundly this ods come shore in ere.\n\nROMEO: liin, then, see!\n\nROMEEO:\nO first'

temperature 1.0, top-k 20:
   'JULIET:\nO Romeo, that foreerly set up ours:\nI had even in the duke issue, that you are\nAnd full of me to touch his'

temperature 1.0, top-p 0.9:
   "JULIET:\nO Romeo, that this service will go:\nHer you had even in the duke is lips'd,\nAnd brought him for he shall look on his"

With and without the KV cache, greedy output is identical: True
   without KV cache: 2.9 ms per token
   with KV cache: 1.8 ms per token
```

What it shows:

- **Greedy decoding loops**: "I am a word to" comes back. Always taking the single most likely token often repeats.
- **Temperature 0.7** is varied and still mostly words. **1.5** falls apart ("ROMEEO", "liin").
- **Top-k and top-p** cut off the unlikely tail, so they can sample at temperature 1 and stay readable.
- **The cache gives identical output and is faster.** Here the gain is small (the window is only 128 tokens and the
  model tiny); with long contexts and big models it's the difference between usable and not, at the cost of memory
  for all those keys and values.

## Make it yours

1. Sample 10 times at temperature 0.7 with different seeds. How often is a line a real-looking speech?
2. Combine top-k 40 with temperature 0.8. Is it better than either alone?
3. Measure the cache's memory: count the numbers stored in all `cache["k"]` and `cache["v"]` after 100 tokens, and
   work out how it grows with layers, heads and length.

## What to take away

- Sampling settings trade safety (greedy, low temperature) for variety (higher temperature, top-p).
- A KV cache saves recomputation and costs memory.
