# Project 1: a tokenizer of your own

From today to day 5 you build **TinyGPT**: a small language model trained from scratch on Shakespeare, one piece a
day. Today, the tokenizer: the part that turns text into the numbers a model reads.

The project folder is above this text. Save all its files in one folder. You need Python 3.10 or newer and, from
day 2, PyTorch (`pip install torch`; the CPU version is enough). `shakespeare.txt` is Andrej Karpathy's Tiny
Shakespeare: about 40,000 lines from the plays (public domain).

## Read the code

- **`SPLIT`** first cuts the text into words, numbers and punctuation, each with its leading space, so merges never
  cross a word boundary (GPT-2 does the same).
- **`BPE.train()`** starts with the 65 characters of the text as tokens. Then, again and again: count every pair of
  neighbouring tokens across all words (weighted by how often each word appears), merge the most frequent pair into
  a new token, and repeat until the vocabulary has 512 tokens.
- **`encode()`** applies the merges to new text, in the order they were learned; **`decode()`** joins the tokens
  back. `save()` and `load()` keep the merges in `tokenizer.json`, which every later project loads.

## Run it

```bash
python p1_tokenizer.py
```

The real output:

```text

3. The whole text: 1,115,394 characters -> 509,633 tokens (2.19 characters per token)
   'the'            -> ['t', 'he']
   ' the'           -> [' the']
   'Romeo'          -> ['R', 'ome', 'o']
   ' Juliet'        -> [' ', 'J', 'ul', 'i', 'et']
   ' unbelievable'  -> [' un', 'b', 'el', 'ie', 'v', 'a', 'ble']
   ' computer'      -> [' com', 'p', 'ut', 'er']
   round trip on the whole text: True
   saved tokenizer.json
```

What it shows:

- The first merges are the commonest pieces of English: `' t'`, `'he'`, `' a'`, and soon `' the'`.
- **Common words become one token** (`' the'`, `' thee'`, `' day'`); **rare ones are split** (`' Juliet'` into five,
  `' computer'` into four, a word Shakespeare never used).
- **The leading space matters**: `'the'` and `' the'` are different tokens. That's why models are sensitive to spaces.
- Shakespeare becomes 2.19 characters per token. Real tokenizers have 50,000 to 200,000 tokens and get about 4
  characters per token in English.
- Encoding then decoding gives back the exact text.

## Make it yours

1. Train with 256 and 2,048 tokens. How do the characters per token change, and the training time?
2. Encode a sentence in another language. How many tokens does it take compared with English? What does that mean
   for cost and context length?
3. Compare with a real tokenizer: `pip install tiktoken`, then encode the same sentence with `cl100k_base`.

## What to take away

- BPE builds a vocabulary by merging the most frequent pairs.
- Common text is cheap in tokens, rare text expensive.
