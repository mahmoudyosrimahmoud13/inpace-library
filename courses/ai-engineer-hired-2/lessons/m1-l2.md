# How you're scored

Interviewers don't only check if your code works. The [Tech Interview Handbook's rubric page](https://www.techinterviewhandbook.org/coding-interview-rubrics/) describes four areas used across top companies:

| Area | Strong signal | Weak signal |
|---|---|---|
| **Communication** | the interviewer follows your thinking without asking | jumping into code without explaining; silence |
| **Problem solving** | clarifying questions, a systematic approach, an optimal solution, correct complexity, few hints | needing many hints; a disorganized approach |
| **Technical competency** | working, clean code with few bugs; good use of the language | many syntax errors; can't turn the idea into code |
| **Testing** | walks through examples, finds corner cases, fixes own bugs | declares "done" without testing |

Each interviewer gives a band: strong hire, hire, no hire, strong no hire. A phone screen has one interviewer, so one weak round there ends the process; in the full loop, mixed results are discussed. **A correct solution with silent, untested code can still fail.** A good conversation that reaches a near-optimal solution often passes.
