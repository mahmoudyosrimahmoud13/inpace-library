# Project TinyKV, step by step

Build a small key-value store in four levels, exactly like the interview version. Put it on GitHub as `tinykv` with the tests below. Level 1 is given; write levels 2 to 4 yourself, one at a time, with all tests passing before you move on. Time yourself: aim for 20 minutes per level.

```python
# tinykv.py: level 1
import time


class TinyKV:
    def __init__(self, clock=time.time, path=None):
        self.clock = clock
        self.path = path
        self.data = {}

    def set(self, key, value, ttl=None):
        self.data[key] = value

    def get(self, key):
        return self.data.get(key)

    def delete(self, key):
        return self.data.pop(key, None) is not None
```

## The levels

1. **Basics:** `set`, `get` (None when missing), `delete` (True if it existed).
2. **Expiry and scan:** `set(key, value, ttl=seconds)`; an expired key behaves as missing. `scan(prefix)` returns the live keys with that prefix, sorted. Take time from `self.clock` so tests can control it.
3. **Transactions:** `begin()`, `commit()`, `rollback()`, and they nest. `rollback` undoes only the innermost open transaction; with none open it raises `RuntimeError`.
4. **Persistence:** with `path`, every change that's final (outside a transaction, or on the outermost commit) is appended to a log file; a new `TinyKV(path=...)` replays it. Rolled-back changes are never written.

```python
# test_tinykv.py
import pytest
from tinykv import TinyKV


class FakeClock:
    def __init__(self):
        self.now = 1000.0

    def __call__(self):
        return self.now


def test_level1_basics():
    kv = TinyKV()
    kv.set("a", 1)
    assert kv.get("a") == 1
    assert kv.get("missing") is None
    assert kv.delete("a") is True
    assert kv.delete("a") is False


def test_level2_ttl_and_scan():
    clock = FakeClock()
    kv = TinyKV(clock=clock)
    kv.set("user:1", "Mona", ttl=10)
    kv.set("user:2", "Omar")
    kv.set("order:9", "tea")
    assert kv.scan("user:") == ["user:1", "user:2"]
    clock.now += 10                       # expires exactly at 10 seconds
    assert kv.get("user:1") is None
    assert kv.scan("user:") == ["user:2"]


def test_level3_nested_transactions():
    kv = TinyKV()
    kv.set("a", 1)
    kv.begin()
    kv.set("a", 2)
    kv.begin()
    kv.delete("a")
    assert kv.get("a") is None
    kv.rollback()                         # undo the inner transaction only
    assert kv.get("a") == 2
    kv.commit()
    assert kv.get("a") == 2
    with pytest.raises(RuntimeError):
        kv.rollback()                     # nothing open


def test_level4_persistence(tmp_path):
    path = tmp_path / "data.log"
    kv = TinyKV(path=path)
    kv.set("a", 1)
    kv.set("b", 2)
    kv.delete("a")
    kv.begin()
    kv.set("c", 3)
    kv.rollback()                         # never written
    again = TinyKV(path=path)
    assert again.get("a") is None
    assert again.get("b") == 2
    assert again.get("c") is None
```

## Design questions to answer in your README

- Expired keys: do you delete them when read (lazy) or in the background? What does each cost?
- Transactions: do you keep an undo log or a copy of the data? Which is cheaper for big stores?
- The log grows forever: how would you compact it?
