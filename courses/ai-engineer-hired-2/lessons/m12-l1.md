# What implementation rounds test

In these 45 to 90 minute rounds you build a small system, and the interviewer adds requirements level by level. The [field guide](https://github.com/alexeygrigorev/ai-engineering-field-guide) lists real examples: a key-value database starting from SET/GET/DELETE, a website crawler, an in-memory database with SQL-like operations, a Unix `cd` with symbolic links, a credits system with expiry rules, and refactoring 100+ lines of tangled code.

## How to do well

1. **Pin down the interface** first: function names, inputs, outputs, errors.
2. **Build the simplest level that works**, with a quick test, before thinking about the next.
3. **Keep the code easy to change**: small methods, one responsibility each. The guide's most common mistake is rigid code that breaks when the follow-up arrives.
4. **Before each new level, refactor** if the design fights you, and say why.
5. **Talk trade-offs** out loud: memory against speed, simplicity against flexibility.
