# Binary search and linked lists

## Binary search, and binary search on the answer

Binary search works on anything **monotonic**: a sorted array, or a yes/no question that flips once ("can she eat all bananas at speed k?" is no, no, ..., yes, yes). Search for the first *yes*:

```python
import math

def min_eating_speed(piles, h):
    lo, hi = 1, max(piles)
    while lo < hi:                     # the answer is in [lo, hi]
        mid = (lo + hi) // 2
        if sum(math.ceil(p / mid) for p in piles) <= h:
            hi = mid                       # mid works: maybe smaller works too
        else:
            lo = mid + 1                   # too slow
    return lo
```

Keep one invariant ("the answer is in [lo, hi]") and the loop ends exactly on it. Most binary search bugs are an infinite loop from `lo = mid` with `mid` rounding down: with `while lo < hi`, use `hi = mid` and `lo = mid + 1`.

## Linked lists

Three tricks cover most problems: a **dummy head** (no special case for the first node), **reversing** in place, and **fast/slow pointers** (the middle, cycles, the k-th from the end).

```python
def reverse(head):
    prev = None
    while head:
        nxt = head.next
        head.next = prev
        prev, head = head, nxt
    return prev


def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```

**LRU Cache** is a favourite because it combines two structures: a dict for O(1) lookup and a doubly linked list (or `collections.OrderedDict` with `move_to_end`) for O(1) recency updates. Be ready to build the linked list yourself if asked not to use OrderedDict.
