# 20 سؤالًا تتكرر في المقابلات

جاوب بصوت عالٍ أولًا، ثم اقرأ الإجابة المختصرة.

1. **ما الفرق بين الحاوية والآلة الافتراضية؟** الحاوية تشترك في نواة المضيف؛ الـ VM فيها نظام تشغيل كامل.
2. **ما الـ namespaces والـ cgroups؟** العزل وتحديد الموارد.
3. **image مقابل container؟** قالب للقراءة مقابل نسخة تعمل.
4. **CMD مقابل ENTRYPOINT؟** وسائط افتراضية مقابل البرنامج الثابت.
5. **COPY مقابل ADD؟** COPY للنسخ فقط؛ ADD يفك الضغط ويقبل روابط.
6. **كيف تصغر image؟** multi-stage، image أساس صغيرة، .dockerignore، تنظيف الكاش في نفس RUN.
7. **كيف تحفظ البيانات؟** volumes.
8. **كيف تتكلم الحاويات؟** شبكة يعرّفها المستخدم مع DNS بالأسماء.
9. **ما الـ build cache؟** إعادة استخدام الطبقات حتى أول تعليمة تغيرت.
10. **لماذا لا تشغل كـ root؟** أي ثغرة تعطي صلاحيات أكبر.
11. **Compose مقابل Swarm مقابل Kubernetes؟** جهاز واحد؛ cluster بسيط؛ منصة كاملة غنية.
12. **Pod؟** أصغر وحدة: حاوية أو أكثر تتشارك الشبكة.
13. **Deployment؟** يدير النسخ والتحديثات والرجوع.
14. **أنواع الـ Service؟** ClusterIP، NodePort، LoadBalancer (وExternalName).
15. **ConfigMap مقابل Secret؟** إعدادات عادية مقابل حساسة (Secret مشفر بـ base64 فقط افتراضيًا؛ فعّل التشفير في etcd).
16. **liveness مقابل readiness probe؟** هل أعيد تشغيلها؟ هل أرسل لها طلبات؟
17. **ما الذي يحدث عند OOMKilled؟** الحاوية تجاوزت حد الذاكرة فقتلت.
18. **CrashLoopBackOff؟** الحاوية تقع وتعود مرارًا: افحص `kubectl logs --previous` و`describe`.
19. **Ingress؟** توجيه HTTP من الخارج حسب الاسم والمسار.
20. **كيف تنشر بلا توقف؟** rolling update مع readiness probes، أو blue/green أو canary.

## سؤال تصميم

> "صمم نشر تطبيق ويب مع قاعدة بيانات على Kubernetes."

Deployment للتطبيق بـ 3 نسخ مع readiness/liveness، وService وIngress أمامه. قاعدة البيانات خدمة مُدارة
(أفضل) أو StatefulSet مع PersistentVolume. الإعدادات في ConfigMap والأسرار في Secret. HPA للتكبير التلقائي،
وrequests/limits لكل حاوية، وCI يبني الـ image ويرفعها ثم يحدّث الـ Deployment.
