# Which rule wins

When several rules set the same property, the browser decides in this order:

1. **Origin and importance**: user-agent styles < your styles < `!important` (avoid it).
2. **Cascade layers** (`@layer`), if used.
3. **Specificity**: inline style > id > class/attribute/pseudo-class > element/pseudo-element.
4. **Order**: the later rule wins when everything else is equal.

Specificity is counted as (ids, classes, elements):

| Selector | Specificity |
|---|---|
| `p` | 0,0,1 |
| `.card p` | 0,1,1 |
| `.isle-scene > svg` | 0,1,1 |
| `#main .card` | 1,1,0 |
| `:where(.card) p` | 0,0,1 (`:where` counts as zero) |

## A real inPace bug

The share icon on the island page was huge. The rule `.isle-scene svg { width: 100% }` matched **every** SVG
inside the scene, including the small icon in the share button. The fix was `.isle-scene > svg`: only the direct
child. Selectors that are too wide are a classic source of "why is this element styled like that?". DevTools'
**Computed** panel shows which rule won and why.

## Inheritance

Text properties (`color`, `font-*`, `line-height`, `direction`) inherit; box properties (`margin`, `border`,
`width`) don't. `inherit`, `initial`, `unset` and `revert` control it.
