# Meaningful elements

Semantic elements say **what** something is, not how it looks:

| Element | Meaning |
|---|---|
| `<header>`, `<nav>`, `<main>`, `<footer>` | Landmarks screen readers can jump between |
| `<article>`, `<section>` | A self-contained item; a themed group with a heading |
| `<h1>`-`<h6>` | The outline of the page; don't skip levels for looks |
| `<button>` | Does something. Focusable and works with Enter and Space for free |
| `<a href>` | Goes somewhere |
| `<ul>`, `<ol>`, `<li>` | Lists; screen readers announce "list, 5 items" |
| `<details>`/`<summary>` | A native show/hide, no JavaScript needed |
| `<dialog>` | A native modal with focus handling |
| `<figure>`/`<figcaption>`, `<time>`, `<progress>` | Exactly what they say |

## The most common interview mistake

`<div onclick="...">Save</div>` looks like a button but isn't one: no keyboard focus, no Enter key, no role. Use
`<button>`. Use a link when it **navigates**, a button when it **acts**.

inPace uses `<details>` for many folding panels (settings sections, lesson notes) and `<progress>` for course
progress.
