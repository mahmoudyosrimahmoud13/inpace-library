# Forms that work without JavaScript

```html
<form method="post" action="/learn/42/explain" data-nav-form>
  <label for="answer">Your answer</label>
  <textarea id="answer" name="text" required minlength="20"></textarea>

  <fieldset>
    <legend>How did it feel?</legend>
    <label><input type="radio" name="feel" value="easy"> Easy</label>
    <label><input type="radio" name="feel" value="hard"> Hard</label>
  </fieldset>

  <button>Send</button>
</form>
```

- `name` is what the server receives. No `name`, no value.
- `<label for>` links the text to the field: clicking the label focuses it, screen readers read it.
- Built-in validation: `required`, `minlength`, `pattern`, `type="email"`, `min`/`max`. Always validate on the server
  too: the browser's checks can be skipped.
- `method="post"` sends the body as `application/x-www-form-urlencoded`, or `multipart/form-data` when the form has
  `enctype="multipart/form-data"` (needed for files: `<input type="file" name="proof">`).
- A form posted with `GET` puts the fields in the URL: fine for search, wrong for anything that changes data.

## Progressive enhancement

inPace's forms are real forms that work with no JavaScript. `app.js` then **enhances** forms with `data-nav-form`:
it sends them with `fetch` and replaces the page, so they don't pile up in history. If the script fails, the form
still works. That's progressive enhancement, a favourite interview topic.
