# Scheduling policies: FCFS, SJF and Round Robin

The **scheduler** decides which ready process runs next. There's no single best answer, because there are two goals that pull against each other.

## Two ways to measure

- **Turnaround time** = when the job finished − when it arrived. Good for batch work.
- **Response time** = when the job first ran − when it arrived. Good for anything interactive.

## The classic policies

| Policy | Rule | Good at | Bad at |
|---|---|---|---|
| **FCFS** (first come, first served) | Run jobs in arrival order, to completion | Simple | One long job makes everyone wait (the *convoy effect*) |
| **SJF** (shortest job first) | Run the shortest job next | Best average turnaround if all jobs arrive together | Needs to know job lengths; long jobs can starve |
| **STCF** (shortest time to completion first) | Like SJF, but can preempt a running job when a shorter one arrives | Turnaround with late arrivals | Same: needs lengths, starvation |
| **Round Robin** | Run each job for a short time slice, then the next | Response time | Turnaround (everyone finishes late) |
| **Priority** | Highest priority first | Important work first | Low priority can **starve** |

## Work an example

Three jobs arrive at time 0: A needs 100 ms, B and C need 10 ms each.

```text
FCFS:  A........................................ B.... C....
       A done 100, B done 110, C done 120  -> average turnaround 110 ms

SJF:   B.... C.... A........................................
       B done 10, C done 20, A done 120     -> average turnaround 50 ms
```

Round Robin with 10 ms slices: A, B, C, A, A, A... B finishes at 20, C at 30, A at 120. Response time is great (everyone starts within 20 ms), turnaround is fine here, but with many equal jobs RR makes them **all** finish near the end.

## Time slice length

- Shorter slices: snappier response, more context switches (overhead).
- Longer slices: less overhead, laggier feel.
- Typical systems use slices of a few milliseconds.

## Preemption and starvation

- **Preemptive** schedulers can take the CPU away (needs the timer interrupt). Every modern general-purpose OS is preemptive.
- **Starvation** is when a ready job never runs. Fix it with **aging**: the longer a job waits, the higher its priority.
