# Signs of intrusion, and what to do

## Indicators worth checking

| Look for | How |
|---|---|
| Logins you don't recognize | `last -a`, `journalctl -u ssh | grep Accepted` |
| New users or keys | `/etc/passwd`, `/etc/group` changes; every `~/.ssh/authorized_keys` |
| Unknown processes or high CPU (crypto miners) | `ps auxf`, `top`; process names imitating kernel threads like `[kworker]` but with a real binary in `ls -l /proc/PID/exe` |
| Unexpected listening ports or outbound connections | `ss -tulpn`, `ss -tnp` |
| New cron jobs, timers, services | `crontab -l` for every user, `/etc/cron*`, `systemctl list-timers`, recently changed units |
| Changed system files | `debsums -c` (Debian) / `rpm -Va` (Red Hat); AIDE |
| Files in odd places | `find /tmp /var/tmp /dev/shm -type f -newer /etc/hostname` |
| Cleared or gappy logs | Missing time ranges in the journal |

## File integrity monitoring

**AIDE** records hashes of system files and reports changes:

```bash
sudo apt install aide
sudo aideinit                         # build the baseline (do this on a known-good system)
sudo aide --check                     # later: what changed?
```

Keep the baseline database off the server (or read-only) so an attacker can't just update it.

## If you think you've been breached

```mermaid
flowchart LR
  A["Don't panic, don't reboot"] --> B["Isolate: cut network or move to a quarantine security group"]
  B --> C["Preserve evidence: snapshot disk and memory, copy logs off"]
  C --> D["Find the way in and the scope"]
  D --> E["Rebuild from a clean image, rotate ALL secrets and keys"]
  E --> F["Patch the hole, then restore data from backups"]
```

- **Don't trust a compromised system to tell you the truth**: tools like `ps` and `ls` can be replaced. Investigate from a clean system using the disk snapshot.
- **Rebuild, don't clean.** You can never be sure you removed everything.
- Rotate every credential the machine could see: SSH keys, API tokens, database passwords, cloud keys.
