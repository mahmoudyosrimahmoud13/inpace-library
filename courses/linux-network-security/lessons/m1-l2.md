# Audit a server: what's exposed?

Before changing anything, find out what you have.

```bash
# What listens, on which addresses?
sudo ss -tulpn
#   0.0.0.0:6379 or [::]:6379  -> reachable from every network (bad for Redis!)
#   127.0.0.1:6379             -> this machine only

# Which services run and start at boot?
systemctl list-units --type=service --state=running
systemctl list-unit-files --state=enabled

# Who can log in?
awk -F: '$7 !~ /(nologin|false)$/ {print $1, $7}' /etc/passwd
getent group sudo wheel
sudo grep -rE '^[^#].*ALL' /etc/sudoers /etc/sudoers.d/

# Programs that run as root for anyone
find / -xdev -perm -4000 -type f 2>/dev/null

# Pending security updates
apt list --upgradable 2>/dev/null | grep -i security

# How the outside sees you (from another machine you own)
nmap -sV -Pn your.server.ip
```

## Read the results like an attacker

| Finding | Risk | Fix |
|---|---|---|
| Database or cache on `0.0.0.0` | Data stolen or wiped by bots within hours | Bind to `127.0.0.1` or a private IP, firewall it |
| Many users with a shell | More passwords and keys to steal | Remove or `nologin` unused accounts |
| `NOPASSWD: ALL` in sudoers | Any stolen account is root | Narrow rules |
| Old packages | Known, published exploits | Update, enable unattended upgrades |
| Unknown SUID binaries | Local privilege escalation | Remove the bit or the package |

## Automated audit

**Lynis** checks hundreds of settings and gives a hardening score with suggestions:

```bash
sudo apt install lynis
sudo lynis audit system
```

Treat its list as input, not orders: understand each item before you change it.
