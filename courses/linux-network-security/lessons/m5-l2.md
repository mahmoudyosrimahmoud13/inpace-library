# openssl in practice, mTLS and expiry

## Everyday openssl

```bash
# What does a remote server present?
openssl s_client -connect shop.example.com:443 -servername shop.example.com </dev/null 2>/dev/null |
  openssl x509 -noout -subject -issuer -dates -ext subjectAltName

# Inspect a certificate file
openssl x509 -in cert.pem -noout -text | less

# Does this key belong to this certificate? (the two hashes must match)
openssl x509 -noout -pubkey -in cert.pem | sha256sum
openssl pkey -pubout -in key.pem | sha256sum

# A self-signed certificate for a lab
openssl req -x509 -newkey ed25519 -nodes -keyout lab.key -out lab.crt -days 30 -subj "/CN=lab.local" \
  -addext "subjectAltName=DNS:lab.local"
```

Modern clients check **subjectAltName** (SAN), not the old CN field. A certificate without the right SAN fails with "name mismatch" even if CN looks right.

## Monitor expiry

Expired certificates are one of the most common outages, even at big companies.

```bash
check_cert() {
  local host=$1 days
  days=$(( ( $(date -d "$(echo | openssl s_client -connect "$host:443" -servername "$host" 2>/dev/null |
           openssl x509 -noout -enddate | cut -d= -f2)" +%s) - $(date +%s) ) / 86400 ))
  echo "$host: $days days left"
  (( days > 14 ))
}
check_cert shop.example.com || echo "RENEW SOON"
```

Run it from a timer, alert on failure (the Bash course's pattern), or let your monitoring do it.

## Mutual TLS (mTLS)

Normal TLS: the client checks the server. **mTLS**: the server **also** checks a certificate from the client. Used between internal services, for admin panels, and for device fleets. In nginx: `ssl_client_certificate ca.crt; ssl_verify_client on;`. Service meshes (Istio, Linkerd) automate mTLS between all services.
