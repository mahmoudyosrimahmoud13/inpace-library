# A hardening checklist

The **CIS Benchmarks** are the industry reference (hundreds of items per distribution). This is the core most servers need.

## Network

- [ ] Default-deny host firewall (nftables), cloud firewall in front.
- [ ] Only needed ports open; databases and caches on private addresses.
- [ ] SSH: keys only, no root, `AllowGroups`, from a VPN or bastion if possible.
- [ ] Docker-published ports checked from outside.

## Kernel network settings

```text
# /etc/sysctl.d/60-net-hardening.conf
net.ipv4.conf.all.rp_filter = 1                 # drop spoofed source addresses
net.ipv4.conf.all.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.tcp_syncookies = 1
net.ipv4.icmp_echo_ignore_broadcasts = 1
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
```

## System

- [ ] Automatic security updates; a plan for kernel reboots.
- [ ] No unused services or packages; minimal SUID binaries.
- [ ] Services run as their own users with systemd sandboxing (`systemd-analyze security`).
- [ ] AppArmor/SELinux enforcing.
- [ ] Time synchronized.

## Accounts

- [ ] No shared accounts; each person their own login.
- [ ] Narrow sudo rules, logged.
- [ ] Unused accounts locked; old keys removed.

## Detection and recovery

- [ ] Logs shipped off the server; alerts on unusual successful logins.
- [ ] File integrity monitoring on critical paths.
- [ ] Tested backups, including off-site and immutable copies.

## Measure it

```bash
sudo lynis audit system      # note the hardening index; re-run after changes
```

Hardening is a trade-off: every item should have a reason. Document what you changed and why, so the next admin doesn't undo it, or keep something you no longer need.
