# Batch normalization

Normalize `z` inside the network, per mini-batch: `z_norm = (z − μ) / √(σ² + ε)`, then `z̃ = γ·z_norm + β`, where
`γ` and `β` are **learned** (so the network can undo the normalization if that's best). The bias `b` becomes useless:
`β` takes its place.

Why it helps: each layer sees inputs on a steady scale even as earlier layers change ("covariate shift"), the loss
surface is smoother so you can use bigger learning rates, and the per-batch noise regularizes a little.

**At test time** there's no batch: use running averages of μ and σ² collected during training. That's why
`model.eval()` in PyTorch (or `training=False` in Keras) matters.

## And in 2026

- **LayerNorm** (normalize over the features of each example, not over the batch) is the standard in transformers,
  and **RMSNorm**, a lighter version, in most large language models.
- BatchNorm is still common in CNNs. It behaves badly with very small batches.
