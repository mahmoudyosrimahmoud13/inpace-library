# Auto Scaling groups

An **Auto Scaling group (ASG)** keeps a number of identical instances running, across AZs, built from a **launch template** (AMI, type, security groups, role, user data).

| Setting | Means |
|---|---|
| Min / desired / max | Never fewer than min, never more than max, aim for desired |
| Health checks | EC2 status, plus the load balancer's health check: unhealthy instances are replaced |
| Scaling policies | How desired changes with load |

## Scaling policies

| Policy | Example |
|---|---|
| **Target tracking** (start here) | Keep average CPU at 50%; or 1,000 requests per target |
| Step scaling | Add 2 when CPU > 70%, add 4 when > 90% |
| Scheduled | 10 instances on weekdays 08:00-20:00, 2 otherwise |
| Predictive | Learns daily patterns and scales ahead |

```bash
aws autoscaling describe-auto-scaling-groups --query 'AutoScalingGroups[].[AutoScalingGroupName,MinSize,DesiredCapacity,MaxSize]' --output table
aws autoscaling start-instance-refresh --auto-scaling-group-name web-asg   # roll out a new launch template version
```

## Design for it

- **Stateless instances**: no uploads or sessions on local disk (use S3, a database, ElastiCache). Any instance can disappear at any moment.
- **Fast, reliable boot**: bake software into an AMI or use a short user-data script; the instance must pass health checks quickly.
- **Instance refresh** rolls out new versions by replacing instances a few at a time: the cloud way to update servers.

This is the heart of "cattle, not pets": servers are replaceable copies, not individuals you nurse.
