# S3: object storage

S3 stores **objects** (files plus metadata) in **buckets**, reached over HTTPS. It's designed for 99.999999999% durability: objects are copied across several AZs.

```bash
aws s3 mb s3://acme-reports-2026                         # bucket names are global across all of AWS
aws s3 cp report.pdf s3://acme-reports-2026/2026/11/
aws s3 ls s3://acme-reports-2026/2026/ --recursive
aws s3 sync ./site s3://acme-site --delete
aws s3 presign s3://acme-reports-2026/2026/11/report.pdf --expires-in 3600   # a temporary download link
```

There are no real folders: `2026/11/report.pdf` is one key; the console just displays prefixes like folders.

## Storage classes

| Class | For | Retrieval |
|---|---|---|
| Standard | Frequently used data | Instant |
| Intelligent-Tiering | Unknown or changing access patterns | Instant; moves objects to cheaper tiers automatically |
| Standard-IA / One Zone-IA | Rarely read, needed fast | Instant, with a retrieval fee |
| Glacier Instant / Flexible / Deep Archive | Archives | Milliseconds to hours, very cheap storage |

**Lifecycle rules** move or delete objects by age: logs to Glacier after 90 days, deleted after a year.

## Versioning

Turn on versioning for anything important: overwrites and deletes keep the old versions, so a bad sync or ransomware can be undone. Pair it with lifecycle rules that expire old versions so costs don't grow forever.
