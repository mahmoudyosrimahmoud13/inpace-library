# IAM: users, groups, roles and policies

IAM answers: **who** (principal) can do **what** (action) on **which** resource, under **what** conditions.

| Thing | Is | Use it for |
|---|---|---|
| **Root user** | The account's owner email | Almost nothing. MFA on, keys never, locked away |
| **IAM Identity Center users** | People, with single sign-on and short-lived credentials | Every human |
| **IAM users** | Long-lived identities with passwords/access keys | Avoid for people; rare legacy machine cases |
| **Groups** | Collections of users | Attach permissions once for a team |
| **Roles** | An identity anyone trusted can **assume**, getting temporary credentials | EC2 instances, Lambda, CI pipelines, cross-account access |
| **Policies** | JSON documents of permissions | Attached to identities or resources |

## A policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::acme-uploads/*",
      "Condition": {"IpAddress": {"aws:SourceIp": "203.0.113.0/24"}}
    }
  ]
}
```

**ARN** (Amazon Resource Name) names any resource: `arn:aws:service:region:account:resource`.

## Roles instead of keys

An EC2 instance with a role (via an **instance profile**) gets rotating temporary credentials automatically from the metadata service. Nothing to copy, nothing to leak. Same for Lambda, ECS tasks, and CI with OIDC (DevOps course).

```bash
aws iam list-roles --query 'Roles[].RoleName'
aws sts assume-role --role-arn arn:aws:iam::123456789012:role/ReadOnly --role-session-name test
```

## Rules that prevent most disasters

- MFA for every human; no access keys for people (use `aws configure sso`).
- Least privilege: start narrow, widen with evidence. AWS managed policies like `AdministratorAccess` are for break-glass only.
- Never put access keys in code, Git, or Docker images. If one leaks, deactivate it immediately: bots find keys on GitHub within minutes.
