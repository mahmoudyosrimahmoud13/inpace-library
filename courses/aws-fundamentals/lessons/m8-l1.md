# Watching it: CloudWatch, CloudTrail and costs

## CloudWatch

| Part | Holds | Example |
|---|---|---|
| **Metrics** | Numbers over time | EC2 CPU, ALB 5xx count, RDS free storage |
| **Logs** | Log lines in log groups | App logs, VPC flow logs, Lambda output |
| **Alarms** | Rules on metrics, which notify or act | "ALB 5xx > 10 per minute for 5 minutes -> email the team" |
| **Dashboards** | Graphs together | |

EC2 doesn't report **memory or disk usage** by default (AWS can't see inside your OS): install the **CloudWatch agent** for those (Cloud Linux Administration course).

```bash
aws cloudwatch describe-alarms --state-value ALARM
aws logs tail /aws/app/web --follow --since 10m
```

## CloudTrail: who did what

Every API call (console, CLI, SDK) is recorded: who, when, from where, what. It's how you answer "who deleted the bucket?" and the first place to look after a suspected breach. Keep a trail delivering to an S3 bucket in a **separate, locked-down account** for real setups.

## Costs

- **Budgets** with alerts (Day 1). Do it in every account.
- **Cost Explorer**: spend by service, by day, by tag.
- **Tags** on everything (`project`, `env`, `owner`) and activated as cost allocation tags, so you know what costs what.
- Weekly habit: look for idle load balancers, unattached EBS volumes, old snapshots, oversized instances, forgotten NAT gateways.
