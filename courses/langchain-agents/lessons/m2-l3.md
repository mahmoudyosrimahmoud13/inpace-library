# Project 2: an agent that looks things up, and tickets your code can file

You'll turn the tools into an agent that runs them itself, then get a **ticket** out of each conversation as a
Python object.

The code is above this text. Save it as `p2_agent.py`.

## Read the code

- **`SYSTEM`** tells the agent when to use each tool, and never to guess a status or a stock level.
- **`create_agent(MODEL, tools=TOOLS, system_prompt=SYSTEM)`** is the whole agent: the model and the tool loop.
  `show()` prints each step: the tool calls, what the tools said, and the answer.
- **`Ticket`** is a Pydantic model. `Literal[...]` limits the category and urgency to fixed values, so your code can
  route on them.
- **`response_format=Ticket`** asks the agent to end by filling in a ticket. Small models sometimes answer in words
  instead, so the code checks: if there's no ticket, a second, focused call with **`with_structured_output(Ticket)`**
  fills it in from the conversation. That's a common, reliable pattern.

## Run it

```bash
python p2_agent.py
```

The real output, with `qwen2.5:1.5b`:

```text
Model: ollama:qwen2.5:1.5b

Customer: Hi, where is my order A1003? I ordered it days ago.
   agent: I'm sorry, but I don't have information on your specific order ID. Could you please provide me with some details about the order so that I can help you better?

Customer: Is the city bike in stock, and how much is it?
   agent asks: check_stock({'product': 'city bike'})
   tool says: [{"name": "City bike, 7 gears", "price": 549.0, "in_stock": 4}]
   agent: The city bike with 7 gears is currently in stock and available for $549. There are 4 bikes available.

Customer: My helmet from order A1002 still hasn't arrived and I need it for a race on Saturday!
   ticket from response_format: None
   ticket from a separate extraction call: Ticket(order_id='A1002', category='order status', urgency='high', summary="My helmet from order A1002 has not arrived yet. It's needed for a race on Saturday.")
   your code can route it: to a person now
```

What it shows:

- **The first question fails**: the agent didn't call `get_order` for A1003, and asked the customer for details it
  could have looked up. The system prompt says to call it; a 1.5-billion-parameter model doesn't always follow.
  Bigger models do this far more reliably, and on day 5 you'll build a version where it can't be skipped.
- The stock question works: tool, result, a correct answer.
- `response_format` gave no ticket; the extraction call did, and correctly: order A1002, high urgency (a race on
  Saturday). Your code routes it to a person.

## Make it yours

1. Run the same three questions with a bigger model (`PEDAL_MODEL=ollama:qwen3`). Count how many tool calls happen.
2. Add a field `customer_mood: Literal["calm", "annoyed", "angry"]` to the ticket. Is it filled in sensibly?
3. Ask ten different questions and count how often `response_format` alone gives a ticket. Is the fallback worth
   keeping?

## What to take away

- `create_agent` is the loop; the system prompt and tool descriptions steer it.
- Structured output turns a conversation into data your code can trust, as long as you check it arrived.
- Small models skip steps. Design for it.
