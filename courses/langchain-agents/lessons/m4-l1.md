# Memory: conversations that continue

An agent call is stateless unless you give it a **checkpointer**. With one, every run is saved under a `thread_id`, and the next call with the same id continues the conversation.

```python
from langgraph.checkpoint.memory import InMemorySaver

chat_agent = create_agent(model, tools=[get_order], checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "customer-7"}}

chat_agent.invoke({"messages": [{"role": "user", "content": "Hi, I'm Mona. My order is A-17."}]}, config)
result = chat_agent.invoke({"messages": [{"role": "user", "content": "What's my name, and where is my order?"}]}, config)
print(result["messages"][-1].content)
print(len(result["messages"]), "messages saved in this thread")
```

You only send the *new* message; the checkpointer adds the history. A different `thread_id` starts a fresh conversation.

## Short-term and long-term

| | Short-term (thread) memory | Long-term memory |
|---|---|---|
| What | the messages and state of one conversation | facts kept across conversations ("prefers Arabic replies") |
| How in LangGraph | a checkpointer (`InMemorySaver` to learn; Postgres or SQLite savers in production) | a **store** (key-value with optional search), read and written by tools or middleware |
| Risk | the history grows past the context window | storing personal data you shouldn't, or stale facts |

## Keeping the history in budget

Long threads get slow, expensive and worse (models miss facts in the middle of long contexts). Add `SummarizationMiddleware` to replace old turns with a summary once the history passes a token budget, and keep tool results short in the first place.

## Privacy

A checkpointer saves everything the user said. Decide how long threads are kept, who can read them, and how a user deletes theirs, before you launch.
