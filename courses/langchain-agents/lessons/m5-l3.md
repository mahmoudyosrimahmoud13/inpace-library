# Project 5: a workflow that can't skip steps, with tests

The agent from days 2 to 4 is flexible, and it skipped lookups it should have done. Today you build the desk as a
**LangGraph workflow**: the model classifies and writes, and plain code does the steps that must always happen.
Then you test it and evaluate it.

The code is above this text: `p5_graph.py` and `tests/test_pedal.py`.

## Read the code

- **`Desk`** is the graph's state: the question, the category, the facts, the answer.
- **`classify`** uses the model with `with_structured_output(Route)`: one of four categories.
- **`gather`** is ordinary code: if there's an order id, it **always** calls `get_order`; for returns and policy
  questions it **always** calls `search_policies`. The model can't skip them.
- **`write`** gives the model the facts and asks for a short answer from them only.
- **`handoff`** sends anything else to a person, without the model writing.
- **`build(classifier, writer)`** wires it: start, classify, then `gather` and `write`, or `handoff`. The model steps
  are parameters, so tests can swap them.
- **`tests/test_pedal.py`** needs no model: it tests the tools, the policy search, and the graph with stand-in
  classifiers. For example, a refund question must put both the order and the returns policy in front of the
  writer.
- The main part runs four cases and checks two things for each: the route, and that the facts the answer needs
  were gathered.

## Run it

```bash
pytest -q
python p5_graph.py
```

What it shows:

- **The facts are always there now**: the order and the right policy reach the model every time.
- **The small model still gets things wrong** with the right facts:
  - It said order A1001 can still be returned. It was delivered on 6 November, 18 days before "today", and ridden
    bikes have 14 days.
  - It routed the sponsorship question as a policy question, and then invented an answer about the shop's
    community work.
- **The evaluation says 2 of 4.** That number, run after every change, is how you know whether a bigger model, a
  better prompt or a new step helped.

2. Route "other" when the classifier is unsure: ask it for a confidence too, and hand off below a threshold.

4. Turn on LangSmith tracing (`LANGSMITH_TRACING=true` and an API key) and look at one run step by step.

## What to take away

- Use an agent where flexibility helps; use a workflow where steps must happen.
- Test the plumbing without a model; evaluate the model's parts with cases you keep.
- Right facts don't guarantee right answers: compute what code can compute.
