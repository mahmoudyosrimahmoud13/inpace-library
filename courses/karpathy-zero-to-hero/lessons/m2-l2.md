# makemore 1: the same model as a neural network

Counting doesn't scale to longer contexts (the table explodes). The second half of the video rebuilds the bigram as a **neural network** trained with gradient descent, a framework that scales to transformers.

```mermaid
flowchart LR
    X[current char index] --> OH[one-hot vector, 27]
    OH --> W["× W (27×27): logits"]
    W --> E[exp: counts]
    E --> N[normalise: probabilities = softmax]
    N --> L[loss: −log p of the true next char]
```

```python
import torch
import torch.nn.functional as F

import os, urllib.request
if not os.path.exists("names.txt"):                       # 32,033 names from the makemore repository
    urllib.request.urlretrieve("https://raw.githubusercontent.com/karpathy/makemore/master/names.txt", "names.txt")
words = open("names.txt").read().splitlines()

chars = sorted(set("".join(words)))
stoi = {c: i + 1 for i, c in enumerate(chars)}; stoi["."] = 0
itos = {i: c for c, i in stoi.items()}

xs, ys = [], []
for w in words:
    seq = ["."] + list(w) + ["."]
    for a, b in zip(seq, seq[1:]):
        xs.append(stoi[a]); ys.append(stoi[b])
xs, ys = torch.tensor(xs), torch.tensor(ys)
print(xs.shape)                                   # about 228,000 training pairs

g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g, requires_grad=True)
xenc = F.one_hot(xs, num_classes=27).float()      # one-hot inputs
for step in range(100):
    logits = xenc @ W                             # same as picking row xs of W
    counts = logits.exp()
    probs = counts / counts.sum(1, keepdim=True)  # softmax
    loss = -probs[torch.arange(len(ys)), ys].log().mean() + 0.01 * (W ** 2).mean()   # NLL + regularisation
    W.grad = None
    loss.backward()
    W.data += -50 * W.grad
    if step % 25 == 0:
        print(step, round(loss.item(), 4))
print("final loss:", round(loss.item(), 4))       # about 2.49 after 100 steps; more steps approach counting's 2.45
```

## Why this matters

- The network learns the **same** table the counts gave: `W.exp()` ends up proportional to the counts. Gradient descent rediscovered counting.
- `one_hot(x) @ W` is just **row lookup**; that's what an embedding layer is (next lesson).
- The **regularisation** term pulls W towards 0, which makes probabilities more uniform: the neural version of `+1` smoothing.
- From here, improving the model means changing only the middle: more context, more layers, attention. The loss and the training loop stay.

Use `F.cross_entropy(logits, ys)` in practice: it does the exp, normalisation and log in one numerically safe step.
