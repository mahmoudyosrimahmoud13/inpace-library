# Terraform basics: providers, resources, plan, apply

Terraform reads `.tf` files written in **HCL**.

```hcl
terraform {
  required_version = ">= 1.6"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}

provider "aws" {
  region = "eu-central-1"
  default_tags { tags = { project = "shop", managed_by = "terraform" } }
}

resource "aws_s3_bucket" "uploads" {
  bucket = "acme-shop-uploads-dev"
}

resource "aws_s3_bucket_versioning" "uploads" {
  bucket = aws_s3_bucket.uploads.id          # a reference creates a dependency
  versioning_configuration { status = "Enabled" }
}

output "bucket_name" { value = aws_s3_bucket.uploads.bucket }
```

## The workflow

```bash
terraform init        # download providers, set up the backend
terraform fmt         # format the code
terraform validate    # catch syntax and type errors
terraform plan        # show what would change: + create, ~ update, - destroy, -/+ replace
terraform apply       # do it (shows the plan again and asks)
terraform destroy     # delete everything this code manages
```

**Read every plan.** The line that matters most is the summary: `Plan: 2 to add, 0 to change, 1 to destroy.` An unexpected destroy or `-/+` (replace) on a database is how outages happen.

## Resources and data sources

- `resource` = something Terraform **creates and owns**.
- `data` = something that already exists that Terraform **reads**:

```hcl
data "aws_ssm_parameter" "al2023" {
  name = "/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64"
}
resource "aws_instance" "web" {
  ami           = data.aws_ssm_parameter.al2023.value
  instance_type = "t3.micro"
}
```

Terraform builds a **dependency graph** from references and creates things in the right order, in parallel where it can.

**OpenTofu** is a community fork with the same language and commands (`tofu plan`); everything here works with either.
