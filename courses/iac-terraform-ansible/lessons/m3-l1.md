# Modules: reusable building blocks

A **module** is a folder of `.tf` files with inputs (variables) and outputs. Your root folder is a module too.

```text
infra/
  modules/
    network/        main.tf  variables.tf  outputs.tf
    web_service/    main.tf  variables.tf  outputs.tf
  envs/
    staging/        main.tf  backend.tf  staging.tfvars
    prod/           main.tf  backend.tf  prod.tfvars
```

```hcl
# envs/prod/main.tf
module "network" {
  source   = "../../modules/network"
  name     = "shop-prod"
  cidr     = "10.20.0.0/16"
  az_count = 3
}

module "web" {
  source             = "../../modules/web_service"
  vpc_id             = module.network.vpc_id
  private_subnet_ids = module.network.private_subnet_ids
  public_subnet_ids  = module.network.public_subnet_ids
  instance_type      = "m7g.large"
  min_size           = 3
}
```

## Public modules

The **Terraform Registry** has well-tested modules, such as `terraform-aws-modules/vpc/aws`:

```hcl
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"          # always pin versions
  name    = "shop"
  cidr    = "10.0.0.0/16"
  azs             = ["eu-central-1a", "eu-central-1b"]
  public_subnets  = ["10.0.0.0/24", "10.0.1.0/24"]
  private_subnets = ["10.0.10.0/24", "10.0.11.0/24"]
  enable_nat_gateway = true
  single_nat_gateway = true   # cheaper for dev; one per AZ for prod
}
```

## Good modules

- Do **one thing** (a network, a service), with a small set of clear inputs.
- Have sensible, **secure defaults** (encryption on, no public access).
- Expose outputs others need (IDs, ARNs, DNS names).
- Are **versioned** (Git tags) so prod can stay on v1.3 while staging tries v1.4.

Don't wrap every single resource in its own module: that adds layers without adding value.
