# Capstone: a whole environment from Git

Recreate a production-style environment from nothing with **one repository**.

```text
shop-infra/
  modules/network, modules/web_service, modules/database
  envs/staging, envs/prod            # Terraform roots, remote state, separate tfvars
  ansible/roles/common, nginx, app   # or packer/ + ansible/ for baked AMIs
  .github/workflows/terraform.yml    # plan on PR, apply on main with approval
  README.md
```

## Requirements

1. **Remote state** in S3 with locking, encryption and versioning (created once by a small bootstrap folder).
2. **Modules** for network, web service and database; staging and prod use the same modules with different variables.
3. VPC in 2 AZs, ALB with HTTPS, Auto Scaling group in private subnets, RDS PostgreSQL with `deletion_protection` in prod.
4. Servers configured by **Ansible roles** (via Packer or dynamic inventory over SSM), passing `ansible-lint`.
5. **No secrets in Git**: RDS-managed password, Vault or Parameter Store for the rest.
6. CI: fmt, validate, tflint, a security scan, plan as a PR comment; apply from main with **OIDC** and a production approval.
7. A scheduled drift check.

## Prove it

- Destroy staging and rebuild it from scratch; time it.
- Change the instance type in a PR and show the plan, review and rolling apply.
- Introduce drift in the console; show the scheduled plan catching it.

## Deliver

Repository link, the README (how to bootstrap, plan, apply, roll back, destroy), and the rebuild time. Then **destroy everything** you don't need running.
