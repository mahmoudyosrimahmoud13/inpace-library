# Terraform and Ansible together

Terraform creates the machines; Ansible configures them. They need a hand-off.

| Pattern | How | When |
|---|---|---|
| **Tags + dynamic inventory** | Terraform tags instances (`role=web`); Ansible's aws_ec2 plugin finds them | Default choice; no files to pass around |
| Terraform output -> inventory file | `terraform output -json` rendered into an inventory | Simple, static setups |
| **Bake with Packer + Ansible** | Packer runs Ansible to build a golden AMI; Terraform launches it | Auto Scaling groups, immutable servers |
| cloud-init only | Terraform passes user data; no Ansible | Small, simple instances |

## The bake pattern

```hcl
# packer/web.pkr.hcl (Packer's language is HCL too)
source "amazon-ebs" "web" {
  region        = "eu-central-1"
  instance_type = "t3.small"
  source_ami_filter {
    filters     = { name = "al2023-ami-*-x86_64" }
    owners      = ["amazon"]
    most_recent = true
  }
  ssh_username = "ec2-user"
  ami_name     = "shop-web-{{timestamp}}"
}
build {
  sources = ["source.amazon-ebs.web"]
  provisioner "ansible" { playbook_file = "../ansible/site.yml" }
}
```

```hcl
# Terraform picks the newest baked image
data "aws_ami" "web" {
  owners      = ["self"]
  most_recent = true
  filter {
    name   = "name"
    values = ["shop-web-*"]
  }
}
```

```mermaid
flowchart LR
  A["Ansible roles"] --> P["Packer build"] --> AMI["shop-web-1731830000"]
  AMI --> T["terraform apply: new launch template version"]
  T --> R["ASG instance refresh"]
```

## Avoid

- Terraform `provisioner "remote-exec"` running long scripts: brittle and hides failures. HashiCorp calls provisioners a last resort.
- Two tools managing the same thing (Terraform and Ansible both editing security groups): pick one owner per resource.
