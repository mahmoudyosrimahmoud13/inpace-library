# Ansible basics: inventory, ad-hoc and playbooks

**Ansible** configures servers over **SSH**, with nothing to install on them except Python. You describe the desired state in YAML; Ansible makes it so, idempotently.

## Inventory

```ini
# inventory.ini
[web]
web01 ansible_host=10.0.10.21
web02 ansible_host=10.0.11.34

[db]
db01 ansible_host=10.0.20.5

[all:vars]
ansible_user=ec2-user
ansible_ssh_common_args='-o ProxyJump=bastion'
```

Everything from the SSH course applies: Ansible uses your `~/.ssh/config`, keys, ProxyJump and ControlPersist.

## Ad-hoc commands

```bash
ansible all -i inventory.ini -m ping
ansible web -i inventory.ini -a "uptime"
ansible web -i inventory.ini -b -m dnf -a "name=htop state=present"    # -b = become root (sudo)
```

## A playbook

```yaml
# site.yml
- name: Web servers
  hosts: web
  become: true
  vars:
    app_port: 8000
  tasks:
    - name: Install nginx
      ansible.builtin.dnf:
        name: nginx
        state: present

    - name: Configure the site
      ansible.builtin.template:
        src: templates/site.conf.j2
        dest: /etc/nginx/conf.d/site.conf
        mode: "0644"
      notify: Reload nginx

    - name: Start and enable nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

  handlers:
    - name: Reload nginx
      ansible.builtin.service:
        name: nginx
        state: reloaded
```

```bash
ansible-playbook -i inventory.ini site.yml --check --diff   # dry run, show changes
ansible-playbook -i inventory.ini site.yml
```

The second run should report `changed=0`: that's idempotence. **Handlers** run only when something notified them, so nginx reloads only when its config actually changed.

Prefer real modules (`dnf`, `template`, `user`, `service`, `lineinfile`) over `shell:`; modules know how to check state, shell commands don't.
