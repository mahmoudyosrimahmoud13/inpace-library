# أدوات بايثون وتعقيد Big-O

اعرف تكلفة كل عملية تستخدمها. فأغلب أخطاء التعقيد في المقابلات تأتي من O(n) مخفية داخل حلقة.

| العملية | التكلفة |
|---|---|
| `list.append(x)` و`list.pop()` | O(1) في المتوسط المستهلك |
| `list.insert(0, x)` و`list.pop(0)` و`x in list` | O(n) |
| `x in set` و`d[key]` و`d[key] = v` | O(1) في المتوسط |
| `deque.appendleft` و`deque.popleft` | O(1) |
| `heapq.heappush` و`heapq.heappop` | O(log n) |
| `sorted(a)` و`a.sort()` | O(n log n) |
| `bisect.bisect_left(a, x)` | O(log n) |
| `s[i:j]` و`list(a)` و`"".join(parts)` | O(الطول) |
| `s += ch` داخل حلقة | O(n²) في أسوأ الحالات: اجمع الأجزاء ثم اربطها مرة واحدة |

![قياس فعلي: x in list يزيد مع n وx in set يبقى ثابتًا](list_vs_set-ar.png)

قيس أثناء كتابة هذا الدرس: البحث عن آخر عنصر في قائمة من 200 ألف عنصر استغرق نحو 1 ملّي ثانية، وفي مجموعة أقل من ميكروثانية بكثير مهما كان الحجم. وهذا هو الفرق بين O(n) وO(1).

```python
from collections import Counter, defaultdict, deque
import heapq, bisect
from functools import cache

Counter("banana").most_common(2)      # [('a', 3), ('n', 2)]

```

## قراءة القيود

حجم المدخلات يخبرك بالتعقيد المتوقع: n حتى نحو 10³ يسمح بـ O(n²)، وحتى 10⁵ أو 10⁶ يحتاج O(n log n) أو O(n)، وn قرابة 20 يلمّح إلى O(2ⁿ) (التراجع)، وn أو نطاق قيم ضخم يلمّح إلى O(log n) (البحث الثنائي). والذاكرة تُحسب أيضًا: قل ما تستخدمه من ذاكرة إضافية.

حد العودية (recursion) في بايثون نحو 1000 استدعاء: وللعودية العميقة (قائمة مترابطة طويلة، أو شبكة كبيرة) استخدم مكدّسًا صريحًا أو `sys.setrecursionlimit`.
