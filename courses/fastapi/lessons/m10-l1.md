# WebSockets

HTTP is request then response. A **WebSocket** stays open, so the server can push messages any time: chats, live
dashboards, notifications.

```python
from fastapi import WebSocket, WebSocketDisconnect


class ConnectionManager:
    def __init__(self):
        self.active: list[WebSocket] = []

    async def connect(self, ws: WebSocket):
        await ws.accept()
        self.active.append(ws)

    def disconnect(self, ws: WebSocket):
        self.active.remove(ws)

    async def broadcast(self, message: str):
        for ws in list(self.active):
            await ws.send_text(message)


manager = ConnectionManager()


@app.websocket("/ws/rooms/{room}")
async def room(ws: WebSocket, room: str):
    await manager.connect(ws)
    try:
        while True:
            text = await ws.receive_text()
            await manager.broadcast(f"[{room}] {text}")
    except WebSocketDisconnect:
        manager.disconnect(ws)
```

## Authentication

Browsers can't set custom headers on WebSockets. Common options: a token in the query string
(`/ws?token=...`), or a cookie. Check it before accepting, and close with a policy-violation code if it's bad:

```python
from fastapi import status

@app.websocket("/ws")
async def ws_endpoint(ws: WebSocket, token: str | None = None):
    user = user_from_token(token)
    if not user:
        await ws.close(code=status.WS_1008_POLICY_VIOLATION)
        return
    await ws.accept()
    ...
```

Dependencies work in WebSocket endpoints too.

## Scaling beyond one process

`ConnectionManager` only knows connections in **its own process**. With several workers or servers, publish messages
through something shared, like **Redis pub/sub**, so every process can forward them to its own clients.
