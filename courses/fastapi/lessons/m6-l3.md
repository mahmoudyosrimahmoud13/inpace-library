# Permissions, CORS and other protections

## Roles and ownership

Build permission checks as dependencies on top of `get_current_user`:

```python
def require_role(*roles: str):
    def checker(user: CurrentUser) -> User:
        if user.role not in roles:
            raise HTTPException(403, "Not allowed")
        return user
    return checker

@app.post("/books", dependencies=[Depends(require_role("editor", "admin"))])
def create_book(...): ...
```

Also check **ownership** on every object: "is this user allowed to touch *this* order?" Missing ownership checks
(called IDOR) are one of the most common API security bugs.

```python
order = db.get(Order, order_id)
if order is None or order.user_id != user.id:
    raise HTTPException(404, "Order not found")     # 404 hides that it exists
```

OAuth2 **scopes** (`Security(get_current_user, scopes=["books:write"])`) give finer control when tokens are given
to third-party apps.

## CORS

Browsers block a page on `https://app.example.com` from calling `https://api.example.com` unless the API allows it:

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],     # never ["*"] together with credentials
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

CORS only affects browsers. It is **not** an access control for your API.

## A short security checklist

- HTTPS everywhere (usually done by your proxy or platform).
- Secrets come from environment variables, not code.
- Limit request sizes and add **rate limiting** on login and expensive endpoints (for example with `slowapi`, or
  at your proxy).
- Validate everything with Pydantic; never build SQL with string formatting.
- Return generic errors for auth failures; log the details on the server instead.
- Turn off `/docs` in production if the API is private: `FastAPI(docs_url=None, redoc_url=None)`.
