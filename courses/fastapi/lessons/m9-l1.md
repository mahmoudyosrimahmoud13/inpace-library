# Routers and project layout

One `main.py` is fine for a weekend. For a real app, split it with `APIRouter`:

```text
app/
  main.py            # creates the app, adds routers and middleware
  config.py          # settings
  db.py              # engine, session, Base
  deps.py            # shared dependencies (DB, CurrentUser...)
  models/            # SQLAlchemy models
  schemas/           # Pydantic models (BookCreate, BookOut...)
  routers/
    books.py
    users.py
    auth.py
  services/          # business logic, no HTTP in here
tests/
migrations/
```

```python
# app/routers/books.py
from fastapi import APIRouter
from app.deps import DB, CurrentUser

router = APIRouter(prefix="/books", tags=["books"])

@router.get("/")
def list_books(db: DB): ...

@router.post("/", status_code=201)
def create_book(data: BookCreate, db: DB, user: CurrentUser): ...
```

```python
# app/main.py
from fastapi import FastAPI
from app.routers import auth, books, users

app = FastAPI(title="Library API", version="1.0.0")
app.include_router(auth.router)
app.include_router(books.router)
app.include_router(users.router, prefix="/admin", dependencies=[Depends(require_admin)])
```

## Keep HTTP out of your business logic

Endpoints should be thin: read input, call a service function, return output. Put the rules in `services/`:

```python
# services/books.py
def publish(db: Session, book: Book, user: User) -> Book:
    if book.author_id != user.author_id:
        raise NotAllowed()
    book.published = True
    db.commit()
    return book
```

Services are easy to test without HTTP and easy to reuse from a CLI script or a worker.
