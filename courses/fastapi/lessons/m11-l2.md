# Docker

A container image packs your code, Python and dependencies so it runs the same everywhere.

```dockerfile
# Dockerfile
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

WORKDIR /app

# Install dependencies first: this layer is cached until requirements.txt changes
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app
COPY migrations ./migrations
COPY alembic.ini .

# Don't run as root
RUN useradd --create-home appuser
USER appuser

EXPOSE 8000
CMD ["fastapi", "run", "app/main.py", "--port", "8000"]
```

```text
# .dockerignore
.venv
__pycache__
.env
.git
tests
```

```bash
docker build -t library-api .
docker run --env-file .env -p 8000:8000 library-api
```

## With a database: docker compose

```yaml
# compose.yaml
services:
  api:
    build: .
    env_file: .env
    ports: ["8000:8000"]
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: library
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
volumes:
  pgdata:
```

Run migrations as a separate step when you deploy, for example
`docker compose run --rm api alembic upgrade head`, before starting the new version.

Never bake `.env` or secrets into the image. Pass them at run time.
