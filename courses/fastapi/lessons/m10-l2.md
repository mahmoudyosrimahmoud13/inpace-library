# Streaming and Server-Sent Events

## Streaming a response

Send data as it's produced instead of building it all in memory first:

```python
from fastapi.responses import StreamingResponse
import csv, io

@app.get("/export.csv")
def export(db: DB):
    def rows():
        buf = io.StringIO()
        writer = csv.writer(buf)
        writer.writerow(["id", "title"])
        for book in db.scalars(select(Book)).yield_per(500):
            writer.writerow([book.id, book.title])
            yield buf.getvalue()
            buf.seek(0); buf.truncate(0)
    return StreamingResponse(rows(), media_type="text/csv",
                             headers={"Content-Disposition": 'attachment; filename="books.csv"'})
```

A million rows now use almost no memory. The generator can also be `async`.

## Server-Sent Events (SSE)

When the server only needs to **push** (progress bars, live logs, AI text appearing word by word), SSE is simpler
than WebSockets. It's plain HTTP, and browsers reconnect automatically.

```python
import asyncio, json

@app.get("/jobs/{job_id}/events")
async def job_events(job_id: str, request: Request):
    async def stream():
        while True:
            if await request.is_disconnected():
                break
            status = await get_job_status(job_id)
            yield f"data: {json.dumps(status)}\n\n"       # each event ends with a blank line
            if status["done"]:
                break
            await asyncio.sleep(1)
    return StreamingResponse(stream(), media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache"})
```

In the browser:

```javascript
const es = new EventSource("/jobs/42/events");
es.onmessage = (e) => console.log(JSON.parse(e.data));
```

| Need | Use |
|---|---|
| Server pushes, client only listens | SSE |
| Both sides send often (chat, games) | WebSockets |
| One big download | StreamingResponse |
