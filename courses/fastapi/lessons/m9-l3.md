# A great OpenAPI and API versioning

Your `/docs` page is the user manual of your API. Make it good.

## Describe things

```python
tags_metadata = [
    {"name": "books", "description": "Search, add and edit books."},
    {"name": "auth", "description": "Log in and manage tokens."},
]

app = FastAPI(
    title="Library API",
    version="2.1.0",
    description="Everything about the library. **Markdown** works here.",
    openapi_tags=tags_metadata,
)


@router.get(
    "/{book_id}",
    summary="Get one book",
    response_description="The book",
    responses={404: {"description": "No book with that id"}},
)
def get_book(book_id: int):
    """
    Returns a book with its author.

    - **book_id**: the book's number
    """
```

## Stable operation ids for generated clients

Front-end teams often generate a TypeScript client from `/openapi.json`. Give operations clean names:

```python
from fastapi.routing import APIRoute

def simple_id(route: APIRoute) -> str:
    return f"{route.tags[0]}-{route.name}"

app = FastAPI(generate_unique_id_function=simple_id)
```

## Versioning

When you must make a **breaking** change, keep the old version alive for a while:

```python
app.include_router(books_v1.router, prefix="/v1")
app.include_router(books_v2.router, prefix="/v2")

@router.get("/old-search", deprecated=True)
def old_search(): ...
```

Non-breaking changes (new optional fields, new endpoints) don't need a new version. Removing or renaming fields,
or changing their meaning, does.
