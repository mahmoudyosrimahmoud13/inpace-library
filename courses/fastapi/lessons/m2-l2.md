# Validation with Annotated, Query and Path

Types check the *kind* of value. To check the *value itself*, add rules with `Query`, `Path`, `Header` and friends,
wrapped in `Annotated`:

```python
from typing import Annotated
from fastapi import FastAPI, Path, Query

app = FastAPI()


@app.get("/books/{book_id}")
def get_book(
    book_id: Annotated[int, Path(ge=1, description="The book's number")],
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None,
    page: Annotated[int, Query(ge=1, le=1000)] = 1,
):
    return {"book_id": book_id, "q": q, "page": page}
```

| Rule | Works on | Meaning |
|---|---|---|
| `gt`, `ge`, `lt`, `le` | numbers | greater / less than (or equal) |
| `min_length`, `max_length` | strings, lists | length limits |
| `pattern` | strings | must match a regular expression |
| `alias` | any | the name used in the URL, e.g. `alias="item-query"` |
| `deprecated=True` | any | shown as deprecated in the docs |

## Why `Annotated`?

The older style was `q: str = Query(None, min_length=3)`. `Annotated` keeps the **type** and the **default** in
their normal places, works with editors and type checkers, and lets you reuse a type:

```python
PageNumber = Annotated[int, Query(ge=1, le=1000)]

@app.get("/books")
def books(page: PageNumber = 1): ...

@app.get("/authors")
def authors(page: PageNumber = 1): ...
```

Prefer `Annotated` in all new code.

## What a validation error looks like

```json
{"detail": [{"type": "greater_than_equal", "loc": ["query", "page"],
             "msg": "Input should be greater than or equal to 1", "input": "0"}]}
```

`loc` tells the client exactly which field was wrong, and where (path, query, body...).
