# Remote commands and SSH in scripts

```bash
ssh web01 uptime                          # run one command, return
ssh web01 'df -h / && free -h'            # quote it so && runs remotely, not locally
ssh -t web01 'sudo systemctl restart nginx'   # -t: give it a terminal (sudo may ask a password)
ssh web01 'bash -s' < local_script.sh     # run a local script remotely
ssh web01 "grep ERROR /var/log/app.log" > errors.txt   # output comes back to your machine
```

## Quoting: what runs where

```bash
ssh web01 echo $HOME       # $HOME expands LOCALLY first (your home), then runs remotely
ssh web01 'echo $HOME'     # expands on the server
```

## SSH inside scripts

```bash
opts=(-o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=yes)
for h in web01 web02; do
  ssh -n "${opts[@]}" "$h" 'systemctl is-active nginx' || echo "$h: problem"
done
```

- `BatchMode=yes`: never prompt; fail if a key isn't available.
- `-n`: don't read the loop's stdin.
- **Never** use `StrictHostKeyChecking=no` in production scripts: it silently accepts impostors. Pre-load `known_hosts` instead (`ssh-keyscan host >> known_hosts`, checked against a trusted source).

## Exit codes travel back

`ssh host 'cmd'` exits with `cmd`'s exit code (255 means SSH itself failed). Scripts can rely on it.
