# Keys, passphrases and the agent

```bash
ssh-keygen -t ed25519 -a 100 -C "sara@laptop-2026"
# ~/.ssh/id_ed25519      private key (never share, mode 600)
# ~/.ssh/id_ed25519.pub  public key (safe to share)
ssh-copy-id -i ~/.ssh/id_ed25519.pub sara@web01    # appends it to web01's ~/.ssh/authorized_keys
```

Without `ssh-copy-id` (Windows, or no password login): paste the `.pub` line into `~/.ssh/authorized_keys` on the server, with `~/.ssh` at mode 700 and the file at 600. Wrong permissions are the most common reason keys "don't work"; `sshd` silently ignores keys others could change.

## Passphrases and ssh-agent

A passphrase encrypts the private key on disk, so a stolen laptop or backup doesn't hand over your servers. The **agent** holds the unlocked key in memory so you type the passphrase once per session.

```bash
eval "$(ssh-agent -s)"           # start an agent (most desktops already run one)
ssh-add ~/.ssh/id_ed25519        # unlock and load
ssh-add -l                       # list loaded keys
ssh-add -t 4h ~/.ssh/id_ed25519  # forget it after 4 hours
```

macOS can keep the passphrase in the Keychain (`UseKeychain yes` in `~/.ssh/config`); Windows has an OpenSSH agent service.

## Restricting what a key may do

Options in front of a key in `authorized_keys`:

```text
from="10.0.0.0/8",no-port-forwarding,no-agent-forwarding,command="/usr/local/bin/backup-receive" ssh-ed25519 AAAA... backup@db01
```

That key only works from the private network and can only run the backup script: perfect for automation keys.

## Hardware keys

```bash
ssh-keygen -t ed25519-sk -O resident     # the private key never leaves the YubiKey; each use needs a touch
```

## One key per device

Use a separate key for each laptop or CI system. When a device is lost, you remove one line from `authorized_keys` and nothing else breaks.
