# Long sessions: tmux and mosh

Your Wi-Fi drops in the middle of a 40-minute database migration over SSH. With a plain session, the migration dies with it (the shell gets SIGHUP). Never run long jobs in a bare SSH session.

## tmux

```bash
ssh web01
tmux new -s migrate          # a session that lives on the SERVER
./long_migration.sh
# Ctrl+b then d               -> detach; it keeps running
exit
# ...later, from anywhere:
ssh web01
tmux attach -t migrate       # right where you left it
```

| Keys (after Ctrl+b) | Does |
|---|---|
| `d` | Detach |
| `c` / `n` / `p` | New window / next / previous |
| `%` / `"` | Split side by side / top and bottom |
| arrow keys | Move between panes |
| `[` | Scroll mode (q to leave) |

```bash
tmux ls                      # list sessions
tmux kill-session -t migrate
```

`screen` is the older tool with the same idea (Ctrl+a instead of Ctrl+b).

## mosh: for bad connections

`mosh` (mobile shell) survives roaming between networks, sleep, and laggy links, and echoes your typing instantly. It uses SSH to log in, then UDP ports 60000-61000 (open them in the firewall).

```bash
mosh web01
```

## For jobs, not just sessions

If it should run unattended, make it a proper service or a one-off unit: `sudo systemd-run --unit=migration /opt/app/migrate.sh`, then `journalctl -u migration -f`. That survives disconnects **and** reboots of your laptop, and logs everything.
