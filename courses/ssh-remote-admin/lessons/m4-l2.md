# Dynamic forwarding (SOCKS) and when to use a VPN

## -D: a SOCKS proxy through the server

```bash
ssh -D 1080 -fN bastion
```

Point a browser (or `curl --socks5-hostname localhost:1080`) at `localhost:1080`, and its traffic leaves from the bastion. You can now open internal web dashboards (`http://grafana.internal:3000`) as if you were inside the network, without a tunnel per port.

```bash
curl --socks5-hostname localhost:1080 http://grafana.internal:3000/api/health
```

`--socks5-hostname` makes the **bastion** resolve the name, so internal DNS names work.

## Tunnel, SOCKS, or VPN?

| Need | Best tool |
|---|---|
| One port on one server, now | `ssh -L` |
| Browse many internal web UIs | `ssh -D` + a browser profile |
| The whole team needs the private network every day | A VPN: WireGuard, Tailscale, or the cloud's client VPN |
| Admin access to cloud servers without open ports | Cloud session managers (AWS SSM) |

Tunnels are perfect for quick, personal, temporary access. For daily team access, a managed VPN is easier to audit and revoke.
