# Server side: Match blocks and SFTP-only users

`sshd_config` can change settings for some users, groups or addresses with **Match** blocks (they go at the end of the file):

```text
# /etc/ssh/sshd_config.d/20-match.conf
Match Address 10.0.0.0/8
    PasswordAuthentication no
    AllowTcpForwarding yes

Match Group admins
    AllowAgentForwarding no

Match Group sftponly
    ChrootDirectory /srv/sftp/%u
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
    PermitTunnel no
```

## An upload-only account for a partner

```bash
sudo groupadd sftponly
sudo useradd -G sftponly -s /usr/sbin/nologin -d /upload partner1
sudo mkdir -p /srv/sftp/partner1/upload
sudo chown root:root /srv/sftp/partner1           # chroot dir must be root-owned and not writable by others
sudo chmod 755 /srv/sftp/partner1
sudo chown partner1:sftponly /srv/sftp/partner1/upload
# add partner1's public key to /home or AuthorizedKeysFile location, then:
sudo sshd -t && sudo systemctl reload ssh
```

The partner can `sftp` in and see only their `upload` folder; no shell, no tunnels, no rest of the filesystem.

## Check the effective settings

```bash
sudo sshd -T -C user=partner1,host=x,addr=203.0.113.5 | grep -Ei 'chroot|forcecommand|forwarding'
```

`-C` asks "what would apply for this user from this address?", the safest way to test Match rules before anyone connects.
