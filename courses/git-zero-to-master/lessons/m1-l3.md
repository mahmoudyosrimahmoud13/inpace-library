# Your first repository

> **Optional video above.** Part of freeCodeCamp's *Git and GitHub for Beginners, Crash Course*, from 17:30 to 20:20. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```bash
mkdir notes && cd notes      # a new folder, and go into it
git init                     # make it a Git repository
echo "# My notes" > README.md  # a first file
git status                   # README.md is "untracked": Git sees it but does not track it yet
git add README.md            # put it in the staging area
git commit -m "Add README"   # save a snapshot with a message
git log --oneline            # the history: one line per commit
```

`git init` made a hidden `.git` folder. **That folder is the repository**: all the history lives there. Delete it and the folder is a normal folder again (with the files as they are now, and no history). Never edit inside it by hand.

## The everyday loop

1. Change files.
2. `git status` to see what changed.
3. `git add <files>` to choose what goes in.
4. `git commit -m "why"` to save.

Repeat this many times a day. Small commits are better than big ones: module 2 shows why.

## What `git status` tells you

| It says | Meaning | Next step |
|---|---|---|
| Untracked files | New files Git doesn't track yet | `git add` them |
| Changes not staged for commit | Tracked files you changed | `git add` them |
| Changes to be committed | Staged, ready | `git commit` |
| nothing to commit, working tree clean | All saved | Keep working |

`git status -s` gives a short version: `??` untracked, `M` modified, `A` added. The left column is the staging area, the right one your working folder.
