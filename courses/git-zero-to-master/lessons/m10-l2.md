# Set Git up like a pro

```bash
git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --all --decorate"
git config --global alias.undo "reset --soft HEAD~1"
git config --global push.autoSetupRemote true   # first push of a branch needs no -u
git config --global fetch.prune true             # forget remote branches deleted on GitHub
git config --global rerere.enabled true
git config --global merge.conflictStyle zdiff3
git config --global diff.algorithm histogram     # clearer diffs
git config --global core.autocrlf input          # Mac/Linux; on Windows: true
```

## Line endings and .gitattributes

Windows ends lines with CRLF, Mac and Linux with LF. A `.gitattributes` file in the project makes everyone's commits the same:

```text
* text=auto eol=lf
*.bat text eol=crlf
*.png binary
```

## Hooks: run checks automatically

A **hook** is a script Git runs at a moment, like before every commit. Put this in `.git/hooks/pre-commit` and make it executable (`chmod +x`): the commit is refused if tests fail.

```bash
#!/bin/sh
npm test --silent || { echo "Tests failed, commit stopped."; exit 1; }
```

`.git/hooks` isn't shared with the team. To share hooks, keep them in a folder like `.githooks/` in the project and run `git config core.hooksPath .githooks`, or use a tool such as [pre-commit](https://pre-commit.com) or Husky. `git commit --no-verify` skips hooks (for emergencies).
