# Find things: log -S, blame and bisect

> **Optional video above.** Part of freeCodeCamp's *Advanced Git Tutorial* (with Tower), from 29:30 to 33:26. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```bash
git grep "TODO"                  # search the files, fast
git log -S "calculateTotal"      # commits that added or removed this text (the "pickaxe")
git log -G "total\s*="           # same with a regular expression
git blame -L 10,20 app.js        # who last changed lines 10 to 20, and in which commit
git blame -w -C app.js           # ignore whitespace, follow lines moved from other files
```

## bisect: find the commit that broke something

Something worked in v1.2 and is broken now, 200 commits later. **bisect** finds the guilty commit by halving the range each time: about 8 steps for 200 commits.

```bash
git bisect start
git bisect bad                 # the current commit is broken
git bisect good v1.2.0         # this one was fine
# Git checks out a commit in the middle. Test it, then say:
git bisect good                # or: git bisect bad
# ... repeat until Git prints "<hash> is the first bad commit"
git bisect reset               # back to where you started

# Even better: let a test decide (exit code 0 = good, 1 = bad)
git bisect start HEAD v1.2.0
git bisect run npm test
```
