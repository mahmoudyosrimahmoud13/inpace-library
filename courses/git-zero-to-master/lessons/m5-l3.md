# When push is refused

The most common error in Git:

```text
! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'github.com:mona/notes.git'
hint: Updates were rejected because the remote contains work that you do not have locally.
```

Someone (or you, from another computer, or a bot) pushed commits you don't have. GitHub refuses so nothing is lost. Get their work first, then push:

```bash
git pull --rebase            # put your new commits on top of theirs (a straight line, no merge commit)
git push

git pull --rebase --autostash   # same, when you also have changes that aren't committed yet: Git puts them
                                # aside, pulls, then puts them back
```

With `git config --global pull.rebase true` (module 1), a plain `git pull` already rebases.

## Force pushing

After you rewrite commits you had already pushed (on your own branch), a normal push is refused. Use `git push --force-with-lease`: it overwrites GitHub's branch **only if nobody else pushed since you last fetched**. Never use plain `--force`, and never force-push `main` on a shared repository.
