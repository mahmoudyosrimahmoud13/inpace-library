# Undo commits: amend, revert and reset

## Fix the last commit

Forgot a file or made a typo in the message?

> **Optional video above.** Part of freeCodeCamp's *Git and GitHub for Beginners, Crash Course*, from 56:30 to 1:01:50. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```bash
git add forgotten.txt
git commit --amend -m "Add login form"   # replaces the last commit (new hash)
git commit --amend --no-edit             # same message, just add what you staged
```

## Undo a commit everyone already has: revert

`git revert <hash>` makes a **new** commit that does the opposite. History stays as it was, so it's safe after you pushed.

```bash
git revert a1b2c3d        # opens the editor with "Revert ..." as the message
git revert HEAD            # undo the last commit
```

## Move the branch back: reset

`git reset` moves your branch to an older commit. The three modes differ in what happens to the changes of the commits you leave behind:

| Command | The commits after | Staging area | Your files |
|---|---|---|---|
| `git reset --soft HEAD~1` | gone from the branch | changes stay **staged** | unchanged |
| `git reset HEAD~1` (mixed, the default) | gone | emptied | changes stay **in your files** |
| `git reset --hard HEAD~1` | gone | emptied | **changes deleted** |

`--soft` is handy to squash the last few commits into one: `git reset --soft HEAD~3` then one `git commit`.

## The rule

**Never rewrite commits other people already have** (amend, reset, rebase on pushed work): their history and yours stop matching. For pushed work, use `revert`. For work only on your computer, rewrite freely.
