# The rescue kit

| Problem | Fix |
|---|---|
| Wrong message on the last commit | `git commit --amend` |
| Forgot a file in the last commit | `git add f && git commit --amend --no-edit` |
| Committed to main instead of a branch (not pushed) | `git branch feature && git reset --hard HEAD~1 && git switch feature` |
| Deleted a branch | `git reflog`, find its last commit, `git branch name <hash>` |
| `reset --hard` too far | `git reset --hard HEAD@{1}` (or a hash from the reflog) |
| A merge you didn't want (not pushed) | `git reset --hard ORIG_HEAD` |
| A pushed commit is bad | `git revert <hash>` |
| A pushed merge is bad | `git revert -m 1 <merge-hash>` |
| A rebase went wrong | `git rebase --abort` (during) or `git reset --hard ORIG_HEAD` (after) |
| Edited a file and want the old one back | `git restore --source=<hash> file` |
| Everything is weird | `git status`, then `git reflog`: they always tell you where you are |

## A secret was pushed

1. **Revoke it first** (new password, new API key). Assume bots already copied it: they scan GitHub within minutes.
2. Then, if you must, remove it from the history with [git filter-repo](https://github.com/newren/git-filter-repo) (`git filter-repo --replace-text secrets.txt`) and force-push. Everyone must clone again. Old copies and forks still have it, which is why step 1 matters most.

GitHub's **push protection** (in the repository's security settings) blocks many known secret formats before they land.
