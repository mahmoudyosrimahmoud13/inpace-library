# Worktrees, submodules and big files

## Worktrees: two branches open at once

A **worktree** is a second folder linked to the same repository, with another branch checked out. Review a pull request or fix a bug without touching your half-done work.

> **Optional video above.** Part of freeCodeCamp's *Advanced Git Tutorial* (with Tower), from 18:42 to 29:30. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```bash
git worktree add ../hotfix main        # a folder ../hotfix with main in it
cd ../hotfix   # ... fix, commit, push ...
git worktree list
git worktree remove ../hotfix
```

A branch can be open in only one folder at a time: if you're on main here, Git refuses to open main in a worktree. That's why you do it from your feature branch.

## Submodules: a repository inside a repository

A submodule pins another repository at one exact commit inside yours (a shared library, a theme).

```bash
git submodule add git@github.com:mona/theme.git themes/mine
git clone --recurse-submodules git@github.com:mona/site.git   # clone with them
git submodule update --init --recursive                       # after a normal clone
git submodule update --remote                                 # move to their newest commit
```

Submodules confuse people (they're pinned, so they don't update by themselves). Use them only when you must; a package manager (npm, pip) is often simpler.

## Big files: Git LFS

Git keeps every version of every file, so 500 MB of videos changed 10 times is 5 GB forever. **Git LFS** stores big files outside the history and keeps a small pointer instead:

```bash
git lfs install
git lfs track "*.mp4"      # writes a line in .gitattributes
git add .gitattributes video.mp4
git commit -m "Add intro video"
```
