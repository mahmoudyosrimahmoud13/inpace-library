# Merge conflicts

If both branches changed the same lines, Git can't choose for you. It stops and marks the file:

> **Optional video above.** Part of freeCodeCamp's *Git for Professionals* (with Tower), from 24:07 to 33:48. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```text
<<<<<<< HEAD
<h1>Welcome back</h1>
=======
<h1>Hello again</h1>
>>>>>>> login
```

Between `<<<<<<<` and `=======` is your side (HEAD), between `=======` and `>>>>>>>` is theirs. To resolve:

1. `git status` lists the files with conflicts ("both modified").
2. Edit each one: keep one side, the other, or a mix, and **delete the three marker lines**. VS Code shows buttons: *Accept Current*, *Accept Incoming*, *Accept Both*.
3. `git add` each fixed file.
4. `git commit` (Git writes the message for you).

Changed your mind? `git merge --abort` puts everything back as before the merge.

```bash
git checkout --ours styles.css      # take your whole version of one file
git checkout --theirs styles.css    # take theirs
git config --global merge.conflictStyle zdiff3   # also show the original lines, which makes conflicts easier to read
git config --global rerere.enabled true          # remember how you solved a conflict and reuse it next time
```

**Fewer conflicts:** keep branches short-lived, merge main into them often, and don't reformat whole files in a feature branch.
