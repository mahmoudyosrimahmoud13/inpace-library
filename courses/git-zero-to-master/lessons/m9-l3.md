# What merge and rebase really do

With objects and refs in mind, the big commands are simple:

- **commit:** write blobs and trees for the staged files, write a commit object whose parent is HEAD's commit, move the branch ref to it.
- **merge:** find the **merge base** (the newest common ancestor, `git merge-base main login`), combine both sides' changes since then, and write a commit with **two parents**.
- **rebase:** for each of your commits, apply its change on the new base and write a **new** commit with a new parent; then move the branch ref. The old commits still exist (the reflog has them) until Git cleans up.
- **reset:** move the branch ref (and, depending on the mode, the staging area and your files).
- **fetch:** download missing objects and update `refs/remotes/origin/*`.

Once this clicks, Git stops being scary: almost every command just writes objects and moves refs.

```bash
git merge-base main login        # the common ancestor
git log --oneline main..login     # commits on login that main doesn't have
git log --oneline --left-right main...login   # commits on either side, marked < and >
```
