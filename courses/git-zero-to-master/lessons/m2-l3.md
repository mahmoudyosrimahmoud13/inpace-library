# .gitignore and the perfect commit

## Ignore what doesn't belong

Some files should never be committed: passwords and keys (`.env`), things your tools make (`node_modules/`, `__pycache__/`, `dist/`), and system junk (`.DS_Store`). List them in a `.gitignore` file at the top of the project:

> **Optional video above.** Part of freeCodeCamp's *Git for Professionals* (with Tower), from 1:27 to 8:07. Everything you need is in the text below, so watch it only if it helps you: inPace remembers where you stopped.

```gitignore
# secrets
.env
*.key

# made by tools
node_modules/
__pycache__/
dist/
*.log

# but keep this one
!keep.log
```

Already committed a file by mistake? Ignoring it later isn't enough: also stop tracking it with `git rm --cached .env` (the file stays on your disk). If it was a password, **change the password**: it's still in the history. [github/gitignore](https://github.com/github/gitignore) has ready files for every language.

## The perfect commit

- **One change per commit.** Fixing a bug and renaming a file are two commits.
- **A subject line** of about 50 characters, in the imperative: *Add login form*, *Fix total when the list is empty*.
- **A body** after an empty line, for the *why*: what was wrong, why this fix. The diff already shows *what*.

Many teams use [Conventional Commits](https://www.conventionalcommits.org): `feat: add dark mode`, `fix: ...`, `docs: ...`. Tools can then write the changelog for you.
