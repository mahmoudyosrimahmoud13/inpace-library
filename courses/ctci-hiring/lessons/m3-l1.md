# Read: Big O (Part VI)

Read **Part VI** today, and do its examples and exercises with a pen. Big O is the language of every technical
interview: after you write a solution, the interviewer will almost always ask "what's the time and space complexity?".

## What to get from each section

| Section | The idea in one line |
|---|---|
| *An analogy*, *Time complexity* | Big O describes how the work **grows** as the input grows, not how many seconds it takes. |
| *Space complexity* | Memory counts too, including the call stack of recursive functions. |
| *Drop the constants* | O(2n) is O(n): we care about the shape of the growth. |
| *Drop the non-dominant terms* | O(n² + n) is O(n²): for large n, the biggest term wins. |
| *Multi-part algorithms: add vs. multiply* | One loop after another: add (O(a + b)). One loop inside another: multiply (O(a · b)). |
| *Amortized time* | An operation that's usually cheap and rarely expensive (like a growing list) can still be O(1) on average. |
| *Log N runtimes* | When each step halves the problem (binary search), the work is O(log n). |
| *Recursive runtimes* | A function that calls itself twice per level, n levels deep, does about 2ⁿ work. |

## A table to keep next to you

| Big O | Name | Typical code | n = 1,000,000 |
|---|---|---|---|
| O(1) | constant | read `a[i]`, look up a dictionary key | 1 step |
| O(log n) | logarithmic | binary search | about 20 steps |
| O(n) | linear | one loop over the input | 1 million |
| O(n log n) | linearithmic | a good sort | about 20 million |
| O(n²) | quadratic | a loop inside a loop | 1 trillion: too slow |
| O(2ⁿ) | exponential | trying every subset | impossible |

A rough rule for interviews: a computer does about 10⁸ simple steps per second. So if the input can have 100,000 items,
an O(n²) solution (10¹⁰ steps) is too slow, and you need O(n log n) or better.

## Common traps

- **Two different inputs need two letters.** Looping over list `a` and, inside, list `b` is O(a · b), not O(n²).
- **Hidden loops.** In Python, `x in my_list`, `my_list.index(x)`, slicing `s[1:]` and `sorted()` all take time. A
  "single loop" with `x in my_list` inside it is O(n²).
- **Strings are not free.** Building a string with `s = s + c` in a loop can copy the whole string each time.

## What to take away

- Big O measures growth: drop constants and smaller terms.
- Add the costs of steps in sequence, multiply the costs of nested steps.
- Watch for hidden loops inside built-in operations.
