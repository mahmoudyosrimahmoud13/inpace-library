# Build: watch Big O happen in Python

Timing code in seconds is noisy: it depends on your computer and on what else is running. Today you **count steps**
instead, so you can see the growth itself. Every number below comes from running the code.

## 1. Linear vs quadratic: finding a duplicate

Two ways to check whether a list has a repeated value. The first compares every pair. The second remembers what it has
seen in a set.

```python
def has_duplicate_pairs(nums):
    steps = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            steps += 1
            if nums[i] == nums[j]:
                return True, steps
    return False, steps

def has_duplicate_set(nums):
    steps, seen = 0, set()
    for x in nums:
        steps += 1
        if x in seen:                 # a set lookup is O(1) on average
            return True, steps
        seen.add(x)
    return False, steps

for n in [10, 100, 1000, 2000]:
    nums = list(range(n))             # no duplicates: the worst case for both
    print(f"n = {n:5d}: pairs {has_duplicate_pairs(nums)[1]:9,d} steps, set {has_duplicate_set(nums)[1]:5,d} steps")
```

```output
n =    10: pairs        45 steps, set    10 steps
n =   100: pairs     4,950 steps, set   100 steps
n =  1000: pairs   499,500 steps, set 1,000 steps
n =  2000: pairs 1,999,000 steps, set 2,000 steps
```

When n doubles from 1,000 to 2,000, the pairs version does about **four times** the work (n² grows that way), and the
set version does **twice** the work. The set version uses more memory, O(n), to save time: a trade you'll make again
and again.

## 2. Logarithmic: binary search

Binary search looks for a value in a **sorted** list by checking the middle and throwing away half each time.

```python
def binary_search(sorted_nums, target):
    lo, hi, steps = 0, len(sorted_nums) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if sorted_nums[mid] == target:
            return mid, steps
        if sorted_nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, steps

for n in [1_000, 1_000_000, 1_000_000_000]:
    nums = range(n)                   # a range behaves like a sorted list, without using memory
    print(f"n = {n:13,d}: found in {binary_search(nums, n - 1)[1]} steps")
```

```output
n =         1,000: found in 10 steps
n =     1,000,000: found in 20 steps
n = 1,000,000,000: found in 30 steps
```

A thousand times more data costs only about ten more steps. That's what O(log n) means: each step halves what's left,
and 2³⁰ is about a billion.

## 3. Recursion: one call or two?

The cost of a recursive function is roughly (number of calls) × (work per call). Here are two ways to compute
Fibonacci numbers, counting the calls.

```python
calls = 0
def fib_slow(n):
    global calls
    calls += 1
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)

def fib_memo(n, memo):
    global calls
    calls += 1
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

for n in [10, 20, 25]:
    calls = 0; value = fib_slow(n); slow = calls
    calls = 0; fib_memo(n, {}); fast = calls
    print(f"fib({n}) = {value:6d}: {slow:7,d} calls without memory, {fast:3d} with memory")
```

```output
fib(10) =     55:     177 calls without memory,  19 with memory
fib(20) =   6765:  21,891 calls without memory,  39 with memory
fib(25) =  75025: 242,785 calls without memory,  49 with memory
```

Without memory, each call makes two more, so the calls grow exponentially: going from 20 to 25 multiplies them by about
11. With a dictionary that remembers answers (memoization), each value is computed once, so the work is O(n). You'll
use this idea again on day 6, in dynamic programming.

## 4. The hidden loop

Python's `in` on a **list** scans the list. This code has one visible loop, but it is O(n²):

```python
def count_common_slow(a, b):
    return sum(1 for x in a if x in b)          # `x in b` scans b: O(len(a) * len(b))

def count_common_fast(a, b):
    b_set = set(b)                               # O(len(b)) once
    return sum(1 for x in a if x in b_set)       # each lookup O(1): O(len(a) + len(b)) in total

a, b = list(range(0, 4000, 2)), list(range(0, 4000, 3))
print(count_common_slow(a, b), count_common_fast(a, b))
```

```output
667 667
```

Same answer, very different growth. In an interview, say this kind of thing out loud: "`in` on a list is linear, so
I'll turn it into a set first."

## What to take away

- Counting steps shows Big O directly: n² work quadruples when n doubles, log n work barely moves.
- Memory can buy time: a set or a dictionary often turns O(n²) into O(n).
- Recursive cost is about calls × work per call; memoization stops repeated calls.
