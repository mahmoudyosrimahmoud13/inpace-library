## Hash tables: the most useful tool you have

A hash table maps keys to values with O(1) lookups on average. In Python it's `dict` (and `set` for keys alone). It
works by turning each key into a number (its hash) that says where to store it.

The interview pattern: **when you're searching the same list again and again, store it in a hash table once.**

```python
from collections import Counter

def is_permutation(a, b):
    """Are the two strings rearrangements of each other? O(len(a) + len(b))."""
    return len(a) == len(b) and Counter(a) == Counter(b)

def first_unique_char(s):
    """Index of the first character that appears once, or -1. Two passes, O(n)."""
    counts = Counter(s)
    for i, ch in enumerate(s):
        if counts[ch] == 1:
            return i
    return -1

print(is_permutation("listen", "silent"), is_permutation("apple", "paple"), is_permutation("abc", "abd"))
print(first_unique_char("swiss"), first_unique_char("aabb"))
```

```output
True True False
1 -1
```

## Resizable arrays: why `append` is O(1)

A Python list keeps extra room at the end. When it fills up, it moves to a bigger block of memory. Moving is expensive,
but it happens rarely, so the **amortized** cost of `append` is O(1) (Part VI). You can watch Python grow the list:

```python
import sys

items, last_size, growths = [], sys.getsizeof([]), []
for i in range(64):
    items.append(i)
    size = sys.getsizeof(items)
    if size != last_size:
        growths.append(len(items))
        last_size = size
print("the list grew its memory when it reached these lengths:", growths)
```

```output
the list grew its memory when it reached these lengths: [1, 5, 9, 17, 25, 33, 41, 53]
```

Only 8 of the 64 appends needed more memory, and the gaps between growths widen as the list gets longer (Python adds
about an eighth of the current size, plus a few spare places, each time), so most appends cost nothing extra. (The exact lengths depend on your Python
version.)

## Building strings

Strings in Python can't be changed. `s = s + c` makes a new string, which can copy everything built so far. Collect the
pieces in a list and join them once instead.

```python
def compress(s):
    """'aabcccccaaa' -> 'a2b1c5a3'; return s itself if that isn't shorter."""
    parts, i = [], 0
    while i < len(s):
        j = i
        while j < len(s) and s[j] == s[i]:
            j += 1
        parts.append(s[i] + str(j - i))      # one character and how many times it repeats
        i = j
    out = "".join(parts)                     # one join at the end: O(n)
    return out if len(out) < len(s) else s

print(compress("aabcccccaaa"), compress("abc"))
```

```output
a2b1c5a3 abc
```

## Two pointers and in-place changes

Many array questions ask you to work **in place**, without a second array. Two indexes that move through the array are
often the answer. For example, rotating a square matrix by 90 degrees clockwise: flip it along the diagonal, then
reverse each row.

```python
def rotate(matrix):
    n = len(matrix)
    for i in range(n):
        for j in range(i + 1, n):
            matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]   # transpose
    for row in matrix:
        row.reverse()                                                 # mirror left to right

m = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
rotate(m)
for row in m:
    print(row)
```

```output
[7, 4, 1]
[8, 5, 2]
[9, 6, 3]
```

## What to take away

- Hash tables give O(1) average lookups: the first tool to try when a search repeats.
- `append` is amortized O(1) because the list grows in bigger and bigger steps.
- Build strings with a list and one `join`; solve in-place questions with indexes that swap values.
