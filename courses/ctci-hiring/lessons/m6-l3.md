## The sorts to know

| Sort | Time (typical) | Worst | Extra space | Note |
|---|---|---|---|---|
| Bubble, selection | O(n²) | O(n²) | O(1) | Only for explaining |
| Merge sort | O(n log n) | O(n log n) | O(n) | Splits in half, sorts, merges; stable |
| Quick sort | O(n log n) | O(n²) | O(log n) | Partitions around a pivot; fast in practice |
| Radix sort | O(k · n) | O(k · n) | O(n) | For integers with k digits |
| Python's `sorted` | O(n log n) | O(n log n) | O(n) | Timsort, stable |

**Stable** means equal items keep their original order. It matters when you sort by one key and then another.

Merge sort is worth writing from memory, because its merge step solves many interview questions on its own:

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:              # <= keeps equal items in order: stable
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    return merged + left[i:] + right[j:]

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
```

```output
[3, 9, 10, 27, 38, 43, 82]
```

## Merging from the back

A common question: array A has enough empty space at its end to hold sorted array B; merge B into A in place. Filling
from the **front** would overwrite values of A you still need. Filling from the **back** never does.

```python
def merge_into(a, m, b):
    """a holds m sorted values followed by len(b) empty places."""
    i, j, k = m - 1, len(b) - 1, m + len(b) - 1
    while j >= 0:
        if i >= 0 and a[i] > b[j]:
            a[k] = a[i]; i -= 1
        else:
            a[k] = b[j]; j -= 1
        k -= 1
    return a

print(merge_into([1, 4, 7, 0, 0, 0], 3, [2, 3, 9]))
```

```output
[1, 2, 3, 4, 7, 9]
```

## Binary search, adapted

Binary search works whenever you can throw away half of the remaining options with one check. In a sorted array that
was **rotated** (`[15, 16, 19, 20, 25, 1, 3, 4, 5, 7, 10, 14]`), one half around the middle is always in order. Check
whether the target lies in that half; if not, search the other.

```python
def search_rotated(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[lo] <= a[mid]:                       # the left half is in order
            if a[lo] <= target < a[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                     # the right half is in order
            if a[mid] < target <= a[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1

a = [15, 16, 19, 20, 25, 1, 3, 4, 5, 7, 10, 14]
print([search_rotated(a, t) for t in [5, 15, 14, 8]])
```

```output
[8, 0, 11, -1]
```

## Sorting as a tool

Sorting first often makes a problem easy: duplicates become neighbours, pairs can be found with two pointers, and
anagrams share a sorted form. It costs O(n log n), which is often acceptable.

```python
from collections import defaultdict

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)      # anagrams have the same sorted letters
    return list(groups.values())

print(group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"]))
```

```output
[['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
```
