# Finding things: grep and find

## grep: search inside files

```bash
grep error app.log               # lines containing "error"
grep -i error app.log            # ignore case
grep -n error app.log            # show line numbers
grep -v DEBUG app.log            # lines NOT containing DEBUG
grep -r "listen" /etc/nginx/     # search a whole directory tree
grep -c error app.log            # count matching lines
grep -E "error|warn" app.log     # extended regex: either word
grep -A 3 -B 1 Traceback app.log # 3 lines after, 1 before each match
```

## A little regex goes a long way

| Pattern | Matches |
|---|---|
| `^ERROR` | ERROR at the start of a line |
| `done$` | done at the end |
| `.` | any one character |
| `.*` | anything |
| `[0-9]+` | one or more digits (with `-E`) |
| `\bcat\b` | the word cat, not "category" |

```bash
grep -E "^[0-9]{1,3}(\.[0-9]{1,3}){3}" access.log   # lines starting with an IPv4 address
```

`ripgrep` (`rg`) is a faster grep that skips `.git` and ignored files; great on code.

## find: search for files by name, type, size, time

```bash
find . -name "*.log"                 # by name, under here
find /var -type d -name "cache*"     # directories only
find ~ -type f -size +100M           # files over 100 MB
find . -mtime -1                     # changed in the last day
find . -name "*.tmp" -delete         # delete what it finds (careful!)
find . -name "*.py" -exec wc -l {} +  # run a command on the results
```

Read `find` left to right: **where**, then **tests**, then **action**.

## locate: instant, but from a database

`locate nginx.conf` searches a database refreshed daily (`sudo updatedb` to refresh now). Fast, but won't see files created since.

## Which one?

- Looking for **text inside** files: `grep -r` (or `rg`).
- Looking for **files** by name, size, age, owner: `find`.
