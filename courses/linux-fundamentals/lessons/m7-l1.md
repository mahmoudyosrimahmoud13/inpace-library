# Users, groups and permissions

## Users and groups

Every process runs as a **user**; every file has an **owner** and a **group**.

```bash
id                      # your user id, group id, and every group you're in
cat /etc/passwd | head  # user accounts (name:x:UID:GID:comment:home:shell)
cat /etc/group | head   # groups
getent passwd sara      # one user, wherever accounts come from
```

- **root** (UID 0) can do anything. 
- UIDs below 1000 are usually system accounts for services (`www-data`, `postgres`).
- Your groups decide what else you can do (`sudo` group: admin rights; `docker` group: use Docker).

## Reading permissions

```text
-rwxr-x---  sara  devs  deploy.sh
 └┬┘└┬┘└┬┘
  │  │  └ others: ---  nothing
  │  └ group devs: r-x  read and run
  └ owner sara: rwx    read, write, run
```

| Letter | On a file | On a directory |
|---|---|---|
| `r` | Read the contents | List the names inside |
| `w` | Change the contents | Create, rename, delete files inside |
| `x` | Run it as a program | Enter it (`cd`) and reach files inside |

Deleting a file depends on the **directory's** `w`, not the file's.

## chmod

```bash
chmod u+x deploy.sh        # owner may run it
chmod g-w report.txt       # group may not write
chmod o= secret.txt        # others: nothing
chmod 640 secret.txt       # numbers: r=4 w=2 x=1 -> owner 6 (rw), group 4 (r), others 0
chmod -R g+rX shared/      # capital X: x only on directories (and already-runnable files)
```

Common numbers: `755` programs and directories, `644` normal files, `600` private files (SSH keys must be this), `700` private directories.

## chown

```bash
sudo chown sara report.txt
sudo chown sara:devs report.txt
sudo chown -R www-data:www-data /var/www/site
```

## umask

New files start from `666` (files) or `777` (directories) minus the **umask**. With the common umask `022`, new files are `644` and directories `755`.

## sudo

`sudo command` runs one command as root, after your own password, if you're allowed (the `sudo` group on Ubuntu, `wheel` on Red Hat, rules in `/etc/sudoers`, edited only with `visudo`).

- Use `sudo` per command, not a root shell all day.
- Everything done with `sudo` is logged (`journalctl | grep sudo` or `/var/log/auth.log`).
