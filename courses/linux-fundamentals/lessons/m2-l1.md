# Commands, options, arguments and help

## The shape of a command

```text
ls   -l -h   /var/log
│    │       └ argument: what to work on
│    └ options (flags): how to do it
└ command
```

- Short options: one dash, one letter, and they combine: `ls -l -h` is `ls -lh`.
- Long options: two dashes, a word: `ls --human-readable`.
- Some options take a value: `head -n 5 file`, `sort --key=2`.
- Spaces separate arguments, so names with spaces need quotes: `cd "My Documents"`.

## Getting help (you'll do this daily)

| Command | What you get |
|---|---|
| `ls --help` | A short summary of options |
| `man ls` | The full manual page. Space for next page, `/word` to search, `q` to quit |
| `man -k copy` | Search manual pages by keyword |
| `tldr tar` | Short practical examples (install the `tldr` package) |
| `type cd` / `which ls` | Is it a shell builtin or a program, and where is it? |

Manual pages are split into sections: `1` commands, `5` file formats, `8` admin commands. `man 5 passwd` is the file format, not the command.

## Builtins and programs

```bash
type cd        # cd is a shell builtin (it has to be: it changes the shell itself)
type ls        # ls is aliased to `ls --color=auto`, or /usr/bin/ls
which python3
```

## Exit codes

Every command ends with a number: **0 means success**, anything else is a kind of failure.

```bash
ls /etc > /dev/null; echo $?      # 0
ls /nope;            echo $?      # 2 (or another non-zero)
mkdir backup && echo "made it"    # && runs the second only if the first succeeded
mkdir backup || echo "already there"   # || runs it only if the first failed
```

Exit codes are what scripts and automation rely on. They come back in the Bash course.
