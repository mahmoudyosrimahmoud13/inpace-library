# Extensibility, testing, and the final list

- **Extensibility:** the design can grow new features without being rewritten. Clear boundaries between parts (for
  example, the video-processing service doesn't care who uploads the video) make this possible.
- **Testing:** a good design is easy to test. Small parts with clear inputs and outputs can be tested alone; the whole
  system is then tested with load tests and failure tests (kill a server on purpose and watch what happens).

## The requirement list, written down

Write the list before moving on. A good beginner list for live streaming:

```text
Functional:      broadcaster sends a live stream; viewers watch it; viewers choose quality; short rewind
Non-functional:  low latency (a few seconds), millions of concurrent viewers, fault tolerant, extensible
Out of scope:    payments, recommendations, comments
```
