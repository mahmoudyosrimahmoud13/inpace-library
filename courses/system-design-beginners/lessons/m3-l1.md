# Network protocols: TCP, UDP and HTTP

| Protocol | Promise | Good for |
|---|---|---|
| **TCP** | every byte arrives, in order; lost packets are re-sent | web pages, APIs, file uploads |
| **UDP** | fast, no re-sending, packets may be lost | live video calls, games, where late data is useless |
| **HTTP** (on TCP) | requests and responses | APIs and serving video segments |
| **WebSocket** | one long-lived two-way connection | chat, live comments, notifications |

The trade-off: **reliability vs latency**. For a video call, a lost frame is better than a late one, so UDP-based
protocols win. For a sports stream where a few seconds of delay is fine, chunks over HTTP (on TCP) are simpler and
work with CDNs.
