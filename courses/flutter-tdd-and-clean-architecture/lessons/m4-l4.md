## What to watch for

Focus on how all the classes created throughout the course are finally connected. Pay special attention to the difference between factories and singletons and to why dependency injection removes manual object construction from UI code.

## The dependency problem

Consider:

```dart
final repository = NumberTriviaRepositoryImpl(
  remoteDataSource: ...,
  localDataSource: ...,
  networkInfo: ...,
);
```

That repository itself requires several dependencies. Those dependencies require more dependencies.

If every class constructs its own dependencies, object creation becomes scattered throughout the application.

## Dependency injection

Instead, dependencies are created outside the class and passed into its constructor.

```dart
class GetTrivia {
  final Repository repository;

  GetTrivia(this.repository);
}
```

The class declares what it needs without deciding how it is created.

## Service locator

The course uses `get_it` as a service locator.

Conceptually:

```text
Register dependencies
        ↓
Service locator
        ↓
Resolve dependencies
        ↓
Construct application graph
```

The dependency container becomes the composition root of the application.

## Factory versus singleton

A factory creates a new instance when requested.

A singleton represents one shared instance.

Presentation logic such as a BLoC is commonly registered as a factory because its lifecycle is associated with a particular UI context.

Stateless services can often be registered as lazy singletons when sharing one instance is appropriate.

The important point is not to choose one lifetime everywhere. Object lifetime should follow ownership and state requirements.

## Async dependencies

Some dependencies require asynchronous initialization.

SharedPreferences, for example, may need initialization before an instance is available.

Therefore, the dependency container itself may need asynchronous initialization:

```dart
Future<void> init() async {
  final preferences = await SharedPreferences.getInstance();
  // register dependencies
}
```

The application waits for initialization before building the UI.

## Summary

Dependency injection moves object construction to a dedicated composition point. Classes become easier to test and reuse because they receive dependencies instead of constructing them internally.
