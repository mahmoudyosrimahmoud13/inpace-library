## What to watch for

Watch how the course moves outward from the stable domain toward the data layer. Focus on why models are different from entities and why repositories act as a boundary between the application and external data sources.

## The data layer

The data layer is where the application meets external systems.

Examples include:

- REST APIs
- databases
- local storage
- files
- platform APIs
- third-party SDKs

These technologies are useful but unstable from the perspective of business logic. APIs can change, storage libraries can be replaced, and network behavior can fail.

Clean Architecture isolates those details.

## Entities versus models

An entity represents business meaning.

A model represents data in a form suitable for a particular data source or serialization mechanism.

For example:

```dart
class NumberTriviaModel extends NumberTrivia {
  const NumberTriviaModel({
    required int number,
    required String text,
  }) : super(
    number: number,
    text: text,
  );

  factory NumberTriviaModel.fromJson(Map<String, dynamic> json) {
    return NumberTriviaModel(
      number: json['number'] as int,
      text: json['text'] as String,
    );
  }

  Map<String, dynamic> toJson() {
    return {
      'number': number,
      'text': text,
    };
  }
}
```

The JSON-specific logic belongs in the model, not in the entity.

## Why this separation matters

Suppose the API changes from JSON to XML. If JSON parsing is embedded throughout the domain, changing the external format becomes expensive.

With models, the conversion remains near the data boundary:

```text
External JSON
     ↓
Data Model
     ↓
Domain Entity
     ↓
Use Case
```

The domain receives an object representing the actual business concept.

## Repository as a boundary

The repository provides the domain with a stable interface while hiding the details of data acquisition.

A repository may decide:

- whether to call the remote source;
- whether cached data is acceptable;
- when to save data locally;
- how exceptions become failures.

This makes the repository a policy boundary, not simply a class that forwards method calls.

## Summary

Models handle external representations. Entities represent domain concepts. Repositories coordinate data access and protect the domain from infrastructure details.
