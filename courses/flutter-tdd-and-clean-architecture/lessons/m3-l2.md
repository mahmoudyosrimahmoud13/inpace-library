## What to watch for

Pay attention to how HTTP behavior is tested without making real API requests. Watch the mapping between HTTP responses, models, and exceptions.

## Remote data source responsibility

The remote data source should know how to communicate with the API.

It should handle details such as:

- URL construction;
- HTTP requests;
- response status codes;
- JSON decoding;
- conversion into models.

It should not decide whether the application should use remote or cached data. That is the repository's responsibility.

## Example flow

```text
Repository
    ↓
RemoteDataSource contract
    ↓
RemoteDataSource implementation
    ↓
HTTP client
    ↓
Numbers API
```

The implementation converts the HTTP response into a `NumberTriviaModel`.

## HTTP success and failure

A successful response can be decoded:

```dart
final response = await client.get(uri);

if (response.statusCode == 200) {
  return NumberTriviaModel.fromJson(
    json.decode(response.body),
  );
}

throw ServerException();
```

The exact status handling depends on the API contract, but the principle is stable: infrastructure-level errors should be represented by infrastructure exceptions.

## Testing HTTP behavior

A unit test should not depend on the real Numbers API.

Instead, mock the HTTP client and provide a fake response.

For example:

```dart
when(mockClient.get(any))
    .thenAnswer(
      (_) async => Response(
        fixture('trivia.json'),
        200,
      ),
    );
```

Then verify that the data source returns the expected model.

A second test can return an unsuccessful status code and verify that `ServerException` is thrown.

## Fixtures

A fixture is a saved example of external data, such as a JSON response.

Fixtures make tests readable and deterministic:

```text
test/
└── fixtures/
    └── trivia.json
```

The test can repeatedly use the same realistic response without contacting the network.

## Summary

The remote data source owns HTTP and JSON concerns. It converts successful responses into models and translates unsuccessful responses into data-layer exceptions. The repository remains responsible for deciding when this source should be used.
