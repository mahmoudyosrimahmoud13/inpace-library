# بناء: شاهد Big O تحدث في Python

قياس الكود بالثواني فيه ضوضاء: يعتمد على جهازك وعلى ما يعمل غيره في الوقت نفسه. اليوم **تعدّ الخطوات** بدلًا من ذلك،
لترى النمو نفسه. كل رقم بالأسفل ناتج عن تشغيل الكود.

## 1. خطي مقابل تربيعي: البحث عن قيمة مكررة

طريقتان للتحقق هل في القائمة قيمة مكررة. الأولى تقارن كل زوج. والثانية تتذكر ما رأته في set.

```python
def has_duplicate_pairs(nums):
    steps = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            steps += 1
            if nums[i] == nums[j]:
                return True, steps
    return False, steps

def has_duplicate_set(nums):
    steps, seen = 0, set()
    for x in nums:
        steps += 1
        if x in seen:                 # a set lookup is O(1) on average
            return True, steps
        seen.add(x)
    return False, steps

for n in [10, 100, 1000, 2000]:
    nums = list(range(n))             # no duplicates: the worst case for both
    print(f"n = {n:5d}: pairs {has_duplicate_pairs(nums)[1]:9,d} steps, set {has_duplicate_set(nums)[1]:5,d} steps")
```

```output
n =    10: pairs        45 steps, set    10 steps
n =   100: pairs     4,950 steps, set   100 steps
n =  1000: pairs   499,500 steps, set 1,000 steps
n =  2000: pairs 1,999,000 steps, set 2,000 steps
```

حين تتضاعف n من 1,000 إلى 2,000، تعمل نسخة الأزواج نحو **أربعة أضعاف** العمل (هكذا تنمو n²)، وتعمل نسخة الـ set
**ضعفه**. نسخة الـ set تستخدم ذاكرة أكثر، O(n)، لتوفر الوقت: مقايضة ستفعلها مرارًا.

## 2. لوغاريتمي: binary search

يبحث الـ binary search عن قيمة في قائمة **مرتبة**، بفحص المنتصف والتخلص من النصف في كل مرة.

```python
def binary_search(sorted_nums, target):
    lo, hi, steps = 0, len(sorted_nums) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if sorted_nums[mid] == target:
            return mid, steps
        if sorted_nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, steps

for n in [1_000, 1_000_000, 1_000_000_000]:
    nums = range(n)                   # a range behaves like a sorted list, without using memory
    print(f"n = {n:13,d}: found in {binary_search(nums, n - 1)[1]} steps")
```

```output
n =         1,000: found in 10 steps
n =     1,000,000: found in 20 steps
n = 1,000,000,000: found in 30 steps
```

ألف ضعف من البيانات لا تكلف إلا نحو عشر خطوات زيادة. هذا معنى O(log n): كل خطوة تقسم الباقي نصفين، و2³⁰ نحو مليار.

## 3. الـ recursion: استدعاء واحد أم اثنان؟

تكلفة الدالة الـ recursive تقريبًا = (عدد الاستدعاءات) × (العمل في كل استدعاء). هذه طريقتان لحساب أعداد Fibonacci، مع
عدّ الاستدعاءات.

```python
calls = 0
def fib_slow(n):
    global calls
    calls += 1
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)

def fib_memo(n, memo):
    global calls
    calls += 1
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

for n in [10, 20, 25]:
    calls = 0; value = fib_slow(n); slow = calls
    calls = 0; fib_memo(n, {}); fast = calls
    print(f"fib({n}) = {value:6d}: {slow:7,d} calls without memory, {fast:3d} with memory")
```

```output
fib(10) =     55:     177 calls without memory,  19 with memory
fib(20) =   6765:  21,891 calls without memory,  39 with memory
fib(25) =  75025: 242,785 calls without memory,  49 with memory
```

بدون ذاكرة، كل استدعاء يُنتج اثنين، فتنمو الاستدعاءات أُسّيًا: الانتقال من 20 إلى 25 يضربها في نحو 11. ومع dictionary
يتذكر الإجابات (memoization)، تُحسب كل قيمة مرة واحدة، فيصبح العمل O(n). ستستخدم هذه الفكرة مرة أخرى في اليوم 6، في
الـ dynamic programming.

## 4. الحلقة المخفية

`in` في Python على **list** تمر على القائمة. هذا الكود فيه حلقة ظاهرة واحدة، لكنه O(n²):

```python
def count_common_slow(a, b):
    return sum(1 for x in a if x in b)          # `x in b` scans b: O(len(a) * len(b))

def count_common_fast(a, b):
    b_set = set(b)                               # O(len(b)) once
    return sum(1 for x in a if x in b_set)       # each lookup O(1): O(len(a) + len(b)) in total

a, b = list(range(0, 4000, 2)), list(range(0, 4000, 3))
print(count_common_slow(a, b), count_common_fast(a, b))
```

```output
667 667
```

الإجابة نفسها، ونمو مختلف تمامًا. في المقابلة، قل هذا النوع من الكلام بصوت عالٍ: "`in` على list خطية، فسأحوّلها إلى
set أولًا."

## الخلاصة

- عدّ الخطوات يُظهر Big O مباشرةً: عمل n² يتضاعف أربع مرات حين تتضاعف n، وعمل log n بالكاد يتحرك.
- الذاكرة تشتري الوقت: set أو dictionary كثيرًا ما تحوّل O(n²) إلى O(n).
- تكلفة الـ recursion تقريبًا الاستدعاءات × العمل في كل استدعاء؛ والـ memoization توقف الاستدعاءات المكررة.
