# Build: three graphs, and naive Bayes on digits

## 1. Check the three graphs by simulation

Each graph uses binary variables. Measure dependence as the change in `p(a = 1)` when we learn b, with and without
knowing c.

```python
import numpy as np

rng = np.random.default_rng(0)
n = 2_000_000

def flip(p):
    return rng.random(n) < p

def report(name, a, b, c):
    gap_free = abs(a[b].mean() - a[~b].mean())
    gap_given_c = abs(a[b & c].mean() - a[~b & c].mean())
    print(f"{name:13s}  a,b dependent? gap {gap_free:.3f}    given c: gap {gap_given_c:.3f}")

c = flip(0.5)                                            # tail-to-tail: a <- c -> b
report("tail-to-tail", flip(np.where(c, 0.9, 0.2)), flip(np.where(c, 0.8, 0.1)), c)

a = flip(0.5)                                            # head-to-tail: a -> c -> b
c = flip(np.where(a, 0.9, 0.2))
report("head-to-tail", a, flip(np.where(c, 0.8, 0.1)), c)

a, b = flip(0.5), flip(0.5)                              # head-to-head: a -> c <- b
c = flip(np.where(a | b, 0.9, 0.05))
report("head-to-head", a, b, c)
```

```output
tail-to-tail   a,b dependent? gap 0.494    given c: gap 0.001
head-to-tail   a,b dependent? gap 0.491    given c: gap 0.000
head-to-head   a,b dependent? gap 0.000    given c: gap 0.448
```

A gap near zero means independence. The first two graphs lose their dependence when c is observed; the head-to-head
graph does the opposite, exactly as the table in section 11.2.1 says.

## 2. Naive Bayes on handwritten digits (11.2.4)

Turn each 8 × 8 digit into 64 yes/no pixels (ink or no ink). Naive Bayes assumes the pixels are independent **given
the digit**. Then each class needs just 64 Bernoulli probabilities, fitted by counting.

```python
from sklearn.datasets import load_digits

digits = load_digits()
X = (digits.data > 4).astype(int)                       # binary pixels
y = digits.target
idx = rng.permutation(len(y))
tr, te = idx[:1300], idx[1300:]

prior = np.array([np.mean(y[tr] == k) for k in range(10)])
# p(pixel on | class), with one imaginary 'on' and one 'off' example per pixel so nothing is exactly 0 or 1
theta = np.array([(X[tr][y[tr] == k].sum(0) + 1) / ((y[tr] == k).sum() + 2) for k in range(10)])

def log_posterior(Xq):
    # log p(class) + Σ log p(pixel | class): the independence assumption turns the product into a sum
    return np.log(prior) + Xq @ np.log(theta).T + (1 - Xq) @ np.log(1 - theta).T

pred = log_posterior(X[te]).argmax(axis=1)
print(f"naive Bayes test accuracy: {np.mean(pred == y[te]):.3f}  ({10 * 64 + 9} numbers, fitted by counting)")
```

```output
naive Bayes test accuracy: 0.887  (649 numbers, fitted by counting)
```

Not bad for a model that ignores how pixels relate to each other, and it trains in a few milliseconds without any
optimization. Its weakness: neighbouring pixels are strongly dependent, and the model counts their evidence as if it
were independent, which makes its probabilities over-confident.

```python
post = log_posterior(X[te])
post = np.exp(post - post.max(axis=1, keepdims=True))
post /= post.sum(axis=1, keepdims=True)
print(f"share of test digits where naive Bayes is more than 99% sure: {np.mean(post.max(axis=1) > 0.99):.2f}")
print(f"accuracy on those 'sure' digits:                             {np.mean(pred[post.max(axis=1) > 0.99] == y[te][post.max(axis=1) > 0.99]):.3f}")
```

```output
share of test digits where naive Bayes is more than 99% sure: 0.70
accuracy on those 'sure' digits:                             0.960
```

It claims more than 99% certainty on 70% of the digits, yet about 4% of those "certain" answers are wrong, when a
well-calibrated model would get fewer than 1% wrong. It is over-confident. Compare with part
2's network, whose confidence on its mistakes was much lower.

## 3. A hidden Markov model, by ancestral sampling

A hidden weather chain (sunny or rainy, sticky from day to day) generates what we observe (an umbrella or not).

```python
stay = np.array([[0.9, 0.1],          # p(next state | sunny)
                 [0.3, 0.7]])         # p(next state | rainy)
p_umbrella = np.array([0.1, 0.8])     # p(umbrella | state)

state = 0
hidden, seen = [], []
for day in range(30):
    hidden.append(state)
    seen.append(int(rng.random() < p_umbrella[state]))
    state = int(rng.random() < stay[state, 1])
print("hidden:  ", "".join("SR"[s] for s in hidden))
print("observed:", "".join(".U"[o] for o in seen))
```

```output
hidden:   SSSSRRRSSRRRSSRRRSSSSSSSSSSSSR
observed: U...UUU..UUUU.UUU....U.......U
```

The observations are noisy hints of a hidden state with memory. Inferring the hidden chain from the umbrellas is the
classic HMM problem; the latent-variable methods of chapters 15 and 16 are its relatives.
