# Meet the dataset

Each row is **one order**. That's the "grain" of the table: always know what one row means.

| Column | Type | Example | Meaning |
|---|---|---|---|
| order_id | number (id) | 10001 | unique order number |
| date | date | 2025-03-14 | day of the order |
| branch | text | Zamalek | one of four branches |
| product | text | Cappuccino | what was sold |
| category | text | Coffee | Coffee, Tea, Pastry, Cold drinks |
| quantity | whole number | 2 | items in the order |
| unit_price | number (EGP) | 70 | price of one item |
| customer_type | text | Member | Member or Guest |
| payment | text | Card | Card, Cash or Wallet |
| sales | number (EGP) | 140 | quantity × unit_price |

## Things to notice before you start

- Prices went up 10% in **July**. That matters when you compare months.
- **Thursday and Friday** are busier.
- `branch_targets.csv` has a monthly sales target for each branch.

## Tidy data, in one rule

**One row per thing, one column per fact, one value per cell.** A sheet with merged cells, totals in the middle and
colours meaning something is a report, not data. Analysts keep the data tidy and build reports **from** it.
