## Queries

- **What is a query?** Read the short refresher on the parts of SQL: data definition (DDL), data manipulation (DML),

- **The life of a query** (Figure 8-2): parse, convert to bytecode, optimize, execute, return results.
- **The query optimizer**: why the same SQL can run fast or slow, and why you should look at its plan.

## Improving query performance

This section is pure practice. Read each tip and note one example from your own work:

- Optimize your **join strategy** and schema: pre-join data that's always joined together, and watch out for **row
  explosion** when a join key isn't unique.
- Use the **explain plan**, and watch query performance: scans, joins, spills to disk, resource use.
- **Avoid full table scans**: query only the columns and rows you need; use **pruning** (partitions, clustering, sort
  keys).
- Know how your database handles **commits**.
- **Vacuum dead records**.
- Leverage **cached query results**.

## Queries on streaming data

Read the basics: fast-follower ("the query runs on a live copy") versus truly streaming queries, then **windows**:
**session**, **fixed-time** (also called tumbling) and **sliding** (Figures 8-5 to 8-7). Then **watermarks**: how a
window decides it has waited long enough for late data. Skim the parts on combining streams with other data and
enrichment.

## After reading

Think of the slowest query you've run. Which of the tips above would have helped it most?

## What to take away

- Read the query plan before you tune anything.
- Scan less: fewer columns, fewer rows, fewer partitions.
- Check row counts before and after every join.
- Streaming queries group events into windows, and watermarks decide when a window is complete.
