# Project 3: loose coupling and planning for failure

Inkwell's web app sends a confirmation email for every order. Today the app calls the email service directly, and
when that service has a bad day, customers can't buy. You'll show the owner why, and what the fix looks like.

The code is above this text. Save it as `p03_decoupled.py`.

## Read the code

- **`send_email()`** is a flaky downstream service: it fails about 40% of the time. Its random generator has a
  fixed seed, so you get the same failures as the output below.
- **`place_order_tight()`**: the order waits for the email, and fails when the email fails.
- **`place_order_loose()`**: the order drops a small JSON file (an event) into `queue/` and returns. A folder is
  the simplest possible queue; Kafka, Amazon SQS and Google Pub/Sub play this part in real systems.
- **`consume()`**: a separate worker reads the queue and, for each event:
  - **retries** up to 5 times. Real systems wait longer between tries ("backoff"): 1 s, 2 s, 4 s...;
  - remembers handled orders in `done.json` **before** deleting the event. If it crashes between the two, the event is
    handled again next time but skipped as "already done": no double email;
  - leaves events that still fail in the queue for the next run. Real systems move them to a **dead-letter queue**.
- At the end, five events arrive **again**, as when a producer retries or a queue redelivers. The consumer must not
  send five more emails.

## Run it

```bash
python p03_decoupled.py
```

The real output:

```text
Tight coupling: 13 of 20 orders succeeded (the rest failed because email did)
Loose coupling: 20 of 20 orders succeeded
Consumer, first run: {'sent': 20, 'skipped_already_done': 0, 'retries': 10, 'gave_up': 0}
Consumer, after duplicates arrived: {'sent': 0, 'skipped_already_done': 5, 'retries': 0, 'gave_up': 0}
```

Seven customers lost their order in the tight design. In the loose one, every order went through; the consumer
needed 10 retries, which nobody noticed, and the duplicates were skipped.

## What to take away

- Tight coupling spreads failures; loose coupling contains them.
- Anything that retries can deliver twice. Consumers must be idempotent.
- Record the big decisions while you still remember why you made them.
