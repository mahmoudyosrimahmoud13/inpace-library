# Project 12, part 2: the whole pipeline, on a schedule

Twelve days ago Inkwell had a web app and a spreadsheet. Now it has a source with change capture, a lake, a tested
warehouse, a dashboard, ML features, a win-back list, privacy controls and backups. The last step: make it run every
night **without you**.

The code is above this text. Save it as `run_all.py`.

## Read the code

- **`TASKS`** is the DAG: each task is a script and the tasks it depends on. `generate` plays one more day of
  business at the shop (in real life the shop does that on its own); then `ingest`, `transform`, and two tasks that
  both need `transform` but not each other: `serve` and `secure`.
- **`TopologicalSorter`** gives the order, as in project 10, one level up: the DAG now links whole steps instead of
  SQL models.
- **`run_task()`** runs a script as its own process (so a crash in one can't take down the orchestrator), and on
  failure **retries** up to 2 more times, waiting 2 then 4 seconds (**backoff**).
- If a task still fails, everything downstream is **skipped**, not run on broken data.
- Every run appends one line to `logs/pipeline_runs.jsonl`: when it started and ended, and each task's result. The
  script exits with code 1 on failure, which is how schedulers know to alert someone.

```bash
python run_all.py
```

## Watch it fail safely

Add a test that always fails (`tests/zz_fails.sql` containing `SELECT 1 AS broken`) and run again. The real output:

```text
Pipeline run 2026-11-24T04:51:56Z
  OK    generate     0.0 s
  OK    ingest       0.3 s
  FAIL  transform  attempt 1: ['[p10] tests failed, nothing published  failed=zz_fails']
  FAIL  transform  attempt 2: ['[p10] tests failed, nothing published  failed=zz_fails']
  FAIL  transform  attempt 3: ['[p10] tests failed, nothing published  failed=zz_fails']
  SKIP  serve      (an upstream task failed)
  SKIP  secure     (an upstream task failed)
Run FAILED
```

`transform` was tried three times, then `serve` and `secure` were skipped: the dashboard and the analyst's file still
show the last good data. Delete `tests/zz_fails.sql` and run again: everything is green.

## Schedule it

- **Windows**: open **Task Scheduler**, *Create Basic Task*, daily at 02:00, action *Start a program*: your
  `python.exe`, with argument `run_all.py` and *Start in* set to your `inkwell` folder.
- **macOS and Linux**: run `crontab -e` and add a line such as
  `0 2 * * * cd /path/to/inkwell && python3 run_all.py >> inkwell_data/logs/cron.log 2>&1`.

The next step up is a real orchestrator. Airflow, Dagster and Prefect all express the same idea you just built: tasks,
dependencies, retries, schedules, run history, alerts. The library's *Data engineering: building production
pipelines* course teaches one of them (Kestra) on cloud services.

## Make it yours

2. Add an alert: when a run fails, write a short message to `logs/ALERT.txt` with the failed task and the time. (Next
   step in real life: send it by email or chat.)
3. Add a **data freshness** check as a final task: fail if the newest day in `mart_daily_sales` is older than the
   newest day in the source.

## What to take away

- An orchestrator runs tasks in dependency order, retries, skips downstream on failure, and records every run.
- A pipeline that fails loudly and safely is better than one that silently publishes wrong numbers.
