# Project 7: ingest Inkwell's data into the lake, safely and only once

Today you move Inkwell's data from its sources into the lake's **raw zone**, using four different patterns, one per
source. The rule for the whole project: **you can run it any number of times, and nothing is lost or doubled.**

The code is above this text. Save it as `p07_ingest.py`. Run project 5 first.

## Read the code

- **State.** `watermarks.json` (in `inkwell_data/state/`) stores how far each source has been read. `save_state()`
  writes a temporary file, then renames it: either the old bookmark or the new one, never half of one.
- **`to_parquet()`** runs a query on the source and saves the rows as one Parquet file, adding two columns every
  data team adds: `_batch_id` (which load brought this row) and `_ingested_at` (ingestion time).
- **books: full snapshot.** Ten rows; copy them all, into a folder named after today's date.
- **orders: batch CDC.** Rows with `updated_at` after the last watermark, up to the newest `updated_at`. The folder is
  named after that window, so re-running the same window replaces it. The **order lines** of new orders come with
  them. The watermark moves only after both files are written.
- **customers: continuous CDC.** Every row of `change_log` after the last `change_id`: inserts *and* updates, so a
  customer who moved city appears twice, once per address. Tomorrow's star schema needs exactly that.
- **events: new files only.** Each events file is read once (the list of done files is in the state). Each line is
  parsed; a line that can't be read goes to `lake/dead_letter/` instead of crashing the run or vanishing. Duplicates
  and late events are **kept**: raw stays as it arrived, and project 10 cleans it.

## Make it yours

1. **Crash test.** In `ingest_tables()`, add `raise SystemExit("crash")` right after the orders file is written and
   before `save_state(state)`. Simulate a day, run ingestion (it crashes), remove the line, run again. Check with
   DuckDB that no order was skipped: `SELECT count(DISTINCT order_id) FROM read_parquet('inkwell_data/lake/raw/orders/*/*.parquet')`
   should equal `SELECT count(*) FROM orders` in `shop.db`.
2. Open a dead-letter file. Write the alert message you'd want the on-call engineer to receive.
3. Batch CDC misses in-between states. Find an order whose `change_log` shows `placed -> shipped -> delivered` but
   whose raw `orders` batches only show `placed` and `delivered`.
4. Add monitoring: make the script print a warning if a load brings **0 orders** on a day the shop was open, or more
   than 3 times the usual number.

## What to take away

- Each source gets the pattern that fits it: snapshot, batch CDC, continuous CDC, new files.
- Write first, then move the bookmark: a crash means re-reading, never skipping.
- Raw data keeps everything, including the mess. Cleaning is the next stage's job.
