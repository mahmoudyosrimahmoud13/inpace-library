# Capstone: publish Inkwell as your portfolio project

You've built a complete small data platform. Now make it something an employer can see in five minutes. A good data
engineering portfolio project shows **decisions and evidence**, not just code.

## 1. Clean the repository

- `inkwell_data/` is in `.gitignore` (data is rebuilt by the pipeline; it never goes into git).
- No keys or passwords anywhere. Search the code for `KEY`, `PASSWORD` and `SECRET` before you push.
- Add `requirements.txt` with one line: `duckdb`.
- Delete scratch files and the test you broke on purpose.

## 2. Write the README

Use this structure. Keep it short: a reviewer spends a few minutes on it.

```markdown
# Inkwell Books: a small data platform, end to end

A batch data platform for a (simulated) online bookshop: change data capture from the shop's database,
a Parquet data lake, a tested star-schema warehouse in DuckDB, a metrics layer serving a dashboard,
ML features and a reverse-ETL list, with privacy controls and an orchestrated nightly run.

## Architecture
(the Mermaid diagram from ARCHITECTURE.md)

## What it does
- Ingestion: snapshot, batch CDC (updated_at watermark), continuous CDC from a change log,
  file-based events with a dead-letter queue. Re-runnable without duplicates or gaps.
- Storage: partitioned Parquet; format choice backed by measurements (link to ADR 4).
- Modeling: Kimball star schema, type 2 customer dimension, point-in-time joins.
- Transformation: SQL models in a DAG, 6+ data tests, write-audit-publish, incremental loads.
- Serving: metrics layer, HTML dashboard, leakage-safe ML features, reverse ETL.
- Security: keyed pseudonyms, least-privilege analyst database, PII check, tested backups.
- Orchestration: dependency-ordered run with retries and run history.

## Run it
pip install -r requirements.txt
python p05_source_system.py && python run_all.py

## Decisions
Links to ADRs 1 to 4, one line each.

## What I'd do next
Cloud object storage, dbt, Airflow or Dagster, a real CDC tool, streaming for the events.
```

## 3. Add evidence

- A **screenshot** of the dashboard.
- The output of a **green run** and of the **safe failure** (`run_all.py` with a failing test).
- Your **TCO table** from project 4 and your **format measurements** from project 6.
- `ARCHITECTURE.md` with your ADRs.

## 4. Push it to GitHub

Create an empty repository on GitHub called `inkwell-data-platform`, then:

```bash
git add .
git commit -m "Inkwell Books data platform"
git branch -M main
git remote add origin git@github.com:YOUR-NAME/inkwell-data-platform.git
git push -u origin main
```

`git add .` stages every file (except what `.gitignore` excludes), `git commit` saves a snapshot with a message,
`git branch -M main` names the branch `main`, `git remote add origin ...` tells git where your GitHub repository is,
and `git push` uploads it. Replace `YOUR-NAME` with your GitHub username. The `git@github.com:` address uses SSH; if
you haven't set up an SSH key, GitHub's "Connecting to GitHub with SSH" guide walks you through it.

## 5. Your CV line

Write it as an outcome with the techniques in it, for example:

> Built an end-to-end batch data platform (Python, SQL, DuckDB, Parquet): change data capture with idempotent
> incremental loads, a type 2 star schema, a tested SQL pipeline with write-audit-publish, a metrics layer, and
> privacy controls with tested backups.

## What to take away

- A portfolio project shows decisions (ADRs), evidence (outputs, screenshots) and how to run it.
- Clean before you publish: no data, no secrets.
