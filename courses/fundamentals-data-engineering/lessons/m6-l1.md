# Read: Chapter 6, Storage

Storage is the "cornerstone" of the lifecycle: every other stage reads from it and writes to it. The chapter builds
up in three layers: the **raw ingredients**, the **storage systems** built from them, and the
**abstractions** data engineers use. Read it in that order.

## Raw ingredients of data storage

Magnetic disks, SSDs and RAM, with their speeds and costs; networking and CPU; **serialization** (turning data into
bytes); **compression**; and **caching**. Note the cache hierarchy (Table 6-1): the faster the storage, the more it
costs per gigabyte. Every storage system is a trade-off along this line.

## Data storage systems

- Single machine versus distributed storage.
- **Eventual versus strong consistency**: read the **BASE** acronym and the trade-off: fresh data versus speed and
  availability.
- **File storage**, **block storage**, **object storage**: read object storage most carefully. It's where modern data
  lakes live (Amazon S3, Google Cloud Storage, Azure Blob). Note what objects *can't* do (change in place) and what
  they're great at (cheap, durable, parallel reads).
- Cache and memory-based storage, HDFS, streaming storage.
- **Indexes, partitioning and clustering**: how storage helps queries skip data.

## Data engineering storage abstractions

The **data warehouse**, **data lake**, **data lakehouse**, data platforms, and **stream-to-batch** storage. Ask of each:
what does it add on top of plain object storage?

## Big ideas and trends

Data catalogs, data sharing, **schema on write versus schema on read**, **separation of compute from storage**
(one of the biggest shifts in the last decade: read why), the **data storage lifecycle** (**hot, warm and cold** data,
and retention), and single versus multitenant storage.

## After reading

For one dataset you know, decide: hot, warm or cold? Which storage system and format would you put it in, and why?

## What to take away

- Every storage choice trades speed, cost, consistency and durability.
- Object storage plus open file formats is the base of the modern data lake.
- Columnar formats like Parquet suit analytics; row formats suit records you read whole.
