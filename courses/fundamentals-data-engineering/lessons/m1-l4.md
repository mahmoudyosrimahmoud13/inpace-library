# Project 1: your workbench for Inkwell Books

**Inkwell Books** is a small online bookshop in Egypt. It sells about ten titles to a few hundred readers. The owner
runs the business from the shop's web app and a spreadsheet. She wants to understand her sales, and she has just
hired you, her first data engineer. In maturity terms, Inkwell is **starting with data**.

Over the next eleven days you'll build its data platform, one lifecycle stage at a time. Today you set up your
workbench.

## 1. Get the project files

This lesson shows every file of the project, `inkwell/`. Make a folder called `inkwell` on your computer (for example
in your Documents), and save the files into it with the same names, keeping the `models/` and `tests/` subfolders.
Use each file's **Copy** button, or **Open it** to see the file on its own.

You'll read each script properly on its own day. Today you only need two of them:

- `common.py`: the paths every project shares. All data goes into one folder, `inkwell/inkwell_data/`. Delete that
  folder at any time to start again from scratch.
- `p01_setup_check.py`: checks that your computer is ready.

## 2. Install DuckDB and check your setup

Open a terminal in the `inkwell` folder (on Windows: open the folder, type `cmd` in the address bar and press Enter).

```bash
pip install duckdb
python p01_setup_check.py
```

`pip install duckdb` downloads the DuckDB library for Python. `python p01_setup_check.py` runs the check. On macOS and
Linux you may need `pip3` and `python3` instead.

The real output (your version numbers may be newer):

```text
Python 3.13.18  -> OK
DuckDB 2.0.1  -> OK
DuckDB answers 1 + 1 = 2
Data folder: inkwell/inkwell_data  -> OK

All set. Next: project 2.
```

If a line says something is missing, it also says what to run to fix it.

## 3. Start your project repository

Every data team keeps its pipeline code in version control. Do the same:

```bash
git init
git add .
git commit -m "Inkwell Books: project files"
```

Add a file named `.gitignore` with one line, `inkwell_data/`, so the data your scripts make never goes into git. Data
is rebuilt by the pipeline; code is what you keep.

## What to take away

- One folder for code (in git), one folder for data (rebuilt, never in git).
- DuckDB gives you a real analytics engine on your laptop, for free.
