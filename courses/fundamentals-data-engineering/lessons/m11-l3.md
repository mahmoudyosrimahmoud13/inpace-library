# Project 11: a metrics layer, a dashboard, ML features, and reverse ETL

Today the warehouse starts working for people. You serve the same data to three users: the owner, a data scientist,
and the email tool.

The code is above this text. Save it as `p11_serve.py`. Run project 10 first.

## Read the code

**1. The metrics layer.**

- `METRICS` defines four metrics, each with its SQL and a sentence a person can read. Note that every metric excludes
  cancelled orders: the rule lives here, once.
- `DIMENSIONS` lists what you can slice by: day, weekday, city (at the time of the order), genre.
- `metric_query(["revenue", "orders"], "day")` writes the SQL for you. No report writes its own revenue SQL.

**2. Analytics.** The dashboard (`serve/dashboard.html`) is one HTML file with bar charts drawn as SVG by `bars()`:
no libraries, opens in any browser, easy to email. Every number on it comes from `metric_query()`. At the bottom, it
prints the metric definitions, so readers know what they're looking at.

**3. Machine learning.** The cutoff is two days before the last sale. `past` holds sales before the cutoff, `future`
the customers who bought on or after it. Features (recency, frequency, monetary value, favourite genre) come **only**
from `past`; the label (`label_bought_again`) **only** from `future`. The result is `serve/customer_features.csv`.

**4. Reverse ETL.** Customers whose last order is at least three days before the last sale go to
`serve/crm_winback.csv`. The query joins to the **current** row of the customer dimension for today's email address,
skips closed accounts, and uses the email tool's own column names.

The database is opened with `read_only=True`: serving should never change the warehouse.

## Make it yours

1. Add a metric, `units` (the number of books sold), and a dimension, `author`. Show "units by author" on the
   dashboard without writing any SQL outside `METRICS` and `DIMENSIONS`.
2. **Cause a leak on purpose.** Change the features to use all sales (remove `AND f.date_key < DATE '{cutoff}'`). How
   does `days_since_last_order` relate to the label now? Why would a model trained on this look perfect in testing?
3. Add an `unsubscribed` flag to the customers in project 5 (a new column, set at random for a few people), carry it
   through staging and the dimension, and keep those customers out of the win-back list.
4. Write a one-paragraph **data product** description for the dashboard: user, decision, freshness, owner, quality
   checks, how to report a problem.

## What to take away

- A metrics layer turns "whose number is right?" into "which definition do we want?".
- Point-in-time features keep models honest.
- Reverse ETL serves the tool's format, with privacy rules built in.
