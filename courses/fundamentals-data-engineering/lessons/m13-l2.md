## The book's big lesson

Tools change every couple of years; the lifecycle and the undercurrents don't. When you meet a new tool, ask which
stage it serves, which undercurrent it helps with, what it costs to run, and how you'd leave it. You can now answer
those questions.

## What to learn next

- **Data engineering: building production pipelines** (in this library): the same ideas on industry tools: Docker,
  Terraform, Kestra, BigQuery, dbt, Spark and Kafka. Your Inkwell project maps onto it one to one: `p07` becomes
  ingestion flows, `models/` becomes a dbt project, `run_all.py` becomes an orchestrator.
- **SQL**: if window functions still feel new, the library's advanced PostgreSQL course.
- **Cloud basics**: the library's AWS fundamentals course, to move the lake into object storage.
- **Deeper theory**: *Designing Data-Intensive Applications* by Martin Kleppmann explains how the databases,
  replication, partitioning and streams you used actually work inside.

## Keep it alive

Run your pipeline once a week for a month and add one improvement each time: a new test, a new source (a public API),
a new metric. A project that grows over time tells an employer more than a perfect one finished in a day.
