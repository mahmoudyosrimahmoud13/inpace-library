# Read: Chapter 8, part 3, Transformations, to the end of the chapter

Today's pages finish Chapter 8. A query answers a question once; a **transformation** is a query (or code) that runs
again and again and saves its result for others to use. That's what turns a data engineer's work into a product.

## Batch transformations

- **Distributed joins**: **broadcast join** (send the small table to every node) and **shuffle hash join** (move both
  sides by key, more expensive). Know the two names; you'll see them in every engine's query plan.
- **ETL, ELT and data pipelines**: where the "T" happens and why ELT became common with cheap, powerful warehouses.
- **SQL and code-based transformation tools**: when SQL is enough, and when Spark or Python is better. Read the
  optimization advice for Spark (prefer built-in functions to user-defined ones).
- **Update patterns**: **truncate and reload**, **insert only**, **delete**, **upsert/merge**. Read the warnings about
  single-row inserts and about updates on columnar storage.
- **Schema updates**, **data wrangling**, and a Spark example.
- **Business logic and derived data**: the hardest part. Read why business definitions belong in one place.
- MapReduce: a short history; skim.

## Materialized views, federation and query virtualization

Views, **materialized views** (a stored result the database keeps up to date), **composable materialized views**, and
querying data where it lives (federation, virtualization). When is each a good idea?

## Streaming transformations and processing

The difference between streaming *queries* and streaming *transformations*; streaming DAGs; micro-batch versus true
streaming.

## Whom you'll work with, undercurrents, conclusion

Read the undercurrents carefully, especially **data management** (data quality tests, lineage, definitions) and
**DataOps** (monitor both the system and the data).

## After reading

## What to take away

- Transformations are queries that run repeatedly and save results others rely on.
- Choose an update pattern on purpose: reload, insert only, or merge.
- Business logic should live in one place, tested.
