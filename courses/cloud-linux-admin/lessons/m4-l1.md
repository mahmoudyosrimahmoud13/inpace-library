# Secrets and configuration

Never put passwords in user data, AMIs, Git or environment files baked into images. Fetch them at runtime with the instance role.

| Service | For | Notes |
|---|---|---|
| **SSM Parameter Store** | Config values and simple secrets (`SecureString`) | Free tier for standard parameters; hierarchical names |
| **Secrets Manager** | Database passwords, API keys | Automatic rotation (e.g. for RDS), costs per secret |

```bash
aws ssm put-parameter --name /shop/prod/APP_PORT --type String --value 8000
aws ssm put-parameter --name /shop/prod/STRIPE_KEY --type SecureString --value 'sk_live_...'
aws ssm get-parameters-by-path --path /shop/prod --with-decryption --query 'Parameters[].[Name,Value]' --output text

aws secretsmanager get-secret-value --secret-id shop/prod/db --query SecretString --output text | jq -r .password
```

## At boot: write an env file only root and the app can read

```bash
#!/bin/bash
set -euo pipefail
install -d -m 750 -o root -g app /etc/app
umask 027
aws ssm get-parameters-by-path --path /shop/prod --with-decryption \
  --query 'Parameters[].[Name,Value]' --output text |
  while read -r name value; do echo "${name##*/}=${value}"; done > /etc/app/env
chgrp app /etc/app/env
systemctl restart app
```

## The IAM side

The instance role may read **only its own path**:

```json
{"Effect": "Allow", "Action": ["ssm:GetParametersByPath", "ssm:GetParameter"],
 "Resource": "arn:aws:ssm:eu-central-1:123456789012:parameter/shop/prod/*"}
```

plus `kms:Decrypt` on the key, and `secretsmanager:GetSecretValue` on the one secret. Staging servers can't read prod secrets, by design.
