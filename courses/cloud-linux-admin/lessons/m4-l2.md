# Connecting to RDS and backing everything up

## App server to RDS

- RDS in isolated private subnets; its security group allows 5432 **from the app's security group**.
- Require TLS: set `rds.force_ssl = 1` in the parameter group and connect with `sslmode=verify-full` using the RDS CA bundle.
- Password from Secrets Manager (with rotation), or **IAM database authentication** (a 15-minute token instead of a password).

```bash
psql "host=shop.xxxx.eu-central-1.rds.amazonaws.com port=5432 dbname=shop user=app sslmode=verify-full sslrootcert=/etc/ssl/rds-global-bundle.pem"
```

Your laptop reaches it through Session Manager port forwarding (Day 2), never by making the database public.

## Backups: one plan for everything

**AWS Backup** applies one policy to EBS, RDS, EFS, DynamoDB and more, selected by **tag**:

```text
Backup plan "prod-daily":
  rule: daily at 03:00, keep 35 days; monthly, keep 12 months
  copy to another region (disaster recovery)
  resources: every resource tagged backup=daily
```

## RPO and RTO

| Term | Question | Example |
|---|---|---|
| **RPO** (recovery point objective) | How much data can we lose? | 5 minutes (RDS point-in-time restore) |
| **RTO** (recovery time objective) | How long can we be down? | 1 hour |

Write both down with the business, then **test a restore**: restore last night's RDS snapshot to a new instance, point a test app at it, time it. The time you measure is your real RTO.
