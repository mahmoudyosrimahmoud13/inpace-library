# cloud-init: configure servers on first boot

**cloud-init** runs on the first boot of almost every cloud Linux image. It reads the **user data** you passed at launch and sets the server up: no clicking, no SSH.

## Two formats

A shell script (starts with `#!`):

```bash
#!/bin/bash
set -euo pipefail
dnf -y update
dnf -y install nginx
systemctl enable --now nginx
echo "ok from $(hostname)" > /usr/share/nginx/html/index.html
```

Or `#cloud-config` YAML, which is declarative and portable between distros:

```yaml
#cloud-config
package_update: true
packages: [nginx, htop]
users:
  - name: sara
    groups: [wheel]
    ssh_authorized_keys: ["ssh-ed25519 AAAA... sara@laptop"]
write_files:
  - path: /etc/myapp/config.env
    permissions: "0640"
    content: |
      APP_PORT=8000
runcmd:
  - systemctl enable --now nginx
```

## Debugging it

```bash
cloud-init status --long           # done? error?
sudo less /var/log/cloud-init-output.log   # everything your script printed
sudo less /var/log/cloud-init.log          # cloud-init's own steps
sudo cloud-init schema --system            # validate the cloud-config you gave
```

## Rules

- User data runs **once**, as root, on first boot. Changing it later does nothing to running instances (unless you force a re-run).
- **No secrets in user data**: anyone who can describe the instance can read it. Fetch secrets at boot from Secrets Manager or Parameter Store (Day 4) using the instance role.
- Keep it short. For heavy setup, bake a golden AMI (Day 6) and let user data do only the last per-instance steps.
