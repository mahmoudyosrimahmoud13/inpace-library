# Private networks: NAT, endpoints and DNS

Production servers live in **private subnets**. They still need to install packages, talk to AWS APIs and resolve names.

| Need | How |
|---|---|
| OS updates, pip, docker pulls | NAT gateway (one per AZ for high availability; costs per hour and per GB) |
| S3 and DynamoDB | **Gateway endpoints**: free, add a route |
| SSM, Secrets Manager, CloudWatch, ECR | **Interface endpoints**: private IPs in your subnets, cost per hour; save NAT traffic and keep traffic private |
| Admin access | Session Manager (Day 2), not a bastion |

## DNS inside a VPC

- Every VPC has a resolver at the **VPC base address + 2** (10.0.0.2 for 10.0.0.0/16), also reachable at 169.254.169.253.
- Turn on **DNS hostnames** and **DNS resolution** for the VPC (needed for interface endpoints).
- **Private hosted zones** in Route 53 give you names like `db.internal.acme` only inside your VPCs.

```bash
resolvectl status | head -20
dig +short db.internal.acme
dig +short ssm.eu-central-1.amazonaws.com    # with an interface endpoint, this returns a 10.x address
```

## Debugging a private instance that "has no internet"

1. Route table for its subnet: `0.0.0.0/0 -> nat-...`?
2. The NAT gateway is in a **public** subnet (with a route to the internet gateway)?
3. Security group allows outbound (default: all)? NACLs allow return traffic?
4. `curl -sv https://aws.amazon.com -o /dev/null` and `dig` from the instance.
5. **VPC Flow Logs** show accepted and rejected packets for the interface.
