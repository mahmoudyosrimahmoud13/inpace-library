# Launching a Linux server the right way

The AWS course showed the pieces. This course is about **running Linux servers in the cloud day to day**, the way a cloud sysadmin does.

## A checklist for every new instance

| Choice | Good default |
|---|---|
| AMI | A current official image: Amazon Linux 2023 or Ubuntu 24.04 LTS. Look it up by SSM parameter, not by a hard-coded ID |
| Type | Smallest that fits; Graviton (`t4g`, `m7g`) is cheaper if your software runs on ARM |
| Subnet | **Private** unless it must be reached directly from the internet |
| Security group | Only the ports it serves, only from who needs them. No port 22 if you use Session Manager |
| IAM role | Always attach one (at least `AmazonSSMManagedInstanceCore`) |
| Metadata | IMDSv2 required |
| Disk | gp3, encrypted |
| Tags | `Name`, `env`, `owner`, `project` |

```bash
# Always get the latest official AMI by name, not by ID
aws ssm get-parameter --name /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 --query Parameter.Value --output text
aws ssm get-parameter --name /aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id --query Parameter.Value --output text
```

## Amazon Linux 2023 vs Ubuntu

| | Amazon Linux 2023 | Ubuntu 24.04 |
|---|---|---|
| Family | Fedora-based (dnf, rpm) | Debian-based (apt, deb) |
| Default user | `ec2-user` | `ubuntu` |
| Support | AWS, tuned for EC2 | Canonical, same as on-premises |
| Pick when | AWS-only, minimal | Same OS everywhere, more packages |

Everything from the Linux courses (systemd, journald, users, permissions, nftables) works the same in the cloud. What changes: no console cable, disks and IPs come from APIs, and servers are expected to be **replaceable**.
