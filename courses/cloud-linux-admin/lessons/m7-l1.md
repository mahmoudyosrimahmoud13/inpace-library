# Break and fix: troubleshooting cloud servers

Cloud problems are usually one of four layers. Check from the outside in:

| Layer | Symptom | Check |
|---|---|---|
| **AWS API/IAM** | AccessDenied, instance can't read a secret | `aws sts get-caller-identity` on the box; CloudTrail for the denied call |
| **Network** | Timeouts | Route tables, security groups, NACLs, Reachability Analyzer, Flow Logs |
| **Instance** | Status check failed, won't boot | EC2 serial console, `get-console-output`, screenshot |
| **Linux/app** | 502/503, errors | Session Manager in; journalctl, nginx logs, `ss -tlnp` |

```bash
aws ec2 describe-instance-status --instance-ids i-0abc     # system vs instance status checks
aws ec2 get-console-output --instance-id i-0abc --latest --output text | tail -50
aws ec2 get-console-screenshot --instance-id i-0abc --query ImageData --output text | base64 -d > shot.jpg
```

## Classic failures

| Problem | Cause | Fix |
|---|---|---|
| Won't boot after editing fstab | Missing disk without `nofail` | EC2 serial console, or detach the root volume, fix it on another instance, reattach |
| ALB says all targets unhealthy | Health check path, app not listening, SG doesn't allow the ALB | Curl the health path from the instance; check SG source |
| Session Manager not showing the instance | No role, agent stopped, no route to SSM endpoints | Attach role, check NAT or endpoints |
| Disk full | Logs, docker images | `du -xh / --max-depth=2 | sort -h`, logrotate, grow the volume |
| Lost the SSH key | | Use Session Manager, or EC2 Instance Connect, or the volume swap trick |

**System status check failed** = AWS's hardware: stop and start (moves to a new host). **Instance status check failed** = your OS: look at the console output.
