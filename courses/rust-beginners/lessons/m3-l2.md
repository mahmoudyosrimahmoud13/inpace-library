# Borrowing, references and slices

Moving every value into every function would be clumsy. Instead you can **lend** a value: give out a reference while keeping ownership.

## Shared references: &T

```rust
fn count_vowels(text: &str) -> usize {
    text.chars().filter(|c| "aeiou".contains(*c)).count()
}

fn length(s: &String) -> usize {
    s.len()
}

fn main() {
    let word = String::from("education");
    println!("{} letters, {} vowels", length(&word), count_vowels(&word));
    println!("still mine: {word}");     // word was only borrowed
}
```

```output
9 letters, 5 vowels
still mine: education
```

`&word` creates a reference; the function borrows the string, reads it, and gives it back when it ends. Nothing moves.

## Mutable references: &mut T

To let a function **change** the value, lend it mutably:

```rust
fn add_exclamation(s: &mut String) {
    s.push_str("!!");
}

fn main() {
    let mut msg = String::from("Goal");
    add_exclamation(&mut msg);
    println!("{msg}");
}
```

```output
Goal!!
```

Both the variable (`let mut`) and the reference (`&mut msg`) must say `mut`. When reading code, you can see at a glance which calls might change your data.

## The borrowing rule

At any moment you can have **either**:

- any number of shared references `&T`, **or**
- exactly one mutable reference `&mut T`

but not both. And references can never outlive the value they point to.

```rust
fn main() {
    let mut scores = vec![70, 85];
    let first = &scores[0];        // a shared borrow
    // scores.push(90);            // error: cannot borrow `scores` as mutable
    println!("first is {first}");  // ...because `first` is still used here
    scores.push(90);               // fine now: `first` is no longer used
    println!("{:?}", scores);
}
```

```output
first is 70
[70, 85, 90]
```

Why the error? `push` might move the vector's items to new, bigger memory. Then `first` would point at freed memory: the exact pointer bug from the C++ project lesson. Rust refuses to compile it. This same rule is what makes data races impossible: two threads can't both change something at once.

`{:?}` prints a value in "debug" form; it works for vectors and most standard types.

## Dangling references don't compile

```rust
fn make() -> &String {        // error: missing lifetime specifier
    let s = String::from("hi");
    &s                        // s is dropped at the end of the function
}
```

The fix is to return the `String` itself (move it out). The advanced course explains **lifetimes**, the compiler's way of tracking how long references are valid.

## Slices: views into part of a collection

A **slice** borrows a range of a string or a list without copying:

```rust
fn first_word(s: &str) -> &str {
    match s.find(' ') {
        Some(i) => &s[..i],
        None => s,
    }
}

fn average(nums: &[f64]) -> f64 {
    nums.iter().sum::<f64>() / nums.len() as f64
}

fn main() {
    let sentence = String::from("hello wide world");
    println!("{}", first_word(&sentence));
    println!("{}", &sentence[6..10]);

    let temps = [30.0, 32.5, 29.0, 35.5, 33.0];
    println!("{}", average(&temps));
    println!("{}", average(&temps[1..3]));   // only items 1 and 2
}
```

```output
hello
wide
32
30.75
```

- `&s[6..10]` is the text from byte 6 up to (not including) 10.
- `&[f64]` is a slice of f64 values; it accepts arrays, vectors and parts of them.

## String vs &str

- `String` **owns** its text, can grow, lives on the heap.
- `&str` is a **borrowed** view of some text: part of a `String`, or a literal like `"hello"` baked into the program.

Write functions that only read text to take `&str`. They then accept both: `first_word(&my_string)` and `first_word("a literal")` both work.

A note on text: Rust strings are UTF-8. Arabic letters take 2 bytes each, so slicing by byte numbers can land in the middle of a letter and stop the program. Use `.chars()` to work letter by letter.

## Summary

- `&T` borrows to read, `&mut T` borrows to change; ownership stays put.
- Many readers **or** one writer, and references never outlive their value. The compiler checks it.
- Slices (`&str`, `&[T]`) borrow part of a collection; take `&str` for text you only read.
