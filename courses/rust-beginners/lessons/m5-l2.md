# Errors: Result, ? and panic

Rust splits errors into two kinds:

- **Unrecoverable**: a bug, like an index past the end. The program **panics**: it stops with a message.
- **Recoverable**: a missing file, bad input. These are returned as a value of type `Result`.

There are no exceptions.

## Result

`Result` is an enum, just like `Option`:

```rust
enum Result<T, E> {
    Ok(T),     // success, with the value
    Err(E),    // failure, with the error
}
```

```rust
fn main() {
    for text in ["42", "abc", "-7"] {
        match text.parse::<i32>() {
            Ok(n) => println!("{text} -> {n}"),
            Err(e) => println!("{text} -> error: {e}"),
        }
    }
}
```

```output
42 -> 42
abc -> error: invalid digit found in string
-7 -> -7
```

Because the result type is `Result`, you can't forget that parsing might fail. The compiler even warns you if you ignore a `Result` completely.

## Your own errors

```rust
#[derive(Debug)]
enum OrderError {
    Empty,
    NotANumber(String),
    TooMany(u32),
}

fn parse_quantity(input: &str) -> Result<u32, OrderError> {
    let input = input.trim();
    if input.is_empty() {
        return Err(OrderError::Empty);
    }
    let n: u32 = input.parse().map_err(|_| OrderError::NotANumber(input.to_string()))?;
    if n > 50 {
        return Err(OrderError::TooMany(n));
    }
    Ok(n)
}

fn main() {
    for input in ["12", "", "lots", "99"] {
        match parse_quantity(input) {
            Ok(n) => println!("order {n}"),
            Err(OrderError::Empty) => println!("nothing typed"),
            Err(OrderError::NotANumber(s)) => println!("'{s}' is not a number"),
            Err(OrderError::TooMany(n)) => println!("{n} is more than 50"),
        }
    }
}
```

```output
order 12
nothing typed
'lots' is not a number
99 is more than 50
```

## The ? operator

Look at this line again:

```rust
let n: u32 = input.parse().map_err(|_| OrderError::NotANumber(input.to_string()))?;
```

The `?` at the end means: **if this is an `Err`, return it from my function right now; if it's `Ok`, give me the value**. It replaces a whole `match` and makes error handling short:

```rust
use std::fs;
use std::io;

fn count_lines(path: &str) -> Result<usize, io::Error> {
    let text = fs::read_to_string(path)?;        // a missing file returns the error
    Ok(text.lines().count())
}

fn main() {
    fs::write("notes.txt", "buy milk\ncall Sara\nfix bike\n").expect("can't write");
    match count_lines("notes.txt") {
        Ok(n) => println!("{n} lines"),
        Err(e) => println!("error: {e}"),
    }
    match count_lines("missing.txt") {
        Ok(n) => println!("{n} lines"),
        Err(e) => println!("error: {}", e.kind()),
    }
}
```

```output
3 lines
error: entity not found
```

`?` only works inside a function that itself returns `Result` (or `Option`). `main` can return a `Result` too:

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let n: i32 = "17".parse()?;
    println!("{}", n * 2);
    Ok(())
}
```

```output
34
```

`Box<dyn std::error::Error>` means "any kind of error". It's a handy return type for `main` and small programs. If an error reaches the end of `main`, Rust prints it and exits with a failure code.

## Panics

```rust
let v = vec![1, 2, 3];
v[10];                 // panics: index out of bounds
None::<i32>.unwrap();  // panics: called `Option::unwrap()` on a `None` value
panic!("this should never happen");
```

A panic is for **bugs**: situations your program can't sensibly continue from. Don't use panics for ordinary failures like bad user input.

`unwrap()` and `expect("message")` turn a `None` or `Err` into a panic. They're fine in examples, tests and quick scripts. In real code, prefer `?`, `match`, `unwrap_or` or `if let`. If you do use one, prefer `expect` with a message saying why it can't fail.

## Summary

- Recoverable errors are values: `Result<T, E>` with `Ok` and `Err`; panics are for bugs.
- `?` returns the error early or unwraps the value; use it in functions returning Result.
- Define error enums for your program; use `Box<dyn Error>` for main and small tools.
