# Enums, match and Option

Rust's enums are far more powerful than in C. Each variant can carry its own data, and `match` makes sure you handle every one.

## A simple enum

```rust
#[derive(Debug)]
enum Direction {
    North,
    East,
    South,
    West,
}

fn turn_right(d: Direction) -> Direction {
    match d {
        Direction::North => Direction::East,
        Direction::East => Direction::South,
        Direction::South => Direction::West,
        Direction::West => Direction::North,
    }
}

fn main() {
    let d = turn_right(Direction::West);
    println!("{:?}", d);
}
```

```output
North
```

Add a fifth direction and forget it in the `match`, and the program won't compile until you handle it.

## Variants with data

```rust
enum Payment {
    Cash(f64),
    Card { amount: f64, last4: String },
    Voucher(String),
}

impl Payment {
    fn describe(&self) -> String {
        match self {
            Payment::Cash(a) => format!("cash {a}"),
            Payment::Card { amount, last4 } => format!("card ending {last4}: {amount}"),
            Payment::Voucher(code) => format!("voucher {code}"),
        }
    }
}

fn main() {
    let payments = [
        Payment::Cash(50.0),
        Payment::Card { amount: 120.0, last4: "4421".to_string() },
        Payment::Voucher("EID25".to_string()),
    ];
    for p in &payments {
        println!("{}", p.describe());
    }
}
```

```output
cash 50
card ending 4421: 120
voucher EID25
```

Each variant holds different data, and `match` unpacks it into variables (`a`, `amount`, `last4`, `code`). This is the `std::variant` + `visit` pattern from C++, built into the language.

## Option: no more null

Rust has **no null**. A value that might be missing has the type `Option<T>`, which is just an enum:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

You can't use an `Option<i32>` as an `i32` by accident. You must first check which it is:

```rust
fn find_price(item: &str) -> Option<f64> {
    match item {
        "tea" => Some(15.0),
        "coffee" => Some(30.0),
        _ => None,
    }
}

fn main() {
    for item in ["coffee", "cake"] {
        match find_price(item) {
            Some(p) => println!("{item}: {p}"),
            None => println!("{item}: not on the menu"),
        }
    }

    // shorter forms
    if let Some(p) = find_price("tea") {
        println!("tea is {p}");
    }
    let cake = find_price("cake").unwrap_or(0.0);
    println!("cake or zero: {cake}");
}
```

```output
coffee: 30
cake: not on the menu
tea is 15
cake or zero: 0
```

- `if let Some(p) = ...` runs the block only when there's a value.
- `.unwrap_or(default)` gives the value or a default.
- `.unwrap()` gives the value or **stops the program** if it's None. Fine in quick experiments; avoid it in real code.

Many standard functions return Option: `vec.first()`, `vec.get(i)`, `text.find(' ')`, `map.get(key)`, `iterator.max()`.

## Useful Option methods

```rust
fn main() {
    let nums = vec![4, 9, 2];
    let doubled = nums.first().map(|n| n * 2);       // Some(8)
    let empty: Vec<i32> = Vec::new();
    println!("{:?} {:?}", doubled, empty.first().map(|n| n * 2));
    println!("{}", nums.get(10).is_none());
    let biggest = nums.iter().max().copied().unwrap_or(0);
    println!("{biggest}");
}
```

```output
Some(8) None
true
9
```

`.map(f)` changes the value inside if there is one, and leaves None alone. It lets you work with "maybe" values without writing a `match` every time.

## let else

When a function can't continue without a value, `let ... else` gets it or leaves early:

```rust
fn shout_first_word(s: &str) -> String {
    let Some(word) = s.split_whitespace().next() else {
        return String::from("(empty)");
    };
    word.to_uppercase()
}

fn main() {
    println!("{}", shout_first_word("hello there"));
    println!("{}", shout_first_word("   "));
}
```

```output
HELLO
(empty)
```

## Summary

- Enum variants can carry data; `match` unpacks it and must cover every variant.
- `Option<T>` (`Some(x)` or `None`) replaces null; the compiler makes you check.
- Use `if let`, `let else`, `unwrap_or` and `map`; keep `unwrap()` for experiments.
