# Traits, generics, modules and tests

## Traits: shared behaviour

A **trait** describes something types can do. Any type can implement it:

```rust
trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> String;
    fn describe(&self) -> String {                 // a default method
        format!("{} with area {:.2}", self.name(), self.area())
    }
}

struct Circle { r: f64 }
struct Rect { w: f64, h: f64 }

impl Shape for Circle {
    fn area(&self) -> f64 { 3.14159 * self.r * self.r }
    fn name(&self) -> String { "circle".to_string() }
}

impl Shape for Rect {
    fn area(&self) -> f64 { self.w * self.h }
    fn name(&self) -> String { "rectangle".to_string() }
}

fn main() {
    let c = Circle { r: 1.0 };
    let r = Rect { w: 3.0, h: 4.0 };
    println!("{}", c.describe());
    println!("{}", r.describe());
}
```

```output
circle with area 3.14
rectangle with area 12.00
```

Traits are like C++ concepts and interfaces combined. The standard library is full of them: `Debug`, `Clone`, `PartialEq`, `Display` (for `{}` printing), `Iterator`, `Add` (for `+`)...

## Generic functions with trait bounds

```rust
use std::fmt::Display;

fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

fn show_all(items: &[impl Display]) {
    for x in items {
        print!("[{x}] ");
    }
    println!();
}

fn main() {
    println!("{}", largest(&[4, 19, 7]));
    println!("{}", largest(&[2.5, 0.5]));
    println!("{}", largest(&['q', 'z', 'a']));
    show_all(&["tea", "coffee"]);
    show_all(&[1, 2, 3]);
}
```

```output
19
2.5
z
[tea] [coffee] 
[1] [2] [3] 
```

`T: PartialOrd + Copy` says T must support comparison and be copyable. Like C++ concepts, the rules are checked when you call the function, with clear errors. `impl Display` is a short way to write the same thing for a parameter.

## Lists of different types: trait objects

Generics make a separate copy of the code for each type. To keep **different** types in one list, use a **trait object**, `Box<dyn Trait>`:

```rust
trait Shape {
    fn area(&self) -> f64;
}
struct Circle { r: f64 }
struct Square { s: f64 }
impl Shape for Circle { fn area(&self) -> f64 { 3.14159 * self.r * self.r } }
impl Shape for Square { fn area(&self) -> f64 { self.s * self.s } }

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![
        Box::new(Circle { r: 1.0 }),
        Box::new(Square { s: 2.0 }),
        Box::new(Circle { r: 2.0 }),
    ];
    let total: f64 = shapes.iter().map(|s| s.area()).sum();
    println!("total area {:.2}", total);
}
```

```output
total area 19.71
```

`Box` puts the value on the heap; `dyn Shape` means "some type that implements Shape", decided at run time. This is C++'s virtual functions, without inheritance.

## Implementing Display

To print your type with `{}`, implement `std::fmt::Display`:

```rust
use std::fmt;

struct Money { piasters: i64 }

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{}.{:02} EGP", self.piasters / 100, self.piasters % 100)
    }
}

fn main() {
    let m = Money { piasters: 5505 };
    println!("total: {m}");
}
```

```output
total: 55.05 EGP
```

## Modules: organizing code

As a program grows, split it into **modules**. In one file:

```rust
mod shop {
    pub struct Item {
        pub name: String,
        price: u32,                 // private: only code in `shop` can touch it
    }

    impl Item {
        pub fn new(name: &str, price: u32) -> Item {
            Item { name: name.to_string(), price }
        }
        pub fn price_with_tax(&self) -> u32 {
            self.price * 114 / 100
        }
    }
}

use shop::Item;

fn main() {
    let pen = Item::new("pen", 100);
    println!("{} costs {}", pen.name, pen.price_with_tax());
}
```

```output
pen costs 114
```

Everything is **private** by default; `pub` makes it visible outside the module. In a real project each module is its own file: `mod shop;` in `main.rs` loads `src/shop.rs`.

Using libraries from crates.io takes one line in `Cargo.toml`:

```toml
[dependencies]
rand = "0.8"
```

Then `cargo build` downloads and compiles it, and `use rand::Rng;` brings it in.

## Tests are built in

Write tests next to your code and run them with `cargo test`:

```rust
pub fn is_leap_year(y: u32) -> bool {
    (y % 4 == 0 && y % 100 != 0) || y % 400 == 0
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn normal_years() {
        assert!(is_leap_year(2024));
        assert!(!is_leap_year(2026));
    }

    #[test]
    fn centuries() {
        assert!(!is_leap_year(1900));
        assert!(is_leap_year(2000));
    }
}
```

```text
running 2 tests
test tests::centuries ... ok
test tests::normal_years ... ok

test result: ok. 2 passed; 0 failed
```

- `#[cfg(test)]` means "only compile this when testing".
- `assert!(cond)` and `assert_eq!(a, b)` fail the test with a message showing the values.
- `use super::*;` brings in everything from the surrounding file.

## Summary

- Traits describe behaviour; `impl Trait for Type` implements it; traits can have default methods.
- Generics with bounds (`T: PartialOrd`) work at compile time; `Box<dyn Trait>` mixes types at run time.
- `mod` and `pub` organize code; `#[test]` functions run with `cargo test`.
