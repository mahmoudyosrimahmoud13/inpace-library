# Constraints go down, sizes go up

The one rule of layout: **constraints go down, sizes go up, the parent sets the position.**

- A parent gives a child `BoxConstraints(minW, maxW, minH, maxH)`.
- The child picks a size **within** them.
- The parent decides where the child goes.

Consequences that explain most layout "bugs":

- A widget can't be any size it wants; `Container(width: 100)` inside a tight constraint is still full width.
- `Row` gives children **unbounded** width; a `Text` or `ListView` inside it without `Expanded`/`Flexible` overflows
  or throws "unbounded width".
- `ListView` inside a `Column` needs `Expanded` (or `shrinkWrap`, which is slower).
- `Center` and `Align` **loosen** constraints, so their child can be smaller.
- `LayoutBuilder` lets you build based on the constraints you got (responsive layouts).

Use the Flutter Inspector's "layout explorer" to see the constraints each widget received.
