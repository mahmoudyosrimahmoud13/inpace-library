Short model answers for the trickiest:

- **setState:** marks the element dirty; on the next frame its `build` runs; children are updated by type and key;
  render objects re-layout or repaint only if needed.
- **Offline-first:** a local database (Drift or Isar) is the source of truth; the UI reads it; a sync layer pushes a
  queue of changes and pulls updates, resolving conflicts (last-write-wins, per-field merge, or server rules).
