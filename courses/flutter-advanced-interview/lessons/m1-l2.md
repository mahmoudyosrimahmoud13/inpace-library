# Sound null safety, late and final

Dart's null safety is **sound**: if the type says `String`, it can never be null at runtime.

```dart
String name = 'Tempo';      // never null
String? nickname;           // may be null
final len = nickname?.length ?? 0;
print(nickname!.length);    // "I promise it's not null": throws if it is. Avoid.
```

| Keyword | Means |
|---|---|
| `final` | set once, at runtime |
| `const` | a compile-time constant; identical instances are shared (canonicalized) |
| `late` | "I'll set it before first use" (checked at runtime); `late final x = compute();` is lazy |

**Type promotion** works on local variables and private final fields, but not on public fields (a subclass could
override them with a getter that returns a different value each time). Copy the field to a local first:

```dart
final user = this.user;
if (user != null) print(user.name);   // promoted
```

Interview favourite: "`const` vs `final`?" `final` is fixed after it's set; `const` is fixed at compile time, deeply
immutable, and canonicalized, which is why `const` widgets skip rebuilding.
