# Layers, dependency injection and errors

A structure most teams recognize:

```text
lib/
  core/              errors, network, result types
  features/courses/
    data/            DTOs, data sources (HTTP, local DB), repository implementations
    domain/          entities, repository interfaces, use cases (pure Dart)
    presentation/    widgets, state (Riverpod/Bloc)
```

- **Dependency rule:** inner layers don't import outer ones. Domain knows nothing about Flutter or HTTP.
- **DI:** pass dependencies in (constructor injection); wire them with Riverpod providers or `get_it`.
- **Errors as values:** return a `Result` (sealed `Ok`/`Err`) from repositories so callers must handle failure;
  exceptions for truly unexpected bugs.

```dart
sealed class Result<T> { const Result(); }
final class Ok<T> extends Result<T> { const Ok(this.value); final T value; }
final class Err<T> extends Result<T> { const Err(this.failure); final Failure failure; }
```

**Don't over-engineer:** a use case that only forwards a repository call adds files, not value. Senior interviewers
like hearing you know when to skip a layer.
