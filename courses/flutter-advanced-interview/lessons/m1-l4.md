# Async: futures, streams, the event loop and isolates

## The event loop

Each **isolate** has one thread with a **microtask queue** (runs first) and an **event queue** (I/O, timers, taps).
`await` doesn't block the thread; it schedules the rest of the function.

```dart
print('1');
Future(() => print('2'));                  // event queue
scheduleMicrotask(() => print('3'));       // microtask queue
Future.value().then((_) => print('4'));    // microtask
print('5');
// 1 5 3 4 2
```

## Streams

```dart
Stream<int> ticks() async* {
  for (var i = 0; ; i++) { await Future.delayed(const Duration(seconds: 1)); yield i; }
}
final sub = ticks().where((t) => t.isEven).listen(print);
await sub.cancel();   // always cancel in dispose()
```

- **Single-subscription** (a file, an HTTP body) vs **broadcast** (UI events, many listeners).
- `StreamController`, `async*`/`yield`, `await for`.
- Forgetting to cancel subscriptions is the classic Flutter memory leak.

## Isolates: real parallelism

Isolates don't share memory; they pass messages. For one-off heavy work:

```dart
final parsed = await Isolate.run(() => jsonDecode(hugeString));   // or compute(fn, arg) in Flutter
```

Use them for parsing big JSON, image processing, crypto. Long-lived workers use `Isolate.spawn` with `SendPort`s.

> **Interview:** "Is Dart single-threaded?" Each isolate is single-threaded with an event loop; an app can run many
> isolates in parallel; they communicate by message passing, which avoids data races by design.
