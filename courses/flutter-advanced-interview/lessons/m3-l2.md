# Provider, Riverpod and Bloc

## Riverpod (modern, compile-safe, testable)

```dart
final coursesProvider = FutureProvider<List<Course>>((ref) async {
  final repo = ref.watch(courseRepoProvider);
  return repo.all();
});

class CourseList extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final courses = ref.watch(coursesProvider);
    return courses.when(
      data: (list) => ListView(children: [for (final c in list) Text(c.title)]),
      loading: () => const CircularProgressIndicator(),
      error: (e, _) => Text('$e'),
    );
  }
}
```

Providers don't depend on the widget tree, can be overridden in tests (`ProviderScope(overrides: [...])`), and are
disposed automatically (`autoDispose`).

## Bloc (explicit events and states)

```dart
sealed class TripEvent {}
class TripStarted extends TripEvent { TripStarted(this.minutes); final int minutes; }
class TripTicked extends TripEvent {}

class TripBloc extends Bloc<TripEvent, TripState> {
  TripBloc() : super(const TripIdle()) {
    on<TripStarted>((e, emit) => emit(TripRunning(left: Duration(minutes: e.minutes))));
    on<TripTicked>((e, emit) { /* ... */ });
  }
}
```

Every change is an event → state transition: very traceable, great for big teams, more boilerplate. `Cubit` is the
lighter version with methods instead of events.

## How to answer "which one?"

| Option | Strengths | Costs |
|---|---|---|
| setState / ValueNotifier | simplest | doesn't scale across screens |
| Provider | simple, official for years | runtime errors if a provider is missing |
| Riverpod | compile-safe, testable, no context needed | concepts to learn |
| Bloc | explicit, auditable, testable transitions | boilerplate |

"I pick by team and app size. For a small app, ValueNotifier or Riverpod. For a large team with complex flows, Bloc's
explicit events help reviews and debugging. Whatever we choose, UI stays dumb, logic stays testable." That answer
beats naming a favourite.
