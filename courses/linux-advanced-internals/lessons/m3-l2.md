# Memory pressure and the OOM killer

## Where memory goes

```bash
free -h
cat /proc/meminfo | grep -E 'MemTotal|MemAvailable|Cached|Dirty|AnonPages|Slab|Shmem'
smem -rk | head         # per-process real use, sharing counted fairly (package smem)
```

| Kind | What it is | Can the kernel reclaim it? |
|---|---|---|
| Anonymous | Heap and stack of processes | Only by swapping |
| Page cache | File data kept in RAM | Yes, cheaply (clean pages) |
| Dirty | Changed file data not written yet | After writing it |
| Slab | The kernel's own caches (inodes, dentries) | Partly |
| Shmem / tmpfs | Shared memory, files in `/dev/shm`, `/tmp` on tmpfs | Only by swapping |

## Overcommit

Linux usually promises programs more memory than exists (`malloc` succeeds), betting they won't touch it all. When they do and nothing can be reclaimed, someone has to die.

## The OOM killer

The kernel picks the process with the highest **badness** (roughly: most memory, adjusted by `oom_score_adj`) and kills it with SIGKILL.

```bash
journalctl -k | grep -i -A5 'out of memory'    # who was killed and why
cat /proc/$(pgrep -o postgres)/oom_score       # current badness
echo -500 | sudo tee /proc/1234/oom_score_adj  # make a process less likely (-1000 = never)
```

For services, set it in the unit file: `OOMScoreAdjust=-500`. Protect the database; let the batch job die first.

## Better than the OOM killer: limits and early action

- Give each service a memory limit (`MemoryMax=` in systemd, Day 6): it gets killed or throttled **alone** instead of hurting the whole box.
- `systemd-oomd` (on by default in Ubuntu and Fedora) watches PSI and kills a misbehaving cgroup before the system freezes.
- A little swap gives the kernel room to move idle pages out before things get desperate.

## Is it a leak?

Watch a process's resident memory over time:

```bash
pidstat -r -p 1234 60       # RSS every minute
```

Steady growth that never comes back under constant load = a leak. A sawtooth (grows, drops) is usually just a garbage collector doing its job.
