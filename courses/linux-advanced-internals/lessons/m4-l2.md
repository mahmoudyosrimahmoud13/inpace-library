# File system troubleshooting

## "Read-only file system"

When ext4 hits a serious error, it remounts itself **read-only** to protect your data (`errors=remount-ro` in fstab). Writes then fail everywhere on it.

```bash
dmesg -T | grep -iE 'ext4|xfs|I/O error'     # why
findmnt -o TARGET,OPTIONS /                  # ro or rw now?
sudo smartctl -a /dev/sda | less             # disk health (package smartmontools)
```

Fix: plan downtime, run `fsck` on the **unmounted** file system (from rescue mode for `/`), replace the disk if SMART shows reallocated or pending sectors.

## Can't delete, can't create

| Symptom | Check | Cause |
|---|---|---|
| "No space left" but `df -h` shows space | `df -i` | Out of inodes |
| "Operation not permitted" as root | `lsattr file` | Immutable attribute (`chattr -i`) |
| "Device or resource busy" on unmount | `sudo lsof +D /mnt/x`, `fuser -vm /mnt/x` | Something still uses it (even a shell's cwd) |
| "Text file busy" | `lsof file` | Trying to overwrite a running program |
| Permission denied with correct rwx | `getfacl`, `ls -Z` | ACLs or SELinux/AppArmor |

## Inode exhaustion

Millions of tiny files (session files, cache, mail queues) can use every inode while space is free.

```bash
df -i
sudo find /var -xdev -type d -exec sh -c 'echo "$(ls -A "$1" | wc -l) $1"' _ {} \; 2>/dev/null | sort -n | tail
```

## Mount namespaces and "missing" mounts

A service started with `PrivateTmp=yes` sees its own `/tmp`. A container sees its own mounts. If a file "exists for me but not for the service", check which mount namespace it's in (Day 5): `sudo nsenter -t PID -m ls /tmp`.

## Undelete?

There's no reliable undelete on ext4/XFS. If a still-running process has the file open: `cp /proc/PID/fd/N recovered-file`. Otherwise: backups. This is the lesson that makes people take Day 7 of System Administration seriously.
