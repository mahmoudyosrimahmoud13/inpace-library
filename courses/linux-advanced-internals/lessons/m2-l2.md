# Watching a process from outside: strace, lsof, ltrace

When a program misbehaves and its logs say nothing useful, look at what it asks the kernel.

## strace

```bash
strace -f -o trace.txt ./app          # run it, follow children, save to a file
sudo strace -p 1234                   # attach to a running process
strace -e trace=file ls               # only file-related calls
strace -e trace=network curl -s example.com > /dev/null
strace -c -f ./app                    # summary: which calls, how many, time spent
strace -T -e trace=read,write -p 1234 # time spent in each call
```

## Reading a trace

```text
openat(AT_FDCWD, "/etc/app/config.yml", O_RDONLY) = -1 ENOENT (No such file or directory)
```

Name of the call, arguments, `=` result. Negative results are errors with a name you can look up (`man errno`).

| Error | Usually means |
|---|---|
| `ENOENT` | File not found: wrong path, missing config |
| `EACCES` / `EPERM` | Permission denied |
| `ECONNREFUSED` | Nothing listening on that address and port |
| `ETIMEDOUT` | No answer: firewall dropping packets, host down |
| `EAGAIN` | Would block (normal for non-blocking I/O) |
| `EMFILE` | Too many open files (ulimit) |

The classic win: a program "silently fails at start". `strace -f -e trace=file` shows the exact config file it looked for and didn't find.

## lsof: who has what open

```bash
sudo lsof -p 1234             # everything one process has open
sudo lsof /var/log/app.log    # who has this file open
sudo lsof -i :8080            # who uses port 8080
sudo lsof +L1                 # deleted files still open (disk space mysteries)
```

## ltrace and perf

- `ltrace` shows calls into shared libraries (`malloc`, `strlen`), not the kernel.
- `perf top` shows which functions use the CPU right now, across the whole system.

## A cost to know

strace slows the traced program a lot (often many times). Fine for debugging, risky on a busy production process. For production, eBPF tools (`bpftrace`, the `bcc` tools like `opensnoop`, `execsnoop`) see the same events with little overhead.
