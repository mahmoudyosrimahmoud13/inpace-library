# طريقة عمل موثوقة لـ Machine Learning

model يحقق نتيجة جيدة مرة واحدة قد يفشل في الاستخدام الحقيقي. وهذا الدرس يغطي العادات التي تجعل النتائج جديرة بالثقة: pipelines، والـ cross-validation، وتجنب الـ leakage.

```python
import pandas as pd
import numpy as np
df = pd.read_csv("cafe_clean.csv", parse_dates=["date"])
df["iced"] = df["item"].isin(["iced latte", "mint lemonade"]).astype(int)
df["weekend"] = df["date"].dt.dayofweek.isin([4, 5]).astype(int)
X = df[["temp_c", "hour", "weekend", "branch", "customer_type"]]
y = df["iced"]
print(X.shape)
```

```output
(1452, 5)
```

## pipelines: التجهيز والـ model كobject واحد

تجهيز البيانات (توحيد مقياس الأرقام، والـ one-hot encoding للنصوص) يجب أن **يُتعلم من بيانات التدريب فقط**، ثم يُطبّق بنفس الطريقة على البيانات الجديدة. و`Pipeline` تجمع الخطوات لكي يحدث ذلك دائمًا:

```python
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

prep = ColumnTransformer([
    ("numbers", StandardScaler(), ["temp_c", "hour", "weekend"]),
    ("text", OneHotEncoder(handle_unknown="ignore"), ["branch", "customer_type"]),
])
pipe = Pipeline([("prep", prep), ("model", LogisticRegression(max_iter=1000))])
print([name for name, step in pipe.steps])
```

```output
['prep', 'model']
```

```mermaid
flowchart LR
  R[الأعمدة الخام] --> P["التجهيز: توحيد مقياس الأرقام + ترميز النصوص"]
  P --> M[LogisticRegression]
  M --> O[احتمال أن يكون مثلجًا]
```

- `StandardScaler` تضع الأرقام على نفس المقياس (متوسط 0 وانحراف 1)، وهذا تحتاجه models كثيرة.
- `OneHotEncoder(handle_unknown="ignore")` لن تتوقف لو ظهر فرع جديد لاحقًا.
- pipeline كله فيه `fit` و`predict`، مثل model واحد.

## الـ cross-validation: نتيجة أعدل

تقسيم واحد إلى تدريب واختبار قد يكون محظوظًا أو سيئ الحظ. و**الـ cross-validation** يقسم البيانات 5 أجزاء، ويدرّب 5 مرات، ويختبر كل مرة على جزء مختلف، ثم يحسب المتوسط:

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(pipe, X, y, cv=5, scoring="roc_auc")
print("AUC per fold:", np.round(scores, 3))
print(f"mean {scores.mean():.3f}, spread {scores.std():.3f}")
```

```output
AUC per fold: [0.834 0.822 0.581 0.911 0.9  ]
mean 0.810, spread 0.120
```

الانتشار يخبرك كم تعتمد النتيجة على البيانات التي صادف أنك اختبرت عليها. وهو هنا كبير: الصفوف مرتبة بالتاريخ، فكل جزء فترة مختلفة من السنة، والـ model أسوأ بكثير في موسم واحد منه في المواسم الأخرى. ومعرفة ذلك مهمة قبل أن يعتمد عليه أحد. واذكر المتوسط **و**الانتشار.

## مقارنة الـ models بعدل

```python
from sklearn.ensemble import RandomForestClassifier

forest = Pipeline([("prep", prep), ("model", RandomForestClassifier(n_estimators=200, max_depth=5, random_state=0))])
for name, m in [("logistic", pipe), ("random forest", forest)]:
    s = cross_val_score(m, X, y, cv=5, scoring="roc_auc")
    print(f"{name:14} AUC {s.mean():.3f} (+/- {s.std():.3f})")
```

```output
logistic       AUC 0.810 (+/- 0.120)
random forest  AUC 0.708 (+/- 0.112)
```

**الـ random forest** تجمع decision trees كثيرة. وعندما يحصل نموذجان على نتيجة متقاربة، فضّل الأبسط والأسهل في التفسير.

## الـ leakage: القاتل الصامت

**الـ leakage** هو عندما تتسلل إلى الـ features معلومات لن تكون متاحة وقت التنبؤ. فيبدو الـ model عبقريًا في الاختبار ويفشل في الاستخدام الحقيقي. مثال:

```python
leaky = X.copy()
leaky["size"] = df["size"]             # the cup size is only known AFTER the order is placed...
leaky_pipe = Pipeline([("prep", ColumnTransformer([
    ("numbers", StandardScaler(), ["temp_c", "hour", "weekend"]),
    ("text", OneHotEncoder(handle_unknown="ignore"), ["branch", "customer_type", "size"]),
])), ("model", LogisticRegression(max_iter=1000))])
print("with leaked feature:", round(cross_val_score(leaky_pipe, leaky, y, cv=5, scoring="roc_auc").mean(), 3))
```

```output
with leaked feature: 0.922
```

الأطعمة والحلويات حجمها دائمًا "regular"، فمعرفة الحجم تكشف أن الطلب مشروب: فتقفز النتيجة. لكننا أردنا التنبؤ بالطلبات المثلجة **قبل** أن تُطلب، عندما لا يكون الحجم معروفًا بعد. وهذه القفزة زائفة.

أسئلة تكشف الـ leakage:

- هل سأعرف هذه الـ feature فعلًا **في اللحظة** التي أحتاج فيها التنبؤ؟
- هل أي feature محسوبة باستخدام الهدف، أو باستخدام بيانات من المستقبل؟
- هل النتيجة جيدة بشكل مريب؟ تحقق قبل أن تحتفل.

وللبيانات الزمنية، اختبر أيضًا على تواريخ **لاحقة** للتي تدرّب عليها (مثلًا درّب على يناير حتى سبتمبر واختبر على أكتوبر حتى ديسمبر)، لأن هذه هي طريقة استخدام الـ model.

## حفظ model

```python
import joblib
pipe.fit(X, y)
joblib.dump(pipe, "iced_model.joblib")
loaded = joblib.load("iced_model.joblib")
example = pd.DataFrame({"temp_c": [34.0], "hour": [15], "weekend": [1], "branch": ["Zamalek"], "customer_type": ["new"]})
print("chance of iced:", round(loaded.predict_proba(example)[0, 1], 2))
```

```output
chance of iced: 0.44
```

## الخلاصة

- pipelines تربط التجهيز بالـ model، فيُتعلم التجهيز من بيانات التدريب فقط.
- الـ cross-validation يعطي نتيجة أعدل مع انتشارها؛ وقارن الـ models بنفس الطريقة.
- انتبه للـ leakage: لا تستخدم إلا الـ features التي ستملكها فعلًا وقت التنبؤ.
