# Capstone: ship your own model

You've taken one model through every step of MLOps. Now do it for a model of your own.

The whole project folder is above this text.

## Choose a model

- A model from another course: the ML refresh's house prices or classifiers, a deep learning or computer vision
  model, a fine-tuned transformer.
- Or a new one on data you care about, as long as it arrives over time (so drift and retraining mean something).

## Ship it, step by step

1. **Train**: one script, all settings in one place, a time-based or otherwise honest split, a baseline, a leak check.
2. **Data**: validation rules and a data version (your own store or DVC).
3. **Track**: every run in MLflow with data version and commit.
4. **Pipeline**: declared steps with caching, and `params.json`.
5. **Registry**: versions, a champion alias, and a promotion gate on recent data.
6. **Serve**: FastAPI with validated inputs, shared feature code, a prediction log, a Dockerfile.
7. **CI**: tests (including the skew test) and a quality gate in GitHub Actions, green on `main`.
8. **Monitor**: a simulated or real stream, an honest reference error, alerts, and a measured retraining policy.

## Hand in

- The repository link, with the Actions tab showing a green run and a red one that the gate blocked.
- A README with: what the model does, how to run each step, the gate's rules and why, the monitoring table, and
  what you'd do next.
- One paragraph on the worst bug you found, and which step would have caught it earlier.

## Looking back

- Which step caught the most problems in your project?
- Where did a number look good and turn out to be wrong?
- If you had one day to make this production-ready for a real team, what would you add first?
