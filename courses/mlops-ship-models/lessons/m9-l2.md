# Project 9: a PyTorch model, checkpointed and exported to ONNX

You'll train a small neural network on Bikecast's features with early stopping, save a complete checkpoint, export to
ONNX, check the export matches, and compare the speed of PyTorch and ONNX Runtime.

The code is above this text. Save it as `p09_deep_learning.py`. It needs `pip install torch onnx onnxruntime
onnxscript` (the CPU version of PyTorch is enough).

## Read the code

- **`Net`** keeps each feature's mean and standard deviation as **buffers**: saved with the weights, never trained.
  `forward()` normalizes, runs two hidden layers of 64, and turns the network's output (log of 1 + count) back into
  bikes with `exp(...) - 1`, clamped at zero.
- **Training** uses Adam on mini-batches of 256, with the loss on the log of the count (so busy hours don't dominate).
  After each epoch it scores the validation window; it keeps a copy of the best weights and stops after 8 epochs
  without improvement.
- **The checkpoint** stores the weights, the network's settings, the feature list, project 1's settings, the data
  hash, the validation score and the PyTorch version. It's reloaded with `weights_only=True` into a fresh network, and
  the predictions must match.
- **`torch.onnx.export`** writes `bikecast_net.onnx`, with a variable batch size. ONNX Runtime runs it on all
  validation hours, and the largest difference from PyTorch is printed. Then 1,000 single predictions are timed with
  each.

## Run it

```bash
python p09_deep_learning.py
```

The real output:

```text
1. Trained 69 epochs in 2 s, stopped by early stopping after 8 epochs without improvement; kept the best, epoch 61
   validation (Jan-Feb 2012): MAE 33.3, bias -8.1   (the tree model from project 1: MAE 28.0)
2. Checkpoint: weights, normalization, settings, feature order and data version in one file; reloaded gives the same predictions: True
3. ONNX export: largest difference from PyTorch on 1,433 hours = 0.0007 bikes
   PyTorch       one prediction: 0.050 ms average
   ONNX Runtime  one prediction: 0.010 ms average
   files: bikecast_net.pt 24 KB, bikecast_net.onnx 21 KB. The service image needs onnxruntime (about 15 MB), not PyTorch (hundreds of MB).
```

What it shows:

- Early stopping ended training after 69 epochs and kept epoch 61.
- **The network loses to the trees**: MAE 33.3 against 28.0. On small tabular data, that's normal. It's still a
  useful second model: a different kind of error, and a check on the first.
- **The checkpoint reloads exactly**, and the ONNX export matches PyTorch to within a thousandth of a bike.
- **ONNX Runtime is about 4 to 5 times faster** for one prediction, from a much smaller install.

## Make it yours

1. Log this model to MLflow with `mlflow.pytorch.log_model` and register it as `bikecast-net`. Run project 5's gate
   against the tree champion. Does it pass?
2. Serve the ONNX file: copy `serve.py` to `serve_onnx.py`, replace the model with an `InferenceSession`, and run
   project 7's tests against it. Do the skew and API tests still pass?
3. Average the tree model and the network (an ensemble). Does MAE improve on the validation window?
4. Change `torch.exp(...) - 1` back to `torch.expm1(...)` and export again. Read the error: this is why you test
   exports.

## What to take away

- A complete checkpoint holds weights, preprocessing, settings and data version; put preprocessing in the model.
- Export for serving, and check the export gives the same numbers.
- The MLOps steps don't change for deep learning; the files do.
